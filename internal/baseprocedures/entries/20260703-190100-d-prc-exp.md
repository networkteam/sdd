The explore procedure takes a set of entries that surfaced — a catch-up lane, an engage neighborhood, a topic cluster — and builds the picture: read wide, return narrow. It is designed to run in a disposable context (a sub-agent connected to this server) so the wide reading burns where it costs nothing; the caller passes the targets and a goal, and only the compressed briefing travels back. Without a goal the compression has no axis — the procedure does not start without one. Run inline it still works; the caller then pays the context.

## unit: inspect

Your mission: build the goal's picture from the graph. The targets and their chains, served in full:

{{.entryChains}}

The goal (verbatim): {{.goal}}

**Read the whole surface — do not be shy.** Your context is disposable; under-reading is the only real failure. Everything past the served depth renders as a one-liner, and one-liners are pointers, not facts: any chain node or search result that could bear on the goal gets read in full (`show`) before you judge its relevance.

**Iterate.** Search the graph from several different angles — a concept phrase from the targets, the goal phrase, key terms from the chains, any known identifier. Read the promising results in full. Full bodies name entries and concepts the first pass didn't — those spawn the next angle. Stop when an iteration surfaces nothing new that bears on the goal.

Record per iteration what you searched and what it surfaced in `widenReport`, and every entry you read in full in `inspectedIds` — the briefing stands on exactly those reads.

## unit: compress

Compress toward the goal — selection, not editorializing. For every entry inspected: **keep** it (its content serves the goal), **drop** it (topically adjacent, does not serve the goal), or **mention it briefly** (not load-bearing, but it flags a tension, blind spot, or open question worth one line). Drop for goal-irrelevance, never for brevity: when in doubt whether the outer dialogue needs an entry's context, include it.

Structure `briefing` exactly:

```
## Goal
<the goal, verbatim — the caller verifies the axis it asked for got applied>

## Targets
<per target: full-id · kind · layer · one-line status-aware summary>

## Picture
<how the kept entries connect — the chains and relationships compressed
toward the goal, full IDs inline>

## Neighbors
<each kept search-surfaced entry: full-id, kind, layer, one-line summary,
one-line goal relevance>

## Mentioned briefly
<full-id and a one-line note each>

## Compression note
<one or two sentences: what was dropped and why, so the caller can ask>
```

Rules: every kept or mentioned entry carries its full ID; each kept entry carries enough context that the caller can dialogue and act on it without re-reading; no interpretation beyond goal-relevance — no move suggestions, no rankings, no proposed decisions (that is the caller's dialogue); never omit an entry you judged load-bearing. When the chains already saturate the goal and search added nothing, say so in the compression note.
