The catch-up procedure is the check-in move: brief the user on where the project stands, threaded like a colleague would tell it, and end by asking what they want to move forward. The lanes below are injected fresh each run — the engine assembles the data, you compose the story.

## unit: compose

Produce a fast, useful catch-up for a competent colleague who knows the project but missed the week. **The lanes below are your entire input for composing the briefing** — work directly from them, no other lookups and no follow-up reads until the briefing is delivered. Compose `briefing` in the exact format at the end of this unit.

{{.viewLayout}}

**How to read the lanes.** Cluster by project thread (current relevance, not kind or layer). The Focus block, plus the aspirations and guiding directives from the session framing, are for threading judgment — never content to restate; render focus as a single italic plain-language summary line at the top (skip it when no focus is active). "Active and hot" carries pending work drawing attention; its indented `→` sub-lines show references whose target is now closed or superseded — background, don't render them. "Open loops" is heat's inverse — the coldest active commitments, fresh and un-acted-on; don't render it as its own section: follow each entry's `→` upstream refs to the thread it belongs to and weave it in there, marked as not-yet-acted-on. A genuinely disconnected open loop is its own short "a new direction opened" beat. Thread every entry once.

**Tone.** Write like you're giving the catch-up at coffee. Find the interesting thing — the unblock, the surprise, the convergence — and lead with it. Use causality to thread events: this finished, so this is now possible. Short sentences, plain words, room to breathe. Test each sentence: if you wouldn't say it to a person, rewrite it.

- Swap the jargon: conflate → mix up · encompass → include · operationalize → start using · leverage → use · surface/uncover/expose (verbs) → find, show, catch · manifest → show up · obviate → make unnecessary · load-bearing → important · hot/warm (heat scores) → describe what's drawing attention.
- Passive surfacings ("X was uncovered") → first person past ("we found X, caught it during Y").
- Abstract noun chains → describe the situation in plain words; "breaks X by Y-ing Z" → say the actual consequence.
- Internal references from entry text — slice numbers, AC numbers, version labels, fixture names, commit hashes — describe the work instead; the reader doesn't have that context. Entries use the banned words verbatim — paraphrase even when copying feels natural.
- One adjective is usually enough. Capture what matters, not every nuance. Real names of real things stay: `sdd view`, CQRS, engage, real entry IDs.

**Format — render `briefing` exactly like this:**

```
*Current focus: <plain-language summary, one sentence, or skip if none>*

**<Story-arc header for thread 1>**

<1–3 short sentences of trail. White space between paragraphs.>

1. <Action-tight item> (`<short-id>`).
2. <Action-tight item> (`<short-id>`).

**<Header for thread 2>**

<Short trail.>

3. <Item> (`<short-id>`).

---

**Other open:**

- A. <area>
- B. <area>

Say *drill A* or *survey* for the full picture.

**What do you want to move forward?**
```

2–4 threads, 6–8 numbered items total. Items and trail sentences ≤ ~15 words, no semicolons. Headers are story-arc phrases in bold, never kind names. IDs in backticks: inline in a trail when it names a specific entry, always at the end of numbered items. Drill items: 2–5 short labels, A–E. Don't print lane output verbatim, don't number every entry, don't re-cluster by kind or layer, don't add per-entry lifecycle commentary, and don't add a stats preamble.

## unit: junction

Present the briefing to the user exactly as composed — it is the deliverable, not raw material to summarize. Then the closing question is theirs: what do you want to move forward?

Drilling is free while their answer is pending — `show`, `search`, and `view` are never gated, so "drill A" or "survey" is ordinary dialogue before the junction resolves; for a wide surface, dispatch the explore procedure to a disposable context instead of flooding this one. The lanes named only a slice of the graph and their lines are pointers — when the dialogue turns to a specific area, widen and inspect before asserting what the graph holds.

Relay the user's answer verbatim: **pursue** carries `selectedThread` — their pick in their words; start the follow-up move (usually engage on the picked entry, or capture) as its own procedure with this instance as `parent`. **conclude** ends the check-in with nothing to move forward right now.
