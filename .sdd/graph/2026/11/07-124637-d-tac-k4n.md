The documentation site carries a configuration reference, and the README is cut down to the entry point 20261107-123911-d-tac-ims describes, both live when v0.18.0 ships alongside the getting-started path and entry kind cards of 20260821-181419-d-tac-hq1.

The configuration reference covers every user-facing configuration key with what it does, its default and the file it lives in, the setups for the LLM and embedding providers, and the requirement that an LLM provider support structured output, which Ollama Cloud does not; Opper is named as a gateway for hosted open-weight models. It is derived from the configuration types in the code, not from the README, and documents the configuration shape as it stands. When the named provider entries of 20261106-162723-d-tac-31y land, the reference is updated with them rather than waiting for them now. The getting-started path links to the reference instead of to README sections, and the README is cut once the site pages exist to link to.

Christopher agreed to this scope while reviewing the first getting-started draft, which had to send readers to README sections because the site had no configuration page. A provider setup step became necessary there because the `claude-cli` fallback is slow and can time out. It is delivered in the same implementation run as 20260821-181419-d-tac-hq1.

## Acceptance criteria

- [ ] The site carries a configuration reference covering every user-facing configuration key with its meaning, default and file, the LLM and embedding provider setups, and the structured-output requirement for LLM providers.
- [ ] The getting-started path links to the site's configuration reference, not to README sections.
- [ ] The README is the entry point 20261107-123911-d-tac-ims describes, with its reference sections removed.
- [ ] The configuration reference and the cut README are live when v0.18.0 ships.
