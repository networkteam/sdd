After a fresh clone, connecting the dependencies a repository declares takes one manual `sdd repo add <clone-url>` per dependency, with a clone URL the user has to work out.

**Actual.** A new team member ran `sdd init` in a freshly cloned private repository that declares two dependencies. Init refreshed the skills, then printed one line per dependency: declared but not connected on this machine, run `sdd repo add <clone-url>`, conventionally `https://<repo-id>.git`. Nothing was connected. This is the delivered behavior (20260708-213621-s-tac-cjr): the clone URL is a per-user record in the global config, the committed config carries none (20260708-184318-d-cpt-6cq), so init can only name what is missing. The suggested HTTPS URL is derived from the repo ID; this team clones over SSH, as their GitLab offers by default.

**Expected.** Ideally one command settles it (Christopher, prompted by this onboarding). Hosts such as GitLab offer several ways to check out, HTTPS or SSH, and more may need considering; which one a user takes cannot be baked into SDD, so the solution has to be thought through from the user's interaction at that point. Asking the user and keeping the answer in local config is one unsettled candidate; how it could work is left for a separate session.
