Who may decide what in a graph, and should SDD check it when an entry is written?

The question arose in a meeting between Christopher and Benno on 2026-11-06. It is separate from provenance: participants (20261106-174926-d-cpt-kx0) record who shaped an entry and whom to return to, not who had the authority to decide it. A role can state that authority in prose (20260818-110100-s-prc-rol), but nothing consults roles when an entry is written. Christopher rated the question low priority and had no idea yet how to solve it well.

Strands raised, all unsettled:

- Record or prevent: let the graph show that someone decided without the authority, or keep such writes out. Benno held that writes by people with no authorization at all must be prevented in any case, which authentication partly covers.
- Write permission per entry kind, proposed by Benno as a simple first step: a customer, for example, may write only their own picture (20261106-225324-s-cpt-d5x). It is a hard, deterministic lock that also binds external tools writing over MCP, and Benno saw it and a finer agent check as complementary.
- Ownership of parts of the graph others built, so that re-deciding there from outside meets resistance. This needs durable clusters (20261030-145726-s-cpt-oa2).
- An agent check beyond pre-flight that tests a draft against roles and rules, possibly a continuation of pre-flight once the rule system exists (20260622-084244-d-tac-eho).
- Any check on SDD's write path is bypassed where people can write to the graph's Git repository directly (20260629-204630-s-cpt-1dz).
- Splitting a graph into several repositories, so repository structure carries the autonomy.
