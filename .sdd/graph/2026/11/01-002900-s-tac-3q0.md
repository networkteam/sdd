Ollama Cloud ignores a request's response schema, so pre-flight and the writing guide, which now send a schema instead of describing JSON in the prompt, fail to parse on `glm-5.3-flash:cloud`, the configuration the provider evaluation recommends.

**Actual.** On 2026-11-01 `https://ollama.com` returned prose for `glm-5.3-flash:cloud` on `/api/generate` and `/api/chat` with `format` and on `/v1/chat/completions` with a strict `response_format`, whatever the thinking setting; a local Ollama daemon returned schema-valid JSON for the same request. On this model the format evals of the structured-output plan (20261031-141038-d-tac-p8l) returned mostly prose, where nearly every response parsed before the change ([probe record](./01-002900-s-tac-3q0/probe-record.md)). Ollama tracks the behavior as [ollama/ollama#12362](https://github.com/ollama/ollama/issues/12362), "JSON reply schema is ignored by Cloud model", open since 2025-09-21.

**Expected.** The plan counts Ollama among the providers that support structured output, and the provider evaluation (20260901-093840-s-tac-ahc) recommends `glm-5.3-flash` at `think=low` on Ollama Cloud for all three purposes.

Christopher kept the native-enforcement requirement (20261004-135748-d-tac-ndh) rather than revisiting it. Remedy for this model: through Opper on an EU route (`greenpt/glm-5.3-flash`, `reasoning_effort: low`) the same evals returned parseable responses in every run on 2026-11-01.
