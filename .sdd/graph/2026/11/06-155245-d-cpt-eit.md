SDD's LLM provider access moves off the gollm fork onto provider clients of its own, written over the providers' HTTP APIs, published under `pkg/llm` and serving three separate ports: text generation, embeddings and classification.

Patching the fork, the course the June evaluation set (20260612-120423-s-cpt-jzo), no longer holds (20261031-233819-s-tac-nyd): each new requirement has needed its own fork patch, upstream is unmaintained, and SDD uses a small part of a large library. This closes that evaluation; its requirement list carries over, extended, into the research record.

No library fits better. The official SDKs break the dependency-hygiene rule (20260601-153050-d-cpt-n3y) and grow the binary with services SDD never calls. goai and litellm are dependency-clean, but goai's defaults work against SDD's requirements and litellm reaches Ollama only through its OpenAI-compatible endpoint. None covers TypeSafe's System One or OpenAI's Decisions API, which the eval judge needs (20261005-160413-d-cpt-3sl, 20261031-174216-d-tac-p83). SDD needs a transport of its own on every route, and beyond it little per-provider code remains.

The clients follow goai's structure, not its abstraction: a shared transport with base URL, auth, typed errors carrying status and `Retry-After`, and usage; one OpenAI-compatible codec for every compatible endpoint (20260921-181638-d-cpt-cnu); a package per native protocol. A compatible endpoint is configured by its documented base URL, and the codec appends each operation's path (20261102-142152-s-tac-xzn). `pkg/llm.Request` stays the only request model.

Each provider's client offers what that provider supports. The ports stay separate because their request and result shapes differ: `llm.Runner`, `embed.Embedder`, and a new classifier port answering typed questions with probabilities. Generation clients enforce a response schema natively (20261004-134853-d-cpt-sw8, 20261004-135748-d-tac-ndh) and carry over what the structured-output work delivered through fork patches (20261102-193234-s-tac-vyd).

This refines the boundary directive (20260830-234501-d-cpt-q6n) twice. Retry becomes a caller-side decorator, as its `Runner` contract demands; 20260902-114838-d-tac-cov kept retry in the adapter because a decorator could not see provider headers, which typed errors now expose. `Purpose` is renamed `Operation`, the name the stats file and `llmops` already use.

The clients are public, in this module. The reason 20260902-114838-d-tac-cov kept adapters internal, coupling to gollm, is gone, and a host composing over `pkg/llm` needs them. Factories reading host-private configuration stay internal. A separate repository would put every fix behind a second release.

The implementing plan also covers the decorators: timeout, rate limit, observation, retry and routing are written once, generic over the call, with a thin typed wrapper per port. The configuration shape is decided separately. Evidence and alternatives are in the [research record](./06-155245-d-cpt-eit/llm-provider-foundation-research.md).
