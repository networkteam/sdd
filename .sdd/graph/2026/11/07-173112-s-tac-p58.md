Beyond both plans the site gained the pages "What is SDD?" and "Working modes", and guides for working with coding agents, teams and processes (written from an interview with Christopher), connected repositories and browsing the graph. Writing them against the code turned up drift that stays unrecorded so far: the agent's `sdd serve` never pulls connected repositories, so their new entries appear only after `sdd repo sync`; the embedding config documents an API key fallback to `llm.api_keys` that the code lacks; `llm.concurrency` is never applied; `sessions.retention` is ignored outside the user-global file while `sdd config` shows it as effective; the default model applies whatever the provider; and the type overview lets any entry close a decision while the code admits only directives and signals.
