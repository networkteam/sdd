A caller outside the agent shells reads graph content from the SDD application as data: it loads entries with their direct references on an exact revision, lists entries by filter with paging and counts, receives what changed between two revisions, and gets search hits as typed entries with scores — without parsing text rendered for an agent. It realizes the structured-results directive (20260928-080143-d-cpt-kv4) for `Show` and `Search` and adds `ListEntries` and `Changes`, the two reads a web surface that browses a graph needs beside them; it follows the composition root's query-struct surface (20260830-114446-d-cpt-xc3).

**Additive, not a replacement.** The rendered text fields (`ShowResult.Entries`, `SearchResult.Results`) and the MCP and CLI output stay as they are; the structured fields are added beside them. Moving the shells onto the structured results, so that rendering becomes their concern as the directive expects, is a follow-up and not part of this plan.

**Exact revisions.** `Show` and `ListEntries` take an exact `Revision` through the existing pinned snapshot read and return the resolved revision, so a caller can pin a view and page through it consistently. Dependency repos are still read at their current head; pinning them per repo is left open.

**Changes between revisions.** `Changes(Branch, From, To)` reports entries added in `To` with the IDs they reference, entries whose derived status differs, and entries whose summary was rewritten — the three ways an entry visible to a reader can change, since body and refs are immutable. The diff is a pure function over two graphs. A `From` that cannot be acquired returns `ErrorRevisionUnavailable`, so a caller can tell "start over" apart from other failures.

**Listing and search.** `ListEntries` filters by type, kind, layer, derived status, participants, creation time and text terms, sorts by creation time, pages by offset and returns the total and per-facet counts; built-in base entries are left out unless asked for. Search hits come as typed entries with score and citations, and `Search` gains a status filter applied before the hit limit, so filtered-out entries do not use up hits. Paging and facets stay with `ListEntries`: semantic search returns a ranked top N, and counts over such a set would mislead.

**Shape.** Exported types live in `pkg/application/types` (`GraphEntry`, `ShowGroup`, `ShowTreeItem`, `EntryRef`, `EntryFacets`, `AddedEntry`, `SearchHit`); mapping, filtering, sorting, faceting and diffing are pure model functions that reuse the derivations the presenters use. Entries below the first level carry no body; a done signal's status reads `none`.

Not committed here: moving MCP and CLI onto the structured results; structured `View`; reporting removed entries in `Changes`; per-repo revision pinning for dependency reads.

## Acceptance criteria

- [ ] `Show` with an exact revision returns that revision's entries and the revision itself; without one, the resolved head.
- [ ] `Show` returns each primary as a typed entry with derived status.
- [ ] `Show` returns each primary's upstream and downstream as typed items with ref kind and description.
- [ ] `Show` returns the total of direct refs per direction.
- [ ] `ListEntries` returns entries matching every given filter, sorted by creation time, paged by offset, with the total and facet counts of the filtered set.
- [ ] `Changes` between two revisions names the added entries with their references, the entries whose status changed and those whose summary changed.
- [ ] `Changes` with an unavailable `From` fails with `ErrorRevisionUnavailable`.
- [ ] `Search` returns typed hits with score and citations, and filters by derived status before the hit limit.
- [ ] MCP and CLI output is unchanged.
- [ ] Tests cover each read at the application surface and each pure function in the model.
