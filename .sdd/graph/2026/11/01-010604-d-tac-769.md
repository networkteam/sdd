The structured-output plan's GitHub Actions workflow evaluates three models through Opper, one path per model, each at the setting it would run with in production: `glm-5.3-flash` at `reasoning_effort: low` and `openai/gpt-5.6-luna` at its default effort (`medium`) on the OpenAI-compatible route, and `anthropic/claude-haiku-5-5` at its default effort (`medium`) on the Messages route. Each run reports schema validity and the cost per model and setting. This refines the plan (20261031-141038-d-tac-p8l), which named Opper's two routes but no models; the workflow is the one `sdd eval` later takes over (20261031-174216-d-tac-p83).

All models run through Opper, so evaluation needs one key and one bill. GLM is pinned to an Opper route that supports structured output, because the pooled `glm-5.3-flash` also routes to providers that list none, and a format failure there would not be SDD's. Claude Sonnet 4.6 is left out, performing too poorly for its cost (Christopher). Data residency plays no role, since the eval material is anonymized or public.

Lower efforts are not compared yet: effort levels do not match across model families, and whether quality holds at a cheaper setting needs the judge `sdd eval` brings. Each combination is recorded by its variant, so cost and latency already separate per setting. The cost is the one Opper reports with every response.

A separate provider smoke workflow, one job per adapter, was set aside. Through Opper it checks the adapters against a translation layer that can be more tolerant than the vendors' own APIs: claude-haiku-5-5 accepted a temperature through Opper that Anthropic documents as rejected for that model. Covering the vendors and Ollama would take more keys and a runner with a local model. And the matrix already runs both adapters, so a broken one shows as every run of its model failing. Request shapes stay covered by the deterministic wire tests; live checks against the vendors' APIs and Ollama stay local runs.
