The exported-surface boundary test's allowlist entry for `ProcedureRegistry` is transitional and bound to the CLI migration the composition-root directive (20260830-114446-d-cpt-xc3) implies: when the CLI write and lint paths move onto the application, `ProcedureRegistry` is unexported and the allowlist entry dropped.

`ProcedureRegistry` returns the internal `*engine.Registry` — engine machinery, not movable data — and its only callers are the CLI's raw-finder wiring for `sdd new` and `sdd lint`, exactly the second composition stack d-cpt-xc3 replaces. An external module cannot call the function, which is the condition the boundary test exists to prevent (20260901-185116-s-tac-ah2), so the exception lives only as a named, commented entry in that test's allowlist. This directive exists so the exception cannot quietly become permanent: dropping it is part of what completes the CLI-onto-application migration, not a separate nicety.
