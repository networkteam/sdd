Drive a real Codex agent with the eval-codex skill through a fresh bootstrap and then one capture per entry kind, in a sandbox project set in the Kōgen Coffee world (`docs/story.md`), to see whether an agent that reads only what sdd serves drafts every kind well. This is validation in real use (the outer lens); the code is not re-verified.

This is the drafting-side completion check of the kind-knowledge plan (20260812-134549-d-tac-9be); its harness re-run (20260813-151935-s-tac-14a) exercised only the writing guide, the checker that reviews a draft, not the agent that writes it. The baseline is the bootstrap friction in 20260722-141659-s-cpt-rza: canonicals drafted from full names instead of the configured participant, aliases not collected, roles not pointing at the actor head, each forcing a supersede or restart. The first eval-codex batch (20260924-120119-s-tac-h61) drove the implementation procedure only, and every capture in it was a done.

Scope:

- Bootstrap a fresh sandbox project as the Kōgen team (Mara, Jun, Priya), including their actor and role captures.
- Then one scenario from the Kōgen world per kind that takes new entries: gap, fact, question, insight, done, annotation, directive, activity, plan, aspiration, focus, procedure. Contract takes none and is left out; actor and role are covered by the bootstrap.
- Some scenarios leave the right kind unclear or give the user a wrong framing, to see whether the agent pulls the kind's authoring fact before drafting and pushes back.
- The scripted user speaks as Kōgen's people, following the skill's rules for playing the user.

Finished when every scenario has run, each deviation is recorded as its own entry, and the scenario cards are added to the skill's references so the batch can be re-run.
