Commits `c5d56e7f`, `4032466d`, and `67ecb2de` on `main` deliver three changes the first external hosted composition of the application needed, surfaced when that composition checked its readiness against `main` and found one defect and two places where it had copied application code into its own tree for want of an export. The dependency-closure walk now decides membership on the resolved project: it compared a declared repo ID to the target project ID before resolving it, so a composition whose project IDs differ from repo IDs could never match a foreign target, and every procedure start and read naming another project failed there. That is a defect in what 20260903-172547-s-tac-kqb delivered, measured against the closure rule of 20260903-152247-d-cpt-yjc, whose words already supplied the fix: the declared string is never compared, and a declaration the composition cannot resolve admits nothing. The walk resolves each declared dependency once, the same resolver calls as before plus one for the match; a composition whose resolution is costly caches inside its resolver, now stated on the interface. `PageAttachment` is exported over `fs.FS`, and the local store's pager is a call into it under its own lock and recovery; a caller's mistake is an `ApplicationError` with `invalid_argument`, a missing file the filesystem's not-exist error. `ReadProjectConfigFS` reads the committed `.sdd/config.yaml` from a repository root into a typed `ProjectConfig` with the graph directory defaulted, over the parser the CLI uses, and `ErrNotAnSDDProject` names a tree without one. The local composition reads each connected dependency's cache through it, which also honours a dependency's own `graph_dir` where the default was hardcoded; the CLI's own config path keeps its overlay-aware reader.
