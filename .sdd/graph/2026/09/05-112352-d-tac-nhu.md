Hosts can maintain a project's vector index independently of search, and search callers must explicitly choose their synchronization scope.

This extends the version-aware indexing delivered in 20260717-000200-s-tac-eyc by exposing its reconciliation operation without requiring a search request or synthetic user identity. The aim is a small API addition that reuses existing indexing behavior. Some repeated embedding after failure is acceptable; checkpointing is not required.

## Acceptance criteria

- [ ] A host holding a composed `ProjectRuntime` can call `ReconcileSearchIndex(ctx, cmd)` to reconcile its current graph snapshot and attachments without query embedding, ranking or a request identity. The host owns authorization.
- [ ] Reconciliation preserves the existing index and adds missing entry versions using the existing manifest or chunk-identity path, including existing attachment and embedded-entry rules. It does not clear or rebuild the index on each call.
- [ ] The command returns an error on failure and offers optional scalar callbacks for stored entry IDs and chunk counts, plus successful completion with snapshot revision and totals. Callbacks report persisted work without prescribing persistence order or batch size.
- [ ] Search requires an explicit mode: `none` performs no document embedding or index writes; `local` first reconciles the selected project branch snapshot; `all` also reconciles the dependencies included in the search. Omitted and unknown modes fail explicitly.
- [ ] Search retains stale-version filtering in every mode. Local synchronization covers eligible entry versions in the selected snapshot, not later writes or a globally synchronized snapshot across projects.
- [ ] Existing callers explicitly select their mode. Local CLI and MCP compositions retain their synchronous behavior; public API documentation and the external-composition example show the required choice and independent reconciliation call.

## Architecture and scope

Following 20260413-142536-d-cpt-ah1, a command carries reconciliation intent and callbacks, a handler owns embedding and persistence, and `ProjectRuntime` exposes and delegates the call. Pure selection and chunk derivation remain below orchestration. Search request/query data carries the mode; application orchestration requests maintenance, while finders rank and filter. CLI and MCP shells translate caller choices.

No work limits, checkpointing, new store ports, scheduling, service identities, deletion or GC changes are required. Durable graph-change subscriptions remain separate under 20260905-111056-s-cpt-ne0. Existing verification and delivery conventions apply without becoming acceptance criteria.
