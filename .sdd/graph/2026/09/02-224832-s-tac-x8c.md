Commits `0b937e85` and `679f0236` on `main` rebuild the MCP surface on handles as capabilities and add the CLI listing, closing the capability directive (20260828-165352-d-cpt-aen), the auto-conclude gap (20260828-164140-s-tac-mss), the served-once reconnect gap (20260826-173028-s-tac-1qr), and the participant-per-project gap (20260902-182446-s-cpt-ny6).

What changed. The connection-to-session map is deleted; the server caches loaded sessions by session ID, shared by every connection that presents the handle, and loads a session it does not hold from the store, checking that it belongs to the request's subject and project and has not ended. `start_session` opens a fresh dialogue on every call. `resume_session` takes the handle as its one required argument and re-serves that session's position; `userWords`, `takeover`, and `fullReplay` are gone. `list_sessions` is removed, the door no longer counts other dialogues, and a call without a handle names the two doors and nothing else. No connection event acts on a session: the leave rule, the disconnect watcher, and the exported `Disconnect` are gone, and `Shutdown` only closes live connections. The attachment stamp records which client last attached and when; the version CAS is the sole integrity mechanism. Served-once memory moved into the session ledger as two engine events, the block hashes served and the reorientation that resets them, so a reconnect or a server restart stubs what the consumer already holds and `resume_session` serves everything in full. Session IDs carry 128 bits of randomness. `sdd sessions` lists this project's sessions with open work and `sdd sessions abandon <handle>` tears one down. The shell's routing text says other dialogues are the user's to name by handle. The participant now resolves per project through a required `AccessResolver.ResolveParticipant`, `Principal` carries the subject alone, and the conformance suite checks the new method.

Deviations and things noticed. Abandon by handle no longer refuses a session with a recent stamp: holding the handle is the participant act. Loading a session stamps the loading client, so a cache miss is a write. The external composition that reported the participant gap also reported that one unresolvable project failed `start_session` and that disconnect cleanup called the resolver outside any request; both code paths are gone rather than fixed. The tool-contract snapshot changed accordingly. The delegate-session route through the isolation gap (20260826-225922-s-cpt-pxq) is closed on the engine side; the gap stays open for the delegate's own session and read set. The disconnect fix the release placement (20260902-113959-d-tac-p28) put in v0.18.0 is delivered here; that directive's release claim stays with the release work. Fourteen test functions asserting the retired semantics were deleted and their invariants re-asserted in the new shape, including dedup across a reconnect and across a server restart.
