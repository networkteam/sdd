The application write path runs pre-flight without the per-repo config, so every engine-served capture that carries a cross-repo ref blocks with a high `cross-repo-dep-undeclared` finding even when the target repo is declared and connected. Observed live in an engine session (sdd 0.17.0-alpha.4, MCP over `sdd serve`) on a dependent graph that declares this repo in `.sdd/config.yaml`: the capture confirm raised one identical finding per cross-repo ref while `show`, `search`, and `sdd repo list` resolved and listed the same dependency in the same session, and local refs drew no findings. Confirmed by code reading: `pkg/application/write_api.go` constructs the pre-flight finder with only the LLM runner and the procedure registry, so `Finder.declaredDependencies()` (internal/finders/finder.go) returns nil and the declared-dependency check runs against an empty list; the CLI write path passes the config (`cmd/sdd/main.go`) and accepts the same refs. A retry after `sdd repo sync` cannot change the outcome, the check reads nothing sync touches. Expected: declared dependencies are committed per-repo state that the pre-flight precondition reasons against (20260708-184318-d-cpt-6cq), and the gate enforces it identically on every write path. The same absent config also withholds participant and language from the engine path's LLM pre-flight, one more surface acquiring per-repo config by its own plumbing (20260901-100956-s-tac-83h). Reasoning from the dialogue, marked as such: the finder degrading to an empty list on nil config is what let the defect ship silently, so the candidate remedies are feeding the runtime's config into the write-path finder and making pre-flight fail loud when it runs without config; neither is decided here.
