Reworked `sdd index gc` after the review of PR #13 in commits 01b02b48 and d86cc1a2 on branch worktree-index-gc, bringing the code under the alignment frame of 20260911-121434-d-cpt-cm2 and extending the delivery recorded in 20260911-093252-s-tac-144.

A `--drop` group a store does not hold is skipped and named in that store's result line instead of failing the run, and a selected repo without a local cache is skipped with a note; only the current group is still refused. The report sizes rows inside the same shared lock that reads the manifest. Both delete paths now save the manifest before deleting rows, and `--force` keeps rows the rebuilt version reuses. The report lists row files no manifest version references, and every drop run removes them.

The review corrected one claim of mine: I had argued that deleting rows before saving the manifest converges harmlessly, but the published read view fails on a missing row, so a failed save would have left every search failing until a rerun. That finding is what the ordering rule in the directive comes from. Merge into main and the release remain pending.
