Commit b8f51b24 on branch `worktree-multi-project-mcp` makes the MCP wrapper serve every project its principal can reach through one endpoint, closing 20260902-000146-d-tac-1z6. The change lands in v0.18.0 (20260902-113959-d-tac-p28).

What changed. `start_session` takes an optional `project`; a sole accessible project is inferred by the application, and with several and none passed the response lists them with status `project-required` instead of opening a session. Every other tool carries the session handle and takes project and branch from it, the reads `search`, `view`, `show`, `read_attachment`, `info`, and `registry` included. The served handle is `<project>:<session-id>`, split at the last `:s_` at the doors that load a session from its store (`resume_session`, `abandon` by handle); a bare session ID still resolves where the project can be inferred. `Options.Project` is optional and pins the project when set. `vocabulary`, which the directive lists among the reads, is not a tool but a field on serves; it now renders from the session's project.

The inventory and what changed on each item: session shell step text (`user-dialogue`): the routing sentence no longer calls reads ungated. Base procedures: catch-up's drilling sentence and bootstrap's readiness read say the same; capture and groom texts stand, since "reads stay free" remains true in the sense that no move gates them. `sdd-engine` skill template and installed renders: unchanged, nothing there names the changed arguments. MCP server instructions and every tool description: rewritten to the handle-on-every-tool contract. Open-threads and resume serves: carry the composed handle. Tool-contract snapshot: new hash. External composition example: drops the pinned project. Documentation site and README: name no session tool, nothing to change. `sdd serve` keeps its pinned project; its stdio tests open a session before reading.

Deviations from the directive. The application is not untouched: it gained one read, `Application.Projects`, because nothing exposed the access resolver's project listing to a shell. The handle form was settled in dialogue during this run: composed in the wrapper rather than minted by the application, so the stored session ID and the local store stay as they were; the alternative, probing every project's store for a bare handle, was set aside as slower and muddier in its errors. `registry`, unlisted in the directive, carries the handle too. `list_sessions` stays out of scope, its removal belonging to the capability rebuild, but without a pinned project it had no project to list; it now lists across the principal's projects, the smallest change that keeps it working until it goes. The door breadcrumb on reads is gone, since a read without a session is now refused naming the doors; only `view` keeps its one-time grammar pointer.

Not exercised: a live run against a hosted multi-project composition. The multi-project shape is covered by tests over a two-project access resolver (`multiproject_test.go`).
