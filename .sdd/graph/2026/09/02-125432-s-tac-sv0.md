The public LLM surface is complete: commit `78346daa` on branch `worktree-llm-composition-surface` adds the chat composition pieces to `pkg/llm`, creates `pkg/llm/embed`, deletes the context-carried sink, the adapters' self-recording, the five-method internal embedder, and the application's embedding port, and recomposes the CLI on the exported pieces.

Against the listing attached to 20260902-114838-d-tac-cov, every named item landed. `pkg/llm` carries `Bounded`, `RateLimited`, `Observed` with `CallStat` and `StatsSink`, and `ByPurpose`. `pkg/llm/embed` carries `Purpose`, `Request`, `Result`, the two-method `Embedder`, `EmbedderFunc`, and the same three decorators. The OpenAI and Ollama adapters return identity and usage, select their template by purpose, and attribute failures through the typed error. `ProjectRuntimeOptions.Embedder` replaces `Embeddings`; the application maps chunks to vector positions and reads the vector space from the fingerprint. The conformance suite, the local adapter tests, and the external composition example moved with it. The CLI composes one stats sink for chat and embedding, and the indexer takes its bucket size from the resolved configuration instead of an interface method, since the two-method contract has no `BatchSize`.

Four points deviate from the listing's signatures. `StatsSink.RecordCall` takes the call's context, so a host sink can read the same request-scoped facts a routing runner reads, and the local debug log line moved into a logging sink in front of the file sink, keeping `pkg/llm` free of a logging dependency. `CallStat` carries a `time.Duration` instead of milliseconds; the file sink converts at the wire, Christopher asked for this during the run. The local embedding factory composes the rate limiter but not `embed.Bounded`: one application `Embed` spans a whole cold reconcile, so a whole-call bound would fail exactly the calls that legitimately take longest, and the per-round-trip deadline stays in the adapters' HTTP client. `embed.Bounded` is exported for hosts whose embedder is one round-trip per call. The recorded operation names change from `embed-documents` and `embed-queries` to `embed-document` and `embed-query`; existing rows keep their names and `sdd stats` shows both.

Two consequences follow. The embedding decorator records one row per `Embed` call with the batch size in `Items`, not one per HTTP round-trip as the adapters did; the CLI indexer still buckets by round-trip, the application path records one row per reconcile. And `Observed` with a nil sink returns its argument unwrapped, so skipping recording shows as an empty stats file rather than a failed call.

A live `sdd search` through the rebuilt path recorded an `embed-query` row with provider, model, items, tokens, and duration. The parse-failure classification gap (20260831-093815-s-tac-k7d) stays open: the observing decorator still sits below the operations that parse. The commit awaits the merge into `main`, which has moved on since the branch point.
