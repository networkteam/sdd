The graph is the authority over the search index, the index's manifest is the authority over its rows, and keeping them aligned runs in two directions of different weight: indexing must be reliable, cleanup is best effort.

The store for one repository and embedder fingerprint serves several graphs at once: the checkout's own, other branches and worktrees, and binaries with another derivation rule (20260708-184318-d-cpt-6cq). Each has its own current versions, and no single checkout can see them all.

Direction one, graph to index, is `sdd index` and the lazy fill before a search: every current entry of the checkout gets a version under the current rule and fingerprint. It fails loud and publishes per entry so progress survives interruption. Read-time filtering keeps only versions whose hash matches the entry's current state, so extra versions never produce wrong results.

Direction two, index to graph, is `sdd index gc` (20260910-183941-d-tac-c9c). Extra versions cost disk and nothing else, and another checkout's current versions look like garbage from here, so cleanup is deliberate and best effort: it reports groups per store, drops only what the user names, skips and reports a group or store it cannot act on, and converges on rerun. Its one hard rule is refusing the checkout's own current versions.

Inside a store, reads materialize the manifest row by row and fail on a missing row (20260906-165355-s-tac-hjq), so the manifest must never name a row that does not exist: a row exists before the manifest names it and is deleted after the manifest stops naming it. Orphan files are the only tolerated inconsistency; the report shows them and every drop run sweeps them. `--force` is direction one redone for the binary's own rule, replacing that rule's old rows the same way.

A fingerprint change starts a new store directory because its vectors are incomparable; a derivation change stays in one store as a group. Both are direction one rebuilding and direction two cleaning. Known scope: a store directory left behind by a fingerprint change is the same garbage one level up and is not yet reported.

Changes to indexing or cleanup are measured against this frame: a safeguard that makes direction two stricter or direction one more lenient is the wrong safeguard.
