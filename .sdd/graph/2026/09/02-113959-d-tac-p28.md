v0.18.0 gains at least two additions, the disconnect fix and the multi-project MCP wrapper; v0.17.0 stays as committed, and the capability and delegation arcs follow after the engine-first focus ends (20260824-093559-d-tac-onl), capability first.

Both additions ride on the retirement plan (20260821-123832-d-tac-ip1) without changing its criteria. The disconnect fix removes the trigger of the auto-conclude gap (20260828-164140-s-tac-mss): a release that declares the engine the only flow must not let a routine reconnect end a dialogue. The multi-project wrapper (20260902-000146-d-tac-1z6) changes the tool contract for every user, which belongs in a release already declared breaking, and a hosted consumer built against the v0.17.0 beta waits on a release that carries it; a v0.18.0 prerelease is that release. The change is confined to the shell, so it does not inflate the release.

The predecessor (20260829-171841-d-tac-46a) fixed the additions at exactly one, and three days later bounded work with a waiting consumer had no release. A minimum keeps the rule that mattered, no unplanned subsystem work bound to a named release, without a supersession each time bounded work arrives.

The capability rebuild (20260828-165352-d-cpt-aen) stays out of v0.18.0 because its plan does not exist yet; the wrapper change is a subset of it and leaves the connection map and `list_sessions` to it. After the focus, the rebuild comes first because it deletes the connection map, consent arguments, and MCP listing that the delegation pair (20260827-232430-d-cpt-voa, 20260829-122157-d-cpt-zpe) would otherwise build around.

Fulfilled when v0.18.0 ships with both additions and the capability implementation plan exists.
