Version garbage collection in `sdd index` evicts index versions written by a binary with a different entry-hash rule, so two sdd binaries sharing one store re-embed each other's work.

Observed on 2026-09-10 on this repository's local store. Commit 07383c65, part of the delivery recorded in 20260906-165355-s-tac-hjq, prefixed the entry state hash with a derivation version, changing every entry hash. The dev binary's `sdd index` re-embedded all entries under the new rule, and its collector dropped every old-rule version older than the retention window: the manifest held no version older than the window and one version per entry from that run. A v0.17.0 MCP server running since 2026-09-08 then found no version matching its rule and re-embedded the whole namespace ahead of each query. That release persists vectors once after the full set, so cancelled calls kept almost none of the embedded chunks.

Expected: the multi-version manifest exists so several writers share one store per repository (20260708-184318-d-cpt-6cq), and the mixed-binary scoping (20260716-235744-d-cpt-vri) held that mixed writes cause only bounded, self-healing churn. The collector as shipped (20260717-000200-s-tac-eyc) treats every version absent from the collecting writer's current hashes as stale, guarded only by the retention window. The guard delays the eviction; it does not prevent it.

Deviation: the scoping analysed manifest-shape changes, where an old binary parses new entries as empty and deletes nothing. A hash-rule change parses cleanly on both sides, so each side's collector deletes the other side's versions, and the losing side re-embeds its whole namespace instead of churning within bounds. The scoping's one-binary-per-store assumption also missed the ordinary case of a CLI upgraded under a long-lived MCP server of the previous release. The `--force` rebuild replaces all versions of an entry and carries the same hazard.

Unsettled reasoning: the discard on cancel is already changed in main by per-entry publication (20260907-154209-s-tac-1j3); the eviction is not.
