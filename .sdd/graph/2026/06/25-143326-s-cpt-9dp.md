Referenced entries need a human-facing surface alongside the mention — bare entry IDs don't communicate to a human reader, so the graph's references should be carried by a surface, not the prose. Two forms: an inline hover gloss (the ID as a definition-like anchor revealing its summary's first sentence on hover) and a dedicated references pane that surfaces the entries being mentioned for browsing as they come up. The inline gloss keeps detail one gesture away; the pane frees the prose from IDs almost entirely. Demonstrated (inline form) in the rule-system design artifact, where every referenced ID became a hover gloss sourced live from the graph's stored summaries. It applies the same two-tier "visible anchor, detail on demand" principle the rule activation index uses (`20260608-232836-s-cpt-smn`) to a human reading surface rather than agent context, gives concrete shape to the "ref hover" UX the agent-agnostic web sandbox direction already names (`20260523-143653-d-stg-6za`), and is a sibling to the visual-browsing-frontend gap (`20260416-113122-s-tac-bta`). Corollary: the summary's first sentence is the natural gloss unit, so summary fidelity and slimness matter at the human reading surface, not only in catch-up.
