SDD asserts an inner/outer, three-point evaluation model but gives the skill no canonical pattern for *capturing* evaluation findings, leaving three things ad-hoc: (1) no marker distinguishing an evaluation entry from a work entry, and no convention to relate sibling inner/outer reviews of one change into navigable coverage; (2) the artifact-durability gate (prior commit / entry-attachment / upstream-attachment) has no path for a human-attested manual verification where nothing was committed because nothing changed in code — a facet that surfaced trying to record a fresh-session verification during a Go-native runtime spike — and we have determined that a participant's attestation *in a human-in-the-loop dialogue* should count as a durable trace, the human-in-loop condition being the anti-loophole that an agent's unilateral self-claim is not (preserving the rigidity fix the gate was built for); (3) no guidance on whether an evaluation finding is a fact, an insight, or a done that addresses the evaluated commitment, so the fact-signal route gets used ad-hoc. Resolving it likely turns the committed-but-unwritten evaluate lens-move into real guidance — a playbook-evaluate.md and/or an evaluation-capture section — plus a durability-gate change; whether evaluations get a first-class marker or stay a reading convention over refs, and how siblings relate (related edges, an annotation cluster, or a new marker), remain open.
