The read-layer ref-kind alias drifts summary-prompt hashes, creating a re-summarize treadmill — render the stored on-disk kind in the summary prompt to end it. The summary-generation prompt (RenderSummaryPrompt -> FormatEntryForPrompt) renders each ref's parse-resolved kind, so the grounds/evidence -> grounded-in alias changes the prompt for every entry that cites those kinds, and its stored summary_hash goes stale under the new binary. Clearing it requires re-summarizing with the exact text (done for ~23 entries so far, 5 from a single merge), which also re-marshals the frontmatter and canonicalizes the refs on disk — broader than "just the hash" and a recurring cost as old-binary sessions keep authoring grounds/evidence object-refs.

The durable fix: the summary-prompt path renders each ref's STORED on-disk kind rather than the parse-aliased kind, so the alias never enters the summary-prompt hash — zero drift, no re-stamp, and legacy files stay byte-stable, honoring the read-layer transform's no-history-rewrite intent. Wrinkle: FormatEntryForPrompt is shared with the pre-flight prompt, which must keep seeing the canonical grounded-in to judge ref-meta. So preserve the raw on-disk kind on the parsed Ref (e.g. an unexported field set in UnmarshalYAML) and use it only in the summary-prompt rendering; pre-flight and user-facing render stay canonical.

The approach is agreed and narrow — implement and short-loop close in a fresh session. Validate by confirming the previously-stale legacy entries (and any new grounds/evidence object-ref entry) report no stale hash without any re-summarize.
