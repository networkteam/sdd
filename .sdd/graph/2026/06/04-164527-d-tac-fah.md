Make the pre-flight system prompt a byte-stable, type-independent preamble (validator role + ref-kind vocabulary + output/verdict format + always-on partials) shared across every check type, and move all variable content — the per-type checks and calibration, plus the graph input (proposed entry, refs, active contracts) — into the user prompt, so sequential captures within a session reuse Anthropic's prompt cache. This realizes the cache-eligible-prefix intent the SystemPrompt/UserPrompt split was built for (d-tac-bes) but never achieved, because the prefix still varied per check type and per graph state (s-tac-osb). The chosen approach, the universal-vs-variable inventory, rejected alternatives (per-type-stable; layered breakpoints), the gollm caching mechanism that constrains the design, the eval-suite validation path, and open questions are in the attached design doc (./04-164527-d-tac-fah/pre-flight-cache-restructure.md). Verifying the win depends on surfacing cache metrics, which the gollm path drops today (s-tac-sae).
