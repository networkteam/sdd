Shipped the ref-meta advisory recalibration: pre-flight now reserves `[high]` for genuine precondition violations (a ref-kind inapplicable to the target's status/kind, or a desc the body refutes) and caps any defensible-but-sharper choice at `[low]`, so ambiguity between applicable kinds no longer blocks. The terminal-`done` tie-break is single-sourced in the ref-kind vocabulary — `addresses` does not apply to a completed fact, so `builds-on`/`grounded-in` are canonical when a later entry takes up a follow-up a done flagged. This realizes the calibration directive (d-prc-v0h) and closes the non-determinism gap (s-prc-uh3): the airtight oscillation case (identical input producing contradictory `[high]` blocks that each recommended the other kind) now produces zero findings on Sonnet, while real precondition violations still fire high. Validated via the pre-flight eval suite on Sonnet — the model the defect was reported on. Implementation reached beyond the directive into the eval harness: the suite moved to an external `llm_test` package driving the real `llm.Preflight` orchestrator through the production factory Runner (provider/model configurable via `SDD_EVAL_PROVIDER`/`SDD_EVAL_MODEL`, default claude-cli + Sonnet) instead of a bespoke single-model CLI reconstruction, with a calibration case pinning the terminal-`done` shape and a category-keyed ref-meta detector. Commits 339b0f1 (calibration + eval refactor), d4e5452 (docs). The directive stays active as the standing calibration rule.
