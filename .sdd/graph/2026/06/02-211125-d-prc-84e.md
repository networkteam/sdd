Treat the sdd dev repo and consumer repos as two tooling contexts with different currency mechanisms. Here the binary is built from source as an untagged dev build that bypasses the version gates (s-tac-3al), so currency comes from the auto-rebuild hooks shipped under d-cpt-lgs — not branch-pinning. Consumer repos install a released, tagged CLI whose participation is governed by the minimum_version write gate, with no tooling-in-repo to keep current. Backward-read-compatibility is universal (d-cpt-i2x) — it holds for both binary types and is not part of this split. The branch-pinning proposal in s-prc-vm7 conflated the contexts; naming them dissolves it.
