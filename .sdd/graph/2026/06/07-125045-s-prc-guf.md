We repeatedly change one part of the system without tracing the change to what it's connected to — by code or by concept — so a connected part gets left un-updated and the system drifts into inconsistency, with no general discipline catching it. Wanted: a change's impact on connected areas gets considered before it ships. Actual: it doesn't, so a new feature or rule risks not being surfaced everywhere it should be, and the inconsistency sits unnoticed. The only existing coverage is the narrow type-system→presentation rule (s-prc-2f2); the general case is unaddressed. Instances: a ref-kind rule change left the eval fixtures that encode it stale (s-prc-lsg); graph features shipped with no CLI surface to reach them (s-tac-z04).
