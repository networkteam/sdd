SDD commits to running on multiple agent harnesses by generalizing its skill and instruction source into agent-neutral templates rendered per agent, with Claude Code becoming one render target among several (Codex first; Pi, OpenCode, Gemini Antigravity anticipated). This is a thin port — skills plus a shell-invoked `sdd` CLI, the same shape Claude Code uses — deliberately orthogonal to the MCP-gate path: an independent reading on whether instruction-carried discipline survives on a foreign agent, in service of agent-agnosticism, not a step toward structural enforcement.

Decisions: (1) full generalization now rather than bolting Codex on incrementally, because several harnesses are anticipated and the restructure is cheaper done once. (2) One template source, dual-rendered to distinct per-agent skill dirs — `.claude/skills/` and `.agents/skills/` hold different rendered content, so they are rendered separately, not symlinked; per-agent deviations (Claude's dynamic `!`cmd`` injection and Skill-tool sub-skills vs Codex's instructed `$skill` invocation and explicit `run sdd …` steps) are template conditionals, never duplicated definitions. (3) Skills conform to the Agent Skills standard (agentskills.io); SDD stamps move under `metadata:`, intended runtime under `compatibility:`. (4) A committed `supported_agents` list in `.sdd/config.yaml` (multi-select at `sdd init`, idempotent re-render of all listed); all rendered dirs are committed, so per-contributor selection is unnecessary — each harness reads only its own dir. (5) Instructions bridge via a canonical `AGENTS.md` imported by `CLAUDE.md` (`@AGENTS.md`), chosen over a symlink because it is the documented Claude Code pattern, cross-platform, leaves room for agent-specific notes, and fits the render model; `sdd init` scaffolds the bridge only when absent, never overwriting.

Alternatives rejected: symlinking the instruction files and skill dirs (cannot express per-agent conditionals, and rendered content differs per agent; weaker on Windows); incremental bolt-on per the cheap-to-add-later principle of the neutrality directive (set aside in favor of generalizing once); and treating the MCP-gate server as the route to Codex (orthogonal — the thin port tests instruction discipline independently and first).

Grounded in the research finding that the format already conforms to the open standard (s-cpt-3gm), resolving the runtime-portability gap (s-cpt-z7l) that had assumed build-time rendering, embodying the single-source principle from the rendering-contract candidate (s-cpt-oql), operationalizing the agent-neutral foundations directive (d-stg-574, which already shaped the install command for multi-agent target selection), and closing the multi-agent install-model gap (s-cpt-vye) by settling its data model: one committed supported-agents list, no per-contributor target.
