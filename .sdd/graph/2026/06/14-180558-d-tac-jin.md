On an existing tree, an explicit `sdd init --agents` selection fully replaces and persists `supported_agents` in `.sdd/config.yaml`, written through a new sequence-capable YAML upsert (mirroring how the existing-tree path already upserts `skill_scope` via the scalar patcher). Chosen over additive-merge (union into the recorded set, never dropping — rejected as asymmetric, since removal would still need a hand-edit) and scope-style reject-contradiction (recorded value stays authoritative, conflicting flag errors — rejected because it leaves the gap's hand-edit workaround in place). Full-replace keeps one intuitive model — `--agents` sets the project's agent list and records it — and the change is explicit and git-reviewed.

When the new selection drops an agent that was in the previously recorded set, `sdd init` prunes that agent's rendered skill files, reusing the same `SkillStatus` content-hash classification that drives overwrite protection — so pruning is symmetric with installation: only files sdd produced and the user has not modified (Current or Pristine) are removed, while user-modified files (Modified) are preserved, reported, and removed only under `--force`, exactly as install refuses to overwrite a modified file without `--force`. Non-sdd skills sharing the directory are not bundle entries, so the classification never sees them and they are never touched. Emptied skill subdirectories and the now-empty parent skills dir are cleaned up; the prune reports what it removed and what it kept.

A bare `sdd init` (no `--agents`) on an existing tree is unchanged: the recorded value still wins, and the upgrade path with no recorded value stays re-derived rather than silently persisting a default. Resolves the upgrade-path-persistence gap (s-tac-kor) left open by the multi-agent render plan.
