Reading an entry's attachment has no CLI surface, so agents fall back to `find`/`grep` through `.sdd/graph/` to locate the file. `sdd show` prints the attachment as a path relative to the graph dir with no hint how to open it, so the agent can't act on it directly and reaches into the on-disk layout by hand — coupling itself to a directory structure that isn't promised stable. The attachment mechanism today is write-only (`--attach`, plus the planned upload-token surface d-tac-6zt); the read side — get me this entry's attachment — is unaddressed for both the local CLI and the forthcoming MCP/external-agent surface.
