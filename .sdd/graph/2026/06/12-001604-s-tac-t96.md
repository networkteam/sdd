sdd's OpenAI LLM provider sends `max_tokens` (via gollm's `SetMaxTokens(4096)` in `internal/llm/gollm/gollm.go`), which gpt-5-class models reject with HTTP 400 — they require `max_completion_tokens` instead. Confirmed against `gpt-5.4-2026-03-05` during the first Codex eval; the Anthropic path is unaffected because Anthropic accepts `max_tokens`, so only OpenAI gpt-5.x pre-flight and summary calls break. sdd has no lever from its side (`SetMaxTokens` is the only token-budget parameter the gollm API exposes); the fix belongs in the networkteam/gollm fork's OpenAI request builder — emit `max_completion_tokens` for models that require it — followed by bumping the `replace` pseudo-version in go.mod.
