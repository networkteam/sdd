`sdd view`'s built-in help — the `viewHelpText` constant printed on a bare `sdd view` invocation — lists only the `active`, `kind`, `layer`, `since`, and `topic` filters and omits `untagged`, `id()`, `not()`, and the `as-counts` render terminator, all of which ship and work in sdd 0.11.1. A reader of the help therefore concludes those features are missing. In a downstream session this caused a real misdiagnosis: the help was read as proof the installed binary was an older slice, when in fact only the help text had drifted — every feature ran correctly when invoked directly. The `cli-reference.md` skill doc documents the full vocabulary correctly, so the drift is solely in the hand-maintained help constant, which was never updated as new filters landed. This is another confirmed instance of the systemic untraced-impact gap (20260607-125045-s-prc-guf): a change shipped without updating a connected surface. The `not(<filter>)` primitive (20260507-214631-s-tac-2b0) is concrete evidence — it shipped with full acceptance criteria and tests, yet the help that enumerates filters was left listing the old set.
