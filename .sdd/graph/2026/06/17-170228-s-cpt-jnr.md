Intaking a living, mutable external source (wiki, docs site, database, knowledge bundle) into SDD's immutable graph turns on two mechanisms that one-shot transports never needed: a stable identifier carrying source attribution for each external item — so a later sync recognizes "this is the same item I took in before, from that source" rather than treating it as new — and change detection — so a re-sync acts only when the item actually changed. Without stable attributed identity, every sync accretes duplicate intake entries; without change detection, the graph silently goes stale against a moved source. With both, re-sync has clean options: re-intake the changed item as a fresh intake signal, or surface only the drift for grooming. OKF offers natural hooks for both (a concept's path-identity and `resource` URI, plus a `timestamp` of last meaningful change), but the principle generalizes to any mutable source — OKF is only a currently-hypothetical example. The intake directive (20260603-172628-d-cpt-fbi) recorded provenance for event-like inputs but never needed a re-syncable identity; the cross-repo reference work (20260529-131915-d-cpt-v8t) already tackles stable external identifiers, though for other SDD graphs rather than arbitrary external sources.
