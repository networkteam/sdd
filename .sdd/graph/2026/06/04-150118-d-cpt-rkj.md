Commit to a deliberate, consistent output policy across the sdd CLI and tooling surface, serving two audiences on purpose rather than by accident: human readers (readable, decorated) and agents/machines (clean, decoration-free, structured). Today neither is deliberate — output is bespoke ad-hoc text whose unspecified syntax is the actual fragility, independent of whether agents currently parse it well (an open, unmeasured question, not a claimed defect).

The policy:

1. Structured-with-prose views like `sdd show` render in a standard format — YAML frontmatter envelope (metadata, refs, closes, supersedes, attachments, derived status/topics) + raw markdown body — rather than invented label/arrow syntax, mirroring how entries already live on disk so output and storage share one shape.
2. Programmatic callers get JSON via `--format json` and MCP `structuredContent`.
3. Operational logging goes to stderr and results to stdout, so progress, lazy-index, and skipped-index chatter never buries the actual output.
4. Decoration (color, TUI) is TTY-detected and honors NO_COLOR, with configuration precedence flags > env > config > defaults.
5. Prefer specified standard formats over bespoke rendering everywhere — the fragility lives in invented syntax, not in any one format choice.

This makes the deliberate decision the agent-vs-human rendering gap called for and closes it (s-cpt-idq). It also supersedes the narrow visual-separation directive for `sdd show` (d-tac-y9q): that directive's goal was clean read-flow between the summary and the body, which this policy carries by removing the blur at its source — the primary's stored summary moves behind an opt-in `--with-summary` (default off), since the canonical body renders immediately after it, so there is nothing to visually separate for the default reader; the summary is retained only for human drift-review. y9q's indent-plus-rule fix was never present in the output anyway.

Per-command operationalization is tactical follow-up grounded in this directive: restructuring `sdd show` (summary opt-in via `--with-summary`, the upstream/downstream tree representation, and a micro-summary-at-depth — the tree and micro-summary settled by measuring against the real graph), separating `sdd search`/`lint`/`index` operational logging onto stderr, polishing `sdd init`/bootstrap output, and wiring MCP `structuredContent`.

External benchmarks favoring YAML for nested-data comprehension are small-model results (GPT-5 Nano, Llama 3.2 3B, Gemini Flash Lite); for SDD's frontier-model reader the comprehension gap narrows, so standardness, token cost, and storage-consistency drive format choices more than the accuracy delta.
