Instrumented the embedding path so it feeds the same `.sdd/stats/llm.jsonl` stats sink the chat path uses, closing the embedding-observability gap. Added an `Items` field to `CallStat` (per-batch input count; 0 for chat) and an exported `llm.RecordEmbedCall` that debug-logs and records a stat for the metadata-less embed path. Both embedders now time each HTTP batch and parse the token count their provider already returns — OpenAI/omlx `usage.prompt_tokens`, Ollama `prompt_eval_count` — emitting one record per call with op `embed-documents`/`embed-queries`, provider, model, items, input tokens, and duration. Verified live against Ollama `qwen3-embedding:8b`: a 19-document batch recorded 4387 tokens in 13.7s (~720ms/doc) and a query embed 23 tokens in 184ms — the hard numbers an Ollama-vs-omlx comparison needs and lacked before. Commit 71a0d36.
