Remove the `sdd status` command entirely and migrate every surface that uses or references it onto `sdd info` (the session header) and `sdd view` (the overview pipeline shipped in d-tac-uww).

Catch-up and `/sdd` session start already run entirely on `sdd view` — Recent done, Active and hot, Open and warm — plus `sdd info` for the `Local participant` / `Language` / `Search` header. `sdd status` is off the hot path, surviving only as a convenience line in `sdd-groom` / `sdd-bootstrap` and as a manual smoke-test. Everything its sections render is already expressible as view layouts: the kind-grouped overview via the `decisions` / `signals` / `aspirations` / `contracts` macros, `participants` via the participants block, and recent work via the `insights` / `done` macros. Keeping a parallel overview presenter is redundant maintenance and a standing drift risk against `sdd view`.

Surfaces to migrate: the `status` command in `cmd/sdd/` and its `query` / `finders` / `presenters` status layer plus tests; the `sdd-groom` and `sdd-bootstrap` "run status" steps (toward `sdd view` + `sdd lint`); the stale `Local participant:` header rule in `/sdd` SKILL.md (it is injected via `sdd info` now); status-notation references in `framework-concepts.md`, `playbook-groom.md`, `search.md`, `meta-process.md`, `vocabulary-de.md`; the `cli-reference.md` command entry; and the `CLAUDE.md` smoke-test line. The Participants-block and derived-status-notation explanations relocate to their `sdd view` / `sdd show` homes rather than disappearing.

Chosen over keeping `sdd status` as a thin alias of a composite `sdd view` layout — an alias preserves a second name and its teaching burden without removing the drift surface.
