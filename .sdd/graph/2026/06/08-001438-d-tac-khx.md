Plan for v1 of `sdd stats`: usage analytics over the LLM/embedding stats sink. Implements the read surface the directive commits to, focused on the two proven needs — usage rollups and provider/throughput comparison — with the dual-audience output contract. TTY rendering builds on the v2 charm stack (lipgloss/table) just put in place. Activity stats (graph-derived) and a live `--watch` monitor are scoped out of v1 and recorded in the attached design as follow-ups. See [design](./08-001438-d-tac-khx/design.md).

## Acceptance criteria

- [ ] `sdd stats` reports usage rolled up by model/provider over a selectable date range (all-time / 30d / 7d): call count, tokens in/out, cache read/create, total duration. [U1]
- [ ] `sdd stats` reports per-op rollups (preflight, summarize, embed-documents, embed-queries) with throughput — tokens/s, ms/call, and items/s for embedding ops. [U2]
- [ ] Non-TTY invocation emits the same aggregates as structured JSON on stdout, no TUI chrome (per d-cpt-mvb). [X1]
- [ ] Reads `.sdd/stats/llm.jsonl`; an absent or empty sink yields a clean "no stats yet" result, exit 0, not an error.
- [ ] The TTY output's visual design — layout, headings, colors, styling — is reviewed and refined with the user before the plan closes; the `design.md` mockups are the starting point, not the final spec.
