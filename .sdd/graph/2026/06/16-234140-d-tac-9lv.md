When the directive `intent` attribute ships (d-tac-n9k), run a one-time pass over the active directives that carry no intent and stamp each — pending, guiding, or settled — by superseding it with an intent-carrying successor. The authoritative scope is computed at execution: check every directive whose intent is still `unknown` at that time, since the graph keeps growing and any list frozen now would read as complete when it is not. Supersede deliberately rather than deriving a default — intent records a decision, not a guess. Each supersede follows the fold-in rule (d-prc-u61): an active refinement is folded into the successor and closed, or deliberately rebased; a refinement pointing at an already-superseded target (surfaced by `expand(refs(inactive))`) is promoted to a standalone directive. New directives created after n9k carry intent at capture, so the unknown set only shrinks. The attached classification (./16-234140-d-tac-9lv/example-classification.md) records the worked example from the reliability + CLI loose-ends sweep that produced this activity — a starting point that illustrates the call, not the full set. Grounded in the intent-attribute directive (d-cpt-cyx).
