Implements cross-repo references end to end in two layers — a reference foundation, then cross-graph discovery — realizing the augmented design (d-cpt-s6q) under the universal ref-resolution invariant (d-cpt-ba7). The foundation lets entries carry `<repo-id>:<entry-id>` refs that store and read back unchanged, render with the canonical repo-id prefix and the remote entry's status from the cache, and resolve-or-block at capture. The discovery layer adds a user-global connected-repos registry and embedding config, sdd-managed read-only caches of other repos, cross-graph search merged by comparable cosine score, and full cross-graph traversal in `sdd show`. repo_id is auto-derived from the git remote at init (host/path, Go-module style) and self-declared; `sdd repo add <clone-url>` derives the id from the cloned repo and registers its clone URL. Depends on the terminal-experience architecture (d-cpt-mvb): the feature is feedback-heavy, so all new operational output goes through slog and reporter callbacks, never ad-hoc stderr. The foundation is independently shippable; discovery follows the terminal-experience groundwork. Design, alternatives, code placement, and file-level changes are in the attached spec.

## Acceptance criteria

**Foundation**

- [ ] Writing a cross-repo ref `<repo-id>:<entry-id>` stores the string verbatim; reloading yields the identical ref (prefix + kind intact), it is not mistaken for a local id, is not indexed as a local ref, and raises no dangling-ref warning; `sdd new --refs` accepts it with syntactic validation of both parts.
- [ ] A cross-repo ref renders with the full canonical repo-id prefix and the remote entry's derived status read from the cached graph, in `sdd show`, `sdd view` expand(refs), and lists; an unresolved repo renders `[unresolved: repo X]`.
- [ ] Capture blocks at high severity when any ref — local or cross-repo — fails to resolve; cross-repo resolution auto-fetches on cache miss and blocks only if the target is absent from the other repo's default branch.

**Discovery**

- [ ] `sdd init` derives and commits `repo_id` (host/path from the git remote, ssh and https forms normalized equal) when absent; it is not user-choosable.
- [ ] A user-global `~/.config/sdd/config.yaml` holds connected repos `{repo_id, clone_url}` and the shared embedding config; `sdd repo add <clone-url>` clones, verifies the repo declares that repo_id, and registers it; `sdd repo list` / `sdd repo remove` manage entries.
- [ ] Connected repos cache read-only at `~/.cache/sdd/<repo-id>/` with lazy clone plus cooldown pull (`sdd repo sync` forces); the local repo keeps indexing itself at `.sdd/index/`.
- [ ] `sdd show <repo-id>:<entry-id>` resolves via the cache and renders the remote entry; cross-repo chains traverse fully, bounded by max-depth with `(repo-id, entry-id)` dedup.
- [ ] `sdd search` and `sdd view` accept `--repo <id>` (repeatable, additive to local) and `--all-repos`; results merge into one list by comparable cosine score with remote hits repo-id-prefixed; a repo indexed under a mismatched embedding config is excluded and flagged by `sdd lint`.
- [ ] Pre-flight runs the ref-meta consistency check against the cached remote entry for cross-repo refs.
- [ ] Cache clone/pull runs as a CLI-orchestrated command, not inside a finder; finders read over already-loaded graphs and indexes; all new operational logging uses slog via `slogutils.FromContext`.
