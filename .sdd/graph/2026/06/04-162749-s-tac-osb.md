Pre-flight's system prompt isn't a stable cacheable prefix: each check type has its own system block, and it embeds volatile graph content (active contracts, and — until dropped — the full open-signal set), so sequential captures within a session can't reuse Anthropic's prompt cache. The same brute-force whole-graph context scales badly as the graph grows — prompt size and latency climb with every added open signal or contract — and risks biasing the validator by diluting its attention from the proposed entry toward unrelated entries. The SystemPrompt/UserPrompt split (d-tac-bes) was introduced precisely for cache-eligible prefix matching, but the prefix it produces isn't byte-identical across captures, so that intended win is largely unrealized. Candidate direction: make the system prompt a byte-stable, type-independent preamble and move all type-specific checks and graph input into the user prompt.
