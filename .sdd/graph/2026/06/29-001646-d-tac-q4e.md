No new `sdd lint` check is needed for a settled directive carrying a closing edge — the anomaly is already caught at load by `validateCloses`. The gap (s-tac-lmu) assumed lint was blind to this, but tracing the capture path showed otherwise. `validateCloses` runs on every entry at every graph construction, not just at capture, so a hand-edited rogue close already surfaces in `sdd lint` today — flagged on the closer, with a message that names the settled directive. Normal capture cannot produce the anomaly at all: the `validateCloses` warning is a hard reject in `model.ValidateEntry`, and `--skip-preflight` does not bypass it (that flag only skips the LLM pre-flight, which runs separately and later). A concurrent-write race is ruled out too, because `intent` is immutable (a directive is born settled, never becomes settled later) and a `closes` edge must resolve its target at capture — so the target is always already settled when checked, and is blocked. A directive-side mirror would therefore add no new detection, only a second warning on the masked entry, and the existing closer-side message already points a reader at that entry. This directive is born terminal: it records a no-action finding and needs no follow-up; if the underlying `validateCloses` coverage ever changes, supersede it.
