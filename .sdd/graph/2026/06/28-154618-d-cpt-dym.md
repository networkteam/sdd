This graph is the development record of SDD-the-product; the base SDD process — how a participant runs the dialogue, grounds claims, captures and maintains the graph — ships inside the framework (skill text and CLI) and must be correct on its own, because it runs on every other project. Therefore the `guiding` value of the intent attribute (d-cpt-cyx) is reserved, in this development graph, for standing context that shapes SDD's development: (1) directives governing SDD's code or tooling (CLI, type system, validator), or (2) meta-direction for how we evolve the methodology. It must never mark (3) concrete process content — the actual rules and conduct a participant follows — because that would make the process's correctness depend on entries that live only in this repo's graph and never travel. A base-process directive is an ordinary development decision instead: pending until its skill text ships, then closed. This meta-pitfall is specific to dogfooding — building the very tool you track — which is also why this principle is itself safely guiding here without needing to travel. It was surfaced while executing the intent backfill (s-tac-i7k), which mis-stamped several base-process directives (dialogue architecture, capture grounding, graph-authoring rules) as guiding.
