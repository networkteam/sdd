Build the v1 graph-resident rule system: a new `rule` decision kind that lets any project grow its own process layer on a lean core, with learnings resurfacing as in-flow guidance and as enforcement at capture. Realizes the rule directive (`20260608-190808-d-cpt-30v`) — the follow-up plan it deferred — and folds in pre-flight-as-second-consumer (`20260611-085648-d-cpt-0ah`). Grounded in the discovery design synthesis (`20260608-232836-s-cpt-smn`) and the prototype evaluation plus 8-rule seed corpus (`20260608-235644-s-cpt-7ca`).

A rule carries `enforcement` (binding|advisory, required) and a bundled `activation` block with `when` (free-text, semantic) and/or `matches` (structured kinds+operations, mechanical) — at least one. The body holds only What to consider / How to calibrate. In-flow delivery is uniform advisory (dialogue pushback + agent context, never blocks); binding gates only at pre-flight, the existing overridable capture checkpoint. Discovery uses an always-loaded, deterministic `when`-only activation index plus a two-agent move at existing junctures. Pre-flight selects rules by `activation.matches`, blocks on violated binding rules and weights severity from advisory ones, and validates rule quality on both the skill capture surface and a `rule_capture` check.

Two conscious deviations from the records: (1) `contract` and `rule` coexist transitionally — this plan deprecates `contract` and supersedes the 7+7 contract (`20260506-191632-d-cpt-ni0`) with a transitional enumeration; removing the kind and migrating existing contracts (with its intent-coordination dependency, `20260610-000444-s-cpt-iuh`) is out of scope. (2) The structured `matches` trigger ships in v1 (not the "later optimization" the synthesis assumed), because folding pre-flight in requires a machine-checkable selector. Rendering is on `sdd view` / `sdd show`, not `sdd status` (being retired by `20260610-000311-d-tac-oei`).

See [the spec](./22-084244-d-tac-eho/rule-system-v1-spec.md) for the full design, alternatives, implementation surfaces, and tests.

## Acceptance criteria

- [ ] A `rule` decision kind exists: required `enforcement` + bundled `activation` (`when`/`matches`, at least one); validation enforces enforcement validity, the at-least-one-trigger rule, well-formed `matches`, and the What-to-consider / How-to-calibrate body sections; entries roundtrip byte-stable.
- [ ] `contract` is deprecated: the skill steers new captures to rules, existing contracts stay valid, and the kind set is a transitional enumeration superseding `20260506-191632-d-cpt-ni0` carrying both kinds (removal and migration out of scope).
- [ ] `sdd rules index` lists active `when`-bearing rules slimly and deterministically (no LLM), excludes `matches`-only rules, and is always-loaded into `/sdd` via inject.
- [ ] Semantic discovery: a rule's `activation.when` embeds as its own chunk, and a discovery move (playbook + sub-skill) surfaces applicable rules with body at planning / pre-implementation / review, delivered as guidance, never blocking.
- [ ] Pre-flight consumes rules: rules selected deterministically by `activation.matches` against (entry kind, check-type); binding violations produce a blocking high finding (overridable via `--skip-preflight`); advisory rules weight severity; a `rule_capture` check validates rule entries (mechanical + calibration); existing code checks are not re-homed.
- [ ] Capture: user-initiated authoring and a graduated system-proposed nudge (light, ignorable to full proposal only on recurring-or-verified friction) are in the skill capture discipline, with "what a good rule looks like" guidance on both the skill and the `rule_capture` check.
- [ ] Usage tracking: applying a rule adds a `grounded-in` ref from the shaped entry; heat surfaces useful rules with no new code beyond the convention.
- [ ] Rendering via `sdd view` / `sdd show`: a `rules` macro, `rule` in the `decisions` macro, `[enforcement: ...]` as a stored attribute on entry lines, `enforcement` groupable for `group(by(enforcement))`, MCP tool schema and docs (framework-concepts, cli-reference, vocabulary-de) updated; `sdd status` untouched.
- [ ] The 8-rule seed corpus from `20260608-235644-s-cpt-7ca` is captured as the first rules and exercised as discovery + pre-flight fixtures.
