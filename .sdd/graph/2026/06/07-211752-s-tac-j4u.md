No CLI surface exists to inspect or monitor the LLM/embedding stats the sink writes — `.sdd/stats/llm.jsonl` can only be read by hand-grepping, which is how both the prompt-cache numbers and this session's omlx-vs-ollama embedding timings were obtained. We need a read surface serving both audiences per the terminal-experience architecture (d-cpt-mvb): a TTY-facing view a human can scan or monitor live (per-op/provider rollups, throughput, recent calls), and clean structured stdout an agent can parse. The data already lands as one JSON record per call (op, provider, model, items, input/output tokens, cache read/create, duration) from the chat path (s-tac-bmw) and now embeddings. Shape questions deferred to dialogue: snapshot vs. live `--watch` monitor; which aggregations and filters (by op, provider, time window) earn their place.
