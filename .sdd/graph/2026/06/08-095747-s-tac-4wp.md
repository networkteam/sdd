Shipped `sdd stats` v1: a read surface over the per-call stats sink (.sdd/stats/llm.jsonl) reporting usage rolled up by model/provider and per operation with throughput, over a selectable --since range (all-time default, durations, or ISO date). Interactive terminals get a lipgloss-styled table; the agent and non-TTY path emits structured JSON with the same aggregates. All five acceptance criteria are met: usage rollups by model/provider (U1), per-op throughput including items/s for embeds (U2), JSON parity on the non-TTY path (X1), a clean "no stats recorded yet" result on an absent or empty sink at exit 0, and the TTY look reviewed and approved live. Implemented across the CQRS layers — pure aggregation and throughput math in model, a reader in llmstats sharing the on-disk Record with the writer (single path, round-trip tested), and query, finder, and presenter on top.

Two deviations from the plan's design doc, both forced by reality rather than chosen. The design assumed lipgloss v1's table package, but the charm v2 upgrade had landed minutes before the plan was captured, so the implementation builds on lipgloss/v2 instead. That turned up a v2 behavior the design did not anticipate: Render emits ANSI unconditionally and downsampling moved to the writer layer, so output routes through a colorprofile writer to keep NO_COLOR and terminal-profile handling — the idiomatic v2 pattern, not a workaround. Three of the design's open questions were resolved at implementation: default --since is all-time, the non-TTY default is JSON rather than a plain table, and throughput is included in the JSON by_op block for agent parity. The deferred items — a live --watch monitor and graph-derived activity stats — remain v1 follow-ups. Code committed; vet, lint, and tests across all layers pass.
