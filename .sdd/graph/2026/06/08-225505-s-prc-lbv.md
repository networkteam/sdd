Pre-flight emitted a blocking `[high]` ref-kind-inapplicable finding whose own text concluded "Retracting — this is not a finding," yet the severity label stayed `[high]` and rejected the entry — the finding's reasoned verdict and its severity score diverged within a single emission. The ref under review was `addresses` on an open `gap` signal, a case where the precondition plainly holds (the framework reserves `addresses` for responding to a gap/question/insight), so this is a fresh post-recalibration leak of the applicable-never-high guarantee (d-prc-v0h). It is the same class as the cross-run oscillation instance (s-prc-pex) but sharpened along a distinct axis: there the verdict flipped across runs; here a single run reasons correctly in prose ("addresses on an open gap is exactly correct") while the blocking severity is decoupled from that conclusion. The only workaround that passed was `--skip-preflight`. Two candidate directions, not yet chosen: couple severity to the finding's textual conclusion (detect a self-retraction and downgrade it), or pull the mechanical "applicable ref-kind → never high" determination ahead of the LLM advisory so applicable cases are never scored by it at all.
