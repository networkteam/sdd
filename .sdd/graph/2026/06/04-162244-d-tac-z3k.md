Restructure `sdd show`'s output onto the policy's renderer model, scoped to this command — cross-command logging cleanup, `sdd init` polish, and MCP `structuredContent` wiring remain separate follow-ups under the policy.

The current bespoke block (padded labels, inline `{status}`, `→ refs (kind)` arrows, `[truncated]`) is replaced by a standard, dual-audience rendering: a YAML frontmatter envelope + raw markdown body for the entry, and a compact markdown tree for the upstream/downstream neighborhood. Two reading renderers share one data model — a lipgloss-styled view for terminals and a plain markdown view for agents and pipes — selected by TTY detection and `--format`. This operationalizes the output policy (d-cpt-rkj) and its three-renderer refinement (d-cpt-5f4) for `sdd show`; `--format json` is deferred so its schema can be defined once alongside MCP `structuredContent` (d-tac-0v4). The rendering conventions and the rejected nested-YAML-tree alternative are recorded in the attached design (./04-162244-d-tac-z3k/show-rendering-design.md).

## Acceptance criteria

- [ ] Primary entry renders as a YAML frontmatter envelope (metadata, refs, closes, supersedes, attachments, derived status/topics) + raw markdown body, replacing the bespoke label/arrow block.
- [ ] The primary's stored summary is omitted by default, shown only when `--with-summary` is passed.
- [ ] Upstream/downstream render as a compact markdown tree — one line per node `<ref-kind> <full-id> (<entry-kind>, <status>) — <first-sentence>`, indentation encoding depth, with a `desc:` sub-line when the ref carries one.
- [ ] Depth (>0) summaries are the referenced entry's first sentence, derived at render time with no change to stored summaries; the full summary renders only on the primary and under `--with-summary`.
- [ ] At the `--max-depth` boundary, a node's unexpanded refs render as an indented child-level line `+N more refs truncated (depth N): <ids>`, never inline on the parent node.
- [ ] Renderer is selected by TTY detection plus a `--format text` override and `NO_COLOR`, precedence flags > env > config > defaults: lipgloss-styled (indent guides, relation-kind color, dimmed status) on a terminal, plain markdown otherwise.
- [ ] Both renderers consume one entry+tree data model produced by the read side (finders); rendering stays in the presenters layer — no graph traversal or status derivation in the renderers.
- [ ] Tests cover both renderers (golden snapshot for the markdown form; styled form asserted with color disabled), including the depth-boundary truncation and a deduped `(see above)` node.
