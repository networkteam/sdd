A framework that runs as a guest inside an agent harness has a hard ceiling on enforcement: it can only hard-gate its own tools, never the agent's native ones — so reliable working-mode discipline must be split by surface. The durable shape that falls out: drive the agent by setting its next goal (host-neutral, no tool ownership, leaning on reliable goal-following rather than self-imposed standing discipline) for the general flow, and reserve hard gates for the framework's own write tools (the capture/record path), where the produced artifact can be checked; any harness-level hook (such as a Claude Code Stop hook) is an optional, agent-specific hardening layer on top. Two honest consequences hold throughout: enforcement can only ever check the recorded artifact or stored state, never the agent's process (forcing a reference into context is possible, forcing that it was absorbed is not), and the goal-driving and hook layers raise the floor against silent skipping without guaranteeing good execution. This reasons from the structural-enforcement finding (s-cpt-h5c), sharpening it with the guest-surface constraint, and generalizes the goal-driving / per-mode-instructions design (s-cpt-r57).
