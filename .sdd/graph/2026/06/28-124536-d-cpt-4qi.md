Summaries are derived artifacts with no automatic staleness tracking: generated once at capture and regenerated only on demand — `sdd summarize <id>` (or `--text`) when someone judges a summary poor or drifted, the same fidelity fix already run right after `sdd new`. There is no skip-hash and no generation-version; `sdd summarize --all` fills only missing summaries, and `--all --force` is the deliberate bulk-regeneration path.

This rests on entry immutability (d-cpt-e1i): an entry's meaning is fixed at creation, so its summary needs no change-detection. The only thing that could date a summary is a neighbor's summary improving — which we already choose not to track — and `sdd show` renders live neighbor status regardless. A per-entry content hash therefore guards against changes that cannot occur while generating false-staleness noise, and sweeping prompt improvements across a large graph by bulk regeneration is not worth the cost.

Supersedes the skip-hash-stabilization plan (d-tac-44v), which is moot under this model — there is no skip-hash to stabilize. It resolves the re-summarize treadmill (s-tac-pfn) and born-stale-attachment (s-tac-gcd) gaps at the root rather than by stabilizing the hash; both close when the on-demand model is implemented. Implementation — removing the hash machinery and reshaping `sdd summarize` / `sdd lint` — is deferred to a follow-up plan.
