`sdd summarize --all` never settles in one pass over cross-referenced entries — each run reports a different, shrinking set of stale-hash warnings until it eventually converges. Root cause: the summary-skip hash is computed over the full LLM prompt (`ComputePromptHash(RenderSummaryPrompt(...).Combined())`), and that prompt embeds the **summary prose** of every refs/closes/supersedes neighbor (`internal/llm/summary.go`). Neighbor summaries are non-deterministic LLM output, so re-summarizing one entry changes its prose and invalidates the stored hash of every entry that points at it — a re-summarize treadmill that damps out only when the prose happens to stabilize, with the most-connected entry settling last. The coupling surfaces whenever a single summary in a dense ref cluster is regenerated: the wave propagates from each re-summarized entry to everything that references it. This is the same treadmill koz named (s-tac-koz); its on-disk-ref-kind fix removed the ref-kind cause but left neighbor prose as a second, deeper source. Distinct from the summary-body content-drift family (s-cpt-tdp): this is hash *stability*, not content fidelity. Candidate fix: compute the skip-hash over stable inputs only — the entry's own body and frontmatter plus neighbor identity — while keeping neighbor summaries in the prompt sent to the LLM.
