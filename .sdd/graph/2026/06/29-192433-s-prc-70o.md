The /sdd skill's instruction to load the evaluation reference (evaluation.md) on entering Evaluate mode is not clear or salient enough to reliably trigger the agent. The instruction exists — the mode table says load the mode's reference first — but "validate it" did not register as the Evaluate trigger ("a done landed, user asks about it"), so the load step never fired and the evaluation (recorded as s-tac-g55) ran without the reference: only the outer lens was applied, and the finding-kind framing was absent at capture time. This is a fresh instance of pattern-matching a new task (s-prc-uq8) — the shortcut, "validate" as a quick check, won out because the mode-recognition cue was not sharp enough to override it. Sibling to the engage-skips-attachment hole (s-prc-lfb), another mode/move discipline that did not fire as intended. Near-term fix: sharpen the trigger and the instruction so entering evaluation reliably engages the reference-load — a clearer mode-recognition cue and an explicit load step (the queued playbook-evaluate.md is a natural home). Making the juncture a hard checkpoint that re-assures the mode before continuing — rather than relying on a clearer instruction — is a separate, harder open question.
