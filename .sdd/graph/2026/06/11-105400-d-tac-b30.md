Change the built-in default LLM model from Haiku to `claude-sonnet-4-6`, so unconfigured installs gate captures on the same model class the pre-flight calibration eval measures. The default was set with the pluggable provider layer in April, when summaries dominated call volume, and was never revisited once pre-flight became the highest-stakes LLM call in the pipeline — a blocking validator tuned on Sonnet but enforced by Haiku on fresh installs is calibrated against the wrong model. One Sonnet-class call per capture is an acceptable cost on the default claude-cli transport, and summaries gain quality from the same change. This also corrects an observation in the reliability rework's verification report (s-tac-lpa): the claim that this graph's live captures ran on the Haiku default was wrong — local configuration here already selects Sonnet via the API, so the default change targets fresh and unconfigured installs, not this graph. A per-operation model split (separate pre-flight and summary models) remains a possible future refinement, deliberately not committed here.
