Adopt the Go agent runtime (agent-sdk-go) for SDD's hosted-agent runtime, superseding the Mastra (TypeScript) direction. This is the verdict the comparative spike plan (d-tac-dcn) was built to produce: both throw-away spikes cleared the shared bar (Go: s-tac-f6k; Mastra: s-tac-i6m), so it is not a capability gap but a stack choice — and Go wins on the dimension that compounds. The entire SDD core is already Go, so an in-process agent calls the existing finders and handlers directly with zero CLI/agent drift, versus Mastra's second Node stack and out-of-process bridge. Mastra's one real edge was UI maturity, and the Go spike showed the assistant-ui/CopilotKit UI is reachable by owning one AG-UI adapter plus the vendorable community Go AG-UI SDK; the accepted cost is a heavy transitive dependency tree and a pre-1.0 agent-sdk-go with rough edges. The runtime is not LLM-free, but its LLM use stays in three clean roles, all served by Go: deterministic rails (mode state, goal sequencing, the mechanical gate); a separate in-loop validator LLM (pre-flight judgment, semantic rule discovery — already in the Go llm package, in-process, the validation-separation contract d-cpt-vt1); and the worker LLM (external Claude Code for the developer case, where SDD embeds none; embedded agent-sdk-go only for the non-technical hosted webapp). Keeping the validator and rule-discovery LLM calls next to the graph in one Go process is a further argument for Go over a TypeScript-to-Go bridge. Consequence: the CLI-parity MCP server (d-tac-0v4) is downgraded from prerequisite to optional — in-process needs no bridge, so it earns its keep only for non-Go external agents. Supersedes the Mastra directive (d-cpt-t3j), whose TypeScript-end-to-end rationale is outweighed once both spikes clear the bar and the single-Go-stack benefit is counted.
