Framework-concepts' retirement table lists "directive retiring it" as a valid close path for `plan` decisions, but `model.validateCloses` rejects any directive→plan close — only directive→{contract, aspiration} is permitted, and every other decision-closes-decision is pushed to supersedes. The documented retirement model and the validator therefore disagree on whether a directive can retire a plan without completion. Hit while capturing d-cpt-4qi, which had to *supersede* the plan it retires rather than close it. Resolve by reconciling the two: either widen `validateCloses` to allow directive→plan retirement with rationale (matching the doc), or correct the retirement table so plans retire only via supersede or a done signal. A concrete instance of the untraced-inconsistency pattern (s-prc-guf).
