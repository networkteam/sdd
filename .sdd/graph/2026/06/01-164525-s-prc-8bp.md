The manual git-worktree workflow has friction at three points — entering the worktree session, carrying over local state, and concluding the merge. When an agent implements a plan in a worktree, it sets up the WIP marker, branch, and worktree but then stalls, because the session stays bound to the main directory; `/add-dir <worktree>` lets the same session continue and is less disruptive than starting fresh. A new worktree copy lacks `.sdd/config.local.yaml` (participant identity, embedding and vector-search config) and the `.sdd/index/` vector index — both gitignored, so `git worktree add` doesn't carry them — so the first search lazily re-generates a large number of embeddings, which is slow and wasteful. And there is no clean recipe for concluding the work: once the user confirms, the natural flow is to sync, merge the branch back into its base, and remove the worktree. This extends the original directory-bound-session friction (s-prc-tha) with a key update — `/add-dir` removes the exact disruption that justified keeping worktrees out of the CLI in the first place.
