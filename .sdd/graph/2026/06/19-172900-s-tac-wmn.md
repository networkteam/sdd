`sdd view` offers no way to filter or group by participant: there is no `participant()` filter, and `group(by(...))` buckets only on kind, layer, or type — so answering a routine question like "what did participant X capture this week" forces a direct grep over entry frontmatter, the one dimension the pipeline does not index. This surfaced while briefing on a single participant's recent captures in a downstream project running sdd 0.11.1, where grepping frontmatter was the only reliable way to pull entries by author. It extends the `sdd view` pipeline delivered by the now-closed view plan (20260506-151345-d-tac-uww), which built filter, group, rank, and render primitives but never a participant dimension. It is the concrete tooling slice of the broader participant-profile question (20260421-213535-s-cpt-5jk), which asks about profile-based relevance filtering and routing; this gap is narrower — just the missing author/participant filter on the existing view surface.
