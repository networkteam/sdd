`sdd view`'s `as-counts` render bakes the grouping axis (topic) into the render terminator instead of exposing it as an explicit, composable pipeline step, leaving two parallel aggregation mechanisms that don't compose. The shape originated in s-cpt-sy4's own "as-counts render" framing, and was reinforced because effective topics are set-valued — an entry carries several, including via annotations — so they don't fit the single-field partition model behind `group(by(kind)):as-grouped`; as-counts therefore shipped as a dedicated terminator (`model.Graph.TopicCounts`) deliberately made mutually exclusive with `group`, `rank`, `n`, and `expand`. The cost is an implicit grouping dimension readable only from the render name and an aggregation path that can't be recombined with the rest of the pipeline. It also aggregates by full leaf label with no roll-up by path prefix, so hierarchical labels never sum to a family row (`type-system/topics` and `type-system/kinds` stay separate) even though `--topic` filtering is already component-wise-prefix aware. Proposed direction: model topic — and topic-prefix or depth — as an explicit grouping dimension (e.g. `group(by(topic))` feeding a counts render), so aggregation composes like every other stage and rolls hierarchical labels up to family level.
