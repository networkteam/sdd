Build slice 1 of the workflow MCP server inside the sdd binary, per the experiment design attached to the workflow-MCP directive (20260609-234656-d-cpt-afn): a `sdd serve` subcommand hosting a per-session state machine with four dialogue-loop tools — open-session, ground, capture, show-entry — whose responses return graph data plus just-in-time instructions, with pre-flight gating writes. The state machine enforces the gate half of the guide/gate split: capture is refused when no grounding call has happened in the session. Serve stdio and streamable HTTP transports, with a bearer-token guard on HTTP (token via flag or environment variable): the agreed evaluation setup runs both clients — the ChatGPT 5.5 and Claude Opus 4.8 desktop apps — over HTTP through an ngrok tunnel, since desktop connectors reach the server from vendor cloud rather than localhost, and the token keeps the briefly internet-reachable write path closed to strangers. Implementation borrows the serve subcommand shape, the modelcontextprotocol/go-sdk choice, and the structured pre-flight findings shape from the CLI-parity plan's spec (20260527-210616-d-tac-0v4); graph state may start as naive load-per-call. Done when the server runs against this repo's graph, an integration test drives all four tools as an MCP client, exercises the grounding gate, and confirms HTTP requests without the token are rejected, and the vet/test/lint gate is clean. The experiment itself stays with the directive: two scripted evaluation runs (one per client), each captured as an evaluation signal with transcript attached and per-behavior hold/partial/fail verdicts against the design note's five observed behaviors.
