Commit to an experiment-first path for the MCP direction: build a minimal stateful workflow MCP server inside the sdd Go binary — session state per connection, dialogue-loop-shaped tools that return graph data plus just-in-time instructions, and pre-flight as the gate on writes — and test whether a foreign agent with no shell access and no skill content can complete one full SDD loop guided only by tool responses. This develops the two-layer specialist insight (s-cpt-r57) into a one-codebase shape: the specialist's actual jobs — session state, serving the right instructions at the right moment, gating writes — fit a deterministic state machine in Go, so the server is deliberately not an agent. The connecting client supplies all LLM reasoning and tool-call orchestration; server-side LLM use stays limited to the existing single-shot pre-flight and summarization calls, with MCP sampling as a later option for routing those through the client. The experiment bar: catch-up orientation, dialogue, and one validated capture completed end-to-end by the client agent — the evaluation script with five observed behaviors and the guide-vs-gate split is in the attached [design note](./09-234656-d-cpt-afn/experiment-design.md).

This deliberately runs parallel to the staged two-phase directive (d-cpt-313), the CLI-parity server plan (d-tac-0v4), and the Mastra architecture choice (d-cpt-t3j) rather than superseding them — enough planning has happened; the experiment's evaluation decides their fate. Instruction compliance confirms the Go-resident specialist in one codebase and retires the CLI-parity stage as a separate deliverable; non-compliance is the signal to add server-side intelligence, where an external agent runtime regains relevance. The doubt motivating this turn: the CLI-parity layer has no standalone consumer — Claude Code does not need it and foreign agents flounder on raw tools without guidance, as the skill-content half of the portability gap (s-cpt-z7l) predicts and this experiment directly tests. Grounded in confirmed protocol facts (s-cpt-80v): per-session state, sampling, and elicitation make a stateful Go-resident server feasible. Closes when the experiment returns a verdict — pass, fail, or partial compliance — captured as an evaluation signal against this directive.
