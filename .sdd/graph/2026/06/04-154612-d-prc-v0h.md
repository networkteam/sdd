Calibrate pre-flight's ref-meta advisory so it never blocks on ambiguity: a ref-kind whose precondition holds for the target is *applicable*, so the strongest finding it may draw is `[low] ref-kind-sharpness` — `[high] ref-kind-mismatch` is reserved for kinds whose precondition is actually violated (e.g. `refines` on a closed target, `depends-on` pointing backwards). High severity must mean *the kind is wrong*, not *a sharper kind might exist*; when several kinds are each applicable there is no error to block on, so by definition it cannot be high. This generalizes d-prc-2is's "demote defensible-but-sharper mediums to low" lever up to the high tier, responding to the gap (s-prc-uh3) where the advisory blocked valid entries with contradictory `[high]` verdicts on equivalent input. It also fixes the advisory's *recommendation*, not just its severity: applied to the recurring terminal-`done`-with-flagged-follow-up shape, the relationship `addresses` names — responding to an open gap/question/insight or realizing a decision's commitment — does not hold for a terminal done (a completed fact is none of those), so the canonical kind is `builds-on` (the next step after a finished chain) or `grounded-in` (only when the body reasons from the done as empirical evidence), never `addresses`. The validator's observed advice to switch `builds-on`→`addresses` on a done target was wrong by the vocabulary, which is why pinning the tie-break matters alongside the severity cap. Alternatives weighed and set aside: pinning model determinism (temperature 0 / N-run agreement) — rejected because the variance is inherent to a fuzzy judgment and the cleaner fix is to stop gating creation on it; a standalone conceptual entry for the tie-break — folded in here since the two levers are one calibration decision. Implementation (rewriting the rubric severity boundary and adding a calibration-eval case for the terminal-done shape) is a follow-up plan; this directive sets the principle, and the gap closes when that ships.
