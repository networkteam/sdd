The corrected worktree recipe — marker created on base before entering, `--force` teardown — held end to end in a real feature-implementation session (the `sdd stats` v1 build), resolving all three friction points this gap named: session binding (handled by the harness via EnterWorktree/ExitWorktree), local config and vector-index carry-over (`.worktreeinclude` brought both, so no slow re-embedding), and the lack of a clean conclude recipe (marker-on-base, enter, work/commit/done on the branch, then exit, pull, merge, wip-done, teardown — no backtrack). The `--force` teardown was genuinely necessary: the `.worktreeinclude`'d gitignored state (config, index, built `bin/sdd`) leaves the worktree non-clean, so a plain `git worktree remove` would have refused. Marker-on-base did its job — visible at base, carried into the worktree via `baseRef:head`, removed at base after the merge.

One limitation, deliberately left for real-world discovery rather than a separate follow-up: only the happy path (a clean fast-forward merge) was exercised. The conflict-on-merge and discard branches of the conclude recipe remain unvalidated; we will learn from the first real conflict case.
