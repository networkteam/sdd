Fixed the OpenAI gpt-5 `max_tokens` incompatibility by teaching the gollm fork's OpenAI request builder to emit `max_completion_tokens` for gpt-5-class models, then repinning sdd to the patched fork. The fix extends gollm's existing `needsMaxCompletionTokens` predicate — which already covered o-series and `4o` models — to `gpt-5*`; both `SetOption` and every `PrepareRequest` variant route through that one predicate, so all request paths are covered. Verified by unit tests in the fork: a model-detection table over gpt-5 / gpt-5-mini / gpt-5.4-2026-03-05, plus a `PrepareRequest` test asserting the body carries `max_completion_tokens` and never `max_tokens`. Shipped as a focused branch off upstream `main` (gollm `6bb6876`, opened as PR teilomillet/gollm#61) and cherry-picked onto the networkteam fork integration branch (`19e75fe`); sdd's go.mod `replace` now pins the combined fork at `v0.0.0-20260614104521-19e75febe86b` (sdd commit `2a7bd9a`). The OpenAI provider path now works for gpt-5 summary and pre-flight calls; the Anthropic path was never affected.
