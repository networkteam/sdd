Implement the directive `intent` attribute — `pending | guiding | settled` — committed in d-cpt-cyx: stored frontmatter supplied explicitly at capture, the `DerivedStatus` terminality branch, `{status: settled}` rendering across all status surfaces, the pending/guiding read split delivered through `sdd view` and the `/sdd` + catch-up injections, and a pre-flight rubric requiring settled directives to justify themselves.

Scoped to the directive kind only — activity and plan are inherently pending, and completed work terminates via done signals, so extending `settled` to other kinds is deferred until a concrete need appears. New directive captures require an explicit `--intent` (no default — a default would fabricate the non-derivable value the attribute exists to capture honestly); legacy directives with no intent read as unspecified, rendered exactly as today. The settled-status rendering extends the derived-status notation already shipped across the CLI (s-tac-xud). The read split lands where it is consumed — `sdd view` gains an `intent()` filter, catch-up folds pending directives into the act-on stream, `/sdd` surfaces guiding as standing context — not in `sdd status`, which is being retired by a separate directive (d-tac-oei). Mechanism and the rejected alternatives (stored closed-status, paired decision+done, a new terminal kind) are settled in d-cpt-cyx and its design record.

## Acceptance criteria

- [ ] Directives carry a stored `intent` (`pending|guiding|settled`), written via `--intent`, surviving a frontmatter roundtrip; invalid values and — for the directive kind — a missing value are rejected in command validation, so every capture path (CLI and the upcoming MCP server) enforces it; the model stays permissive so legacy directives without intent remain valid reads
- [ ] A directive with no `intent` reads as unspecified — rendered exactly as today, never coerced to a value
- [ ] `DerivedStatus` treats `intent == settled` as terminal with no closing edge; pending/guiding derive active until a close or supersede edge; precedence is superseded-by over settled, and closing a settled directive is rejected in validation
- [ ] A settled directive renders status `settled` (no id) wherever derived status renders — `{status: settled}` in `sdd list` / `sdd view` / chains, `status: settled` in the `sdd show` envelope, and `(<kind>, settled)` in `sdd show` trees (the tree formatter shows the segment for settled and omits it for done); settled directives drop out of active listings like any other terminal entry
- [ ] `sdd view` gains an `intent(pending|guiding|settled)` filter composable within `not()`; catch-up "Active and hot" includes active pending and unspecified directives and excludes guiding; `/sdd` session start surfaces active guiding directives as a standing-context block; `[intent: guiding]` renders on entry lines while pending/unspecified stay quiet and settled shows via its status
- [ ] Pre-flight emits a medium-severity finding when a directive with `intent: settled` does not justify its terminality in the body
- [ ] Dependent surfaces updated: `cli-reference.md` documents `--intent` and the `intent()` filter; the stale `Local participant: … sdd status` note points to `sdd info`; bare `sdd new d` examples and test helpers carry `--intent`
