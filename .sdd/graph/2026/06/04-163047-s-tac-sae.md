LLM cost and cache metrics are invisible on the gollm/anthropic path: gollm's Generate returns response text only and leaves RunResult.Meta nil (gollm.go:146), so the per-call token counts, cost, and cache_read/cache_creation breakdown that Anthropic returns are dropped — even though the agent-neutral LLMMetadata abstraction (d-tac-gyk) already exists to carry them and the claude-cli path populates it. Now that the active provider is gollm-anthropic and we maintain the gollm fork, we can thread the usage through. Candidate direction: surface the fork's usage into LLMMetadata and collect it to a local stats sink (e.g. a JSON file) so prompt-cache effectiveness and per-operation cost become measurable over time.
