Fix worktree isolation (s-prc-vvl) by correcting worktree instructions — not a structural guard. The failure is contradictory and missing guidance, not discipline that can't be followed: the recipe had no re-anchor step, the ambient "prefer absolute paths" habit pointed at the base checkout, and this repo's worktree note implied `direnv allow` activates the worktree's devbox env when it does not. Well-written, non-contradicting instructions are followed (s-tac-e7u transferred the full loop on instructions alone), so the fix makes the instructions clear and non-contradicting, in three moves.

**#1 — Fill the missing step** (universal worktree recipe, bundled `/sdd` skill, Claude render). Add re-anchoring at the boundary: pre-entry grounding is graph-only (`sdd show`/`sdd search`); read no source you intend to edit until after `EnterWorktree`; once entered, the worktree path is the only valid edit target — re-Read there. For already-decided work no pre-entry source read is needed.

**#2 — Resolve the absolute-paths contradiction** (same recipe). Name that the "prefer absolute paths" habit points at the base checkout after `EnterWorktree`: `EnterWorktree` moves cwd and git context but leaves file tools — which take absolute paths — pointing wherever they were read, so paths held from before are stale.

**#3 — Resolve the devbox/direnv contradiction** (this repo's `CLAUDE.md` "## Worktrees"). `EnterWorktree` leaves the devbox/direnv/`PATH` env inherited from base, and Claude Code has no supported way to auto-activate the worktree env on entry (verified: `worktree` settings are only `baseRef`/`bgIsolation`; the Bash env is a frozen snapshot from session start; direnv doesn't re-fire per non-interactive call). So the per-command form is the answer: run devbox scripts as `devbox run -c "$PWD" <script>` from the worktree root — plain `devbox run` hits main via the inherited `DEVBOX_PROJECT_ROOT`; check devbox's `Running script … on <dir>` line. `sdd` on `PATH` is the base build, so call `./bin/sdd` for the worktree binary. `direnv allow` only scopes an interactive terminal.

A structural guard was considered and rejected: a "target must be in the session's checkout" hook breaks legitimate cross-repo editing (graph in one repo, edited code in another) and any edit outside a repo, trading one silent failure for many false blocks. This stays inside the worktree division-of-labor (d-cpt-927): recipe and repo-doc edits, no CLI or harness mechanism.

Closes s-prc-vvl: the gap's concern becomes this committed instruction fix; the closing done signal lands when all three edits ship (recipe rebuilt + reinstalled, CLAUDE.md updated).
