All framework instruction text — concepts and situational guidance alike — must live in exactly one source and render into every surface that carries it; no surface holds hand-maintained duplicate instruction text. The surfaces this spans: the per-agent skill renders (Claude, Codex, future harnesses), the MCP server's just-in-time tool-response instructions, and the hosted-agent prompts. Duplicated instruction text has repeatedly missed a surface during framework iteration — a copy updated in one place and forgotten in another — and foreclosing that recurring failure is the rule's purpose. The multi-agent render work (20260611-153445-d-cpt-tdi) already proved the pattern for the skill surface: one neutral template tree rendered per agent, with per-agent deviations expressed as conditionals rather than copied files. This contract generalizes that proven pattern into a standing constraint covering the instruction surfaces still ahead, so single-sourcing is the default for every new surface rather than a decision re-litigated each time one is built.
