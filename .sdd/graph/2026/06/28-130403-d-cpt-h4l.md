The worktree workflow for sdd is harness + git + a skill-resident process recipe — the sdd CLI owns no part of the worktree lifecycle. Session entry/exit belongs to the agent harness (EnterWorktree/ExitWorktree), branch operations are generic git plumbing, and the worktree process guidance lives in the bundled /sdd skill that `sdd init` ships and refreshes. This is a standing scope boundary on what the CLI does and does not own, keeping the core neutral while the Claude-Code-specific recipe rides the cheap agent-specific layer — hence guiding.
