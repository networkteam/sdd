If done signals are ever given derived topics, derive them from the `closes` edge only — binary membership, the single edge where the done unambiguously retired its target, so the target's topic transfers without guessing. Deliberately excluded: `addresses` and broader completion kinds (they start a slope away from clear-only), and a weighted per-ref-kind transfer across all refs. Weights add nothing under binary membership — they reduce to "which kinds transfer," the same kind-selection — and only bite by making membership fractional, which would force a threshold or push fractions through the `topic` filter, `as-counts`, and `<topic>` rendering. Scalar "how central" gradation already lives in heat weighting (d-tac-cpw); topics stay membership. This would be the first implicit edge-following topic derivation in the system — today effective topics are inline plus annotation-membership only — so the first step stays minimal. Implementation is deferred and low-confidence: done-topic coverage is a secondary enhancement, since capture-time tagging already covers active work. Grounded in the topic primitive contract (d-cpt-ni0) as grounded-in rather than refines, because that contract is slated for supersession by the rule system and a refinement would only go stale (d-prc-u61).
