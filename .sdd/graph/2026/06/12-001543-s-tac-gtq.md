Codex's sandbox permission model adds first-run friction to the SDD loop: in a fresh project the first network- or graph-touching commands — `sdd search --query` (reaching the local embedding endpoint) and the provider-backed pre-flight and summary calls in `sdd new` (reaching the LLM API) — each require explicit user approval before they run, and `sdd search --query` degrades to text-only if denied. This is a Codex-runtime concern, not a graph-loop or provider failure: in the first real Codex eval the capture reached pre-flight, but the approval prompts and a blocked localhost call interrupted the path. The baseline should measure not only whether Codex follows the dialogue discipline but whether the rendered skill and onboarding can guide a user through Codex's sandbox approvals so the first capture does not feel broken.
