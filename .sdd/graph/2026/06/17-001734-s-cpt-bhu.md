OKF (Open Knowledge Format) v0.1 is Google's open, vendor-neutral format for representing knowledge as a directory of markdown files with YAML frontmatter — an interchange substrate for agent-consumable knowledge "bundles" (the distribution unit: git repo, tarball, or subdirectory). Each file is a "concept" whose identity is its path minus `.md`. The only required frontmatter field is `type`, a free, non-registered string; recommended fields are `title`, `description`, `resource`, `tags`, `timestamp`. Producers may add arbitrary extension keys, and consumers must preserve unknown keys and must not reject unknown keys or types. Relationships are plain markdown links treated as untyped directed edges (meaning conveyed by prose); broken links must be tolerated. `index.md` (directory listing) and `log.md` (newest-first change history) are reserved filenames. Conformance is intentionally minimal — parseable frontmatter plus a non-empty `type` — with a deliberately permissive consumption model so bundles stay usable as they are refactored and partially agent-generated. Versioning is `<major>.<minor>`. Ecosystem: a one-page open spec (GoogleCloudPlatform/knowledge-catalog), reference enrichment agents, a zero-backend static HTML visualizer, and Google Cloud Knowledge Catalog ingestion. Full field, conformance, and link-model reproduction plus source URLs are in the attached spec summary ([okf-spec-v0.1.md](./17-001734-s-cpt-bhu/okf-spec-v0.1.md)).
