Fix supersede-chain resolution in the model so refs and reported status always land on the live head, never a superseded intermediate. Today `Graph.DerivedStatus` takes `SupersededBy[id][0]` / `ClosedBy[id][0]` — one hop, first-by-insertion — so a reader following a ref into a multiply-superseded chain hops link by link to reach the live entry, and an entry with multiple closers can report a superseded closer. Both are one defect with two faces.

The fix is a model-layer resolver returning a `ResolvedRef` — generalizing the actor-identity head-walk (`ActorChain.Head` / `ChainForCanonical`) that the type-system contract (d-cpt-ni0) establishes for role-status — that walks `SupersededBy` transitively to the live head and retains the ordered path. Head, origin, staleness, and the render-only path are exposed via methods; the path slice stays unexported so an intermediate can't be mistaken for the head. The selection face skips superseded closers/superseders and reports an active one. This lives at read time, not capture time: because the graph is immutable a historical ref can't be rewritten, and under concurrent work even a carefully-reffed head can be superseded before the entry lands.

Consumers: status reporting (closes the wrong-closer gap s-tac-ohl); the ref sub-lines in `sdd show` and `sdd view` `expand(refs)`, which render the path to the head for stale targets only; and pre-flight's ref context, which takes `Head()` (closes the transitive-resolution gap s-tac-5p5). The `sdd show` restructure (d-tac-z3k) consumes this resolved status and owns the final display format. A fork — an entry with more than one superseder — is flagged by `sdd lint` rather than handled by the resolver, which assumes linear chains.

## Acceptance criteria

- [ ] A model resolver returns a `ResolvedRef` for any target ID — the ordered path from origin to the transitive live head — exposing `Head()`, `Origin()`, `IsStale()`, and a render-only `Path()`, with the path slice unexported.
- [ ] `Graph.DerivedStatus` reports `closed-by` / `superseded-by` by selecting an active closer/superseder, skipping ones that are themselves superseded.
- [ ] `sdd show` and `sdd view` `expand(refs)` sub-lines render the supersede path to the live head for stale targets; refs to active targets render unchanged.
- [ ] Pre-flight ref context resolves each ref target to its live head before reasoning about it.
- [ ] `sdd lint` flags a fork (an entry with more than one superseder) as an anomaly.
- [ ] Tests cover the resolver (active target, single hop, multi-hop chain, active-closer selection among multiple closers) and a render snapshot of a stale-ref path sub-line.
