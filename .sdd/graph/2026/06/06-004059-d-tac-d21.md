Give attachment reads a CLI-owned surface so agents never derive storage paths themselves, returning the form each runtime can use. Locally, `sdd show` prints each attachment as an absolute filesystem path the agent opens directly with its native read tool — absolute over relative to avoid cwd guesswork, a path over content so large files stay partially readable. Over MCP, where a remote agent can't open a local path, a dedicated tool returns attachment content with paging (offset/limit, mirroring the local read tool) so large files don't come back whole. Both go through a read accessor on the AttachmentStore (d-tac-0v4) so path resolution and paged content share one source of truth, keeping the on-disk layout an implementation detail the agent never touches. Rejected: materializing/checking out attachments to a temp location (adds a cleanup/staleness lifecycle to solve what a read accessor solves statelessly); returning content locally (loses partial reads on large files); `sdd show` printing only a command hint (costs a second round-trip). See [design note](./06-004059-d-tac-d21/design.md) for per-surface detail, alternatives, and open questions.
