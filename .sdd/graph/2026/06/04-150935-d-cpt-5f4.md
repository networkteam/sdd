Sharpen the output policy's audience→format mapping (d-cpt-rkj) into three distinct renderings rather than two: human readers in a TTY get genuinely styled CLI output (lipgloss layout, color, framing), agents and other non-TTY readers get the YAML frontmatter + markdown body, and programmatic callers get JSON via `--format json` / MCP `structuredContent`.

The parent directive's phrase "YAML+markdown for reading by humans and agents alike" over-flattened the case: YAML+markdown is the agent-reading format, while humans in a terminal deserve a designed presentation better than raw markdown+frontmatter — the well-designed-human-output half of the rendering gap (s-cpt-idq), not merely color layered on top of the agent format.

Renderer is selected by TTY detection plus `--format`, with precedence flags > env > config > defaults: styled when stdout is a terminal, YAML+markdown when piped or `--format text`, JSON when requested or over MCP. Implementation is a presenter layer holding one entry-data model with three renderers, sitting on the existing CQRS presenter split — which is the dedicated presentation layer the gap called for.

lipgloss is in-family: the project already uses charmbracelet/bubbles for `sdd init` (d-tac-s2g), so this is no new dependency bet. This refines the policy in place; concrete per-command styling lands in the tactical `sdd show` restructure and the broader human-output work grounded in d-cpt-rkj.
