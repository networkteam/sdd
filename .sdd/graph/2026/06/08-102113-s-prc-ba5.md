The `/sdd` implementation playbook directs the agent to commit code before capturing the closing done signal, but never says to cite the commit hash in that done signal — so done signals routinely record "code committed" without an explicit, durable artifact pointer. Pre-flight's artifact-durability check catches the omission after the fact (it fired at low severity on the `sdd stats` v1 done signal), but because the playbook itself is silent, the agent only learns at capture time. Adding "cite the commit hash(es) in the closing done signal" to the implement-then-close step makes the artifact pointer explicit and pre-empts the finding. This is unrelated to worktree handling — it applies to every implement-then-close, whether in place, on a branch, or in a worktree.
