Connecting an arbitrary MCP client to the workflow server required developer-grade setup at every step, observed across both evaluation runs: connectors in both Claude Desktop and ChatGPT reach servers from vendor cloud only, so a local server needs a public tunnel; neither connector UI supports bearer-token auth, so the token had to be injected at the tunnel edge; Claude Desktop acted on the tools only after switching tool access to "preloaded"; ChatGPT required developer mode, a multi-step app creation with a risk-acknowledgement dialog, per-chat activation via the plus menu, write actions are tier-gated, and custom apps are web-only. Each hurdle was survivable for a developer running an experiment — and each would stop a business owner or domain expert cold, which bears directly on the aspiration of reaching non-developers through the agent they already use (20260422-122523-d-stg-x0l). The observation is confirmed; the resolution is not — how the customer journey should work, whether sdd can be distributed as a ready-made connector or app, and which hurdles hosting removes versus which are vendor territory is a research topic needing its own evaluation. Hosted deployment with proper auth (20260610-232719-d-tac-47d) is one known piece; the rest is open.
