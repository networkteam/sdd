Implement the robust concurrent-worktree workflow end to end: first enforce merge-pull and a content-based branch-merged check in the CLI (realizing d-tac-4ff), then add the `sdd wip --worktree` lifecycle — creation, local-state carry-over, base-branch capture, and a guarded teardown — plus the skill conclude recipe (realizing d-tac-fla). Foundation lands first so the merged check is correct before the worktree teardown relies on it. The end-to-end design overview (git interactions, CLI/agent split) is attached to d-tac-fla.

## Acceptance criteria

- [ ] The CLI provides a sanctioned merge-pull (e.g. `sdd sync --pull`): on a clean working tree it runs `git pull` with merge (never rebase); on a dirty tree it refuses and defers. The `/sdd` sync-reaction guidance invokes it instead of instructing raw `git pull --rebase`.
- [ ] `Brancher.BranchMerged` reports merged-ness by patch-equivalence against the current HEAD (e.g. via `git cherry`), so a branch whose commits are present under different hashes after a base rewrite is reported merged.
- [ ] A regression test reproduces the orphaning scenario — base history rewritten so the branch tip is no longer an ancestor but its content is present — and asserts `sdd wip done` deletes the branch with `git branch -d` (no `--force`); a paired test asserts a genuinely-unmerged branch is still preserved.
- [ ] The rebase-shaped conflict-resolution guidance (s-prc-jpx) is rewritten to a merge shape (resolve once, conclude with a commit; no per-commit continue).
- [ ] `WIPMarker` gains a base-branch field that round-trips through the marker frontmatter, and `sdd wip list` surfaces it.
- [ ] `sdd wip start --worktree <entry>` creates the feature branch and a worktree (`git worktree add`), records the current branch as the base in the marker, and copies `.sdd/config.local.yaml` and `.sdd/index/` into the worktree.
- [ ] A fresh `--worktree` copy runs `sdd search` immediately with no re-embedding (the carried-over index manifest matches; first search performs zero lazy embeds).
- [ ] `sdd wip done` rejects unless the current branch equals the marker's base branch (actionable message naming the base); on match it runs the content-based merged check, removes the marker, deletes the merged branch, and removes the worktree (path re-derived via `git worktree list`).
- [ ] Plain `--branch` (checkout-only, no worktree) behavior is unchanged (regression test).
- [ ] The `/sdd` skill and branching guidance document the worktree conclude recipe (sync base in, capture the done signal in the worktree, `cd` to base, merge, `sdd wip done`) and the session-continuation choice (`/add-dir` vs a fresh session).
- [ ] `go vet ./...`, `go test ./...`, and `golangci-lint run ./...` are clean; skill changes are made in `internal/bundledskills/` and the installed `.claude/skills/` copy is re-stamped.
