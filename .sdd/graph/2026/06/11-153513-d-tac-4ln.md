Implements the agent-agnostic render approach committed in the directive (d-cpt-tdi) end to end: restructure the skill/instruction source into one neutral template set rendered per agent, wire `sdd init` to a committed supported-agents list, render Codex as the first non-Claude target, and run the first Codex evaluation. The Claude render must stay behavior-equivalent to today's bundle so nothing breaks for current users.

## Acceptance criteria

- [ ] Skill/instruction source restructured into agent-neutral templates under `internal/bundledskills/` with per-agent render profiles; `claude/` becomes a profile, no longer the source.
- [ ] Rendering the Claude profile yields output behavior-equivalent to the current bundled Claude skills (parity smoke test on `/sdd` and its sub-skills — no functional change).
- [ ] `sdd init` reads `supported_agents` from `.sdd/config.yaml`, offers a multi-select on first run, and idempotently re-renders every listed agent on each run; all rendered skill dirs are committed.
- [ ] Codex skills render into `.agents/skills/` conforming to the Agent Skills standard: `name` matches the directory, SDD stamps under `metadata:`, `compatibility:` set; validated by `skills-ref` or equivalent.
- [ ] Per-agent deviations are expressed as conditionals from the single source (Claude: `!`cmd`` injection + Skill-tool sub-skills; Codex: instructed `$skill` invocation + explicit `run sdd …` steps), with no duplicated definitions.
- [ ] `sdd init` scaffolds the instruction bridge (`AGENTS.md` + a `CLAUDE.md` importing it) only when the files are absent, never overwriting.
- [ ] This repo dogfoods the bridge: agent-neutral guidance moves from `CLAUDE.md` to `AGENTS.md`, Claude-only guidance stays in `CLAUDE.md` after `@AGENTS.md`, and the import is verified to expand in a fresh Claude Code session.
- [ ] A first Codex evaluation run is completed and its findings captured against the behavioral baseline (s-tac-qy8): whether instruction-carried discipline holds (catch-up-first, dialogue-before-capture) and whether instructed sub-skill invocation works without a native Skill tool.
