`sdd init --agents` on an already-initialized repo doesn't persist the chosen agents to `supported_agents` in `.sdd/config.yaml`, so adopting a new agent (e.g. Codex) post-init doesn't stick — the next bare `sdd init` falls back to the default and drops the unrecorded agent. The fresh-init path persists the list via `FormatConfig`, and the existing-tree path upserts `skill_scope`, but `supported_agents` has no equivalent upsert because `SetYAMLField` is scalar-only and writing a YAML sequence needs a sequence-capable patcher. Today post-init adoption requires a manual committed edit to `config.yaml` (as done for this repo's Codex adoption). Closing it means adding a sequence upsert — extend the YAML patcher or a dedicated `supported_agents` writer — and wiring the existing-tree init path to persist an explicit `--agents` selection.
