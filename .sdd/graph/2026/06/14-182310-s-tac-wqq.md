Implemented the existing-tree `--agents` persistence and symmetric prune committed in d-tac-jin (commit 6c3f56f). Added `model.SetYAMLSequence` — a sequence-capable sibling of the scalar `SetYAMLField` that shares one descent/parse/encode path and writes flow style, so a sequence upsert matches FormatConfig's `[claude, codex]` shape. On an existing tree an explicit `sdd init --agents` now fully replaces and persists `supported_agents`; when the selection drops a previously-recorded agent, its rendered skills are pruned via the same `SkillStatus` content-hash classification that drives overwrite protection — Current/Pristine files removed, user-modified files preserved and reported (removed only under `--force`), non-sdd files untouched, emptied skill subdirs and the parent skills dir cleaned up. A bare `sdd init` is unchanged: the recorded value wins, no prune. Verified by unit tests (SetYAMLSequence round-trip, replace-wholesale, comment preservation; five handler cases covering persist, replace+prune, modified-preservation, --force removal, and bare-init no-op) and an end-to-end CLI run — adopting codex, editing a codex skill, dropping codex (15 pristine files pruned, the 1 modified file preserved with a --force hint, config flipped to [claude], Claude render intact), then re-adopting codex. Full vet/test/lint gate clean.
