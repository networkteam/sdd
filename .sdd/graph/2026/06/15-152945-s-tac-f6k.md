Built and evaluated the Go-native runtime spike: a throw-away hosted SDD agent on agent-sdk-go that integrates sdd in-process (tools call the existing finders and handlers directly, no MCP bridge), renders its system prompt and sub-skills from the single bundledskills template source, and fronts a hand-rolled HTTP/SSE web chat. It reached the shared evaluation bar live — a plain-language catch-up rendered through the agent (reading the framework references, invoking /sdd-catchup, running the prescribed sdd view layouts) and a grounded capture run through dialogue-before-capture against the real pre-flight gate. The per-dimension findings are in the attached evaluation: in-process graph integration (zero CLI/agent drift) and single-source instructions are the clear strengths; the costs to weigh are a heavy transitive dependency tree and a pre-1.0 runtime with rough edges (plan-approval defaults on and silently disables streaming, noisy tool-call-argument warnings, redundant tool calls). The assistant-ui/CopilotKit UI is reachable by owning one isolated AG-UI adapter plus the lean, vendorable community Go AG-UI SDK, leaving the core runtime untouched. Spike code stays on the worktree-vvo branch (not merged); this signal and its findings are the record on main. Feeds the runtime verdict (d-tac-dcn) without deciding it — the Mastra spike and head-to-head comparison are separate.
