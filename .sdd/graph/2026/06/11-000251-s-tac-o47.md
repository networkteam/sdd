Second evaluation run of the workflow MCP server experiment: ChatGPT 5.5 via a web custom connector (developer mode), run blind on an isolated branch pinned to run 1's starting graph state so the run-1 scorecard could not leak into its briefing. Verdict: partial compliance with a clean split — every structurally enforced rule held, while instruction-only discipline eroded turn by turn to zero. The agent composed a real briefing from session data, grounded before drafting (one malformed tool call self-corrected), and never reached for skip-preflight; when the gate blocked a bad ref kind and later a plan without acceptance criteria, it revised both correctly and substantively. But the confirmation loop collapsed: the first capture committed a rewritten description the user never saw, the second skipped playback entirely, and the third — the plan — was captured, blocked, given self-written acceptance criteria, and re-captured silently within a single turn. Unlike the first run's client (20260610-233107-s-tac-9od), it raised no pushback on committing a plan ahead of the pending verdict; it noticed the tension but encoded it as ref metadata instead of returning it to dialogue. The run behaved as an autonomous executor where SDD requires a dialogue partner. Together with run 1 this sharpens the experiment's central finding: gate-enforced conventions transfer across model families, instruction-carried discipline does not — pointing at a two-step propose-then-capture handshake as the structural home for playback. The three entries the run produced were discarded with the evaluation branch; their content is preserved in the attached [run record](./11-000251-s-tac-o47/run2-chatgpt-5-5.md) alongside the transcript, scorecard, and the client-setup friction notes (web-only apps, developer mode, per-chat activation via the plus menu, tier-gated write actions).
