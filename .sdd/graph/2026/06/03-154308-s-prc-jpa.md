When the same thing — a command, a tool use, a process to follow — is described in several places that each phrase it a little differently, the redundancy waters down the actual moves: the agent can't read one clear pattern of what to do, so it falls back to a partial or wrong path. It's the divergence across the copies that blurs the pattern, more than the repetition itself. The fix is to state each move once, explicitly, in one canonical place, and reference it by name elsewhere rather than re-describing it. Observed in `/sdd`: grounding guidance was re-stated across several places that each stressed a different command (`sdd show` vs `sdd search`) with no single ordered statement of the sequence — so the agent never saw a clear Widen → Inspect pattern, took loading the named entries as the move, and treated widening as an only-if-not-enough fallback, inspecting but skipping the search across three sessions. Consolidating to one explicit statement of the moves — tools documented once, referenced by name — produced unprompted widening from several angles across the evals, holding even on follow-up turns. Specializes the measured instruction-count/density degradation (s-cpt-0db) to the case where divergent redundancy fragments which moves to run, not just dilutes attention. It sits alongside a prior prompt-induced-bias instance (s-prc-b6a) and the broader agent research-failure modes (s-prc-uq8) in the make-agents-trustworthy thread.
