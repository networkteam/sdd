Claude Code's `.claude/rules/` is a mechanism for splitting a large project's CLAUDE.md into modular instruction files — static, human-authored text loaded at session start at the same priority as `.claude/CLAUDE.md`, optionally narrowed to specific files via a `paths:` glob so it loads only when matching files are open (per the Claude Code memory docs, https://code.claude.com/docs/en/memory.md). It is location/path-keyed static instruction memory — not a dynamic, dialogue-configurable, graph-resident mechanism. So despite the name, it is not the Claude Code seam the graph-resident-process-rules gap (s-cpt-k8i) reaches for: that gap wants the `sdd` CLI to emit graph-derived extensions into skill markdown at session start (the command-output injection seam), and `.claude/rules/` should not be conflated with SDD's own graph-resident `rule` kind. Recorded so the seam search for that gap skips this candidate.
