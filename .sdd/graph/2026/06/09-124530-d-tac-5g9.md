Build the interactive terminal output experience for `sdd index` and `sdd search` lazy-fill in a new reusable `internal/cliout` package, realizing the per-command terminal-experience implementation that the architecture directive (20260605-182704-d-cpt-mvb) deferred. Today both wire their progress callbacks to raw `fmt.Fprintf(os.Stderr, …)` — the per-entry indexed/skipped lines, and the lazy-indexed lines that bury `sdd search` results. The design keeps producers oblivious: handlers and finders log only through the context logger, and the CLI surface alone decides whether that logger drives a transient TUI or the plain leveled stderr handler.

On a TTY, the CLI runs the work under a transient bubble tea view — spinner, a determinate bar where a total is known, and a scrolling tail of recent log entries — that tears down on completion (alt-screen on stderr, restored on quit) so only the result reaches stdout. A `NewLogPipe` constructor returns a pair: a `slog.Handler` installed into the context (and slog default) for the operation, and a bubble-tea-free `LogConsumer` stream the model drains via a thin `tea.Cmd` adapter. Two producers feed the one model: progress via the reporter callbacks (a new `OnBatchStart` so the bar advances per embedding round-trip), reported as absolute counts; and logs via the handler doing a non-blocking, drop-on-full send. The work runs on its own goroutine while the bubble tea loop drains a bounded ring buffer of structured `logEntry` snapshots — not flattened strings, `WithAttrs` honored, styled at render time. The data channel is never closed (a separate done channel signals end-of-work), so unknown producers can't panic on a closed channel. The program launches only when there is work, so no-op runs take the plain path with no alt-screen flash.

A policy decouples the durable record from the ephemeral display: `Display` sets the live view's level (chattier, since it vanishes), `KeepAtOrAbove` re-emits important entries to the stderr sink on teardown, and a fingers-crossed mode flushes the last N entries (any level) when an error occurs — so routine lazy-fill noise disappears while a warning or the context around a failure survives. The agent/non-TTY path respects the configured floor (Warn default; explicit `sdd index` raises its floor to Info; `-v`/`-vv` raise further), independent of the TTY display level. The coordinator is reusable for any future long-running command.

Rejected: composing one handler with both a TUI and stderr branch (the TTY fork picks exactly one); a blocking channel send (render would throttle indexing); a slog-only cleanup with no coordinator (the goal is the designed experience, not just silence); pre-rendered joined log strings (lose slog structure and re-wrap); closing the data channel (send-on-closed panic); inline teardown via an empty final view (does not erase scrollback in bubble tea v2 — verified).

Full architecture, the settled decisions, and the end-to-end flow are in the [design doc](./09-124530-d-tac-5g9/plan.md).

## Acceptance criteria

- [ ] A reusable transient-view coordinator (`internal/cliout`) runs an operation on an interactive terminal under a bubble tea program — spinner, determinate progress where a total is known, and a scrolling tail of recent log entries rendered with structured styled formatting (level, message, attrs) — and tears the view down on completion, leaving only the result on stdout.
- [ ] Handlers and finders emit only via the context logger; all terminal-UI wiring lives in `cmd/sdd` + `internal/cliout`, and `LogConsumer` exposes a bubble-tea-free stream (the `tea.Cmd` is a thin adapter over it).
- [ ] While the view is active, no operational log reaches stderr directly and the work goroutine never blocks on the display: log sends are non-blocking (drop-on-full) and progress is reported as absolute counts so dropped updates self-correct.
- [ ] On a non-TTY consumer or with `NO_COLOR` set, there is no program — operational logs go to stderr through the leveled handler and the result to stdout; agents never see a TUI.
- [ ] A configurable policy persists entries at or above a kept level by re-emitting them to the durable stderr sink on teardown, independent of the live display level.
- [ ] A fingers-crossed mode flushes the last N entries (any level) to the durable sink when an error occurs during the operation.
- [ ] `sdd index`: progress advances per embedding batch via a new `OnBatchStart` callback, per-entry indexed lines log at Info, skipped entries collapse and log at Debug, the command defaults its level floor to Info, and it prints a final summary line.
- [ ] `sdd search` lazy-fill: at default verbosity an agent sees no indexing output (raised verbosity reveals it); a TTY user sees the transient scrolling view, which clears before the search results render.
