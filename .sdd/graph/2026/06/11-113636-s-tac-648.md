`sdd view` cannot express edge-level queries: every filter and aggregation operates on entries, never on their outgoing references, so questions that key on the refs themselves — all `builds-on` refs whose targets are currently active or open, or per-kind ref counts across the graph — fall back to raw grep over entry files. During the pre-flight reliability work (s-tac-lpa) this happened twice: grounding the applicability matrix's soft-cell decision required counting builds-on refs by target status, and scoping the body-to-edge consistency check required diffing body-typed IDs against edge sets; both were answered with ad-hoc shell over the graph directory instead of the pipeline. The existing surface comes close but does not compose for this: `expand(refs)` renders sub-lines only for an already-filtered entry set, `refs(inactive)` is the single target-status filter with no active inverse and no ref-kind dimension, and `as-counts` aggregates topics, not edges. A ref-level filter family (by ref kind, by target status, with counting) would make edge queries first-class. The planned `refs-of()` drill filter (d-tac-jqq) traverses refs to expand an entry set — adjacent, but it selects entries, not edges, so it does not answer these queries.
