Shipped provider-aware LLM retry with backoff by forking gollm and wiring it into SDD's LLM layer, resolving the no-retry deficiency (s-tac-m1b) and realizing the fork directive (d-cpt-n3y). The fork (networkteam/gollm, module path unchanged) adds llm/retry.go: classifies errors as retryable-transient (408/409/5xx incl. Anthropic 529, network errors), rate-limited (429 honoring Retry-After / retry-after-ms / x-ratelimit-reset-* hints), or permanent (other 4xx, OpenAI insufficient_quota); applies full-jitter exponential backoff floored by any server delay; returns the underlying error on exhaustion; and logs attempts at Debug so batch summarize no longer floods. SDD points at the fork via a module-path replace (pseudo-version, removable once upstream PR teilomillet/gollm#60 merges), drops the forced SetMaxRetries(0), and exposes a retry config block (max_attempts/base_delay/max_delay, defaults 5/2s/60s) covering both the sdd new pre-flight and sdd summarize paths. Key decisions: retry stays gollm-only (the claude-cli bridge does its own retry); RetryDelay's meaning shifts from fixed delay to backoff base; GenerateWithSchema is left on its existing retry-on-any loop as an out-of-scope follow-up. All eight acceptance criteria met; table-driven and loop tests pass, go vet and golangci-lint clean. Fork commit 9389047; sdd commit 74fbafe; draft PR teilomillet/gollm#60.
