The gollm fork that SDD's Anthropic, OpenAI and Ollama adapters run on falls short as their foundation: preparing structured output for pre-flight and the writing guide (20261031-141038-d-tac-p8l) turned up defects in its core and a missing feature on every path that plan touches, each needing its own fork patch.

**Actual.** Found on 2026-10-31 by reading the fork at `aa9e2d1` and confirmed for the first item by a local request probe of the implementation session:
- The system prompt is sent twice: `attemptGenerate` sends `prompt.String()`, which prefixes "System: … (Cache: …)", as the user content, while the provider also sends it as the system message (`llm/llm.go`, `llm/prompt.go`).
- `generate` writes each call's system prompt into the client's shared options, so overlapping calls can send each other's; a mutex guards the write, so this is a logic race.
- The schema path flattens the prompt into one string, losing the cacheable system part, returns no usage, and for Anthropic writes the schema into a system message that replaces the caller's (20261004-134853-d-cpt-sw8). Only OpenAI sends a native schema; Ollama has none.
- The Anthropic URL is hardcoded, against 20260921-181638-d-cpt-cnu.
- OpenAI request parameters are chosen by model-name prefix, which provider-prefixed names such as Opper's match only by accident.

**Expected.** A thin, correct client for the requirements the June library evaluation listed (20260612-120423-s-cpt-jzo): system/user split with caching, per-call usage, retry. Native structured output and configurable base URLs have become requirements since. That evaluation chose to keep patching the fork and to watch `zendev-sh/goai` as the clean way off it; the patch list has since grown well past small fixes.

The plan itself still builds on patches to the fork.
