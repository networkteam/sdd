Valid structured output becomes a guarantee of the LLM boundary instead of something each prompt asks the model for: an LLM operation that expects structure declares a response schema on its request, and each provider adapter either enforces that schema through the provider's native mechanism or declares that it cannot.

The same failure, a model response that is not valid JSON, has surfaced four times, and each repair targeted its trigger. In June a pre-flight eval run failed on an unescaped quote and a prompt instruction was added; that record already named tool-use structured output as the durable guard, noted and never built (20260606-125155-s-tac-sk1). In August drafts containing an ASCII double quote broke the writing guide, and both prompts were taught standard JSON escaping (20260828-154428-s-tac-j90). In September brace literals broke pre-flight (20260906-231136-s-tac-ynt), answered by the parser fix in `d17b7a0c`. [GitHub issue #20](https://github.com/networkteam/sdd/issues/20) now reports drafts quoted with German typographic marks („…“): when the model cites the draft, it writes the closing U+201C as an unescaped ASCII `"`, which ends the JSON string, and an added prompt rule left 0 of 6 responses valid. The model takes itself to be copying a typographic mark, so no escaping rule reaches it. Common to all four: the operations ask the model to write JSON as free text, and nothing enforces validity.

The schema field is earned by an observed flow, the test the boundary directive (20260830-234501-d-cpt-q6n) sets for every port element. That directive removed an `OutputSchema` field because nothing produced or consumed it; pre-flight and the writing guide now do.

Adapter state at decision time. The claude CLI enforces a schema natively through `--json-schema`. In the gollm fork only the OpenAI provider sends a native strict `response_format`. The Anthropic provider writes the schema into a system message that replaces the caller's system prompt and enforces nothing. The Ollama provider has no schema path, although Ollama's API accepts a schema in `format` and gollm copies options into the request body; that route is untested. gollm's schema path also flattens the prompt into one string, losing the cached system-prompt split, and returns text without usage. Enforcement therefore means work in each adapter and in the fork.

The guarantee covers syntax, not content. Under enforced output the substituted `"` is expected to end a quote early or to survive as an escaped character, giving valid JSON whose quote differs from the draft. Whether such a quote still lets its reader locate the passage is for the eval suite to judge, a separate decision.

Unsettled: how an adapter that cannot enforce a schema is treated, refused for structured purposes or kept on free-text JSON with today's prompt rules and parser. What happens to the prompts' JSON construction rules follows from that answer.
