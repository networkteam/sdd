The capture's summary check lets a defective summary into the graph even after the agent has seen the defect, because it asks only whether the summary keeps the body's meaning.

Actual. In another project, the check served a summary holding two drafts joined by a literal `</think>` tag (20261005-172136-s-tac-c8r). The capturing agent noticed the tag, mentioned it in its fidelity note and answered faithful, since both drafts were correct in content; the summary was stored with the tag. Asked afterwards, the agent judged its answer wrong. The check's instruction asks whether the summary introduced a participant, shifted the commitment framing, dropped the core idea or corrected an intentional identifier, and offers two answers, faithful or drifted. Leaked markup and a doubled summary match none of those questions, so faithful was the answer the instruction supported. The fidelity note is collected and read nowhere, so the one place the agent recorded the defect reaches no one. The instruction reads the same in sdd 0.17.0 and on main.

Expected. The check exists because overview surfaces and briefings render the stored summary and fixing it is cheap at that point (20260703-094500-d-prc-cap). A summary that breaks the summary contract (20260901-112834-d-cpt-75a) in any respect, not only in meaning, should fail it, and a defect the agent has noticed should not be stored.
