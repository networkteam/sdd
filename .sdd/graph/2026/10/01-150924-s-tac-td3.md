A participant counts as known only when it equals an active actor canonical exactly; the capture check (`participantCoverageFindings` in `internal/finders/preflight_mechanical.go`) and lint never consult aliases. So a session participant configured as a short name blocks capture with a high finding once the user chooses the full name as canonical, even with the short name recorded as an alias, the case aliases exist for. Observed in a bootstrap in another project, where the agent offered to override the check or write a corrective entry.
