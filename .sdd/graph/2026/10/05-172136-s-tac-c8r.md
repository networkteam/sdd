On the recommended Ollama setup, a generated summary can carry the model's reasoning into the graph: a summary stored in another project holds two drafts joined by a literal `</think>` tag.

Actual. A user of that project reported it and supplied the call record, the sdd version and the stored entry. The call ran sdd 0.17.0 on Ollama Cloud with glm-5.3-flash at think=low, the setup the provider evaluation recommends (20260901-093840-s-tac-ahc) and Christopher runs locally. Against the same day's other summarize calls on similar input, it used about twice the output tokens and twice the time, consistent with two drafts in one answer. The stored summary holds a shorter draft, the tag, then a longer draft, each correct in content. The entry sits on a feature branch and has since been replaced. Separately, on that setup on Christopher's machine, two outputs quoting the tag lost it: the generated summary of the predecessor entry rendered it as `##thinking`, and a writing-guide finding on this entry's draft dropped it.

Expected. A summary is one summary, a pointer to the body that asserts nothing the body does not state (20260901-112834-d-cpt-75a). A reasoning trace or a second draft is neither.

What the code shows. The summarize operation trims whitespace from the model's answer text and stores it; nothing checks the text further. Through the gollm adapter with Ollama, sdd keeps only the response's answer field and leaves separating reasoning from answer to Ollama's thinking setting. The capture's two LLM checks, pre-flight and the writing guide, are moving to schema-enforced output (20261004-134853-d-cpt-sw8); summarize, a text purpose, stays outside that guarantee. This repo's graph holds no summary with the tag.

Candidate causes, unverified: Ollama's separation of reasoning from answer failing for this model, which the lost tags on Christopher's machine may also point at; or sdd's call shape, which uses Ollama's generate endpoint with the system prompt pasted into the user text.

This replaces 20261005-154132-s-tac-bkt: the reporter's records answer its open questions, and the call record rules out its third candidate, a provider other than Ollama.
