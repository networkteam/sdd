Claude Code from 2.1.314 titles a session opened with a bare `/sdd` from the expanded skill text, so every such session gets the same title, "SDD decision graph workflow", and parallel SDD sessions cannot be told apart in terminal titles, a terminal multiplexer's agent list, or the `/resume` picker.

**Actual.** Observed 2026-10-31 when two SDD sessions in a terminal multiplexer showed the same title. Claude Code records the auto title as an `ai-title` line in the session transcript. Every bare-`/sdd` session checked on 2.1.312 or earlier got its title only after the user's first real message, and a specific one; every one on 2.1.314 or later got the generic title from the skill text alone. A 2.1.316 session opened with a plain request, `/sdd` invoked later, got a specific title from that request. The title is set once: no session checked ever received a second one. In the 2.1.316 binary, the terminal title takes the `/rename` title first, then the auto title. Claude Code 2.1.316 offers the model no tool that sets the session title; no title write path in the binary starts from a tool call. The paths that exist: `/rename`, `claude -n`, `/branch` with a title, a hook returning `sessionTitle` on `SessionStart` or `UserPromptSubmit`, and an SDK or host `title` or `rename_session`.

**Expected.** A session's title names its subject, so parallel sessions stay distinguishable: Claude Code's own behavior up to 2.1.312, and what its title prompt demands ("A generic label that could sit on dozens of sessions is not a name").

Candidate remedies, unsettled: report the change upstream; state the task in the same message as `/sdd`; `/rename` a session whose title came out generic; or retire the `/sdd` skill and carry its pointer to the session door in the project's agent instruction file (`AGENTS.md`, `CLAUDE.md`), so a session opens with the user's demand or question instead of a skill invocation. That last one also acts on the explicit `/sdd` entry point that 20260422-130007-s-tac-6on finds at odds with ambient capture.

It neighbors the question of how a user finds a past session to continue (20261026-190029-s-cpt-cbi): resuming the host conversation through its picker is one route back, and identical titles break it.
