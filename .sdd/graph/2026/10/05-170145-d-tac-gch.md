A quote that an LLM check returns to point at draft text identifies the passage; it is not text to match. The writing guide's `quote` carries enough of the draft's words to locate the passage unambiguously, need not reproduce it character for character, and its prompt shows an example of such a quote. Excerpts that pre-flight observations cite follow the same rule. When capture serves the findings, it tells the drafting agent the same: the quote points to a passage in the draft the agent holds, and the agent locates the passage from it instead of matching it.

Exactness buys nothing here. No code matches quotes against the draft; capture serves them to the drafting agent, which holds the draft and only needs to find the passage. Demanding verbatim reproduction is what turned the model's character substitutions into a contract violation, and under enforced structured output (20261004-134853-d-cpt-sw8) a substituted or shortened quote is harmless as long as it still locates the passage. What a quote must keep is provenance: it points at a passage that is in the draft, the failure 20260901-220355-s-tac-owp records. The evaluation judges quotes by exactly this standard (20261005-160413-d-cpt-3sl), so the prompt contract and the evaluation measure the same thing.

Today the writing-guide prompt asks for the draft's words verbatim (`internal/llmops/writingguide_templates/writing_guide.tmpl`), the shared JSON string rules tell every check to reproduce cited text exactly, and capture's guide-findings serve says nothing about how to use the quote.
