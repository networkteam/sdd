Pre-flight and the writing guide use the structured output of the LLM providers to prevent JSON parsing errors from invalid generated output. SDD requires every provider it integrates to support structured output and sends the schema with each check; whether an endpoint honours it is not SDD's to check. The Claude CLI, Anthropic, OpenAI, Ollama and Opper all support it. Their quotes need only locate a passage, and layered tests, runnable live in GitHub Actions, show both. This realizes structured output as a guarantee of the LLM boundary (20261004-134853-d-cpt-sw8), the requirement of native schema support with the prompts' JSON rules removed (20261004-135748-d-tac-ndh), the locating quote contract (20261005-170145-d-tac-gch) and a configurable base URL on the Anthropic path (20260921-181638-d-cpt-cnu), and fixes GitHub issue #20.

## Acceptance criteria

Responses and providers:

- [ ] Pre-flight and writing-guide requests carry a JSON schema for their result on `pkg/llm.Request`.
- [ ] The Claude CLI adapter passes the schema through `--json-schema`.
- [ ] The OpenAI adapter passes it as strict `response_format`, also on a configured base URL such as Opper's.
- [ ] The Anthropic adapter passes it through Anthropic's native structured output.
- [ ] The Ollama adapter passes it through `format`.
- [ ] On the schema path, every adapter keeps the cacheable system/user prompt split and reports usage.
- [ ] The prompts carry no JSON construction rules: the shared escaping partial and the output-format instructions are gone.
- [ ] The writing-guide prompt asks for a quote that locates the passage and shows an example; pre-flight's cited excerpts follow the same rule.
- [ ] The capture procedure's served instructions tell the agent to locate the passage from the quote.
- [ ] The fork's OpenAI provider picks parameters without matching model names: `max_completion_tokens` by default, `temperature` only when configured, replacing the prefix matching extended in 20260614-130830-s-tac-4gm.
- [ ] The Anthropic base URL is configurable.

Deterministic tests, run in CI on every change:

- [ ] Adapter wire tests assert the schema field and the kept prompt split in the request, usage in the result, and a set of problem characters passing through request and faked provider response unchanged.
- [ ] The parser tests in `internal/llmops` carry #21's cases, anonymized: typographic quotes parse, an unescaped `"` is rejected.
- [ ] Prompt tests assert that the JSON rules are gone and the quote example is present.
- [ ] A procedure test asserts the capture instructions on quotes.

Live tests, under the eval build tag:

- [ ] Format evals, added to the existing writing-guide and pre-flight eval suites together with #21's eval case, return schema-valid responses in every run over the example set, on all four providers and through Opper's OpenAI and Anthropic routes. The set: the anonymized #21 German draft crossed with `„…“`, `«…»`, `‚…‘`, an ASCII `"` as closing quote, English `“…”`, braces, a backslash path, a regex and an excerpt with a line break, plus the past failures the research of 20261005-160413-d-cpt-3sl lists, with the configured language set to `de` for pre-flight (the writing guide takes no language).
- [ ] The example set lives in data files, not Go literals.
- [ ] Run on the code before the change, the new format evals show failures.
- [ ] A GitHub Actions workflow runs the format evals against Opper with an `OPPER_API_KEY` secret, on manual dispatch and on a label on pull requests from this repository, never on push or for pull requests from forks, and uploads the raw responses as artifacts for later re-scoring.
- [ ] Issue #20 and PR #21 are closed.

**Order.** Write the parser cases and format evals first and run them on the current code to show the failures. Then the fork (parameters, Anthropic base URL, schema paths that keep the prompt split and usage), then the boundary and adapters, then prompts and the quote contract, then the workflow.

**Out of scope.** The eval-tag format evals are a stopgap: `sdd eval` (20261005-160413-d-cpt-3sl) replaces them over the same data files, and the workflow then calls it. Also out: judgment tests, whether findings hold and quotes point to the right passage before and after the change, with their judge and its calibration, which come with that command; summarize, though structured output may serve it later too; Anthropic prompt caching through Opper's OpenAI-compatible route; the Claude CLI and Ollama in CI, which stay local runs. Facts behind the plan and the alternatives set aside are in the [alignment record](./31-141038-d-tac-p8l/alignment-record.md).
