Repository identifiers become a strict custom type, `RepoID`, across the whole SDD codebase, the exported API included, replacing the plain strings that carry them today.

The type is defined in the dependency-free `pkg/application/types` leaf beside `ProjectID` and aliased into `internal/model`, following the pattern and boundary test of the exported-surface cleanup (20260901-192933-s-tac-ctm), since exported signatures may not name internal types. It covers the URL-shaped repository identifier of the cross-repo design (20260529-131915-d-cpt-v8t) wherever it travels: the per-repo config's `repo_id` and `dependencies`, the connected-repos configuration and caches, the cross-graph assembly and its member lookup, the repo half of a split cross-repo ID, the dependency-closure walk, and the exported surface, namely the repo-ID parameter of `AccessResolver.ResolveDependency`, `ProjectRuntimeOptions.Dependencies`, and `ProjectConfig.RepoID` and `Dependencies`. Conversion from and to text happens only where text is parsed or rendered: YAML, flags, and the `<repo-id>:<entry-id>` form.

Why: Christopher's review of the experimental graph export (https://github.com/networkteam/sdd/pull/22) objected to repo IDs passed around as `[]string`. A repo ID and a project ID are different identities that coincide only in the local composition, and the closure-walk defect fixed in 20260903-221901-s-tac-u5j compared a declared repo ID to a project ID; with distinct types such a comparison needs an explicit conversion instead of passing as a plain string match.

Alternative weighed: typing only the code the export and the shared dependency walk touch, converting at the boundary to the remaining string signatures and migrating the rest later. Rejected by Christopher: it leaves both forms in the codebase and keeps the asymmetry the review objected to.

Consequences: the exported API breaks. An external composition implementing `AccessResolver` adapts its `ResolveDependency` signature, which fails loudly at compile time, and the release notes list the change under Breaking. The work lands in a follow-up pull request to #22, after #22 merges with its review fixes, together with the shared dependency-closure walk, one context-aware walk in `internal/model` that serve and the CLI both use, recorded as its own directive referencing this one. Entry IDs, including the entry half of a cross-repo ID, stay plain strings; typing them is a separate question.

The directive is fulfilled when no signature or field in `internal/` or `pkg/` carries a repo ID as a plain string.
