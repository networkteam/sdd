The /sdd skill has no named playbook move for new plan capture — dialogue the design space, pressure-test scope, name open dimensions, then draft ACs. Existing playbooks cover augmenting an active plan (`playbook-augment-plan.md`), implementing a captured plan (`playbook-implementation.md`), and engaging on entries (`playbook-engage.md`), but creating a new plan from scratch falls into inline Capture mode with structural guidance only ("ACs must be verifiable outcomes"). Default behavior becomes jump-to-ACs without surfacing the design dimensions that should shape them.

Surfaced in this session: drafting a six-AC plan on the topic system without first dialoguing scope (one or two plans), grooming surface (playbook vs sub-skill), display direction, or label vocabulary policy. Hand-waving was visible enough the user called it out directly.

Same shape as `s-prc-p6q` (no "mine" move for external sources): a dialogue pattern that exists in practice but isn't named, so it gets skipped. Likely belongs in the mode table refactor surfaced by `s-prc-fc0` — either as an explicit "plan-from-scratch" engage flavor or as guidance inside inline Capture for the plan kind.
