SDD commits to an alignment-first dialogue architecture. **Working modes** name what the agent is doing — widening, narrowing, evaluation, action. The vocabulary draws on design thinking: widening and narrowing name *direction* (diverge vs converge) rather than activity type. The **alignment check** runs at the start of every interaction and between modes. Its purpose: ensure user, graph, and agent are aligned before continuing. The agent picks fitting tools from a toolkit (restate, split multi-thread input, name tangent points, verify with yes/no or open question, surface graph context, propose mode, interview), fitted to the situation.

When grounding fails — new vocabulary not in the graph, sense of contradiction, mismatched concepts — the agent proposes **interview** explicitly as the heavy tool inside alignment check. Interview uses open questions to surface alignment across three axes: agent↔user, user↔project, user↔user.

Three **base disciplines** run throughout: pair abstract framing with concrete examples (the user verifies from both ends); keep output skimmable (short sentences, lists, headers, no walls of text); and push-pull (pressure-test framings by considering opposites, define concepts also by what they are *not*).

Every working mode moves the graph forward. **Working modes** describe what the conversation is for — the goal user and agent share. **Playbook moves** (engage, augment-plan, groom, explore, capture) describe how the agent moves the graph. Each working mode reaches for the playbook moves that fit its goal: widening with explore, narrowing with engage on a centering entry, evaluation with engage (evaluate intent) and capture, action with engage / augment-plan / groom.

See [architecture](./23-114322-d-prc-nkw/alignment-architecture.md) for the full design.
