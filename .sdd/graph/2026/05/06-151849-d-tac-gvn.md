Plans the type-system extension to 7+7 kinds — adding `kind: annotation` (signal) for topic clustering and `kind: focus` (decision) for intent declaration with involvement triples — plus the CLI capture surface, display rendering, pre-flight rules, and the new contract entry that supersedes `d-cpt-ygn` to codify the rules.

**Type system change.** Signal kinds become 7: gap, fact, question, insight, done, actor, **annotation**. Decision kinds become 7: directive, activity, plan, contract, aspiration, role, **focus**. Existing kinds and their structural requirements (write-once canonical, plan-acceptance-criteria, done-closure-target) carry forward unchanged. The plan's closing done signal captures a new `kind: contract` entry that supersedes `d-cpt-ygn` and codifies the 7+7 rules; the plan itself does not supersede the contract directly (cross-kind supersession is not a graph primitive).

**`kind: annotation` signal.** Purely structural — excluded from catch-up narrative rendering. Frontmatter carries `topics: [{label, members}]` where each entry has a `label` (string, topic-path canonical form) and `members` (list of full IDs). Annotations exist to be queried for clustering, not read as observations.

**`kind: focus` decision.** Dual lifecycle: supersedable when priorities shift mid-cycle, completable via done signal when a cycle finishes naturally. Frontmatter carries:

- `involvement: [{target, actors?, when?}]` — list of involvement triples
- Optional top-level `actors: [canonical, ...]` — default involvement set
- Optional top-level `when: {from?, to?}` — default temporal scope

Per-involvement values override top-level defaults. Resolution: per-involvement value if present, else top-level value, else empty/null. Three involvement states emerge: **attributed** (resolved actors non-empty + heat above stalled threshold), **stalled** (resolved actors non-empty + heat below threshold), **pull-available** (resolved actors empty — in scope, awaiting pickup). Pull-available enables pull-based collaboration aligning with the autonomy aspiration (`d-stg-7lu`).

`when:` allows open intervals — `{from: ...}` only (open-ended), `{to: ...}` only (deadline), both (full window), or absent (timeless). At least one of `from:` or `to:` required when `when:` is present.

**Topic data model.** Topics are first-class on every entry kind via inline `topics: [<label>, ...]` frontmatter (zero-ceremony at capture); `kind: annotation` entries provide retroactive/bulk reorganization via their `topics: [{label, members}]` structure. Internal representation: `[]string` of path components (e.g., `UX/CLI` is `["UX", "CLI"]`). I/O representation: components joined by `/`. Component validation: `[\p{L}\p{N}\-]+` (Unicode letter/number plus hyphen, no `/` within a component). Comparison case-insensitive on each component; first-seen casing preserved as canonical for display. No alias mechanism in v1 (deliberate scope).

**CLI capture surface.** Decoupled from frontmatter shape via JSON in repeated string flags — keeps storage refactorable without breaking captors:

- `--actors NAME[,NAME...]` — top-level focus actors (canonical-only CSV)
- `--when '{"from":"YYYY-MM-DD","to":"YYYY-MM-DD"}'` — top-level focus window (JSON object)
- `--involvement '{"target":"<id>","actors":["..."],"when":{...}}'` — repeatable, JSON object per involvement triple
- `--topic '{"label":"path/to/topic","members":["<id>", ...]}'` — repeatable, JSON object per cluster (only on `kind: annotation`)
- `--topics LABEL[,LABEL...]` — CSV inline topic labels, valid on any entry kind

JSON parse errors and shape errors produce clear messages with field locations. Single-quoted outer / double-quoted JSON inner is the documented quoting convention.

**Display rendering.** Topics render as `<label1, label2>` between `{status: ...}` and summary on entry lines in `sdd list`, `sdd status`, and (consumed by) `sdd view`. `sdd show <id>` displays topics as a derived field — inline `topics:` from frontmatter merged with annotation-entry membership pointing at this entry, deduplicated, first-seen casing.

**`sdd list` filtering.** `sdd list --kind annotation` and `sdd list --kind focus` use the existing `--kind` filter. `sdd list --topic <label>` filters via prefix-match on topic-path components, case-insensitive — uses the `topic(L)` filter primitive from Plan 2's (`d-tac-uww`) shared `internal/finders/` so the implementation is shared across `sdd list` and `sdd view`.

**Pre-flight rules.** Mechanical-shape only on focus captures (involvement list, target resolution, canonical actors, when format) at high severity. Pre-flight does not enforce supersession-vs-done-closure rubrics or commitment-completeness for focus entries — focus is fluid by nature, and lifecycle reasoning is exactly the territory that oscillates per `s-prc-vvd`. Three observation patterns surface as low-severity informational findings (not blocking, intended to drive dialogue): focus closed via done signal but no targets carry done signals; focus superseded with zero shared targets; focus with all involvement unattributed.

**Routing-vs-involvement boundary.** Focus carries only involvement (actively driving). `kind: role` (already shipped via `d-cpt-ygn`) remains the source of routing (should weigh in). They reference the same actor pool but answer different questions on different cadences. `s-cpt-5jk`'s broader scope (profile filtering, profile inference, profile evolution) carries forward as a separate question; this plan only settles the boundary.

**CQRS decomposition** (per `d-cpt-ah1`): annotation/focus/topic-path types in `internal/model/`; capture command structs in `internal/command/` with handlers in `internal/handlers/`; pre-flight in `internal/llm/`; topic filter primitive in shared `internal/finders/` so `sdd list` and `sdd view` consume the same logic; display rendering in `internal/presenters/` extending the existing entry-line presenter to include topic field.

**Migration semantics.** Forward-only. Existing entries are not retroactively annotated. Topics on historical entries can be added via supersession (changing the entry to add inline `topics:`) or via new `kind: annotation` entries pointing at the historical members.

**Out of scope** (deferred): topic alias mechanism, topic-tree rendering (covered by Plan 2's reserved `source(topics)` + `as-tree`), retroactive annotation backfill on historical entries, focus involvement-state visualization beyond the algorithm Plan 2 implements.

See [design](./06-151849-d-tac-gvn/design.md) for full type system spec, frontmatter schemas with worked examples, CLI capture quoting patterns, pre-flight rubric details, and the new contract entry's structure.
