Comparative examination of three popular Claude Code skill bundles (GSD, gstack, beads) yields a routing-and-modularization spectrum: GSD operates a two-stage namespace router with deterministic state-machine dispatch from inside workflows (~120-token cold-start, down from ~2,150; recurring stale-slash-command pitfalls after consolidations); gstack runs 50+ flat sibling skills relying on hand-tuned trigger prose, voice-trigger arrays, and an injected project CLAUDE.md routing table (1–3K line SKILL.md inflated by duplicated tier preambles; recurring trigger-collision class against host built-ins like `/debug` and `/checkpoint`); beads keeps a single skill with `bd prime` SessionStart/PreCompact hook injection and a 605-word always-loaded surface (under-triggering activation as the main risk).

The findings recommend Pattern A — extract heavy playbook prose into on-demand references with explicit load-gates following GSD's `<progressive_disclosure>` shape — as the strongest first move for /sdd modularization (s-prc-nxy). GSD's quantified ~13K → ~0 token win on entry-point load maps directly to /sdd's playbooks (catch-up, augment-plan, transition-to-implementation, grooming, explore are conditionally relevant and 50–100 lines each); gstack's trigger-collision experience argues against aggressive sub-skill proliferation; reusing the existing `references/` pattern is structurally low-risk and reversible.

A refinement to the service-vs-mode test surfaced during dialogue: a service's output is a discrete artifact the caller moves past; a mode'"'"'s "output" is the caller'"'"'s continuing context. Under this test `/sdd-catchup` is mode-shaped — its briefing doesn'"'"'t substitute for entry knowledge, the outer agent re-loads anyway — and the upcoming plan should bundle catch-up'"'"'s demotion from sub-skill to playbook moves (quick / full / topic-drill differentiation) alongside Pattern A. `/sdd-explore`, `/sdd-groom`, `/sdd-bootstrap` hold under the refined test.

The design commitment is captured separately as a forthcoming tactical plan; a conceptual insight on graph-as-record vs DB-as-record (beads-as-foil) is captured separately at the conceptual layer.
