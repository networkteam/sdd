Establishes "augment plan via downstream directive" as a named pattern in the SDD skill so plans can accumulate refinements during implementation without supersession or ceremony. Implementation playbook moves and a new "Augment plan" playbook move land as concrete skill updates.

The pattern fills a gap between two existing options for refining a plan: mechanical fixes (typo-shaped, no supersession needed) and full supersession (heavy for small refinements). When implementation reveals a substantive but narrow refinement — e.g. an AC that turned out too specific in scope, a missing edge case in a chunking strategy — the cost of superseding the entire plan dwarfs the value of capturing the refinement. The result has historically been either silent drift (refinement made in code, never captured) or noisy supersession chains. This directive operationalizes a third path that fits between these (refining d-cpt-e1i's mechanical-fix-vs-supersede distinction): a downstream directive that refs the plan, captures the refinement, and gets folded into the plan's implicit acceptance contract.

Two concrete skill updates land:

1. **Implementation playbook (skill `Transition to implementation` section)**: the implementing agent must run `sdd show <plan-id> --downstream` before beginning work and treat any downstream directives that ref the plan as extensions of its acceptance criteria. The closing done signal must address both the original ACs and the downstream refinements with the same dialogue rigor.

2. **New `Augment plan` playbook move**: when implementation reveals a refinement that's too substantive for a mechanical fix but too narrow to warrant supersession, the agent captures a directive that refs the plan, articulating the refinement and its rationale. The plan stays active; the directive becomes part of the plan's implicit AC chain. The done signal closes both.

The trade-off is real and explicit: a plan's acceptance contract is now distributed across the original entry plus its downstream refinements, so closing requires reading the full chain rather than a single document. This cost is accepted as the price of fluid, dialogue-shaped work, aligning with d-stg-3k0's commitment to no parallel artifacts and no ceremony.

Operationalization: skill source under `internal/bundledskills/claude/sdd/` is updated to add the downstream-fetch instruction in `Transition to implementation` and to introduce the `Augment plan` move alongside the existing playbook moves; `.claude/skills/sdd/` regenerated via `./bin/sdd init --scope project`; both committed in the same commit.
