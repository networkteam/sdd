The catch-up sub-skill's "drill A" / "drill B" verb is intended to expand a topic cluster into more entries — load the underlying signals via ref-graph traversal so the user sees the landscape before engaging on any one entry (per `d-tac-qom`). The current implementation skips the expansion step: typing "drill C" triggers engage-mode behavior directly — chain reads via `sdd show --downstream`, synthesis brief, decision-dimensions list, candidate moves, orienting question — collapsing two distinct steps (expand area → choose engage target) into one.

This was observed in a fresh-session evaluation where "drill into C" produced a paired-entry engage brief on `s-cpt-k7z` + `s-cpt-zsd`, when the intended behavior was a numbered list of entries clustered in the heat-scoring/ref-qualifier area with engagement triggered separately. The fall-through happens because the sub-skill specifies the "Say drill A or survey" prompt as render output but never specifies what the verb should do — the agent defaulted to engage on the entries it could resolve from the still-loaded catchup data.

Resolution likely extends `/sdd-catchup` (or adds a sibling drill mode) with explicit expand-first behavior: numbered list of entries in the area's cluster, one-line each, ending with "which entry do you want to engage on, or wider?" — and only then a bare number or ID triggers the engage flow. See [design idea](./17-171030-s-prc-bxk/design.md) for the proposed flow and the open dimensions (placement, cluster computation, render shape, engagement trigger) that need dialogue before plan capture. `d-tac-qom` remains open pending this resolution.
