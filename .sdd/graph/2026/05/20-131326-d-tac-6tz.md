## Capture-time topic procedure

The /sdd skill gets a new move in the capture playback: before proposing the entry, research what topics are in use and how connected entries are labeled. The goal is consistent use across the graph.

1. `sdd view --layout='active:as-counts'` — what topics exist and how many entries each carries. Once per session unless they change.
2. `sdd view --layout='id(<id1>,<id2>):as-list'` — topics on entries this one refs. Connected entries usually share clusters; matching their topics keeps the graph consistent.
3. If 1+2 don't surface a clear fit, also run `sdd search --query "<short cluster phrase>" --max-citations 0` — topics on semantically similar entries that aren't refed.

Then propose at least one topic for the entry. Use existing topics when they fit. When none fits, propose a new one and name what cluster it starts. User can adjust or skip.
