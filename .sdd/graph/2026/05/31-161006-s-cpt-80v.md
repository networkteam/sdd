Feasibility research for the workflow-agent-via-MCP direction, run 2026-05-31 as two Perplexity passes (attached). MCP supports the stateful design: it is a stateful protocol with per-session state — process-bound on stdio, keyed to `MCP-Session-Id` over Streamable HTTP — and supports server-initiated mid-operation interaction via sampling (server asks the client's model) and elicitation (server asks the user). Both are negotiated client capabilities with uneven support (VS Code had elicitation mid-2025; Claude Code did not), so they must be feature-detected, not assumed. Returning "call X next" in tool output is host-driven convention, not protocol-enforced — so deterministic rails require sampling/elicitation, while request/response tool-output steering is the universal advisory fallback. Remote multi-user hosting uses OAuth 2.0/OIDC with session state keyed to the authenticated user. On the platform side, all five major assistants (ChatGPT, Claude, Gemini, Copilot, Perplexity) act as MCP clients in 2026; the cleanest non-developer onboarding is pasting a remote connector URL (Perplexity, ChatGPT, and Claude — the most mature consumer MCP story), while the third party must host the server over HTTPS. ChatGPT leads reach (~400M weekly actives); Claude has small consumer reach but the strongest MCP integration. Protocol facts are primary-sourced and firm; client-support and market-share figures carry source caveats, and Perplexity's self-ranking as easiest is discounted as biased.
