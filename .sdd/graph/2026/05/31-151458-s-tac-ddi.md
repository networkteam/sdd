When `sdd init` refreshes a project's installed skills, it doesn't compare the local binary's skill version against the version the project is already on before overwriting. A newcomer running init with a different binary version can therefore silently change the project's committed skills — up or down — with no reconciliation step.

Prior work (d-tac-kud) write-gates an older binary against a newer project schema, but from the user's view the skill-refresh path still doesn't check local-vs-project skill version in the newcomer-clobber direction.

**Proposed direction** (not decided): an explicit, version-aware update that compares versions and warns or refuses on mismatch, decoupled from registration. Raised by a first-time SDD user on first run.
