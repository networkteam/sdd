Refines the `group(...)` macro form on the `sdd view` plan (d-tac-uww §5) from the colon notation `group(by:kind)` shown in the plan to the nested-call form `group(by(kind))`, treating `by` as a marker function symmetric with `rank(by(date))`. The parser grammar (§3) defines args as `func | number | identifier | string` with no `key:value` form; the nested form lands without parser changes.

Dialogued at slice 5 pickup. Three alternatives were considered: (a) extend the parser to accept `key:value` args (would match the plan text verbatim but adds grammar surface for one primitive's sake); (b) drop `by:` entirely so `group(field)` is bare (simplest grammar but loses the directional cue and drifts further from the plan text); (c) adopt the nested-call form `group(by(kind))` (zero parser changes, mirrors the already-working `rank(by(date))`). Option (c) was chosen for grammar minimality and call-site symmetry.

Slice-5 implementation, slice-6 macros (decisions, signals, and any future grouping macro), and any user-supplied layouts therefore use `group(by(<field>))` rather than the colon form. The plan's §5 macro table is otherwise unchanged; the closing done signal at AC 23 should note the refinement explicitly so readers comparing plan text to implementation see a single captured rationale.
