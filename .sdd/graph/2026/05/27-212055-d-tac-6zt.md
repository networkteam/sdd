Commit to a CLI upload-token surface — `sdd attach upload` returning a token plus `sdd new --attach-token <token>` — as a follow-up after the MCP server plan (d-tac-0v4) lands. It eases multi-attachment and long-description ergonomics, where the CLI today is limited to a single `-` stdin slot and temp-file juggling for combining a heredoc description with several attachments. The work rides on the transport-agnostic `AttachmentStore` and `AttachUploadCmd` that d-tac-0v4 introduces, so it is functionally blocked until those ship. Scope explicitly includes updating `references/cli-reference.md` and the `/sdd` SKILL.md so agents learn the new attachment flow — the surface change isn't done until the docs and skill guidance match. A full plan with acceptance criteria will be drafted once d-tac-0v4 ships and the store's real shape is in hand; this directive records the commitment and the sequencing so the follow-up isn't lost.
