Refines d-tac-cs0 AC 9 (render scope) and AC 11 (lint surfacing) based on slice 2 implementation findings: both surfaces were too broad, producing two unwanted side effects on the current graph that the refined scope resolves.

**AC 9 — scope the multi-line ref block to preflight prompts only; fall back to flat format for legacy refs.** The slice 2 implementation changed `FormatEntryForPrompt` to render refs as a multi-line `(kind: K)` block with optional desc. That helper is also called from the summary prompt path (`RenderSummaryPrompt` → `FormatEntryForPrompt`), so changing it invalidated every stored summary hash — 481 entries report "stale summary hash" because the prompt now differs from when the summary was generated. Refinement: when rendering an entry's refs, check whether every ref carries `Kind == RefKindUnknown` (the legacy bare-string fallback). If so, render the original flat `Refs: id1, id2` format. Otherwise (any ref with a capturable kind — i.e., object-form refs) render the multi-line block. This preserves byte-identical prompts for legacy entries, keeping their hashes stable; the ref-meta consistency check still applies to new captures via the multi-line block on the proposed entry.

**AC 11 — accept legacy bare-string refs as a valid permanent state; drop the lint surfacing.** The slice 2 implementation flagged every `Kind == RefKindUnknown` ref at lint time, producing 1231 warnings across the historical graph. These refs are not corruption — they're an accepted parser fallback for read-side traversal, and the mechanical pre-flight (slice 1 AC 8) already prevents *new* entries from carrying bare-string refs. Refinement: drop the `LintRefKinds` lint surfacing entirely. Closed-set validation happens at YAML parse time (any kind value outside the closed set fails to load); lint adds nothing beyond what parsing already enforces. Legacy bare-string refs continue to render as `kind: unknown` for traversal but are not lint findings. The upgrade path is supersession of the parent entry, not retroactive lint cleanup — historical refs stay legacy forever unless their parent entries are superseded.

**Net effect.** The current graph reports zero lint warnings from the per-ref kind work and no stale summary hashes. New captures still get the LLM ref-meta consistency check via the preflight-only render path (proposed entry's refs in the multi-line format); new entries still cannot carry bare-string refs (the mechanical pre-flight from slice 1 still blocks at high severity). The d-tac-cs0 commitment — per-ref kind metadata as the structural foundation for downstream consumers — holds; this directive narrows two implementation surfaces that overreached.
