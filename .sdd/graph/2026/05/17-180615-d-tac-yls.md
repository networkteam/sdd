Adds an `expand(refs)` per-row render modifier to `sdd view` so list-shape outputs surface each entry's outgoing refs as nested sub-lines with derived status and the per-ref `kind`/`desc` that `d-tac-cs0` adds. Resolves the temporal-blur observation from the catch-up sub-skill evaluation (`s-tac-7uy`) where `d-prc-iqw`'s summary said the engage refactor was pending while `d-prc-kyz` had already closed via `s-prc-st0` — the agent had no signal of the state change because `sdd view` rendered the captured summary text without surfacing referenced entries' current state.

Depends on `d-tac-cs0` (per-ref kind taxonomy) shipping first. With `kind` in place, the render uses each ref's kind as the verb (`grounds`, `builds-on`, `addresses`, `surfaces`, `evidence`, `depends-on`, `related`) — the verb-position carries relationship semantics unambiguously, distinct from the entry-kind that appears as plain identity qualifiers elsewhere on entry lines. Legacy bare-string refs (parsed as `kind: unknown` per `d-tac-cs0`) render with the generic verb `refs`. Status renders unconditionally; `desc` renders after status when present.

Naming follows existing view vocabulary: `expand(refs)` extends the `expand(involvement)` precedent (per-row expansion transform), distinct from sibling plan `d-tac-jqq`'s `refs-of(<id>)` filter (set transformation by seed ID). The two compose orthogonally. Default behavior emits all outgoing refs; an optional nested call `expand(refs(state-changed))` narrows to refs with `closed-by` or `superseded-by` derived status for lean catch-up output. Direction is outgoing only — downstream (`refd-by`, `closed-by`) would need its own transform, out of scope.

Forward-compatible with the short-summary direction captured separately as a low-confidence gap. When `short_summary` lands, `expand(refs)` adopts it as a trailing clause (`— <short_summary>`) via a small refinement directive without further plan revision. Together this plan, `d-tac-cs0`, and the short-summary gap surface the four primitives (identity, relationship+narrative, state, referenced-entry-content) that complete the per-ref information an agent needs to thread correctly.

CQRS decomposition per `d-cpt-ah1`: parser change in `internal/query/`, finder method in `internal/finders/` walking each result entry's refs and resolving derived status from the loaded graph, presenter helper in `internal/presenters/` writing the nested lines. No model changes (the model layer ships in `d-tac-cs0`). Ships independently of `d-tac-jqq` (drill plan, parallel position in the view grammar). See [design](./17-180615-d-tac-yls/design.md) for failure decomposition, naming rationale, verb-as-qualifier rationale, sequencing, and the four-primitives constellation.

## Acceptance criteria

- [ ] Depends on `d-tac-cs0` landing first (per-ref `kind` and optional `desc` available in the model layer). This plan makes no changes to `internal/model/`.
- [ ] `sdd view` accepts an `expand(refs)` per-row render modifier on `as-list` outputs. Per entry in the result, the modifier emits one indented sub-line per outgoing ref. Tests cover entries with zero refs, single ref, multi refs, mixed `kind` values (including `unknown`), mixed derived status, and composition with `active`, `kind`, `layer`, `topic`, `not`, `since`, `rank`, `n`.
- [ ] Default filter is `all` outgoing refs (no argument: `expand(refs)`). Optional nested call `expand(refs(state-changed))` restricts to refs whose derived status is `closed-by` or `superseded-by`. Filter grammar follows the existing nested-call pattern (`rank(heat(exp-14d))`, `group(by(<field>))`).
- [ ] Sub-line shape uses the per-ref `kind` as the verb: one of `grounds`, `builds-on`, `addresses`, `surfaces`, `evidence`, `depends-on`, `related`; or `refs` when `kind` is `unknown` (legacy bare-string refs parsed per `d-tac-cs0`). Status renders unconditionally as `{status: active|closed-by <id>|superseded-by <id>}`. `desc` renders after status as `: "<desc>"` when present. Full IDs render in all forms. Sub-line shape composes additively as adjacent primitives land (short_summary appends as `— <short_summary>` via future directive).
- [ ] `expand(involvement)` retains its focus-block-only scope unchanged; `expand(refs)` is a distinct variant valid on `as-list`. No regressions on the involvement-expansion path.
