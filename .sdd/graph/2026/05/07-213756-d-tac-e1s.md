Adds a generic `not(<filter>)` primitive to the `sdd view` layout grammar, scoped initially to negating `kind`, `layer`, and `topic` filters; defers negation of `active` and `since` and disallows nested `not(not(...))` for the first cut. The plan resolves the filter-negation gap (s-tac-x1n) surfaced during `sdd view` first-real-use evaluation, where standing entries (contracts, aspirations) dominated `top(N)` rankings and only positive-disjunction `kind()` was available as a workaround. Family A (general primitive) was chosen over B (negation tokens within `kind()`, asymmetric and ambiguous in mixed mode) and C (macro-level default exclusions, opinionated and non-composable) because the parser already supports nested function args for primitives like `rank(by(date))` and `group(by(kind))`, so the grammar surface adds zero parser cost while preserving symmetry across filter primitives and keeping authority with the user composing the layout. See [plan](./07-213756-d-tac-e1s/plan.md) for alternatives detail and implementation sketch.

## Acceptance criteria

- [ ] `not(kind(K1, K2, ...))` excludes entries of those kinds; composes with positive `kind(...)` calls under intersection (positive includes ∩ negative excludes)
- [ ] `not(layer(L))` excludes entries at that layer
- [ ] `not(topic(L))` excludes entries whose effective topic set has L as a component-wise prefix
- [ ] `not()` with an unsupported inner filter errors with a listed-supported-set message naming kind, layer, topic
- [ ] `not()` with zero or multiple arguments errors with a clear message (e.g. `not: requires exactly one filter argument, e.g. not(kind(contract,aspiration))`)
- [ ] `not` is registered in `knownFunctions` so unknown-function errors don't shadow real misspellings
- [ ] The bundled `cli-reference.md` adds a minimal Filters-table row for `not(<filter>)` and a single worked example, with no expanded rationale or alternatives commentary
- [ ] One executor test per supported inner filter (kind/layer/topic) plus one rejection test per error class (unsupported inner, arity)
