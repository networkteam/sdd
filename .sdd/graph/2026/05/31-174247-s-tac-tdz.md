`sdd`'s automatic git commits scope their `git add` to the files the command touched, but then run `git commit -m <msg>` with no pathspec — which records the *entire* staged index. Any change an agent pre-staged before invoking a graph-writing command (`sdd init`, `sdd new`, `sdd summarize`, `sdd wip`, `sdd lint --fix`, `sdd rewrite`) is silently folded into the CLI's own commit. Observed when an agent ran `sdd init` to restamp installed skills, then could not reconcile its edited file already sitting in HEAD under `sdd: refresh installed skills and metadata` and spent several tool calls chasing an empty `git diff`. Two committer functions in `cmd/sdd/main.go` share the pattern: `gitCommit` (init, new, summarize, wip start, lint fix, rewrite) and `gitRemoveAndCommit` (wip done). The fix is to pass `-- <paths>` to each `git commit` so it records exactly the touched files regardless of index state — the same discipline as the project's own never-`git add -A` rule, applied to the CLI's automation. Announcing the commit was considered as a separate readability aid but is out of scope; the core defect is index contamination, not silence.
