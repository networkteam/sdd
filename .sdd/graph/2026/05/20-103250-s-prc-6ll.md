SDD capture discipline lacks a pre-draft grounding step for claims in dialogue — the play-back-first rule pulls drafting forward from dialogue substance without first checking whether claims in that substance reflect the world. When dialogue assumes or proposes facts the agent could verify with available tools (graph search, file reads, web search, project-specific tools), the agent should ground them so captured entries carry correct claims, not echoed phrasing. When a claim *cannot* be grounded with available tools, the skill should push the agent to question it rather than admit it as established fact. The discipline applies both ways: users can be wrong too — stale memory, conflated systems, repeated assumptions — so grounding serves the dialogue as a whole, not just agent self-correction. The purpose underneath: SDD should help participants capture good and grounded decisions, not just well-formed ones.

Observed in another project's /sdd session: a user's message contained a multi-step plan that included a pointer to a specific repo where a named pattern was said to already exist; the agent collapsed the plan into "capture the gap, then engage" and echoed the named pattern verbatim into the draft entry without opening the repo. User push-back exposed that multiple configuration dimensions (scope, placement, shape) were all unaddressed by the draft. Why current rules miss this: "fold substantive dialogue into entry content" treats dialogue input as substance to preserve, not as claims to verify; pre-flight checks narrative shape and cannot verify external assertions against the world. The structural shape — verify named identifiers before asserting them — already shows up in agent-memory rules elsewhere, but not in live dialogue capture; a claim that names a specific thing is a claim it exists in that form. Confidence medium — observed once cleanly, needs more instances to confirm how broadly it generalizes.
