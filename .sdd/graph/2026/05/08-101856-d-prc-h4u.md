Adopt a project-scoped release skill at `.claude/skills/release/SKILL.md` to codify the SDD CLI release flow. The proven minimal pattern is a single command — `gh release create vX.Y.Z --title vX.Y.Z --notes-file <path> --target main` — which creates the tag, pushes it, publishes the release with curated body, and triggers the GoReleaser workflow. GoReleaser respects the existing release at the tag via the default `release.mode: keep-existing`, attaching binaries and the Homebrew cask update without overwriting the body.

Anti-patterns surfaced via the v0.5.1 mishap and captured in the skill: (1) `gh release create --draft` leaves an orphan because GoReleaser does not honor a third-party draft as its target — it creates a competing published release at the same tag; (2) deleting a partial release after the Homebrew tap was pushed creates state divergence — recovery is `gh run rerun` (idempotent), not delete-and-redo.

The skill's survey step uses `git log $(git describe --tags --abbrev=0)..HEAD --oneline` for authoritative scope plus batch `sdd show <ids> --max-depth 0` for graph context (full body + immediate closes/refs, deeper chain truncated — the right level for highlight prose). The leaner alternative `sdd view --layout='kind(done):since(<tag-date>):...'` was rejected after smoke tests showed ~78% of results were already-released entries from the same calendar day as the prior tag (the `since` filter is date-precision, not tag-time-precision). Skill route chosen over CLAUDE.md + reference for slash-command discoverability and self-contained operational footprint. The skill gates explicitly on user confirmation before any release-creating command runs.
