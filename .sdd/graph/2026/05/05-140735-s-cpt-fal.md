Beads' embedded Dolt store provides a clean foil for SDD's graph-as-record approach: beads pays a structural cost (32-migration schema, bifurcated history split across live `issues` rows + `events` audit log + `issue_snapshots` point-in-time captures, Dolt-native cell-level merge plus a custom `merge_slot` mutex primitive) to get indexed queries, atomic claim semantics, and constant-time live-state lookup. SDD's immutable-markdown substrate gets versioning, history, and conflict resolution from Git for free at the cost of cross-graph traversal in Go.

A structural equivalence worth naming: beads' `bd prime` SessionStart hook is doing what SDD does at session start (injecting state via `sdd status`) — different substrate, same pattern of "auto-inject the current view of the record into the agent's context." The hook pattern is independent of the storage substrate.

The trade-off between substrates reduces to: structural cost (schema migrations, bifurcated history modeling, merge-strategy choice) vs computational cost (cross-graph traversal at read time, which scales with graph size). At ~409 entries traversal is cheap and the immutable-file model wins on simplicity, friction-free Git-native conflict resolution, and alignment with no-parallel-artifacts (d-stg-3k0). At much higher scale (10K+ entries with indexed-query needs) the cost ratio shifts — the `sdd search` plan (d-tac-lqr) is already a partial response to the read-side scaling pressure.

The insight informs strategic positioning more than immediate design: SDD's graph-as-record is a first-class architectural choice, not an implementation convenience. It aligns with dialogue-first (d-stg-beb) where the record is the dialogue artifact, parallel-coherence (d-stg-qlt) where Git semantics handle coordination, and no-parallel-artifacts (d-stg-3k0) where the substrate refuses to bifurcate.
