AC 13 of `sdd view` (closed plan d-tac-uww) implemented section-level deduplication only for `as-list` sections following an `as-focus-block` in the same layout: focus targets get stripped from later flat lists. The implementation is opportunistic — it solves one observed noise pattern (focus + top showing the same target twice) without committing to a general rule about cross-section repetition.

Two coherent design directions exist, and the current state picks neither cleanly:

1. **Universal dedup with `(see above)` markers** — every section drops repeats from earlier sections, mirroring how `sdd show` handles up/downstream chains. Reader sees each entry's full line at first occurrence, then a stub on later occurrences. Maximizes signal density.
2. **No dedup; sections are independent slices** — each section renders fully on its own information, and an entry appearing in two sections is intentional (each surface shows different metadata: state in focus-block, heat score in top, kind grouping in decisions). Maximizes per-section coherence.

The complication that makes (1) awkward: different render shapes carry different information per entry. A focus-block target shows `{state: stalled} {score: 0.000}`; the same entry in `top(N)` would show `{score: 7.872}`; in `decisions` it would sit under a `### plan` header. Stubbing later occurrences as `(see above)` loses that per-section information.

Removing AC 13's mechanism (revert dedup so all sections render independently) until a deliberate decision lands on (1), (2), or a hybrid. Captured as a question rather than a gap because the resolution is a design choice, not a missing feature — and because the user observation that prompted this was that picking a special-case dedup without naming the principle felt wrong. The revert restores per-section independence as the conservative default; layered dedup can be added back deliberately if direction (1) wins.
