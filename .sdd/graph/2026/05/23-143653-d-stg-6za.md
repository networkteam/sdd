Pursue a self-hostable, agent-agnostic web UI sandbox for SDD dialogue, capture, and reporting as the primary path to lower the entry bar — dogfooded by the existing technical team first, then expanding to less-technical participants. Direction commits to: a web UI for dialogue / capture / reporting rather than in-repo development, an agent backend running with skills and tools in a sandbox with Git access, an open-source self-hostable stack only (no closed SaaS), and runtime portability so SDD is not locked to one agent or provider — Claude Code is restricted programmatically and we want SDD open to other agents anyway. Starting with external newcomers as user one was considered and rejected as too ambitious; technical-team dogfooding is the dependable path to polish the rough edges. Specific stack choice (Langflow currently being explored as a candidate; alternatives like Claude Agent SDK or headless Claude Code wrappers were considered) is deferred to a follow-up tactical plan after the exploration concludes. See [design context](./23-143653-d-stg-6za/design-context.md) for the three runtime shapes considered and how the agent-agnostic constraint reshapes the trade-off.
