Plan to land Pattern A modularization for /sdd: extract heavy playbook prose (catch-up, augment-plan, transition-to-implementation, grooming, explore) into on-demand `references/playbook-<name>.md` files with explicit load-gates in SKILL.md, while keeping high-invariant constraints (capture discipline, type/layer/kind rules, canonical-only participants, sync-check, language, vocabulary register) always-loaded. Bundles the structural demotion of `/sdd-catchup` from sub-skill to a sixth playbook reference under the refined service-vs-mode test, with `/sdd-bootstrap`'s hand-back updated to invoke the full-catch-up move directly. Branch-based implementation with a 10-scenario routing-reliability rubric; closing done articulates whether the change lands or reverts based on token reduction, scenario-eval pass rates, and dialogue-flow quality.

The Modes of working section (currently lines 186-212 of SKILL.md) becomes the gate table — one row per mode naming the trigger condition and reference path, following GSD's `<progressive_disclosure>` shape. SKILL.md projects from ~447 lines to ~217 lines (~52% reduction). Capture-detail blocks (attachment assessment, infer participants, canonical names, language, sync-check) remain inline in this round; round-2 evaluation of those candidates depends on observed Round-1 reliability.

Mode differentiation for catch-up (quick mode with warmth, topic-drill via semantic search) is deferred to a follow-up directive scoped to activate after `sdd search` (d-tac-lqr) ships. This plan does the structural correction only; quick-mode and topic-drill are feature work with external capability dependencies.

Grounded in the comparative examination findings (s-prc-gu6) and addressing the modularization gap (s-prc-nxy); measured against the s-tac-n8u baseline; informed by instruction-density research (s-cpt-0db).

## Acceptance criteria

- [ ] **References extracted**: catch-up, augment-plan, transition-to-implementation, grooming, and explore playbook prose live in `references/playbook-<name>.md`; SKILL.md retains only the dispatcher (Modes of working) with reference paths per mode
- [ ] **Always-loaded invariants preserved**: capture discipline, type/layer/kind rules, canonical-only participants, sync-check guidance, language handling, vocabulary register, and the modes-of-working dispatcher remain inline in SKILL.md
- [ ] **Load-gate format adopted**: SKILL.md's Modes of working section is refactored into a gate table — one row per mode, each naming the trigger condition and the reference path; the agent is instructed to load only the references whose triggers match the current dialogue
- [ ] **`/sdd-catchup` sub-skill removed and bootstrap hand-back updated**: the sub-skill is deleted from `internal/bundledskills/claude/` (and `.claude/skills/`); full-catch-up content moves to `references/playbook-catchup.md`; `/sdd-bootstrap`'s hand-back invokes the full-catch-up move directly instead of `/sdd-catchup`
- [ ] **Token baseline captured**: post-implementation cold-start metadata cost and post-`/sdd` total Messages via `/usage` against s-tac-n8u; per-reference file token counts via Anthropic `count_tokens` API; results in the closing done
- [ ] **Routing-reliability scenario eval run**: 10-scenario rubric (session start, capture, decide, evaluate, transition-to-implementation, augment-plan trigger, grooming sweep, explore drill, sub-skill hand-back, casual non-mode dialogue) tested in fresh agent sessions against the candidate branch; each scenario specifies expected reference loads; results in the closing done with pass/fail per scenario
- [ ] **Decision criterion applied**: closing done articulates whether the change lands or reverts based on (a) no scenario regressions vs baseline, (b) measurable token reduction on cold start and per-mode loads, (c) qualitative read of dialogue flow against existing experience
- [ ] **Mode differentiation deferred**: a follow-up directive captures the quick-mode and topic-drill catch-up enhancements, scoped to activate after `sdd search` (d-tac-lqr) ships

See [plan](./05-152402-d-tac-ab1/plan.md) for the design discussion, gate format design, scenario rubric, and token-measurement methodology.
