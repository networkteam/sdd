Registering as a participant in SDD is underbuilt in two ways. First, it isn't a standalone step — the only path is `sdd init`, which also sets up the project and installs/refreshes skills, so a newcomer who only wants to join an existing project's discussion is forced through project-mutating side effects. Second, what registration writes (the local participant config) doesn't make you a participant the graph recognizes: a newcomer still needs a separate `kind: actor` entry to be a valid author, and — as observed live this session (s-prc-5zj) — that entry can't be self-authored, since the not-yet-active canonical fails the participant-drift check and an existing participant must vouch the newcomer in.

**Proposed direction** (not decided): a dedicated, version-neutral participant-setup step that both writes local config and establishes graph identity, separate from project init. Raised by a first-time SDD user on first run.
