Making SDD usable outside Claude Code requires both the graph access surface and the skill content itself to be portable — neither is today. The current shape bundles skills in Claude Code's skill format (slash commands, sub-skills via the Skill tool, on-demand `Read references/foo.md` loading) and instructs CLI calls (`sdd new`, `sdd show`) directly in skill bodies; both assumptions break under other agent runtimes such as Langflow, the Claude Agent SDK, or future GUI fronts. Proposed direction (sketch — not yet committed): abstract graph operations behind an *adapter reference* loaded based on environment, where the existing `cli-reference.md` becomes the Claude Code adapter and alternates target MCP or API surfaces; and shift skill *content* from Claude Code's bundle format toward prompt templates and snippets, with a build step that renders the runtime-specific output (Claude Code skill bundle today, Langflow system prompt + tool definitions next). One open question persists: how to model dynamic reference loading (today's mode-triggered `Read references/foo.md`) in runtimes that have a single static system prompt — candidates are inline-all, references-as-MCP-tools, hybrid, sub-flow dispatch, or the prompt-template-as-tool pattern surfaced during PoC. An initial Langflow PoC produced an on-format catchup using the prompt-template-as-tool approach with hard-coded graph data; full findings folded into the attachment. See [design sketch](./25-184931-s-cpt-z7l/portability-sketch.md) for what ports, what doesn't, the proposed direction, and validation so far.
