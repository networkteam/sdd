Adds `sdd search` with three retrieval modes — text (always-on grep over `.sdd/graph/`), vector (opt-in via configurable embedding provider), and hybrid (RRF fusion when both are configured) — returning ranked entries each accompanied by the best-hit chunk's breadcrumb and snippet so callers understand the citation. The two retrieval arms take separate input arguments (`--term` repeatable for keyword/AND, `--query` single phrase for vector), reflecting that exact-token and semantic-concept queries want different input shapes; hybrid is the case where both are provided.

This addresses the semantic-search gap reopened at 5x graph scale (s-tac-ixt), where grep alone misses conceptually related entries and the LLM-as-semantic-matcher workaround in sub-skills is expensive and unreliable. The vector index is local-only (per-participant, gitignored, rebuildable), trading coordination cost for free per-participant experimentation across embedding models. The plan operationalizes dialogue-first reasoning (d-stg-beb) by serving the agent's reasoning loop rather than replacing it, and parallel coherence (d-stg-qlt) by surfacing connections the agent would otherwise miss. CQRS decomposition follows the planning contract (d-cpt-ah1).

The plan ships with empirical evaluation against hand-curated should-be-related pairs from the current 399-entry graph so the friction claim that motivated s-tac-ixt gets a measured response in the closing done signal.

See [design](./04-235258-d-tac-lqr/design.md) for rationale, alternatives considered (in-frontmatter vs local index; chromem-go vs coder/hnsw vs hand-rolled), GraphRAG patterns kept and skipped, chunking strategy detail, and the manual-eval test outline.

## Acceptance criteria

### Search shape and CLI surface

- [ ] `sdd search --term "<keywords>"` runs text mode (live grep over `.sdd/graph/`); `--query "<phrase>"` runs vector mode; both flags together run hybrid (RRF fusion). At least one of `--term` / `--query` is required; no positional argument.
- [ ] `--term` is repeatable; multiple values combine with AND (entry must contain a match for every term). OR semantics achievable via regex alternation in a single value (`--term "(X|Y)"`); no dedicated OR flag.
- [ ] Each result row carries the entry header line plus a best-hit citation: matching chunk's breadcrumb and a ~150-char snippet from the matched chunk text.
- [ ] Filter flags `--type`, `--layer`, `--kind` compose with `sdd search`, matching `sdd list` semantics.
- [ ] Default behavior excludes `{status: superseded-by}` entries from seed results; `--include-superseded` overrides.
- [ ] `sdd status` header carries a `Search:` capability line — `Search: text` or `Search: vector,text` based on whether an embedding provider is configured.

### Embedding provider abstraction

- [ ] `internal/llm/` exposes an `Embedder` interface (`Embed(ctx, []string) ([][]float32, error)`, `Dimensions() int`, `Fingerprint() string`).
- [ ] An embedder factory parallels the existing chat-runner factory: dispatch by provider, wrap remote providers with `rate.Limiter` using provider-specific RPS defaults.
- [ ] Adapters ship for OpenAI-compatible (`/v1/embeddings`) and Ollama (`/api/embeddings`) endpoints.
- [ ] Embedding configuration is independent of chat/summary provider via separate `embedding.*` keys in `.sdd/config.local.yaml`.

### Chunking and embedding

- [ ] Entry summaries are embedded as one chunk per entry, tagged `is_summary`.
- [ ] Description bodies are split via `github.com/yuin/goldmark` AST traversal at `##` and below, leaf-scoped (subsection text excludes parent prose; parent intro is its own chunk).
- [ ] Each section chunk carries breadcrumb metadata (array form) and a heading-chain context line prepended into the embedded text.
- [ ] Heading-only sections (no body content) are skipped, not embedded as empty chunks.
- [ ] Sections > 800 tokens are recursively split with ~10% overlap inside the section; no overlap across heading boundaries.
- [ ] Frontmatter values (type, layer, kind, participants, confidence) are stored as filterable metadata, not embedded as text.
- [ ] Entries without `##` headings produce summary + a single body chunk; covered by a unit test case.
- [ ] Attachments referenced by an entry are chunked and embedded under the parent entry's ID; chunk metadata records the source attachment path.

### Indexing lifecycle

- [ ] Vector index lives at `.sdd/index/` (gitignored), backed by `github.com/philippgille/chromem-go` with persistence enabled.
- [ ] Each row carries `entry_id`, `chunk_path`, `depth`, `content_hash`, `model_fingerprint`, plus `is_summary` / `is_attachment` flags.
- [ ] `sdd index` is the explicit warm-up command — builds the index from scratch over all entries on disk.
- [ ] `sdd search` lazy-fills any entries present on disk but missing from the index before querying.
- [ ] Branch reconciliation: results are intersected with entries currently present under `.sdd/graph/`; rows for entries not on the current branch are silently filtered.
- [ ] Model drift: rows whose `model_fingerprint` differs from the configured embedder are lazily re-embedded; `sdd lint` reports the count of mismatched rows.

### Retrieval and ranking

- [ ] Text mode: live grep over `.sdd/graph/`, ranked by match count and position; honors filter flags and multi-term AND.
- [ ] Vector mode: chromem-go cosine search over chunks; per-entry score is the max chunk score; result carries the winning chunk's breadcrumb and snippet.
- [ ] Hybrid mode: RRF (k=60) fuses text and vector ranked lists; result carries a citation chunk from whichever side ranked the entry highest. Multi-term AND is preserved on the text arm before fusion.
- [ ] Depth-aware scoring: summary chunk hits get a small boost; deeper section chunks get a small penalty.

### CQRS decomposition (per d-cpt-ah1)

- [ ] `internal/command/` defines `BuildIndexCmd` for the warm-up write path.
- [ ] `internal/query/` defines `SearchQuery` carrying mode (derived from flags), filters, and term/query strings.
- [ ] `internal/handlers/` defines `IndexHandler` (the only side-effecting code path: build + lazy-fill).
- [ ] `internal/finders/` defines `SearchFinder` (pure reads: text grep, vector lookup, hybrid fusion).
- [ ] `internal/model/` carries pure types (chunk, breadcrumb, search result, citation).
- [ ] `internal/presenters/` renders search results with citation snippets.

### Skill bundle and apply

- [ ] Skill source under `internal/bundledskills/claude/sdd/` updated with search guidance — when to use search in explore and groom playbook moves, query composition rules per flag, citation reading.
- [ ] Skill guidance is unambiguous: `--term` is for token/ID lookup (always available), `--query` is for semantic intent (requires `Search: vector,text`), both for important explorations; `--query` with a single keyword is forbidden as a misuse pattern.
- [ ] `.claude/skills/sdd/` regenerated via `./bin/sdd init --scope project` and committed alongside the source bundle in the same commit.

### Smoke testing

- [ ] Unit tests cover chunker (heading splits, leaf scoping, heading-only sections, oversized splits with overlap), scoring (depth penalty, summary boost, RRF fusion), and finders (text grep including multi-term AND, vector lookup, hybrid RRF).
- [ ] End-to-end Go tests with a mocked embedder validate the full path: index build, lazy-fill, branch reconciliation, citation accuracy, mode dispatch via `--term` / `--query`. Pure `go test ./...` — no shell scripts, no external services.
- [ ] Manual eval tests against real providers (Ollama + OpenAI), following the existing `*_eval_test.go` build-tagged pattern in `internal/llm/gollm/`. Excluded from default CI runs; runnable on demand for empirical validation before merge.

### Empirical evaluation

- [ ] Hand-curated evaluation set of ≥10 should-be-related entry pairs drawn from the current graph, with each pair's expected relation documented.
- [ ] Recall benchmark: each pair queried in term- or phrase-shaped form as appropriate, validating the related entry appears in top-N=10 under text / vector / hybrid modes; results logged for comparison.
- [ ] Evaluation findings drive the closing done signal — recall numbers, surprises, mode-comparison observations folded in so the friction claim of s-tac-ixt gets a measured response.

### Out of scope

- CLI-side cross-encoder re-rank — agent does the judgment via dialogue.
- ANN indexes (HNSW/IVF) — flat scan via chromem-go is sufficient at current and projected scale.
- Matryoshka Representation Learning cluster-then-widen — deferred until basic flow is validated.
- Community detection / hierarchical clustering — graph already encodes hierarchy via layer + typed edges.
- LLM entity extraction — entries are already typed.
- Semantic topic labels for user-facing addressing — separate thread (s-cpt-vpl).
- Conversation mining — separate threads (s-cpt-bn1, s-cpt-5ox).
- Background-daemon indexing — `sdd index` warm-up + lazy fill is v1 lifecycle.
