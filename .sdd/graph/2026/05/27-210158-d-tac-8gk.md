Implement an MCP server in sdd that exposes the CLI surface as tools over stdio and streamable HTTP, giving any agent runtime structured read/write access to the graph without shell execution — the foundation for the Mastra-based agent runtime PoC. The server reuses the existing handler/finder/presenter layer with CQRS preserved: queries dispatch to finders, commands to handlers, and the mcpserver layer is pure dispatch that mutates nothing itself. Graph state is held in memory behind a `GraphFileSyncer` that reloads on any file change (own writes, terminal git pull, parallel sessions) via fsnotify, with lock-free reads and a cancelable single-in-flight reload; the swapped `*model.Graph` is immutable once constructed. The plan introduces a pluggable, transport-agnostic `AttachmentStore` (filesystem-backed default in `.sdd/tmp/`) with an upload-token flow that survives pre-flight blocks, and unifies the existing stdin-save retry path onto it. As a project rule, all I/O-bearing `Reader` methods become context-bearing — single signature, no contextless fallback. HTTP authentication and a CLI upload-token surface are explicitly out of scope (separate follow-up plans; the CLI surface plan must also carry skill + reference updates). Full design, structural code, and test layers in the attached spec.

## Acceptance criteria

- [ ] `sdd serve` runs an MCP server over both stdio and streamable HTTP, selected by `--transport` (HTTP binds loopback by default).
- [ ] All read operations (status, info, view, show, list, search, lint, wip_list, sync_status) are exposed as tools; presenter-rendered tools match CLI output byte-for-byte.
- [ ] All write operations (new, summarize, wip_start, wip_done, sync_rebase, attach_upload) are exposed as tools returning structured JSON.
- [ ] `sdd_new` returns structured pre-flight findings and blocks on `high` severity unless `skip_preflight` is set; a blocked call writes no entry.
- [ ] `sdd_sync_rebase` rebases only on a safe sync state (checked inside the handler), reports its outcome via a result callback, and the agent never invokes git directly.
- [ ] The graph is served from an in-memory snapshot kept fresh by `GraphFileSyncer`, reloading on file changes via fsnotify with lock-free reads.
- [ ] All I/O-bearing `Reader` methods take `context.Context` (single signature, no contextless variant); the syncer's reload is cancelable.
- [ ] Attachments flow through a pluggable `AttachmentStore` (filesystem-backed default); `sdd_attach_upload` stages content and returns a token, and `sdd_new` consumes the token on the write path so a blocked pre-flight leaves it reusable.
- [ ] The existing CLI stdin-save retry path is unified onto the `AttachmentStore` — no duplicate staging mechanism remains.
- [ ] `docs/mcp-server.md` documents the tool surface, transports, structured result shapes, and the upload-token flow.
- [ ] Test coverage: `GraphFileSyncer` unit tests (incl. cancellation under burst), per-tool happy/unhappy paths (incl. pre-flight block + token reuse), and stdio + HTTP integration tests with CLI parity.
