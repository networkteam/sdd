**Slice 2 work, by AC.**

- **AC 9 (LLM ref-meta consistency check).** Added shared partial `ref_meta_consistency.tmpl` wired into every entry-capture template that includes `entry_quality` (decision_refs, closing_decision, closing_done, signal_capture, short_loop, dissolution, aspiration_capture, supersedes, role_capture, actor_capture). `FormatEntryForPrompt` renders refs as a multi-line block with `(kind: K)` and optional desc when any ref is object-form, and falls back to flat `Refs: id1, id2` when every ref is legacy (`Kind == RefKindUnknown`). Calibration per d-tac-tzw + d-tac-olh: `high` for direct desc-body contradiction OR wrong kind; `low`/`medium` for topical drift, granularity, wording variations; no finding when consistent.
- **AC 11 (sdd lint kind validation).** Per d-tac-4ub, dropped the per-ref lint surfacing entirely. Legacy bare-string refs are accepted as a permanent state (closed-set validation runs at YAML parse time; slice-1's mechanical pre-flight in `finders/preflight_mechanical.go:refKindFindings` prevents new entries from carrying them at high severity). The AC 11 framing — "validates kind values against the closed set" — is satisfied by parse-time enforcement; the additional lint warning shape was too aggressive on the historical graph (1231 false positives) and is dropped.
- **AC 14 (LLM portion).** Added four eval-tagged tests in `preflight_eval_test.go`: `..._RefMeta_DescConsistent_NoFinding`, `..._DescContradicts_High`, `..._WrongKind_High`, `..._TopicalDrift_NotHigh`. All four passed against the real Claude CLI (haiku-4-5). Direct contradiction produced `high` `ref-desc-body-contradiction`; wrong kind on a gap signal produced `high` `ref-kind-mismatch` ("grounds" → suggests "addresses"); consistent metadata zero findings; topical drift surfaced `low` `ref-kind-precision` in one run and no finding in another — both within the softer band. Re-ran `..._WrongKind_High` after the `refines` addition (d-tac-l6e) to confirm no regression with the expanded vocabulary. Drive-by fix: four pre-existing eval-test cases passed `Refs: []string{...}` which was broken since slice 1's type migration to `[]model.Ref`; updated so the `-tags=eval` suite compiles.
