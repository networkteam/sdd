A two-layer way to deliver SDD through whatever generalist agent a participant already uses, instead of building a standalone SDD agent. An *executing agent* — the user's own ChatGPT/Claude/Gemini/Cursor, holding the conversation and the user's tools — consults a *workflow agent*: an SDD specialist behind MCP that holds per-session mode state and drives the loop. The workflow agent is a state machine (controller) plus two LLM-judgment roles kept structurally separate per the validation-separation contract (d-cpt-vt1): a *guide* that reads the graph directly and is fed only the dialogue residue not yet captured, emitting the next instruction for the current working mode; and a *gate* that is dialogue-blind and validates artifacts against graph state from a mechanically-derived evidence package. Because the gate judges without the dialogue, it forces every durable artifact to stand on its own — turning "the graph is the sole record" (d-stg-3k0) from an aspiration into something enforced.

The loop is a turn-by-turn handshake: init, then each turn the workflow agent emits an instruction plus callback info and the executing agent acts and calls back with evidence. The starting mechanism is plain request/response — instructions ride in tool output and the executing agent honors "call me back" — which works on every MCP client but is host-driven convention, not protocol-enforced, so it carries the soft instruction-following bet (s-stg-3vr), kept friendly by being minimal and one step at a time. MCP also defines deterministic server-initiated interaction (sampling, elicitation), but as negotiated capabilities with uneven client support; these are a graceful upgrade where a host offers them, not the foundation.

This develops the agnostic sandbox-agent direction (d-stg-6za) toward generalist-plus-connector, and gives the graph-resident process-rules idea (s-cpt-k8i) a runtime-agnostic home: modes, gates, and per-mode evidence schemas become per-project configuration shaped through dialogue — additive over a non-negotiable base of core invariants (dialogue-presence, the independent gate, canonical-only, immutability) that rules may extend but never remove. It realizes non-developer direct access (d-stg-x0l) and cross-participant coherence (d-stg-qlt), guarded by dialogue-first (d-stg-beb): the workflow agent orchestrates and protects dialogue, it does not produce decisions. Deployed as a remote, OAuth-secured, session-stateful MCP server (Streamable HTTP, state keyed to user and session), "without installation" means a participant pastes a connector URL rather than installing a CLI — shifting the burden to a hosted service and complementing the self-hostable path (d-stg-6za) for technical teams. Protocol feasibility is confirmed by research (the attached fact); layer 1 is the planned CLI-parity MCP server (d-tac-0v4), layer 2 is this stateful workflow façade.
