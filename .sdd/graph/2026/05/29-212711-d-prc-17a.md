Adds a third commitment to the ref-kind friction directive, sharpening lever 3 in place: feed each referenced entry's derived status into the pre-flight prompt so the validator can apply the status-dependent kind rules — `grounds` (active standing structure) vs `builds-on` (closed / next-step) vs `refines` (active, in place) — that it currently cannot, because the per-entry prompt formatter emits the target's type and kind but never its derived status. Reuses the existing `model.DerivedStatus` computation that already powers `{status:...}` in status/list/show and that the view path consumes via `RefExpansion` (d-tac-yls); pre-flight's `assembleContext` already holds the graph, so this is wiring, not new infrastructure. Without it, lever 3's recalibration is only half-possible: the validator cannot separate genuine undersell from a correct call when it cannot tell whether the target is active or closed. Two low findings on the parent directive's own capture are concrete evidence — the validator floated `grounds` for a terminal done signal and `refines` for a closed directive, both ruled out by status it could not see.
