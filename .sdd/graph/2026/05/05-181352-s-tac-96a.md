Shipped `sdd search` with text/vector/hybrid retrieval modes, persistent chromem-go index at `.sdd/index/`, vendored langchaingo markdown chunker emitting metadata-bearing chunks, and per-citation relative-percentage rendering — closing the search plan (d-tac-lqr) and its two augmenting directives (d-tac-jvd, d-tac-85r) plus the originating semantic-search gap (s-tac-ixt).

The implementation lands every AC across the plan's nine groups (CLI surface, embedder abstraction, chunking, indexing lifecycle, retrieval, CQRS decomposition, skills, smoke tests, eval), with deviations documented in the attachment where the augmenting directives or session-driven eval feedback redirected the spec. Real-corpus evaluation against Qwen3-Embedding 8b on local Ollama indexed all 417 entries (1822 chunks) in 12m27s; **vector recall@10 is 83% (10/12)** on hand-curated should-be-related pairs.

**Notable surprise: hybrid mode is currently weaker than pure vector** (67% vs 83%). RRF rewards consensus across rankers, and when text mode has very low recall on conceptual links — most pairs share no verbatim tokens — text contributes mostly noise that drags fusion away from vector's better picks. The implementation is correct; the finding is that hybrid as currently tuned doesn't pay off for this corpus and embedder. Worth a follow-up signal exploring confidence-weighted RRF or hybrid fallback to pure vector when text recall is degenerate.

The friction claim that motivated `s-tac-ixt` is measurably resolved: vector queries surface dialogue-first aspiration, parallel-coherence aspiration, and structural-separation contract for queries sharing no exact tokens with those entries' summaries; multi-citation rendering surfaces the chromem-go alternatives section in design.md alongside the d-tac-lqr summary on a "vector storage" query. The tooling cost replaces per-query LLM-as-matcher cost with a one-time embed cost (~12 minutes locally), amortized over many queries thereafter.

The session also produced eval-driven improvements not in the original ACs: bucket-by-batch index build with manifest checkpointing, status-aware ranking demoting closed entries, multi-citation per entry with per-citation relative scores, `Embedder.BatchSize()` exposed on the interface so the indexer can pack work into model-shaped buckets without a magic constant, and stable Ollama fingerprint (no dims-discovery race). Each was caught by running real queries against the real corpus and seeing where the output didn't match what an agent actually needs.

See [evaluation findings](./05-181352-s-tac-96a/evaluation-findings.md) for the per-pair recall table, AC-by-AC coverage with deviations, and the eval-driven improvement narrative.
