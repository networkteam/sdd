The /sdd skill provides no surface for capturing, surveying, or grooming topics, despite the topic primitive shipping in the 7+7 type system (d-cpt-ni0). Capture playback enumerates type, layer, kind, refs, closes, supersedes, confidence, and participants — never topics. No skill move surveys existing labels for consistency. No playbook drives retroactive annotation. The s-cpt-8h8 design synthesis explicitly committed to "the agent suggests matching labels at capture time," but that behavior never landed.

After 481 entries the result is 5 labels with visible drift — `catch-up-scaling` vs `catch-up/performance`, `CLI/UX` vs `infrastructure/cli` — and exactly one annotation entry (s-cpt-vpc), so the primitive built for retroactive reorganization sits unused.

A secondary asymmetry surfaced during this survey: annotation entries' own topics aren't part of their effective topic set (AnnotationTopics and Topics are mutually exclusive in the code), so s-cpt-vpc carrying `catch-up-scaling` doesn't render under `topic()` filters or `sdd show`. Possibly intentional, but undocumented and surprising.

This gap motivates a plan covering capture-time guidance, retro-assignment grooming flow, and the supporting infrastructure (untagged-entry filter, `as-counts` aggregation), folding s-cpt-sy4's narrower catch-up concern into the same delivery.
