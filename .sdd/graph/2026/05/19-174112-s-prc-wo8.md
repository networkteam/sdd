Claude Code in SDD repos defaults to suggesting auto-memory writes, but auto-memory is per-user local persistence that doesn't carry across team members — context, rules, and conventions captured there are invisible to anyone else on the project. The current mitigation lives only in this repo's CLAUDE.md, leaving every other SDD-using repo exposed to the same drift. Candidate directions for resolution include baking the rule into bundled skill content, having `sdd init` ensure a section in CLAUDE.md (or future AGENTS.md) carries the guidance, or — if Claude Code supports it — disabling auto-memory via project-scoped settings written by `sdd init`. Each direction has different implications for upgrade behavior, cross-tool reach, and reliance on agent compliance versus mechanical enforcement. Builds on the aspiration to eliminate parallel records of reasoning (`d-stg-3k0`) and shares a concern with graph-resident process customization (`s-cpt-k8i`).
