SDD's current mode table treats Explore and Act/Implement as separate modes when they're one continuum: every session anchored on a graph entry follows the same universal entry move (anchor → read chain via `sdd show --downstream` → brief → offer next moves) and only diverges after the user picks an action. This insight emerged from observing wrong load order and stale semantic-search guidance in `/sdd-explore` (s-prc-kaw) — refs the prior LLM-as-semantic-matcher closure (s-tac-2y8) which explicitly flagged re-evaluation at the order-of-magnitude scale we've now reached, and the search shipment (s-tac-96a) that makes the new approach possible.

The synthesis re-shapes the mode table around a single **Engage** mode whose playbook routes to peer post-engage moves (implement, plan it, decompose, evaluate, refine, close, short-loop, more research, external research). Post-engage moves split into two flavors — **acting on** the entry (graph change against it) and **using** the entry as a lens (read other work through it: evaluate against a commitment, compliance check against a contract, alignment check against an aspiration, progress check against a focus). The lens-flavor branch is undernourished today: Evaluate is misrouted at `playbook-catchup.md`; compliance, alignment, and focus-progress checks have no surfacing.

`/sdd-explore` repositions as a **goal-tagged research mission compressor** — the outer passes a target *and* a goal ("for implementation," "to find tensions"), the sub-skill expands widely from anchor and compresses toward the goal. Without a goal, compression has no axis. The sub-skill is invoked from inside Engage when chain + neighbors would bloat the outer, not as a precondition of mode entry.

**Brief shape is kind/intent-dependent** — an AC-status table for plan + implementation intent (✓ Done / ◐ Partial / ☐ Remaining); a narrative for signal + explore intent; a divergence list for contract + compliance-check intent — and the offered moves narrow accordingly. Mid-flight pickup is a recognizable sub-pattern: the most recent partial done signal in the chain carries pickup notes, surfaced via the downstream traversal, and the AC-status brief shapes around what's outstanding.

Evaluation itself has two anchor points (engage on the commitment "did we deliver?" vs engage on the done signal "what do we make of this?") and two perspective axes (outer behavioral: E2E + user feedback; inner structural: code + architecture + conceptual review). Both perspectives must be reasoned about together so neither is dropped.

Full per-kind move matrix, blind-spot inventory, brief shapes by intent, evaluation framing detail, and sequencing recommendation in [synthesis](./07-102919-s-prc-fc0/synthesis.md). Sequenced as: Engage refactor first (follow-up plan, closes s-prc-kaw); lens-flavor moves layer second (follow-up directive, starts with `playbook-evaluate.md`).
