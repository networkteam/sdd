Commits to a three-surface register rule for user-facing content, addressing the agent-authored artifact drift in s-prc-uoo. Different surfaces have different register expectations because the user is doing different things at each one.

Three surfaces, three registers:

1. **Entry playback** (before `sdd new`): structured technical detail — type, layer, kind, refs, closes, supersedes, confidence, participants shown as labeled fields, description verbatim. The user verifies frontmatter against the proposed entry to spot issues; stripping these defeats the playback's purpose.

2. **Narration about SDD activity** ("I'll capture this", "this resolves the gap", "want me to run it?"): plain, outcome-focused — describe the meaningful step. The agent issues CLI commands; it does not recite them.

3. **Generated artifacts** (workshop agendas, meeting notes, summaries, generated docs): plain language focused on outcomes the audience cares about. Entry IDs for precise referencing are fine; SDD vocabulary stays out unless a concept genuinely needs naming.

Across all three: CLI command shape (`sdd new d prc --kind ...`), flag names (`--closes`, `--participants`, `--refs`), validator and lint pass names, and internal mechanics like "write-once invariant" stay out of user-facing prose. Field-shaped labels (`kind: directive`, `layer: process`, `confidence: medium`) appear in playback only. User-facing concept names (entries, kinds, aspirations, gaps, decisions, the loop, layers when relevant) appear throughout in plain words, with bootstrap's teaching pattern for first-time introduction.

Implementation: add a "Vocabulary register by surface" subsection to `/sdd/SKILL.md`'s "How you behave" section. Bootstrap's tactical patterns (concise scannable output with bold headers, plain-words-first-then-bold teaching pattern, split-at-draft for actor/role) stay where they are as flow-specific refinements of this cross-cutting principle.
