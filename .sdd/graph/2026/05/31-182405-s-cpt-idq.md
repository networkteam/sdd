The sdd CLI's output presentation is weak across commands — there's no clean split between terse, agent-readable output and polished human output, and operational logging clutters results. The goal: every command renders for two audiences — clean, decoration-free output when called by an agent (no colors or TUI flourishes), and well-designed output for human users. Today neither is deliberate. The highest-traffic commands — `sdd lint`, `sdd search`, `sdd index` — are where this bites most. There's no unobtrusive logging channel: lazy-indexing and skipped-index messages print inline and bury the actual results (seen live this session — one `sdd search` dumped ~80 `lazy-indexed … (N chunks)` lines before any result appeared). And `sdd init` bootstrapping reads plainer than comparable CLI tools. The throughline is a missing output-presentation layer that separates operational logging from results and adapts rendering to the caller.
