`sdd`'s LLM calls for pre-flight and summary generation make exactly one attempt and fail on any transient error — no retry, no backoff. We deliberately set gollm's `MaxRetries(0)` (`internal/llm/gollm/gollm.go:49`) to stop batch-summarize WARN floods and deferred retry to "the SDD caller," but that caller-level policy was never built: `Run()` calls `Generate` once and returns the error. Reading gollm v0.1.11 directly, its built-in retry is shallow anyway — a fixed `RetryDelay` (no exponential growth, no jitter), it retries every error including permanent 4xx (no retryable/permanent classification), it collapses any non-200 into a generic `ErrorTypeAPI` with the status code in a string, and it discards the response headers entirely, so a 429's `Retry-After` is never honored. The exponential-backoff strategy gollm ships is wired only into streaming, not `Generate`. Observed failure: a single interactive `sdd new` died on a transient `connection reset by peer` ("failed to generate after 1 attempts"). This realizes the friction s-tac-a4s anticipated when it deferred backoff work, though the mode differs — a one-call network blip, not the bursty-429 case the deferral expected.
