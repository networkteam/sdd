Shipped the `expand(refs)` render modifier for `sdd view`: a per-row transform that renders each entry's outgoing references as indented sub-lines on `as-list` output, each carrying the ref-kind as a verb, the referenced entry's current derived status, and the optional per-ref desc — so stale summary prose can no longer hide that a dependency has closed or been superseded (resolves s-cpt-kfl). Optional `expand(refs(inactive))` narrows to refs whose target is currently inactive, defined as the exact inverse of the `active` filter (closed, superseded, or a non-active role). CQRS split per d-cpt-ah1: a `RefExpansion` model type and `FlatList` field (model), nested-call parsing (query), the `expandRefs` finder resolving derived status from the graph (finders), and the sub-line presenter (presenters); no handler state. `expand(involvement)` keeps its focus-block-only scope unchanged, and `expand(refs)` composes with filters, `rank`, and `n`.

Two deviations from the plan, both dialogued and confirmed. (1) AC 8's smoke exemplar (d-prc-iqw to d-prc-kyz) was unsatisfiable because d-prc-iqw references d-prc-kyz only in prose, not in its `refs:` frontmatter; the mechanism was instead validated on real closures (d-tac-0v4 to d-tac-hsu, d-tac-yls to d-tac-cs0). (2) The plan's `state-changed` filter token was renamed to `inactive`. Christopher evaluated the proposed name during review and found it did not fit: it implied a transition (changed since being referenced) that the filter does not actually detect, since it reports the referent's current state. The token was renamed to `inactive` and the semantics sharpened to the true inverse of the `active` filter — now also surfacing cascade-closed/orphan roles so an inactive role ref cannot fall through both the active and inactive views. Code in commit de15b75; full tests, vet, and lint clean.
