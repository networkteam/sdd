Vendor langchaingo's `textsplitter` package (MIT) into `internal/textsplitter/` as the starting point for the markdown chunker in d-tac-lqr, then adjust to fit our metadata-bearing chunk model — instead of building from scratch on goldmark AST or importing langchaingo as a library dependency. Source: https://github.com/tmc/langchaingo/tree/main/textsplitter (`markdown_splitter.go`, `recursive_character.go`, `options.go`).

Rationale: the heading-state machine, oversize recursive split with overlap, separator priority, list/table/code-block handling, and second-splitter dispatch are non-trivial edge cases the library has already worked through. Importing as a dep is a poor fit because `SplitText` returns `[]string` only — wrong shape for our breadcrumb / depth / `is_summary` / `is_attachment` per-chunk metadata. Copying lets us change the return type to carry metadata natively while keeping the worked-through edge-case handling.

Adjustments expected:

- Return `[]Chunk` (struct carrying text, breadcrumb array, depth, source-attachment path, summary/attachment flags) instead of `[]string`.
- Strip YAML frontmatter at the package entry point; surface frontmatter values to the caller as filterable metadata, not embedded text.
- Replace `WithHeadingHierarchy`'s multi-line markdown header stack with the `Entry: <summary>` + `Breadcrumb: <chain>` preamble shape (per d-tac-jvd).
- Flip `CodeBlocks` default to true (upstream default drops code blocks — wrong for our content).
- Verify heading-only sections produce no chunk; add explicit handling if vendored behavior diverges.
- Preserve MIT notice: copyright header on each vendored file plus a `LICENSE-langchaingo` (or `NOTICE`) alongside the package.

This replaces d-tac-lqr's `goldmark` AST traversal in the chunker AC; the vendored package brings `gitlab.com/golang-commonmark/markdown` as the codebase's sole markdown parser (no existing markdown consumer to consolidate against).

Spec-sharpening within d-tac-lqr's chunker direction (still markdown-aware chunking with metadata-bearing chunks; goal unchanged), captured as a downstream augmenting directive.
