The type-system 7+7 plan (`d-tac-gvn`) and the `sdd view` plan (`d-tac-uww`) both reference the `topic(L)` filter primitive, and Plan 1's acceptance criteria contain an internal inconsistency about who ships it: design §9 places `topic_filter.go` under Plan 1's CQRS scaffolding, while one AC reads "reuses `topic(L)` filter primitive from Plan 2's shared internals." This directive resolves the ambiguity in Plan 1's favor: Plan 1 ships `internal/finders/topic_filter.go` as part of its delivery, and that primitive is the canonical implementation other CLI commands consume.

Scope is Plan 1 only — this directive does not retroactively constrain Plan 2. Plan 2's own ramp-up will dialogue whether its existing AC about pipeline primitives in shared internal packages reads as "callable from other CLI commands" (consumption-friendly) or requires its own refinement.

Closure trigger: Plan 1's closing done signal must address this directive's commitment alongside the original ACs and list both `d-tac-gvn` and this directive's ID in `--closes`.
