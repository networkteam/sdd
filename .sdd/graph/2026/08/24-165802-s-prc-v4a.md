SDD v0.17.0-alpha.3 is published as the third prerelease of v0.17.0, and cutting it added a tag check to the release skill. The tag sits at `dd2e6844` and carries three items: close validation judged by what the closing entry says rather than by its kind (20260820-162242-s-tac-677), pre-flight's new closing-signal check with signal closures routed by target kind (20260824-132018-s-tac-e87), and MCP `show` honoring an explicit zero depth (20260821-103659-s-tac-jnj). Notes, four platform archives, checksums, build provenance and `install.sh` are attached.

**Why a third alpha.** The current focus (20260824-093559-d-tac-onl) holds v0.17.0 for the release that tells users to work in the engine, gated by transition messaging, size-bounded automatic serves, loud capture failures and two direct gap fixes. None of that shipped here, so the delta went out as a prerelease and v0.17.0 stays free.

**The missing tag check.** Christopher asked for v0.17.0-alpha.2, already published four days earlier. The skill's survey step reads the git log from the last tag but never checks the version being asked for, so both the number and the drafting span were wrong at the start; reading the tag list during the survey caught it, not any instruction. Step 1 now fetches tags before anything else, since a tag pushed from another machine is otherwise invisible and the baseline is wrong, and checks a named version against the tag list before drafting, pointing at the Recovery section's existing rule that tags are never reused. This follows the precedent that release-process learning is absorbed into the skill rather than recorded as its own decision (20260508-102334-s-prc-lep), and the pending port of the skill into a graph-local procedure (20260707-143547-s-prc-tso) inherits the check.

**Evidence.** The release is at https://github.com/networkteam/sdd/releases/tag/v0.17.0-alpha.3; the skill change is commit `436eef56`, which lands after the tag and changes no published artifact, since the release skill is project-scoped and not bundled into the binary.
