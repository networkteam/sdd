The current tactical focus is shipping the engine-first transition across two releases: v0.17.0 says work in the engine, v0.18.0 makes the engine the only flow. The cut into two releases follows the release triage (20260815-000432-s-tac-xlw). Christopher and Claude carry the whole period; the targets are not pre-assigned per person, work on them is picked up session by session.

v0.17.0 gathers what must hold before the engine is recommended to everyone, and these three run in parallel: the transition messaging users see (20260820-162456-d-tac-o2v), responses that no harness truncates (20260820-165139-d-tac-wlq), and no silent loss on what is about to become the only write path (20260821-105247-d-tac-q1x). Two small gaps ride along as direct fixes without plans, because each one breaks trust in the engine's surfaces and needs no design: agents cannot see why a search hit matched (20260814-160042-s-tac-rst), and the binary points users at the wrong configuration file (20260710-144212-s-tac-z7j).

v0.18.0 then removes the fallback, which takes two pieces: the retirement work itself (20260821-123832-d-tac-ip1) and a place to send newcomers once the old skills are gone (20260821-181419-d-tac-hq1). The removal waits on the bootstrap parity verdict (20260726-195300-d-tac-fim); that line is carried by the type-system knowledge focus running beside this one (20260811-231119-d-tac-uea), which this focus does not replace.

Deliberately not in this period: the declared-binding design for capture fields (20260812-160448-d-tac-ymk), which waits with the construction model it hangs on, and the docs example world, which stays with the full docs plan (20260715-181235-d-tac-c7b).

This focus ends when v0.18.0 is released with the engine as the only flow.
