Which fields a capture step can still correct is fixed by that step, and playback's list stops at the entry's prose, refs, topics, index, confidence and intent — so a fault found there in anything else costs a redraft rather than an edit. A focus capture in this session hit it: the body had been revised to name four advancing targets while the frontmatter still carried three, and the field holding what a focus advances is not among those playback collects. The corrected value, reported alongside the adjustment, was dropped without an error, so nothing signalled that it had not landed; the mismatch was visible only by re-reading the draft's persisted state. The way out was to abandon the draft and rebuild it from assemble, which sent the writing guide over a body it had already judged — the second pass the capture procedure otherwise avoids within one capture — and put the whole entry back in front of the user for a second confirmation (20260703-094500-d-prc-cap).

The same step leaves other collected state neither shown nor correctable, and the second instance stayed inside the session only by luck of where the field lives. A draft also carries the record of what was searched and read before drafting, and in this one that record still explained a scope boundary against an entry the body no longer mentioned, because the dialogue had removed it. No entry field carries that record, so nothing false reached the graph — but playback never displays it either, so the contradiction had no surface on which to appear, and it was caught only because the redraft rewrote it. What the confirmation step can verify is bounded by what it can collect; everything else a draft holds passes the one step built for checking unseen.

This is the sibling of the lifecycle-field friction already recorded (20260731-083611-s-cpt-wag), with the mechanism reversed and the remedy far cheaper. There the fields are declared as params, which the engine bars from any step's collect list, so the repair is a declaration migration whose choice that record defers to the authoring-model redesign (20260726-195739-s-cpt-hcp). Here the fields are already state — assemble collects them — so the engine permits a wider list and only the procedure's own step declaration withholds it, which means this instance can be repaired without waiting for that redesign. What generalizes across both is that the correctable set is decided per step, while the need to correct arrives whenever the dialogue or a reader finds the fault, and nothing keeps the two aligned.
