Capture's lifecycle fields are now declared as state rather than params, so a closure discovered mid-draft can be written at assemble — and withdrawn again — instead of being forced into `refs`, where it recorded a responding relationship and left the target deriving as open. Delivered in commit `f0e0de71` with engine-level regression tests that fail before the change and pass after, per the standing contract for code-path fixes (20260416-141340-d-prc-8vh).

**Why this closes the gap.** The gap had already established that the start-only property belonged to params and not to these fields: `SetStart` splits its inputs, so a declared state field is seedable at start exactly as `captureBranch` already was. Moving both fields under `state:` therefore keeps every start-time call and every dispatch handoff working unchanged, while additionally making them collectible. That is the declaration move the gap named first among its options and deliberately left unchosen, deferring the param/state split to the broader procedure-authoring redesign it points at (20260726-195739-s-cpt-hcp) — the one that would treat state declaration, collection semantics, expressions, and serve projection as a single authoring contract. It was taken now on two grounds: the defect is wrong under any authoring model, and the sibling repair at the same declaration had landed hours earlier (20260812-155139-s-tac-cd1), so leaving this half would have meant patching one declaration twice. It stays a point repair inside that redesign's territory — one declaration moved, four collect lists widened — and settles nothing about the collection semantics the redesign names among the concerns to unify.

**Where the fields became reachable.** Both join the collect list at assemble and at every step that can still correct a draft: the writing guide's revise and recheck, playback's adjust, and the write gate's revise. Reporting `null` withdraws an edge, so a claim can be taken back out and not only put in — without that direction a mistaken closure would still cost an abandoned draft, which is the shape of dead end the gap was about.

**The body's obligation moved out of the conditional branch.** The retirement-rationale requirement lived behind `{{if .closes}}`, which renders only when assemble is served with the field already set. Probing the three routes a lifecycle field can arrive by showed that an author who batches it into one complete report cascades straight to playback and never sees an assemble re-serve — so that instruction would have reached them never, not late. It now sits in the unconditional lifecycle paragraph the opening serve carries, before any field is reported; the conditional lines only name which entries are affected. State provenance also brings the fields inside the confirmation binding, since the snapshot a confirmation binds to fingerprints state values only: correcting a lifecycle field after playback was confirmed reopens playback rather than writing an edge the user never saw.

**A second gap is partly answered.** The write gate's revise now reaches these fields, so the rejection recorded in (20260707-170235-s-prc-0p1) — a `closes` that mechanical validation wants as `supersedes` — is correctable in place instead of forcing park-and-restart. That gap stays open on its own substance: the bare `validation failed: N issue(s)` that names neither rule nor field, journals no event, and leaves no pending chooser is untouched here.

**What this does not deliver.** The external bug report behind the gap — filed against `sdd lint`, and carried verbatim as the record attached to the gap this closes — remains unanswered on its own terms: nothing detects an entry whose prose asserts a closure its frontmatter lacks, which is an absent category rather than a missing rule. A hand-written `sdd new` without `--closes` reproduces the reported entry exactly as before, and the promised body-to-edge enforcement remains unbuilt (20260614-225650-s-tac-dxh), which even built would not catch this shape because the ID sits legitimately in `refs`. The sibling narrowness of the playback step (20260811-232108-s-tac-kus) is likewise only grazed — its collect list gained these two fields, but the field its own instance turned on, what a focus advances, is still not correctable there.
