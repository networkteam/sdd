The construction-model work carries one further requirement: every entry field the capture path can write must reach the entry through a declared binding, so that no value the user has confirmed can be lost between what an agent reports and what the entry carries. The engine variable carrying a field names the entry field it lands in, the binding performs the translation, and a binding whose transformation is not a permitted one is refused mechanically.

**What this ends.** Today a field's shape is asserted independently in two places — once by the procedure's variable declaration, once by whichever consumer reads that variable — and nothing compares them. When they disagree, a value the user already confirmed at playback is discarded with no error at any layer, and the only surface that would reveal the absence is the playback that displayed it correctly (20260812-140802-s-tac-exr). With the binding owning the translation, no consumer assumes a shape, so there is no second assumption left to contradict the first. The class stops existing rather than becoming detectable.

**What makes a transformation permitted.** The test is that the translation be total and lossless over the input shape: every value the engine variable admits maps onto a value of the entry field, with nothing silently dropped and nothing invented. Widening a single entry ID into a one-element list passes — every input has an image and no information is lost. Reading strings out of a structured value fails, because it discards the structure it cannot carry, which is the same silence in a new place. Enumerating the permitted set belongs to the design; what is fixed here is the test each candidate must pass.

**Why not simply give the variable the entry field's type.** An engine variable is an input shape — what an agent reports, tuned for how it is collected and served — while the entry field is a storage shape, and there are legitimate reasons for them to differ, including adaptation that belongs to neither side alone. Forcing them equal would buy consistency by surrendering that freedom. A declared binding keeps the two shapes separate and connects them explicitly, so the difference stays expressible and stays checked.

**Coverage is checked from the entry side.** The property to enforce is that every capturable entry field is covered by a binding — not that every variable declares one. Most procedure variables carry no entry field at all; they are bookkeeping. Requiring each of those to declare that it binds to nothing would impose ceremony on the many to catch omissions among the few, and would put the discipline exactly where discipline is least reliable. Asking which entry fields no binding reaches needs no declaration on bookkeeping variables and places the check beside the fields themselves, where anyone adding one is already working.

**This states the property, not the mechanism.** The binding's form and the permitted set are for the plan to design alongside the construction model; fixing them here would pre-empt that design on less information than it will have.

**What it does not buy.** A binding that is declared, permitted, and simply wrong in intent still writes the wrong field. It writes it visibly, though — at playback and in the entry — rather than dropping a value in silence. Silence is what this buys out; correctness of intent remains a human matter settled in dialogue.

**Scope.** The one-field instance is already repaired (20260812-155139-s-tac-cd1), and that repair is precisely the per-field vigilance this replaces: it made one declaration agree with one consumer, leaving every other captured field resting on the same unchecked coincidence. A sibling silence exists one boundary earlier, where a reported field is discarded because the step does not collect it (20260811-233331-s-tac-bjn); that is a different boundary with an unsettled remedy, and this directive commits nothing about it.
