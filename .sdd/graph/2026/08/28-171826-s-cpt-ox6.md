A host mechanism that copies a conversation copies its session handle with it, so two conversations can continue one dialogue and the engine cannot tell them apart.

Actual, from the host surfaces in use: Claude Code's `/branch` splits a conversation into two that both carry the full context, a fork-style sub-agent inherits the parent conversation whole, and resuming one transcript into two clients has the same effect. Under the capability model the handle in that context is the only correlation between a conversation and its session (20260828-165352-d-cpt-aen), so every copy holds a live capability to the same dialogue, duplicated by a host act the engine never sees.

Expected, on two grounds. Delegation expects a delegate to hold only the child handle it was dispatched with (20260827-232430-d-cpt-voa); a fork-dispatched sub-agent holds the parent handle by inheritance, violating that by construction. And the session contract accepts a branched conversation only as a detectable anomaly: divergence surfaces informatively at the first write (20260718-131626-d-cpt-9of), which protects the log but says nothing about serving two live consumers.

The deviation shows in the serves. The capability directive keys served-once deduplication to the session: the engine derives from the session ledger what the dialogue's consumer already holds, and a reorientation, an agent presenting the handle and asking for its position, resets that record (20260828-165352-d-cpt-aen). That model assumes one consumer per handle. With two branches, each branch's reorientation resets the record the other accumulates against, so one branch is served stubs for text it never saw while the other is re-served text it holds. The isolation expectation stays bypassable through the same seam (20260826-225922-s-cpt-pxq).

Candidates from this dialogue, unsettled: dispatch instructions that keep the parent handle out of a copied context, a declaration at the reorientation seam so a copy announces itself, and host support where a branch event is observable.
