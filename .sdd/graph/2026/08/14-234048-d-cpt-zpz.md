A reported field must not carry a fully structured syntax inside a string: no JSON and no YAML embedded in a string value. A value that has structure is declared with that structure, so the served report schema advertises its real shape and the boundary validates it on arrival.

**The line.** Every field an agent reports is a typed value whose shape the served schema declares. Hiding a structured document inside a string defeats the whole arrangement: the schema says only "string", the boundary validates nothing, and every syntax slip inside the hidden document — quoting, brackets, indentation — surfaces late, as a gate rejection at best and a silent misread at worst. Simple closed syntaxes in strings remain fine: a guard expression or a view layout string is a small language whose errors the engine names at load. The line is general-purpose structured formats, whose entire grammar rides opaquely inside another format's scalar.

**Where it came from.** The procedure workflow field first shipped carrying its params, state, and steps as YAML in one string; a cold-start authoring probe tripped on quoting inside it three separate times, and the worked example's own authoring tripped once — every failure invisible to the served schema, caught only downstream. Rebuilt the same day as one structured value with a hand-written schema fragment, the entire error class ceased to exist at the boundary.

**Conversion to a rule.** Guidance that carries an activation — a "when" naming the situation it fires in — is rule-shaped; standing guidance without one stays a guiding directive. This rule has an activation: it fires when declaring how a reported field is carried. It is recorded as a guiding directive only because the rule kind has not shipped; once the rule system lands (20260622-084244-d-tac-eho), this converts into a binding rule activated on interface and procedure-field design.
