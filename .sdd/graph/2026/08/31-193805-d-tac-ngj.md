The sdd MCP server keeps the spec envelope: every tool result carries `structuredContent` beside the `content` text mirror, and the structured-only default with its `--compat` flag (20260831-125530-d-tac-4dz) is withdrawn, removed in commit 36affc20. Live usage on Codex CLI overturned that ruling's premise within hours of shipping. Three trials against the running host ([trial record](./31-193805-d-tac-ngj/codex-content-projection-trials.md)), each opening an engine session, whose opening response is the largest automatic payload the server sends: with `content` empty the agent read the result as a failed call and repeated the opening call; with a one-line pointer in `content` it still needed a second call to reach the payload; with both fields the flow ran clean, and Codex's on-disk session log recorded the opening response once, at about 29KB with no truncation marker. A fourth exchange established that no documented precedence rule exists for this host: its wrapper decides what enters context, `content` is what the default path prints, and `structuredContent` is a programmatic value for scripted field selection with no inherent token savings.

The doubled measurements behind the withdrawn ruling were an observer effect: every capture of the payload appearing twice in model-visible output came from an agent explicitly inspecting its response envelope, prompted by a verification task or by the duplication question itself. On a verified host's default projection the payload arrives once: Codex projects `content`, Claude Code prefers `structuredContent` and drops the duplicate text block (20260816-205521-s-tac-x9l). This is the same class of harness-introspection evidence that fact flagged as unreliable, and this arc confirms its caveat from the other direction.

Settled: the protocol requires `structuredContent` where an output schema is declared and recommends the mirror, both fields ship as the SDK produces them, and nothing remains to follow up. The per-part bounds on the engine's automatic responses are what make the shape fit: a single copy of about 30KB sits under the ~10K-token host budget, where the roughly 50KB unbounded responses that first surfaced the truncation problem (20260719-122103-s-tac-jom) did not. A lean envelope returns as an opt-in only when a client that projects both fields into model context shows up in real usage, with rollout-grade evidence rather than an agent's self-report.
