The `resume_session` call must require an explicit session handle, and the branch that answers it from the MCP connection is removed.

Today the server keeps an in-memory map from MCP connection to session, and a resume call carrying no arguments returns whatever that map holds for the connection the call arrived on. A connection identifies one client process, never a conversation, and the two have come apart three ways: several agents share one connection when a client dispatches sub-agents, one conversation gets a new connection when the client restarts the server as Claude Code's `--continue` does, and remote transports re-mint connections on their own. The session contract already forbids this, holding that a dialogue's identity is its durable handle and never a transport connection (20260718-131626-d-cpt-9of). The resume path is the one place still deriving identity that way, and the code concedes the point where it treats its own map as a cache rather than authority.

The replacement already exists inside the same function. When no binding is present, the call returns the sessions with open work. That becomes the only answer to a handle-less resume. The one-shot full re-serve keeps working when it accompanies a handle. The connection map itself stays, because it still answers whether this connection is the current attachment and it still keys the served-once deduplication. What it stops doing is answering which dialogue the caller is in.

The cost is one extra call after a context loss, plus the user's word when more than one session is listed. That is an honest recovery rather than a lucky one, and the tool text and server instructions must be rewritten to match, since both currently advertise the no-argument call as the way back after compaction.

This closes the exposure the delegate-session directive left open (20260827-232430-d-cpt-voa) and removes the discovery route recorded in the isolation gap (20260826-225922-s-cpt-pxq): a delegate is never told the parent's handle, and once the no-argument answer is gone it can no longer find one, so a delegate reaching the dialogue that dispatched it stops being mitigated and becomes impossible.

It does not settle the sibling use of the same map, where the connection stands in for a consumer's context and a reconnecting agent is re-served an orientation it still holds (20260826-173028-s-tac-1qr). That question needs an identifier the agent itself sends, and stays open.
