Ship the ref-kind vocabulary as a base fact written to match the current type-system facts, point the type-system overview at it, and reduce capture's assemble text to a teaser that requires the fact to be pulled before references are drafted.

The vocabulary exists today only as prose in a reference file of the legacy `/sdd` skill render, which the v0.18.0 retirement plan (20260821-123832-d-tac-ip1) removes from the binary — so this work has to land first, or the plan's own criterion leaves the vocabulary with no home at all. The base-facts directive (20260707-140544-d-cpt-dtv) named the ref-kind taxonomy among the reference knowledge that would move into the graph, and it is the one named item never built.

The fact carries what that reference file carries: the kind table with its apply-when and not-when columns; the rule that a ref is written on the source pointing at the target, most kinds pointing backward at prior context and a small forward-captured set (`surfaces`, `required-by`) pointing at what comes out of it; and the calibration notes — `related` as the floor rather than a default, a terminal done never being addressed. The text is rewritten rather than lifted across: the reference file predates the per-kind authoring facts and does not follow the form they settled, and the fact should read like the ones beside it. It is enrolled in the retrieval index, so it is reachable before a reader knows the word for what they need.

Two consumers change alongside it. The type-system overview (20260812-180000-s-prc-typ) introduces entries, kinds and layers and never says that entries connect at all, so a reader who pulls the map to plan a structure learns nothing about edges; it gains the pointer to the new fact. Capture's assemble step currently serves a condensed vocabulary of its own, which once the fact exists becomes a second surface a reader could mistake for the whole — the failure the knowledge-homes directive (20260730-110228-d-cpt-rh6) names explicitly. It gives up the definitions and takes on one job instead: requiring the fact to be pulled before any reference is drafted. The teaser states that plainly — the fact is read at least once before references are constructed — so reaching for it is the expected step, not an option to skip.

Deliberately out of scope, so the closer is not measured against them: pre-flight's own vocabulary load (20260824-165218-s-tac-7w6) stays as it is — shipping the fact does not rewire that code path, and rewiring it is that gap's to resolve — and the cue that makes an agent reach for the fact while designing a structure ahead of any capture, which is the other half of what the structure-time gap (20260826-002704-s-cpt-mas) needs and is not delivered here.

Finished when the vocabulary is a base fact reachable by search and citable as a ref, reading as its neighbours read; the overview points at it; and the assemble step no longer restates it but requires it to be read before references are drafted. It leaves behind one new entry in the shipped fact set and two edited surfaces.
