A done signal's evidence conventions read as writing flaws to a generic eye, and the writing guide's first live done-kind specimens supply the discriminator its general calibration lacks: a done is judged by whether a future reader can trust and locate the completed work, so evidence density that would spoil another kind is load-bearing here. Both misreads fired on the same specimen — the guide's own closing done (20260811-154427-s-tac-yzg). Commit hashes in the opening sentence were flagged as dilution, though a closing done must cite the commits that carry the work — the hashes are the durable proof, not decoration. And the description of the delivered artifact was flagged as conflation, reasoning that the design is a separate pull — though a done is precisely the record of what shipped: when the delivered thing's shape was settled in the dialogue that produced it, the done's body is the only place that meaning lands, and cutting it strands it rather than splitting anything.

The general form both misreads share: for a done, provenance — commit hashes, attached records, verification evidence — and the description of the delivered thing are the entry's own content, never another entry's, because the pull a done serves is 'what happened, can I trust it, where do I look further'. Per-kind guidance for the done kind starts from this discriminator. It is the first specimen banked under the sweep path the rollout directive commits (20260811-141038-d-tac-rvu), surfaced by the guide's outer evaluation (20260811-160201-s-tac-0j5).
