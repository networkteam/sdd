The harness-side dispatch handoff becomes a supported surface: SDD ships the artifacts through which a host agent dispatches a delegate that reaches the engine's MCP tools and holds exactly its child handles.

The engine side of delegation is committed: a task-class procedure forks a child session on dispatch and its result returns as a transition into the dispatching instance (20260827-232430-d-cpt-voa). What leads a host agent onto that path was never built; the delegation gap records the missing pieces, down to a shipped delegate skill that cannot reach the MCP tools (20260826-222535-s-cpt-dkv). This directive commits to building that half, and it is two pieces. Served dispatch instructions on the dispatching step: they name the launch (a fresh-context sub-agent), the exact first call (`resume_session` with the child session handle, which serves the child instance at its current step with the schema to continue), and what the sub-agent prompt may contain, the child handles and the resolved inputs, never the parent handle. And per-harness launch configuration: the sub-agent definition whose tool allowlist grants the engine's MCP tools. The delegate's working path is MCP only; the CLI reads and graph-file greps the delegation gap observed go entirely, so the working path stays host-neutral and only the launch configuration is per-harness.

Two pieces of understanding carry the commitment. First, under issued-never-published handles the dispatch prompt is the complete statement of what a delegate may touch; the engine mints the child session and instance before any sub-agent exists, so the delegate can only act on what its prompt carried (20260828-165352-d-cpt-aen). Second, the harness assembles and runs the launch, and the engine can verify nothing about it (20260629-204630-s-cpt-1dz), so the served instructions carry the one rule that matters: the parent handle never enters the sub-agent prompt. For the same reason fresh context is the only supported launch mode; a fork-context delegate holds the parent handle by construction, the context-copy gap's dispatch seam (20260828-171826-s-cpt-ox6), and this directive supplies that gap's dispatch-instruction candidate without settling its other seams.

The dispatched flow costs the parent exactly one engine call beyond its normal walk. Dispatch rides the chooser answer that starts it: the engine forks the child in that call and serves the dispatch instructions on the parent's next step, an ordinary gate holding on the delivered field. The child's final transition writes the declared values into the parent instance, and the parent's pickup call passes the gate and serves them; while the delegate still runs, the same call re-serves the waiting instructions, a clean poll. The engine cannot push into the outer conversation, so the pickup call is the transport's minimum, and routing the payload through the sub-agent's host-side text return is the host-carried-results shape the delegate-session directive set aside. The attached [dispatch call sequence](./29-122157-d-cpt-zpe/delegate-dispatch-sequence.md) carries the concrete exchange from both sides.

The first committed application is graph research: a research ask in free dialogue or a catch-up dispatches an explore-class delegate, so the wide reading spends the child's context instead of the outer conversation's. The procedure constrains what returns, entry IDs and a brief, pointers rather than substance; the summaries-as-sources failure mode that rolled back the earlier sub-agent catch-up is answered structurally, because the child's reads never count for the parent session and the engage and implementation serves instruct pulling entries in full. Which top-level procedures offer dispatch is follow-up work.

Implementation includes the served knowledge artifacts, which were forgotten before when only the machinery moved: the procedure-spec reference documents the prose dispatch bridge, the child writing nothing into the dispatching run's store (20260814-100000-s-prc-psr), and that section must be rewritten when task-class delivery ships; its field and type lists render from the running engine, its prose does not.

Fulfilled when a delegate dispatched through the shipped artifacts drives a served task-class procedure over the MCP surface in live use, holding no handle beyond what dispatch issued it, with graph research working from at least one top-level procedure.
