SDD commits delegated work to a forked non-interactive session, with its result returning through the engine into the instance that dispatched it.

A procedure declared task class is the delegate form: a move dispatches it with resolved inputs, and the session never offers it as a move a user picks. It now also runs in a child session the engine mints on dispatch, so forking is decided by the spec rather than by agent discretion and no new tool is needed. The child inherits the parent's branch binding and project target, and carries a lineage pointer to the parent session and the dispatching instance. It inherits nothing else: empty read set, no instances, its own shell.

Inheriting branch authority is what forces a fork rather than a plain fresh session. An unbound session resolves the graph against the configured default branch, and reads against the wrong tree return present entries as absent, a silence already misdiagnosed once as a broken tool (20260728-004132-s-tac-cjt). A delegate researching for a worktree-bound dialogue would otherwise produce a briefing wrong in a way nothing reports.

Non-interactive is a declared property of the session, not a fact about one shell. Procedure text and choosers may branch on it, and a user chooser on a live path of a procedure reachable in a non-interactive session is a spec error rather than a runtime surprise. Two things follow. A delegate cannot capture, because capture reaches the graph only through a user chooser and there is no user to answer it, so no prohibition is needed. And autonomous work that should capture stays possible through procedures written for it, which is what the intake model's channel-reactive agent requires (20260603-172628-d-cpt-fbi).

A non-interactive session is driven by handle. Today a session is reachable only through the transport connection currently bound to it, and every work tool checks that binding, so one connection drives one session. Opening a child never moves that binding: the parent stays reachable where it is, and a non-interactive session is instead driven by presenting its handle, needing no user consent and rebinding nothing. Consent is untouched, because consent guards attaching to a dialogue the user is having (20260718-131626-d-cpt-9of) and a delegate session has no user in it. Interactive sessions keep the binding check and the consent rules exactly as they stand.

The result returns as a transition, not through the host. The child's final transition delivers declared values into declared fields of the dispatching instance and completes the child, which then concludes. The parent's step does not move, and that is the whole distinction between the engine delivering a result the parent asked for and the delegate driving the parent. Delivery lands regardless of where the parent currently is, and an undeliverable delivery fails loudly or arrives as a named notice rather than being dropped.

The engine neither blocks nor notifies. A parent is never suspended waiting for a child, and whether the host waits for its delegate or backgrounds it is the host's business, as is telling the parent the delegate finished. The engine owes only that the value is present when the parent next looks and that its serve shows the parent the state it now holds, which handover fidelity already requires (20260719-124405-d-cpt-0tm).

The read set stays with the agent that read. A delegate's inspections are its own, so entries it surfaced count as un-inspected in the parent, and a capture there must read them before it can write. That is the intended cost: a delegate's report carries the weight of a summary rather than a source, enforced where the delegation happens instead of asked for in instructions.

One exposure is left open rather than solved. A delegate shares the parent's connection and the surface cannot tell one caller from another, so nothing structurally stops it from reaching the parent's session. It is never told the parent handle, but a resume call carrying no arguments returns whatever session the connection is bound to, which hands it one. That convenience is the whole of the exposure, and it is not load-bearing: listing the sessions with open work is a free read and the user's own words disambiguate, so a handle an agent lost is recoverable without it, and a hosted transport cannot let a connection stand in for a dialogue at all. Whether it survives is a separate decision. Until then this design removes every reason for a delegate to make that call, which is mitigation resting on the recorded guest-surface ceiling, where enforcement reaches the artifact and the stored state but never the agent's process (20260629-204630-s-cpt-1dz).

The attached design record carries the call sequence from both sides and the shapes set aside: the plain fresh session, passing the parent's own handle, widening the binding rule by one case, host-carried results, collection by the parent, and engine-side notification.
