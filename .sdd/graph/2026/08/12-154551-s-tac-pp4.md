The user-dialogue shell now declares its four overview sections — aspirations, guiding directives, focus, participants — as four separate framing lanes rather than one joined view pipeline, so each dedups on its own content hash and a change in one no longer re-serves the other three (commit 972049c7 on branch worktree-split-framing-lanes, pending merge).

**Why the gap is retired.** The gap named the dedup unit being coarser than the change unit and prescribed exactly this repair. Code inspection confirmed the repair is declaration-only: a framing lane is one declared inject call, the composer emits one string per call, and the serve path hashes each block independently — so lane granularity is declaration granularity and nothing in the renderer or the hashing needed to move. With the shell's declaration split (20260704-100000-d-prc-dlg), the delta the gap measured no longer exists, and the per-lane intent stated by the served-once dedup (20260705-010751-d-tac-dbk) holds at the granularity it was written for. The split isolates whichever section actually changes, regardless of which one that is.

**What was preserved.** All four sections render byte-identical to their portion of the former combined block — each was rendered standalone and compared against the live combined framing before the edit — so the agent reads the same framing and only the granularity of what is withheld changes. Lane order is unchanged, keeping the working-principles lane first and the byte-capped recent-movement lane last, which the lane-order assertion in `mcpapp/principles_framing_test.go` depends on.

**Evidence.** A new regression test in `mcpapp/server_test.go` drives a fixture graph carrying one entry per section, converges a reorientation to empty, then writes a second actor entry — a change confined to the participants section — and asserts that section re-serves while aspirations, guiding directives, and focus stay stubbed. Run against the pre-fix joined declaration it fails on all three, so it pins the repair rather than passing beside it. Inner verification is clean: go vet, the full test suite, and golangci-lint.

**What remains.** Outer validation is open — the effect has not been observed in a live session, because the running server still serves the pre-merge build; it will show on the first session after the merge. This corrects the granularity that shipped with shell-declared framing (20260719-015148-s-tac-khq) without disturbing anything else that slice delivered. The duplication-class constellation this belongs to (20260811-164958-s-tac-9l8) keeps its other two members open: per-instance instruction fragments that never hash-match, and report schemas served outside dedup entirely. Both need render-level work rather than a declaration change.

**Convention note.** The shell spec was edited in place rather than superseded by a successor entry, which is what the base-procedures README prescribes for shipped revisions. In-place editing is the established pre-release practice for this file and was followed deliberately, not by oversight.
