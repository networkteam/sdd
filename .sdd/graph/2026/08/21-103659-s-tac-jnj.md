Commit `ed16a30b` fixes MCP `show` zero-depth handling by representing `up` and `down` as optional integers and applying their defaults only when callers omit them, so explicit zero values now reach the application unchanged. The public tool descriptions now state both sides of that boundary: omitted values select depths 2 and 1, while zero disables the corresponding traversal.

The MCP-level `TestShowDepthDefaultsPreserveExplicitZero` regression test was added and observed failing against the original handler before production code changed; it now guards documented default expansion for omitted depths, primary-only output for explicit zero, and preservation of entry-local `refs` frontmatter. The intentional MCP contract snapshot was updated for the clarified schema.
