A sub-agent sent to research the graph reads it with the `sdd` CLI and `grep`, where a path over the engine's own tools was expected, and nothing points it at one.

Observed 2026-08-26. A session dispatched a sub-agent to research a set of entries and report back, so the wide reading stayed out of the outer context. The delegate used CLI calls and `grep`. Asked why, it gave three reasons. This repo's `AGENTS.md` sends sub-agent graph reads to `sdd search`. It knew the MCP read tools are ungated and chose the CLI anyway, to keep a read-only delegate clear of session state. And the MCP search tool defaults to no citation evidence where the CLI defaults to showing it (20260814-160042-s-tac-rst), so the CLI reads better unasked.

The user stated the expectation in this dialogue, on two grounds. An agent on another host has no `sdd` binary, so a CLI-shaped delegation path does not port. And a delegate running a served procedure is held to the reading discipline that a delegate on `grep` is not.

The explore procedure was built for this. Its body says it is designed to run in a disposable context, a sub-agent connected to this server (20260703-190100-d-prc-exp). The engine end of that works. A probe run in this session confirms a dispatched sub-agent shares its parent's MCP connection and is therefore already attached to the parent's session: a call naming the session with a nonexistent instance failed on the instance alone, and an argument-less resume returned the parent's live session. Handing a sub-agent the session and instance handles is enough to drive an explore instance today, at the cost of giving a read-only delegate the parent dialogue's full write access. Whether other hosts give a sub-agent its own connection was not tested.

What is missing is everything that would lead an agent there. Explore is task-class, so the session shell never offers it, and only engage and catch-up serve the dispatch instruction. The one shipped delegation artifact, the bundled `sdd-explore` skill, allows only Bash, Read, Grep and Glob, so a delegate launched through it cannot reach the MCP tools. The engine emits a fork-preferred execution hint on task-class serves that no served text, skill or fact explains. The path has never been run. The procedure's tests drive it inline, in-session.

The host-neutrality rule stops short of this. It binds served procedure text and puts skill prose out of scope (20260707-134311-d-cpt-476). Delegation is where served text hands off across that line. A procedure tells the agent to dispatch a sub-agent against this server, and nothing governs what that sub-agent is told to use.
