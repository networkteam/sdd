This plan makes the capture path's tool exchange efficient in both directions — the engine serves nothing a connection already holds, and the agent re-transmits nothing whole that changed only in part — bundling the committed repetition fixes so one session holds many captures without exhausting its context, spending fewer input and output tokens per entry. The measurement grounding the goal and the priority order is the capture-at-scale evaluation (20260825-234504-s-tac-jro): most of a capture-heavy session's context went to capture, and wall clock was dominated by review rounds.

One principle governs every serve, without exception: the engine never serves what this connection already holds — neither what it served before nor what the agent itself reported. That settles the per-lane default the named-lanes directive left open (20260826-003425-d-tac-87o) and revises its one planned exception: the topics lane renders as bare labels — stable bytes, so the dedup hash can fire — and deduplicates like every other lane. The exception existed to keep an agent that silently lost the label list from minting near-duplicate labels; but parallel captures by different participants mint duplicates anyway, so the durable repair is label grooming, not repetition — named below as future work rather than guarded against here.

Playback's serving rules follow from separating the two audiences — the agent, whose context every serve fills, and the user, who reads what the agent presents. What the user reads is the agent's presentation duty; what the engine serves is only what the agent lacks. The first round echoes small fields whole — confirming normalization, defaults, and derived values — while the body, which the agent authored moments before, returns as a fixed-size head-and-tail acknowledgment with the middle marked elided, plus a diff only where the engine changed it against the report. Later rounds serve engine-computed deltas: changed small fields whole, list fields item-level, the body as a content-anchored unified-style diff without line numbers, and an explicit nothing-changed marker — the measurement recorded revision rounds that changed nothing at all. Anchoring the diff on what the engine last served keeps the base an engine-owned fact, which settles the trade the re-serve gap recorded as open (20260826-000339-s-tac-fyi): every byte the user reads is engine-rendered — the first round's full presentation plus engine diffs — so no confirmation-round full render is needed. Guarding further against agent mispresentation was weighed and rejected as machinery against a failure mode that exists equally under full re-serves. This bounds the first-round-whole commitment (20260826-003953-d-tac-ktg) to what the connection does not already hold.

Upstream, the same rule: a body edit reports as an ordered list of exact search-replace pairs — each old text matching uniquely when applied, the list applied in sequence and atomically, a failing pair refusing the whole report by name — with full-body re-report remaining valid for genuine rewrites. Search-replace pairs were chosen over agent-generated unified diffs for reliability; the engine's answering diff then confirms effect against intent. Staged attachments follow the same rule: a staged file is edited in place through the same atomic search-replace shape, addressed by its handle, and read back in bounded ranges — so a small correction in a large record costs neither a full re-stage nor a full re-read.

Delivery runs in two slices, each expected to land as a partial done naming the criteria it covers, with closure left to the act that finishes: first the static-serve dedup (schema as derived lane, named lanes, bare-label topics) — the largest measured win, with no open design questions; then the loud capture path and widened correctable field set (20260821-105247-d-tac-q1x) together with the delta-and-patch rework, because they rework the same playback surfaces and built separately would contradict. The slices are the route; what done means stays the criteria below.

Deliberately not committed here: the serve size caps (20260820-165139-d-tac-wlq) — bounding one response's weight where this plan bounds repetition across many, its own line by both entries' reasoning; a dedicated step serving the current full draft mid-capture (whole-position replay stays the escape, the step addable later if wanted); per-lane pulls; a grooming or merge mechanism for duplicate topic labels, which parallel capture makes inevitable and which deduplicating the topics lane accepts as existing debt; and capture-path LLM telemetry. Outer validation — re-measuring a comparable capture-heavy session by the same method — is evidence the plan worked, not part of done.

## Acceptance criteria

- [ ] The report schema of an engine response deduplicates across a connection like any served lane: a schema this connection already received arrives as a stub, re-serialized in full only by resume or whole-position replay.
- [ ] Step serves compose from named lanes, and a lane whose bytes this connection already received is withheld; the topics lane renders as bare labels and deduplicates like any other.
- [ ] Every lane deduplicates by default with whole-position replay as the escape; no lane serves every time.
- [ ] Playback's first round serves small fields whole and acknowledges the body with a bounded head-and-tail excerpt, serving body content only where the engine changed it against the report.
- [ ] Playback rounds after the first serve only what changed: small fields whole, list fields item-level, the body as an engine-computed content-anchored diff, and a round in which nothing changed says so explicitly.
- [ ] A body edit can be reported as an ordered list of unique-match search-replace pairs applied atomically; a failing pair refuses the report naming the pair, and full-body re-report stays valid.
- [ ] A staged attachment can be edited in place through the same atomic search-replace shape, addressed by its handle, without re-staging the whole file.
- [ ] A staged attachment can be read back in bounded ranges, so verifying or editing a large record does not require serving it whole.
- [ ] Resume and whole-position replay serve full state, untouched by any of this.
- [ ] No value a user confirmed in dialogue vanishes silently on the capture path: an undeliverable dispatch seed, a declared field reported at a non-collecting step, and a body asserting an attachment the entry does not carry each fail loudly or arrive as a named notice (per 20260821-105247-d-tac-q1x).
- [ ] A capture's attachments, entry kind, and layer are correctable on the revision paths without abandoning the draft, with state licensed only by a superseded kind cleared or refused at the gate (per 20260826-003953-d-tac-ktg).
