The SDD assistant UI prototype is the new tactical focus: building the web surface where the SDD dialogue itself lives, per the prototype plan (20260831-223336-d-tac-2gf), starting with the agentic-UI feel-spikes and iterating toward the demo scenarios in real sessions. Christopher and Claude carry the period; work is picked up session by session, with no fixed end.

It supersedes the runtime-and-hosted-webapp focus (d-tac-hza), whose finish line was reached but never recorded: the runtime spikes returned their verdict at the end of June (d-cpt-8k5), settling the runtime question, and the hosted-webapp half of its intent continues here in changed shape, a UI over the engine's MCP HTTP transport driven by a thin external agent instead of an embedded hosted agent.

This focus stands beside the engine-first transition focus (d-tac-onl) and the type-system knowledge focus (d-tac-uea), a third parallel strand rather than a replacement; assistant-UI findings that demand engine changes queue behind the transition work those foci carry.

Deliberately outside this period: the hosted SDD surface (a separate story in a separate repository) and any final UX or UI direction, which the prototype exists to inform.

The period ends, in the plan's own terms, when a real session can be driven end to end in the assistant UI and the recorded findings are in the graph to inform the next UX decisions.
