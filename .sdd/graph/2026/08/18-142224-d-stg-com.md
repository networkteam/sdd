SDD must not become an issue tracker: everything an issue tracker provides — what is open, who is working on it, what comes next — is derivable from the graph and can be served through surfaces, reports, and agentic UIs tailored to participant roles, so no duplicating system is needed. That positive framing comes straight from the sole-record aspiration (20260422-123237-d-stg-3k0): no parallel systems that duplicate information are needed, because whatever the work produces is the record. The deeper reason is a prediction about the agentic world: preparing issues as pre-chewed work scope and assigning them to people is push coordination built for a time when handing over context was expensive and execution capacity scarce — while providing the reasoning and decision background so humans and agents work autonomously, aligned to the project's goals and focus, is the better fit. The effort moves from packaging work to direction and alignment, including the housekeeping — done with agent assistance — that keeps the graph true to the project world. The graph already carries part of what an issue tracker holds — actors, roles, focus with its time ranges and involvement — and planning happens in dialogue that captures execution constraints (availability, timelines, priorities) back into the graph, where decisions over the actual execution order are formed from them; why an order was chosen matters more than the order itself, and a "high" priority label carries less value than understanding why the work outranks what competes with it. Rebuilding issue-tracker mechanics — assignment queues, status workflows, sprint boards — would therefore imitate the tool instead of deriving the answers, and pull execution ceremony into a record meant for reasoning and shared context. A project fully embracing SDD can work without an issue tracker; the path there is derived, role-tailored views, never issue-tracker features.

At the same time, SDD works with the world rather than fighting it: where a team runs an issue tracker — notably customer projects where it is today's system of record — SDD connects to it, treating it as transport for intake and as an outbound target, never absorbing it. How long that coexistence lasts depends on the stakeholders and the project; it is a transitional step, not the end state. This fixes the posture for the open coexistence gap (20260617-182152-s-cpt-yve) without closing it — the outbound emit-and-mirror model still needs to be settled — and answers that gap's proposal to permanently narrow the aspiration to a reasoning record: no narrowing is needed, since with the right surfaces the graph provides all the information, and connection covers the transition.
