Exported Go packages live under `pkg/`: the repo root carries `cmd`, `internal`, and `pkg` as its only Go package trees, a new exported package never adds a root folder, and the existing exported packages (`application`, `local`, `mcpapp`, `sddtest`) move under `pkg/` in one import-path rewrite, keeping their package names. The rewrite is bounded one-time work this guideline obliges: its completion lands as a done referencing this directive without closing it, while the guideline itself keeps applying to every later package.

The root had accumulated four exported packages beside `cmd` and `internal`, and the LLM boundary contract (20260830-234501-d-cpt-q6n) was about to add a fifth with `pkg/llm`. The `pkg/` convention is community practice rather than a Go-team standard, but with `cmd/` and `internal/` already present it completes the triad and makes the exported surface legible from the root listing. The timing carries the decision: no external consumer has pinned the current import paths, because the planned hosted sdd service is not yet built and the in-repo consumers move with the rewrite, so the move is one mechanical change now and a deprecation cycle later.
