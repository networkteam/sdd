This directive settles the implementation architecture for the bounded-serves plan (20260829-173342-d-tac-rzi): cut mechanics in a new `internal/truncate` leaf, size policy and bounded-part construction in a new `internal/serveview` layer, per-query serving knowledge declared once at query registration, and two cap axes whose byte-safety the plan's measurement harness enforces. The full seam map with file-level touchpoints is in [the architecture record](./30-112915-d-tac-qwc/bounded-serves-architecture.md).

`internal/truncate` separates data from meta. Queries and projections return carriers, `List[T]` and `Text`, each pairing the payload with a `Cut` record naming dropped count, total, bytes, and a ready-to-run pull expression. The package carries no notice wording; each surface renders a `Cut` in its own register. The engine unwraps carriers at the inject seam: the payload enters the template context unchanged, so authored templates keep their shape, while the meta flows out of band into the serve's cut accounting and an engine-owned cuts lane beside the existing draft lane. A template cannot swallow a cut because the notice never passes through it. The three existing cut styles (the silent lane byte cap, the view guard, the collected-value cap) become callers of this one mechanism.

`internal/serveview` is to serves what presenters are to finders: a pure construction layer shaping what the agent receives, owning `Budget`, `Cap`, `PartKind`, and the calibrated `Default()`. The engine stays orchestration; it walks lanes and injects, delegates each scaling part, and never truncates authored instruction text.

Per-query serving knowledge (part kind, default cap, pull composer) is declared exactly once, as a `Bound` on the engine query at registration. The registry itself is the resolver the worst-case arithmetic takes as a parameter; the arithmetic is a pure spec method with the budget passed as a value, never reachable from spec loading. A name-keyed table with a fallback was rejected: a resolver miss means the spec names an unknown query, which spec validation rejects before the arithmetic runs.

Caps have two axes. `MaxBytes` governs producer-rendered text, cut byte-precisely at whole rendered-chunk boundaries before joining. `MaxItems` governs typed data that templates range over, where per-item bytes are unknowable before rendering; count caps stay byte-safe through measured per-item allowances, and the measurement harness fails when template growth breaks the fit. A shrink-and-re-render loop was rejected as complexity buying the guarantee the harness already gives.

Three forks were settled with the plan's scope unchanged: a pre-flight override also skips the budget finding, since lint catches the spec on every later sweep; the cuts lane joins ordinary per-lane dedup, since full replay restores it after context loss; and the graph-health framing block keeps its named-count form without a pull expression, an accepted carve-out from the plan's cut-pointer criterion, because lint stays a CLI surface rather than an agent tool.
