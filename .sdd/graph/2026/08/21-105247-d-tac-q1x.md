No value a user confirmed in dialogue may vanish silently on the capture path: every drop the engine cannot deliver becomes a visible error or a served notice. Four verified losses define the scope, all from live sessions:

- Engage hands its anchor to a dispatched capture and the engine skips the copy without error, because capture declares the field under params while the copy rule writes only declared state (20260814-233547-s-tac-bqt).
- The report boundary refuses an undeclared field with a named error but silently discards a declared field sent to a step that does not collect it. The agent cannot tell a landed correction from a dropped one (20260811-233331-s-tac-bjn).
- An entry landed with a body asserting an attached review while carrying no attachment, because the staged file was never listed in the report and nothing checked the claim (20260707-175502-s-prc-lgu).
- Playback renders a fixed subset of the draft (body, refs, topics, index, confidence, intent, lifecycle), so every other field is written without ever appearing at the confirm step (20260811-232108-s-tac-kus).

The scope is loudness, deliberately. The declared-binding directive (20260812-160448-d-tac-ymk) ends the write-path translation class by design, but it covers only that boundary: its own scope note excludes the report-collection sibling, attachment claims live in the body, and playback is display. That work also hangs on the entry-construction model, which sits on the other release's critical path. The release triage (20260815-000432-s-tac-xlw) found the narrower cut that unblocks the engine-first release: once capture is the only write path, a silent drop is corrupted state nobody sees.

On attachments the harmful case is the entry lying about what it carries, not the leftover file. A staged file nobody writes about loses nothing a truthful entry needs, and the complete playback shows the attachment list at confirm time. So this plan adds no tracking of staged files; it checks the claim instead, at the write gate, where pre-flight already reads the body. An earlier draft tied each staged file to an owning capture; we dropped that because the parked-capture ambiguity it had to solve only exists for a requirement we do not need.

Remaining mechanism choices per boundary (fail the call or serve a named notice) are settled during implementation; what the plan fixes is that silence is never an outcome. Each boundary fix is a bug fix and follows the standing regression-test rule.

Out of scope: the binding design itself, tracking or warning about staged files never referenced by an entry, and making every field adjustable at playback. Playback here gains visibility, not a wider adjust surface.

## Acceptance criteria

- [ ] When a procedure dispatches a follow-up with a declared value copy (engage seeding its anchor into capture), a copy whose target field cannot receive the value fails the dispatch with an error naming the source and target fields, or arrives as a served notice naming what did not land. The copy is never skipped silently.
- [ ] A report carrying a declared field at a step that does not collect it is answered with a message naming the field and why it did not land, matching how undeclared fields are refused today.
- [ ] An entry whose body asserts an attached record while its attachments field carries no matching file is blocked at the write gate; no entry lands claiming a file it does not have.
- [ ] Playback renders the entry as it will be written, complete frontmatter and body, instead of today's fixed field subset, so the user confirms the real entry.
