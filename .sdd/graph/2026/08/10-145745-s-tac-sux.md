Slice 4 of the session-subsystem rebuild (20260730-093011-d-tac-k4q), the transport-vocabulary directive it implements against, the branch-precedence consolidation, and a read-side recovery of lost session endings are delivered in commits `2e961f00`, `7b4fee69`, `1fb24286`, `627ed373` and `a08266b4` on branch worktree-k4q-session-rebuild, with the live binary-swap criterion proven against a real store: the durable session log records only participant acts, concluding is terminal with continuation carried by a fresh session, one effective-branch rule serves reads and writes alike, and every session the user ever concluded is finally collectable.

Commit `2e961f00` realizes 20260731-081528-d-cpt-rw7 in full, which is why this signal closes it: the transport causes (`disconnect`, `shutdown`, `switch`) and the append-only `AttachmentHistory` are gone, one `SessionEnd` terminal record (concluded or abandoned) is what ends a session, displacement is derived from the live stamp, and a dropped connection only clears that stamp.

Commit `7b4fee69` fixes a defect the smoke test exposed: the plan expresses retention in days, but `sessions.retention` accepted only Go durations and silently fell back to the 14-day default on anything else — `1d` quietly meant fourteen days, a direct fail-loud violation. Retention now parses whole days alongside Go durations and an unparseable value stops `sdd serve` at startup with a named error.

Commit `1fb24286` is slice 4. Conclude ends the session on the spot, with the shell's ending event and the terminal record in one append; the shell spec's discharge gate — the `threads` step that looped conclude back until every move was settled — is deleted in favor of the plan's letter, so open threads are named specifically as left behind rather than walked. The door no longer re-serves a finished session; moves and resume against one are refused, every refusal carrying the same way-on statement; an ended session stops counting as open work in every listing surface; a quiescent session that loses its connection auto-concludes into a collectable end; and the shell spec teaches ending as part of the dialogue arc — name what is open, offer the wrap, never punish silence.

Commit `627ed373` consolidates effective-branch precedence, the one wg5 item independent of relocation: reads honored an explicit `workBranch` that writes ignored, so a procedure's reads and writes could resolve different branches. One `effectiveTarget` rule — explicit procedure-state branch, then session binding, then configured default — now serves both sides, with a table test proving they agree across every combination and that capture playback states the branch the write lands on.

Commit `a08266b4` exists because Christopher challenged this signal's own draft, and the challenge overturned a diagnosis. The draft claimed exactly one session had ever been concluded, echoing 20260731-080621-s-tac-jkw's reading that almost nothing on the store ever ends and that teaching users to conclude was therefore the load-bearing half. The truth is the opposite: 36 of the store's 58 sessions have a completed shell and 17 more an abandoned one — Christopher concludes nearly every dialogue — but the engine recorded each conclude only as the shell's own event, while the metadata-level record the collector reads was never written, its write site lost in the mid-July session-model rebuild. The store was not full of unended dialogues; it was full of endings the engine had failed to record. A read-side store decorator now derives the terminal record from the shell instances' terminal events when metadata carries none — one authority behind the session store, so collection, listings and resume-refusal always agree — making 53 of 58 real sessions derive as ended and refusing their revival.

Verification went beyond the suite (all green, lint clean) and beyond fixtures. A real stdio crash appended a single stamp-clearing line with zero transport vocabulary; a live MCP dialogue that concluded over an open capture produced the threads-left-behind serve, the typed refusal on the spent handle, a fresh handle from the door, and the session's disappearance from open-work listings while its log stayed readable. Against copies of this machine's real store, the collection pass removed exactly one session before the derivation fix and fifty at a 24-hour retention after it, leaving only the genuinely open and the recently ended; an independent run at the default fourteen days removed forty-three and was idempotent. The binary-swap criterion was met literally: the previous main-build binary and the rebuilt one served the same real store copy concurrently, the old process appending to its running session while the new binary listed that work — no stop, no acknowledgement, no offline window. The swap surfaced a forward-compatibility gap outside this plan's scope, captured as 20260810-144515-s-tac-8ae: strict config parsing makes any new config key fatal to older binaries sharing the user-global config.

The plan stays open: the port conformance-suite criterion was not re-verified by this run, and the teaching arc's outer evaluation — a real dialogue where the agent offers the wrap unprompted — remains to be observed in use.
