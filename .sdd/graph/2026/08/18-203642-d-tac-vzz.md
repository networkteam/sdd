Every session that captures an entry will reach composition with the type-system overview already served in full and with a clear route to the chosen kind's authoring fact, so the first draft is informed by graph-resident kind knowledge rather than repaired into it by the writing guide. The hard outcome is reliable overview reach before kind choice and drafting. The behavior to test is concrete: when capture points to the detailed authoring fact for the chosen kind, does the agent pull that fact before writing its first draft?

This is a focused delivery plan under the active kind-knowledge plan (20260812-134549-d-tac-9be). It acts on the live outer evaluation (20260818-195028-s-tac-cw4), where the detailed directive fact improved the draft once pulled but the capture lane failed to create that pull beforehand, and builds on the completed authoring-fact layer (20260818-192127-s-tac-hda). The change refines the shared capture procedure (20260703-094500-d-prc-cap) rather than creating another move, and takes the graph-resident overview (20260812-180000-s-prc-typ) as its single type-system map.

A capture whose session has not received that overview in full presents it in the procedure's initial response, before the first draft report. Capture automatically serves the overview at most once per durable SDD session: a prior full read anywhere in that session satisfies the grounding and prevents repetition even after the session is parked, disconnected, resumed, or re-attached, while a summary does not. This does not prevent an explicit later read. The sequence presented to the drafter is overview, kind choice, detailed kind fact, then draft. For a preselected kind, the specific authoring fact is named immediately. For an unselected capture, the overview supplies the complete authoring-fact index and the instruction to pull the chosen fact before composition.

The overview remains the choosing surface. It already carries the direct tests and says when to pull the separate discrimination fact, so capture adds no parallel discriminator cue. Detailed-fact use stays instructional and observable rather than enforced: neither the overview nor an authoring fact participates in the draft's reference-inspection gate or any new transition condition. The writing guide remains the downstream audit, and a post-delivery outer evaluation records whether an unprimed agent pulled the selected-kind fact before its first draft and what kind-specific correction, if any, the guide still supplied.

Implementation is deliberately a small composition change over existing capabilities. It reuses capture's initial assemble serve, the workflow injection registry, the durable session read ledger, existing live-graph resolution, and the existing kind-to-authoring-fact mapping. Production code adds only the capture-specific query and wiring plus the capture instruction text; focused tests cover the behavior. It introduces no new MCP, CLI, or application-facing surface, no new finder or presenter, no new engine state or predicate, no procedure step or chooser, and no generalized instruction-transport mechanism.

The exact query, live-head resolution, durable session-ledger deduplication, failure behavior, and code-level verification surface are preserved in the attached design record. Out of scope are universal overview priming at every session open, copying discrimination prose into capture, a new chooser or preliminary procedure step, and mechanically requiring an authoring-fact read.

## Acceptance criteria

- [ ] A capture started without a prior full overview read serves the complete live type-system overview in its initial response, before the session's first draft report, and records that grounding as a full session read.
- [ ] A prior full overview read anywhere in the same durable SDD session prevents capture from automatically repeating the overview body, including after park, disconnect, resume, or re-attachment; a summary-only read does not suppress it, and an explicit later read remains available.
- [ ] An unselected capture reaches the drafter with the overview and an explicit overview → kind choice → detailed kind fact → draft sequence before the first draft report.
- [ ] A capture started with a preselected kind names that kind's exact live authoring fact in the initial response before drafting.
- [ ] Capture contains no separate discriminator cue or copied discriminator prose; the served overview remains the single path and contains the discrimination-fact pointer.
- [ ] Overview and authoring-fact reads participate in no assemble guard, requiredRefs set, or refsInspected check, and the existing reference-inspection behavior is unchanged.
- [ ] Missing, unresolved, or empty drafting facts fail loudly instead of silently omitting type-system guidance.
- [ ] Production changes are confined to composing existing capture, injection, read-ledger, graph-resolution, and authoring-fact-mapping capabilities; engine and MCP contracts remain unchanged and no new user-facing or generalized serving surface is introduced.
- [ ] Automated coverage exercises fresh, prior-full-read, summary-only-read, preselected-kind, unselected-kind, and re-attached-session starts through the engine/application boundary and the initial MCP start response.
- [ ] One live outer evaluation after delivery records whether an unprimed agent pulled the selected-kind fact before its first draft and whether the writing guide repeated kind-specific guidance already carried by that fact.
