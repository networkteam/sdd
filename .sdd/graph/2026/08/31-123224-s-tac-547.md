Commit `336d63ee` restores CI to green on `main` and adds a local guard against the same breakage recurring. Three pushes had failed since 55df825d added `Identity()` to the `application.LLMExecutor` port. The nested `examples/extendingsdd` module carries a hand-rolled `llmExecutor` in its test files that never gained the method, so that module failed to build on both the ubuntu and macos jobs. The lint job stayed green throughout, and nothing in the root module was affected.

The stub now returns `LLMIdentity{Provider: "example", Model: "stub"}`, and the example's `main.go` executor sets the matching `IdentityFunc`. Neither had to. `LLMExecutorFuncs.Identity` is nil-safe and returns a blank identity, so `main.go` compiled as it stood. The example is what documents the port, and the port's doc comment calls Identity required, so compiling on the blank default would have taught the opposite.

CI already ran the example module as its own step, because the root module's `./...` does not enter nested modules. That arrangement dates from the module's arrival (20260713-001910-s-tac-ill). What it never had is a local counterpart, so drift surfaced only on push. A `go.work` does not supply one. Tested with both modules in a workspace, `go list ./...` from the root returns the same package set as without it. A workspace only makes the nested module addressable by name, which still needs a second explicit target. The guard is therefore a `devbox run test` script running both invocations, mirroring `.github/workflows/ci.yaml`, and `AGENTS.md` now names it as the way to run the tests in place of `go test ./...`.

The example will drift again. The committed LLM boundary rebuild (20260830-234501-d-cpt-q6n) deletes this static `Identity()` method, moving identity to per-call reporting on the result, so the method conformed to here is already slated for removal. The script makes that break at dev time rather than on push.
