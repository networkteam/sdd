Tests live at the layer that owns what they assert, and no test fakes another layer's contract.

**The pattern.** A package's own semantics get unit tests over synthetic fixtures the test package owns. Composed behavior gets integration tests at the layer that wires the composition — over the real parts, with only true externals scripted (the LLM, the clock, temp stores). A fake of another layer's contract — its registered names, its serve shapes — is not a test double but a drift trap: it keeps passing when the real contract changes, and it teaches the tests behavior the real path does not have.

**The concrete map.** internal/engine tests engine semantics — spec loading, store, choosers, gates, replay — over synthetic procedure specs owned by its test files. internal/proctest tests every shipped procedure's behavior against the real application: real registry, real ops writing real entries and WIP markers, real read ledger, a scripted call-counting LLM. application keeps unit tests for its own surfaces (stores, bindings, snapshots). mcpapp tests transport concerns (serve dedup, framing, restart and re-attachment).

**Why.** The migration that produced this split, run in the 20260818-203642-d-tac-vzz delivery, showed the cost of contract fakes directly: the engine-level fakes had invented behavior the real path does not have — a fake write gate re-ran pre-flight after an override where the real one skips it — and an MCP test passed against a simplified fixture capture while the shipped procedure went unexercised. Real-path tests caught what the fakes could not; the full defect inventory is recorded with that delivery.

**Rule migration.** Once the rule-system plan (20260622-084244-d-tac-eho) ships the rule kind, this placement line is the candidate to become a rule activated on test authoring.
