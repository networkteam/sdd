Automatic two-way graph sync exists to give collaborating participants immediate feedback on each other's movement — so nobody starts work someone else already marked in progress — and it runs under a single safety rule: sdd moves only commits it made itself. Without it, two people on one graph see each other's thinking only when somebody remembers to push and somebody remembers to pull. The cost lands in three places: duplicated work, since the WIP markers that announce work in progress travel as ordinary graph commits and so arrive exactly as late as everything else; stale reasoning in the session underway, since a decision or signal captured elsewhere may bear directly on what is being discussed here; and a burden of memory on the user, who gets no indication whether a capture ever reached anyone. Today neither direction is automatic on the surface that matters: push has never been automated (20260430-212941-s-tac-jnd), and while `sdd sync --pull` and the background fetch shipped (20260608-002510-s-tac-qk2, 20260423-144715-s-tac-2y0), they were wired into the CLI and the /sdd skill, so on the engine path nothing fetches and nothing pulls. Users reasonably assume a captured entry is published; it is not.

The rule is whole-branch, because git publishes a branch and not a selection of commits: "only sdd commits" cannot mean pushing a subset. Push proceeds when every unpushed commit on the branch matches `^sdd:`, and otherwise does not happen at all. Symmetrically, an automatic pull runs only when every incoming commit matches `^sdd:` — the symmetry earns its keep more on this side, since a pull carrying other people's code commits would move the user's working tree mid-session. Detection is cheap on both sides: the existing pattern-filtered count over `@{u}..HEAD` (or `HEAD..@{u}`) compared against the same range unfiltered, equal counts meaning safe. That also closes a shortcut the shipped code concedes in a comment, where the filtered count stands in for raw divergence. WIP markers need nothing extra to participate: they are committed under the same `sdd:` prefix, so they cross with the entries.

When the rule does not hold, the outcome is a report, not silence: the engine states that entries are captured but unpublished, or that remote movement is waiting behind commits sdd will not move, so the agent can tell the user to push or pull themselves. This is the accepted cost of the whole-branch reading — someone mid-feature in a shared repo keeps their captures local — and it is bounded by where the graph lives: a graph in its own repository satisfies the rule by construction, since every commit in it is an sdd commit, so the default simply works there and degrades to an honest prompt elsewhere. That is judged better than today's silence and sufficient for a first version. Publishing the graph on a separate ref so it syncs independently of the code branch was weighed and rejected as more machinery than the separate-repository answer needs.

The pull must author its own merge commit with an `sdd:` message. Two participants both capturing diverge, so a merge is the ordinary collaboration case rather than an edge, and a default `Merge branch ...` message would leave an unpushed non-sdd commit on the branch — permanently disabling safe push in exactly the situation this exists to serve.

Arriving movement is ambient, not an event. Entries and WIP markers alike ride the shell's declared framing lanes with per-lane content-hash dedup (20260719-015148-s-tac-khq): a pull re-renders the changed lanes, dedup means they reach the agent only when something actually moved, and the agent folds that into the dialogue — naming a marker on work this session is about to touch, or a decision that bears on it — rather than narrating every arrival. No new announcement channel is introduced.

All of it runs as engine capabilities — fetch on interaction gated by a threshold since the last attempt, plus the pull and push transitions — never as served instructions pointing at the `sdd` CLI, per host-neutrality (20260707-134311-d-cpt-476). What this settles is behavior; the mechanism, how that interaction threshold relates to the fetch cooldown background sync already carries, and the configuration surface for opting out remain for the plan that follows.
