A project's business domain has no explicit home in the graph: nothing declares which term the project uses for a thing, nothing records that two words mean the same thing, and a term's meaning survives only implicitly in prose spread across entries.

That missing declaration is the core of it, and two costs follow from it. Terms vary: the same thing is named differently across entries written weeks apart, because no entry says which word the project has settled on and none records that an older word and a newer one point at the same thing. And reasoning about the domain is expensive: answering a question about how this project's world actually works means reading widely across the record, collecting mentions and inferring the shape they imply, instead of reading a statement of it. Both costs land hardest on a participant who was not in the original dialogues — a newly joined person, or an agent in a fresh session.

Actual state, from a dedicated exploration sweep of this graph on 2026-08-18 searching from several angles — ontology, glossary, domain vocabulary, shared semantics, domain modeling, term definitions: no entry treats a project's domain as explicit vocabulary, and no decided direction exists for it. A second observation arrived within minutes of the first capture: two sessions working in parallel each coined a different topic label for this very subject. The gap produced an instance of itself while being recorded.

Expected state, grounded in the process-side precedent: SDD's own working vocabulary — kinds, reference kinds, topics, actors, procedures — lives as graph-resident, supersedable knowledge (20260812-180000-s-prc-typ), where a term is defined once, pointed to instead of restated, and revised through the same dialogue that moves everything else. What SDD does for its process vocabulary it should be able to offer for a project's subject matter, because diverse participants — domain experts, designers, agents — reasoning over one project need terms with settled meaning. Topic labels come closest today and are a different thing: they group entries for retrieval rather than defining anything.

Candidate direction, explicitly a candidate and not a commitment: declare the domain vocabulary in the graph itself, possibly extending to an ontology — concept entries with typed relations over the domain — so the semantics are recorded rather than inferred each time. How that would relate to the fact kind is open: a fact records discovered knowledge about the world, and what a domain term means is arguably exactly that, but a vocabulary needs to be reachable as an enumerable set rather than found one entry at a time.
