A capture draft substantially rewritten after its writing-guide pass cannot be returned to the guide: the guide judges the assemble-time draft once, and the shipped flow offers no re-judgment from playback, though the capture-guide architecture grants exactly that as an agent judgment.

Expected, per the capture-guide architecture (20260810-141555-d-cpt-20r): neither guide is a hard gate, and returning a substantially changed draft to the guides is the agent's judgment. Findings are drafting input on the draft the user then confirms.

Observed, firsthand in this session's captures under the shipped wiring (20260811-141038-d-tac-rvu): when the guide's single pass returns findings, the review step offers a recheck that discards the run and judges a rewrite fresh; when the pass is clean, the flow goes straight to playback, whose only options are confirm, adjust, and abort, so every adjust rewrites the body beyond the guide's reach. Reported secondhand from the prior session's continuation notes: a done signal for the stats work was redrafted at playback three times, each redraft unjudged, and the capture was abandoned each time.

The deviation: the re-judgment path the architecture commits exists only on the branch where the first pass found something; after a clean pass, or for any revision made at playback, there is no way back to the guide.

Reasoning from the dialogue, marked as such: the miss is structural rather than cosmetic, because the guide's core test, whether the entry stands alone outside the dialogue, is exactly the test an author cannot run on their own rewrite, so playback-stage rewrites are where a fresh judgment is needed most.
