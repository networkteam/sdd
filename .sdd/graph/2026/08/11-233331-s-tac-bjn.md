A state field reported at a step that does not collect it is discarded without error, while a field no procedure declares at all is refused with a typed message naming it — so the report boundary speaks up for the clearly wrong report and stays silent for the plausible one.

Both halves were exercised during captures in one session. First, a report to an assemble step carried `confidence_note`, a name no procedure declares; the call failed outright with `field "confidence_note" is not declared in state — reports can only write declared state fields`, naming both the field and the rule. Later, a report to the playback step of a focus capture carried `involvement` — a field that same procedure declares as state and collects at assemble — next to the adjustment being made. That call returned the ordinary playback serve: no error, no mention of the field, nothing to distinguish it from a report that had taken effect. A read of the session's recorded state afterwards showed the value untouched, still the three-target list the draft already held rather than the four-target one just sent.

The silent half is the costly one, because the agent has no way to distinguish a landed correction from a dropped one and no prompt to go looking. Reading the persisted state back is the only check, and nothing suggests doing it — which is how a known fault with an attempted repair still ended in an abandoned draft (20260811-232108-s-tac-kus): the repair was made and lost, not missed.

What follows is neither observed nor settled: two repair candidates for a later discussion, recorded so the thinking is not lost, and explicitly not findings. One is to refuse the report with a named error, mirroring the undeclared case exactly. The other is to write the value anyway, which would cut against the apparent purpose of a per-step collect list. Choosing between them turns on what that list is meant to bound, and no entry answers that. Report collection is already named as one of the concerns the closed authoring model conflates (20260726-195739-s-cpt-hcp), so a redesign there may absorb the question rather than answer it in this form.
