Shell-served working principles ship in three pieces — an `as-bodies` render function in the view grammar, a "Working principles" framing lane on the user-dialogue shell selecting active facts under `principles/interactive`, and a thinking-posture base fact carrying the operative prose — realizing the always-on serving mechanism committed in (20260810-134906-d-cpt-a2a) with no new engine surface beyond the one render function.

## The render

`as-bodies` joins the view grammar's render terminators. Per entry it emits an identity header — full ID plus the layer/kind/type words, deliberately without the summary sentence, because the summary derives from the body and serving both would duplicate — then the full body with its headings demoted by the nesting depth, relative hierarchy preserved, so no body heading ever outranks the lane or section structure. Heading demotion ships as a reusable Markdown transform with `as-bodies` as its first consumer — the same mechanics available to every serve surface that embeds entry bodies, not logic private to this render. A body that opens with a heading contributes it as the section title with the identity line as byline; a heading-less body falls back to the identity line as its header. Selection, ordering, and capping all come from the existing grammar: any filter combination can render bodies, the rank vocabulary provides deterministic order, and `maxBytes` bounds a lane. Two alternatives were rejected: a dedicated inject function (`factBodies` with kind/topic args) would re-invent the selection vocabulary the view grammar already owns, and pseudo-XML wrapping would mix two structural grammars in one serve where heading demotion keeps it pure Markdown.

## The lane

The user-dialogue shell's embedded spec (20260704-100000-d-prc-dlg) gains a first framing lane — `{fn: viewLayout, args: {layout: 'active:kind(fact):topic("principles/interactive"):as-bodies:name("Working principles")'}}` — rendering after the engine's info block and before the process core and move enumeration, which is what primed-rather-than-pulled means positionally. The lane machinery is untouched and supplies the re-entry semantics for free: content-hash dedup on a plain reorient, full re-serve on fullReplay after context loss, change-driven refresh when a fact is superseded mid-session, and silence when the selector matches nothing. Other shells opt in by declaring their own lane.

## The fact and the name

The posture base fact carries the operative prose of the way-of-thinking directive (20260810-123226-d-cpt-ei0), terse and standalone, under topic `principles/interactive`. As a base fact it ships embedded with no participants and no project refs per the base-fact contract (20260707-140544-d-cpt-dtv) — the linkage to the directive lives only on this graph's side. It carries no index block: principles are pushed in full, and enrollment in the retrieval index (20260719-133529-d-cpt-qhn) stays a separate, deliberate choice. The topic family deliberately renames the anchor's provisional `priming/*` to `principles/*`: priming names the mechanism's effect on the agent, principles names what the fact is — and the second component keeps the session mode (`interactive` now, automated families later), so shells still select by component-wise prefix. The view-grammar reference fact (20260717-110000-s-prc-vwg) is the documentation surface where the new render must appear.

## Acceptance criteria

- [ ] A fresh session open serves the working principles in full as the first framing block after the session info — before the process core and move enumeration — visible to any connecting agent.
- [ ] The same words render at the CLI via an `as-bodies` view layout, so a human inspects exactly what agents are primed with, from the same single home.
- [ ] After context loss, fullReplay re-serves the principles lane; a plain reorient dedups it like any unchanged lane; superseding the fact mid-session re-serves the changed lane.
- [ ] A project fact superseding the base principles fact changes the served words at the next session open with no code change; adding or retiring a fact under the topic changes the served set through graph resolution alone.
- [ ] A shell declaring no principles lane serves none, and an empty topic match serves no block.
- [ ] Rendered bodies keep their internal heading hierarchy demoted beneath the lane and entry headers — no body heading outranks the lane structure in any `as-bodies` output.
- [ ] Heading demotion is implemented as a reusable transform, exercised by `as-bodies`, available to other serve surfaces.
- [ ] Served order is deterministic across repeated session opens.
- [ ] The live view-grammar reference documents `as-bodies`, so an agent discovers the render without reading source.
