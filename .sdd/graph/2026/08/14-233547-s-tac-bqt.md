Starting a capture from engage silently loses the anchor: engage declares that its `anchor` and `widenReport` values are copied into the next procedure it dispatches, but the engine copies only into fields the receiving procedure declares under `state`, and capture declares `anchor` under `params` — so the copy is skipped, without any error.

**Expected.** The user picks a capture at the end of an engage and the agent starts it as a sub-move. Engage's junction option declares `dispatch: {seed: {widenReport: widenReport, anchor: anchor}}`, so the engine copies both values from the engage instance into the new capture instance. The capture then begins already knowing its anchor: its first step tells the agent "this capture is anchored on … — read its chain before drafting", and the written entry carries that anchor — without the agent re-supplying anything.

**Actual.** The engine copies `widenReport` — capture declares it under `state` — and skips `anchor`, because capture declares it under `params` and the engine's copy rule writes only into declared state. The capture begins with no anchor: the anchored instructions never appear, the written entry has no anchor, and nothing — no error, no log line — records that half the declared copy did not happen. The anchor reaches the capture only when the agent passes it explicitly as a start input, which engage's body happens to suggest; the declared copy of `anchor` (20260703-190000-d-prc-eng → 20260703-094500-d-prc-cap) never fires.

**Class.** An instance of the silent-loss class the binding-coverage directive commits to ending (20260812-160448-d-tac-ymk).

**Repair options.** Three, and they compose rather than compete:

- (a) Declare capture's `anchor` under `state` instead of `params`, mirroring the lifecycle-fields repair (20260813-092611-s-tac-75b): one declaration, no engine change, and a field declared under `state` can still be passed at start. But it fixes this one field — the next procedure that declares a seeded field under `params` recreates the bug. The class survives.
- (b) Let the copy rule fill declared `params` as well as `state`: a dispatch seed is a start input supplied by the parent instead of the caller, arriving through the same start path — and an explicitly passed value still wins, since the copy skips fields already set. This ends the class at the landing side. It widens the params contract: a parent can then supply any of the child's start inputs, which every constructed case so far wants, but which is a deliberate semantics change, not a patch.
- (c) Make an undeliverable copy loud regardless of the landing rule: a declared seed pair that cannot land fails the start or arrives as a named notice in the serve, never a silent skip. This ends the silence for whatever pairs remain undeliverable.

Recommended: (b) with (c); (a) alone is the instance fix that leaves the class alive. A regression test covers the engage-dispatched capture inheriting its anchor either way.
