Markdown served into a composed context must form one coherent heading hierarchy: any embedded content — an entry body, a generated section, any fragment stitched into a larger rendered document — is demoted beneath its container's headings with relative order preserved, so no embedded heading outranks the structure serving it. This holds for every surface that composes Markdown, agent serves (framing lanes, injected chains, step instructions) and CLI rendering alike.

Heading levels are the structure a reader parses containment from — sharpest for LLM agents, who take hierarchy as a meaning signal: an embedded body whose `#` outranks the section header above it makes the document lie about what contains what, degrading comprehension exactly where structure was supposed to carry it. The rule was prompted by live observation that existing serve injections already mix hierarchy this way; bringing those surfaces in line — starting with an inventory of the exact composing consumers — is recorded as its own follow-up.

Pseudo-XML wrapping was rejected as the repair: mixing two structural grammars in one document blurs which carrier is authoritative, while demotion keeps composition in a single grammar. The rule complements the output policy (20260628-131525-d-cpt-owo) — that directive chooses the format per consumer; this one governs structural coherence within served Markdown itself. Its first realization is the reusable heading-demotion transform shipping with the working-principles plan (20260810-151913-d-tac-41n), built deliberately as shared mechanics rather than logic private to one render.
