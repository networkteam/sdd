The door serve — the orientation payload a session opens with, carrying the shell's framing lanes and instructions — now runs a few kilobytes over its own 25KB contract on this project's graph, while the test asserting that contract passes, because its fixture contains none of the entry kinds that feed the two framing lanes carrying no bound at all. The contract was set and asserted when the shell-composed door shipped at roughly 18.5KB (20260719-015148-s-tac-khq); nothing has re-measured it against a real graph since, and the growth that broke it is the ordinary accumulation of project content, not any change made to the shell.

**There is no single offender.** Framing is around three-fifths of the payload and the instructions about a third, and framing splits fairly evenly across its six lanes with none dominating. Inside the instructions the moves catalogue is the largest block at roughly two-fifths, eight near-identical descriptions of the available moves. Nothing here can be deleted for a cheap win.

**The mechanism is in the lane declarations.** The user-dialogue shell (20260704-100000-d-prc-dlg) declares six framing lanes, and only one — recent movement — carries a byte cap. Aspirations and guiding directives are capped by item count but not by bytes, so a graph whose summaries run long pays proportionally. `focus:brief` and `participants:brief` carry neither a count nor a byte cap, so they scale without limit — with the number of active focuses and their expanded involvement, and with team size. The working-principles lane renders `as-bodies` with no count and no cap, so each additional principles fact enters the door in full. Four of the six lanes are graph-derived: an adopting project busier than this one gets a proportionally larger door, and nothing stops it.

**Why the test cannot see this.** `TestDoorPayloadUnder25KB` builds a fixed synthetic fixture of sixty entries emitting only aspirations, guiding directives, and gap signals — no focus, actor, or role entries — so the two uncapped lanes render nothing. Those lanes are together about a fifth of the real payload, which is roughly the margin by which the fixture stays under the limit. Being fixed-size and synthetic, the fixture cannot observe the one mechanism that actually breached the contract: content growth in lanes it never populates. The test is not weakly written — it is structurally blind to the failure it exists to catch.

**And the measured quantity is one copy.** The contract counts the serve result, while the wire carries the payload twice (20260816-205521-s-tac-x9l). Whether that second copy costs model context is client-dependent and unproven, so it does not double the budget — but it does mean the number the contract asserts has never described what a client receives. The per-lane measurements behind this entry are in the record attached to that fact.

**Not Codex-specific.** The host budget recorded for that harness (20260719-122547-s-tac-40d) is what makes the overage bite there first, but a door whose size is a function of how much a project has thought about itself is wrong on any host.

**The candidate direction is push/pull.** Per Christopher: serve only the most important information, in a form that can be bounded by size — the door pushes pointers and instructions, and the agent pulls views over the graph on demand for whatever the dialogue actually turns to. Recorded as one idea rather than a commitment, but it is the same move already recorded for catch-up (20260719-124754-s-cpt-s37), which is why the two surfaces belong together — with the door the harder case, because it is what orients an agent that has pulled nothing yet and so must carry enough to make the first pull the right one. The moves catalogue is the clearest instance of the pointer shape: static text needed only when routing, reducible to names plus a line each with the full description pulled when a move is actually chosen.

**Byte caps are containment, not the answer.** Capping the unbounded lanes would restore the contract cheaply and remains available, but a cap truncates mid-content and the lanes differ in what that costs: a truncated list simply shows fewer entries, while the principles lane carries prose whose whole purpose is to install a thinking posture — cut mid-sentence it does not degrade gracefully, it arrives as an instruction that stops. Which content must be primed and which can be pulled is the question a cap postpones rather than settles.
