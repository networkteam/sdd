The `application` package is the single composition root of the SDD Go application: CLI and MCP are shells over it, and its exported surface speaks the existing CQRS vocabulary, taking command and query structs from `internal/command` and `internal/query` rather than growing a parallel method dialect.

The package was born as the engine and MCP host and quietly became a second composition root beside the CLI's direct wiring of handlers and finders: it constructs its own finders and injects the LLM runner, while `sdd lint` and `sdd new` built theirs raw. Two stacks composing the same lower layers drift apart, and knowledge that lives only in the application, such as per-query serving bounds declared at registration, is unreachable from CLI paths except through side doors. An exported resolver constructor was considered during the bounded-serves work (20260829-173342-d-tac-rzi) and rejected as exactly such a door; this directive is the structural answer. It extends the CQRS decomposition (20260413-142300-d-cpt-l3s) with the layer that decomposition left implicit: commands and queries need one place that composes their dependencies.

Two standing rules come with the promotion. Lint is an application query decomposed into categorized providers: each linter function owns a category (graph shape, index, connected repos, procedure runtime), findings carry category, code, severity, and entry, and advisory severity never flips the exit code. And a spec-authoring advisory is never an entry warning: warnings feed the graph-health framing block on every session opening, so an advisory authoring note would spend serve bytes on the very surface being bounded.

Lint stays a CLI and hosted surface rather than an agent tool: an agent dialogue cannot act on storage mechanics, and the one finding an agent can act on, budget overshoot while authoring a procedure, reaches it through capture pre-flight at the moment of authoring. Should grooming ever sweep lint findings, that arrives as a served engine query under host-neutrality, not as an agent-facing lint tool.
