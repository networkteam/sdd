The LLM boundary is rebuilt around one public contract in a new `pkg/llm` package: a one-method `Runner` interface over shared `Request`, `Result`, `Identity` and `Usage` types, replacing the mirrored port types in `application` whose hand-copied bridges silently dropped three fields in one day.

The defect this answers: `application/llm_port.go` mirrored the internal LLM types, and two hand-written bridges copied fields between them, one in the runtime adapter and one in the CLI shell, where the local path round-tripped an internal runner through the public executor and back. Usage metadata, then Model, then Variant each vanished silently, engine-mode only; the chain surfaced while working the engine-stats gap (20260811-234304-s-tac-ual). Inspection showed most port fields had no producer or consumer at all (OutputSchema, RequiredCapabilities, Routing, PromptDigest, IdempotencyKey, ExecutorFingerprint, FinishReason, a Capabilities method): surface designed for imagined hosts, not derived from observed flows.

The contract. `Runner` is one method, `Run(ctx, Request) (Result, error)`. `Request` carries `Purpose` (a closed enum: purposes are minted only by application operations, so hosts route on the constants and never invent values) and the two-part prompt; ctx carries request-scoped facts such as a tenant. `Result` reports what served the call: `Identity` (provider, model, variant) per call, never as a static property of an instance, because implementations may route. `Usage` is the common format for provider-reported consumption; an unreported field stays zero, never reconstructed. A failed call may attribute itself through a typed error carrying `Identity`. Routing lives entirely outside `application`: the injected instance resolves purpose and context to providers however it composes. Locally an internal factory builds a purpose mux with decorators from the host-private config; a hosted implementation can resolve per-tenant API keys from ctx. `model.LLMConfig` and the factory stay internal, because a config schema is each host's private concern, adapted to instances at its own composition site.

Ownership follows the composition-root directive (20260830-114446-d-cpt-xc3). `ProjectRuntimeOptions` takes one LLM dependency: the `Runner`. Everything that varies by configuration is the host's composition duty, never an application service: recording needs no fact the port data does not already carry, and a deadline is configuration that may vary by purpose exactly like the model, so observation and timeout both arrive already composed into the injected instance as decorators, while `application` contributes only the facts it alone holds, the `Purpose` and the prompts. Keeping a timeout option in `application` would split one host config across two consumers; instead the contract makes bounding a call the instance's duty, the local factory always composes the configured timeout, and a host that passes an unbounded runner gets a visible hang, never an invented default. The local host wraps the factory's runner in an internal observing decorator that writes the stats rows `sdd stats` reads (replacing the context-carried sink on the chat path); a hosted deployment observes with its own decorator and record shape. Recording is thereby a composition convention, not a framework guarantee, and the failure mode of skipping it is a visibly empty stats file, never silent corruption. The package split separates client machinery (`internal/llm`, with provider adapters, factory, and the observing decorator beneath it) from the LLM operations (`internal/llmops`: pre-flight, summarize, writing guide, with their prompts), which every host reuses through application operations, so nothing purpose-shaped needs publishing. New exported packages land under `pkg/`, keeping the repo root flat.

Two rules carried the design and keep applying. A port element is earned by an observed flow, never an imagined host: the interface carries only facts the instance alone holds, and everything reconstructible composes around instances instead of being served by `application`. And the test that the abstraction is right is that each hardening requirement simplifies the surface instead of growing it: per-purpose model selection deleted the static identity method, tenant-key routing deleted routing from `application`, host-owned observability deleted the stats hook, per-purpose deadlines deleted the timeout option, and the port ended at one method over pure data types with the runtime options at one field. The full type listing, requirement replays, parity check against current behavior, and the alternatives rejected are in the attached [architecture write-up](./30-234501-d-cpt-q6n/llm-boundary-architecture.md).
