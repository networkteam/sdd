The capture writing guide now sees what a draft closes or supersedes, and the specimen-sweep harness that proved it is banked in the repository — delivered in commits `9b5074b3` and `826abdc7`.

Each closure edge reaches the guide as its relation, target ID, kind, and the target's first summary sentence: enough to tell a delivery from a retirement, and deliberately short of the target's body, which would turn an isolated reading of the draft into a judgment of its neighborhood — the separate graph-fit check's job, not this one's. Two layers had to change and only one was the prompt: the capture step never copied the closure fields out of the procedure's collected state, so they would have been empty however well the prompt rendered. A model helper derives the descriptors, the query carries them so the read side stays graph-free, and the stranding axis now states that a target listed among the closure edges anchors mentions of it exactly as a ref does; without that sentence the data arrives and nothing tells the guide to use it. An unresolvable ID is described by ID alone rather than dropped, since the edge was still declared and blocking one is the write gate's business.

The evidence is one specimen and one three-run protocol, run before and after. Before, every run returned a substantive stranding finding against a retirement done that does anchor its target; after, that finding is gone entirely, two runs come back clean, and the third returns a single minor dilution — the shape dialogue had settled as this specimen's ground truth before the guide ever ran. What the runs confirm is the reading that predicted them: the finding measured what the guide is shown, not absent per-kind guidance (20260811-175406-s-cpt-b6g). `go vet`, the full test suite and `golangci-lint` are clean, with a table test over the descriptor derivation and a prompt assertion that the section carries its summary sentence and stays absent when a draft has no closure edges.

The harness earns a place in the tree rather than deletion after one use: it loads specimens from this repository's own graph, runs the live guide repeatedly over each, and logs every finding beside the ground truth while asserting nothing, because the judgment belongs to the dialogue. It is the instrument the remaining per-kind sweeps use, and carries a build tag so no ordinary build sees it — realizing an instrument the sweep method assumed without advancing its calibration path (20260811-141038-d-tac-rvu).

Only the architecture-independent half of the kind-knowledge gap is delivered here, so that gap stays open (20260811-183929-s-tac-fu8): the guide still has no framework floor and no per-kind checklist.
