Engine step serves duplicate static content across a connection: in one live session, four capture runs each received the capture procedure's full assemble and playback instruction text, the complete report schema arrived on every response, and the full topics table was served per capture — roughly 30–40KB of near-identical text whose cost lands permanently in the agent's context window, not in transport. Connection-keyed content-hash dedup already exists and stubs identical rendered blocks (20260705-010751-d-tac-dbk), but three duplication classes escape it:

- **Static step units, re-served per instance.** A procedure's instruction units are versioned with the procedure and cannot change within a connection, yet every new instance serves them in full: per-instance fragments woven into the rendered unit — the line naming this capture's anchor entry, the injected topic view — mean the rendered bytes are never identical across instances, so the hash never fires.
- **Report schemas, outside dedup entirely.** Every response repeats the procedure's full report schema, including fields irrelevant to the running capture's kind, although the schema is static per procedure version.
- **Injected views mixing volatile and static content.** The topics vocabulary serves all labels with counts and heat, where heat drift alone breaks byte identity between captures — and the numbers serve the composer, not the reading agent: choosing an existing label over minting a new one needs the label strings, with sort order carrying salience.

The direction the observations point: extend served-once stubbing from shell blocks to procedure units and schemas, at a granularity that separates volatile from static render parts so hashes can fire, and reduce the topics serve to plain label strings. This is the cross-serve duplication sibling of the single-serve size gap (20260719-122103-s-tac-jom): that one is about any one serve fitting a host's tool-output budget, this one about the sum of a connection's serves fitting the agent's context budget — with the stub-versus-context-loss trade-off and its escape hatch standing as settled there.
