A sub-agent dispatched from a session can move the outer dialogue's state and feed its evidence gate, where a delegate should leave the outer session untouched.

Observed 2026-08-26 by probe, in the dialogue that recorded the delegation gap (20260826-222535-s-cpt-dkv). A sub-agent shares its parent's MCP connection, so that connection is already attached to the parent's session. The delegate need not even be told the handle: an argument-less resume returned it the parent's live session, its handle, and every open instance with its pending chooser, including a capture sitting at playback with its collected draft. From there nothing on the surface distinguishes the delegate from the agent that dispatched it, so it can relabel the session, advance or park a move, confirm a capture into the graph, or conclude the dialogue. Its reads land in the outer session too: the read set the capture grounding gate evaluates is session-level by design, so that a dispatching parent's inspections count for the children it seeds, and a delegate's reads would satisfy that gate for entries the outer agent never saw.

The expectation, stated by the user in this dialogue, is isolation in both directions. A delegate's work leaves the outer session's procedure state exactly as it found it. Its reads are its own, because what has been inspected belongs to the agent context that did the inspecting, so a delegate can never stand in as the outer dialogue's evidence. And the argument-less resume handing an unnamed caller the outer session is itself part of what should not happen.

The session contract's consent guards do not reach this. Crossing into another dialogue requires the user's verbatim ask, and attaching to an actively driven one requires an explicit takeover flag (20260718-131626-d-cpt-9of, invariant I5), but both key on the transport connection, so neither fires for a delegate arriving on the connection that already holds the session. What those guards exist to prevent is on record: an uninvited driver relabelled a live session, abandoned an in-flight move for reasons belonging to another dialogue, and left duplicate sequence numbers in the append-only log (20260709-174818-s-cpt-c2i).
