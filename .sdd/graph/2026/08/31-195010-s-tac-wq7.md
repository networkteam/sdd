The LLM boundary rebuild (20260830-234501-d-cpt-q6n) and the pkg/ root move (20260831-092538-d-tac-zhc) are delivered on main in two commits: `babbb374` moves the exported packages (application, local, mcpapp, sddtest) under `pkg/` in the one-time import-path rewrite, package names kept; `7781bd89` rebuilds the boundary around the pkg/llm Runner contract.

The rebuild lands the settled design as written: pkg/llm carries the closed Purpose set, Request, Identity, Usage, Result, the one-method Runner with RunnerFunc, and the attributing Error. The application port mirror, both hand-written bridges, the functional executor adapter, the internal runner mirrors, and the stopgap (`4bcb6fbb`) that hand-carried the Identity Variant field across the old port's bridges are deleted — with Identity existing once, a dropped field is no longer representable. The operations move to internal/llmops, each stamping its Purpose into the request — the internal op string dies, ending the summary/summarize routing drift on the canonical value summarize. internal/llm keeps the machinery: the observing decorator, the timeout decorator, CallStat/StatsSink, and the embed plumbing, which stays on the context-carried sink. ProjectRuntimeOptions carries one LLM field; the factory always composes the configured timeout, and the per-op context deadlines in application, handlers, command, and query are deleted. The examples module reimplements the port at one method; sddtest's executor conformance suite is deleted with the port.

Deviations and judgment calls made in the doing: Request.Combined is carried onto the public type — single-payload transports need the flatten and the alternative was duplicating it per adapter. The factory's purpose mux is not built, because model.LLMConfig has no per-purpose section yet; the mux slots in when that config lands. The per-command timeout flags (--preflight-timeout, --timeout) survive by overlaying into the factory's config, so `sdd new`'s summary call now shares the command's single bound instead of its own fixed 60s.

Engine and CLI chat calls now flow through the same composed observed runner, and a new end-to-end test asserts failure rows keep attribution through the typed error — the mechanism behind the engine-recording gap (20260811-234304-s-tac-ual) is gone, but that gap stays open until capture-time recording is confirmed on a live engine session. The parse-failure classification gap (20260831-093815-s-tac-k7d) survives by design: the decorator still sits below the operations where parsing happens.
