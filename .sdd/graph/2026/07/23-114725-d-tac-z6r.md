The transient output coordinator gets an explicit coordinator-owned lifecycle — dormant, armed, live, done — with slog records routed by state, plus a declarative view-component layer and one shared TUI foundation, so the whole class of startup/teardown terminal corruption becomes structurally impossible instead of being patched per command. The root cause of the clone-path scroll (20260723-112802-s-tac-bnw) is pinned in bubbletea v2.0.7 source: the renderer's cell buffer is created at full terminal height and only shrinks on the first ticker-driven flush, while tea.Printf's insertAbove cursor-jumps past the buffer height — and no readiness hook exists; upstream acknowledges the fragility (#1666) and the fast-quit DEC mode-query leak (#1627) but ships no fix, so the remedy must be architectural on our side.

The lifecycle: the coordinator itself implements slog.Handler, installed once into the work context (the slog.SetDefault swap is removed — no global mutable logger state, no wrong-handler window; the routing moves, not the installation). Dormant, display-eligible records render plainly to stderr. Armed — a ~60-80ms debounce after the first display-worthy event — records buffer; work that finishes inside the window flushes plainly and never starts a bubbletea program, which kills the fast-path escape leak (20260709-161249-s-tac-bg7) and the footer flash structurally and retires the per-command willClone-style gating: the coordinator owns the start decision. Live, the model buffers durable lines until a first-paint gate (WindowSizeMsg plus a frame-margin tick), then commits them to scrollback via tea.Printf — eliminating the full-height scroll race. Ctrl-C becomes a coordinator-owned cancelled-by-user sentinel rather than a raw context-canceled matched exactly at the top of main. Done keeps today's fingers-crossed re-emit.

The component layer: commands declare views composed from reusable components (spinner+label, determinate bar, phase indicator, log stream); work reports typed phase events (connecting → syncing → indexing) through the existing reporter mailbox, and footer labels derive from the reported phase, never from a bare string at the call site — fixing the mislabeled text-only-search footer (20260709-152943-s-tac-jbm) by construction and finally realizing the reusable-styled-feedback and per-command-UX-design capabilities the terminal-experience architecture (20260628-131545-d-cpt-dgk) already commits to. Logs and progress stay two deliberate channels: slog is the durable narrative committed to terminal scrollback, the reporter is transient footer state — never route progress through log records or derive durable output from footer state. One TUI foundation unifies the coordinator and the six init prompt models behind a shared program runner and a single palette shared with the presenters.

Alternatives rejected: rendering log lines as model view state (inverts durability — the frame is transient and capped, terminal scrollback is the correct infinite durable store; the model is a staging area, not the destination); a writer-plus-mutex coordinator without bubbletea (defensible, but forfeits input handling and the teatest harness); forking bubbletea (the only hard fix of the root cause, rejected for the rebase-per-release maintenance surface — instead the one-line cellbuf fix is filed upstream while local buffering stays as defense-in-depth). Accepted trade-off: a display-eligible line may appear up to ~80ms late — imperceptible on stderr, the price of never starting a program for instant work. The stale alt-screen comment in the tui runner is corrected, and a teatest regression asserts no full-height cursor-down is ever emitted before the first frame.
