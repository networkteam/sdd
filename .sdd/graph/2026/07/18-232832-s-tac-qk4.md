Slice 3 of the session-model realization plan shipped in the session-model worktree (commits c80af3a, 4ae1ec6): the holder lease is deleted — TTL table, expiry, liveness flag, generation fencing, and the per-operation bind append are gone — replaced by an informational attachment stamp (subject, client, MCP session id, last activity) that rides each event append's metadata, with an attachment history whose causes form the closed six-value enum (disconnect, switch, shutdown, claim, conclude, abandon) threaded from the transport layer. Serves are pure reads (served events are no longer persisted); binding verification reduces to subject/project immutability, attachment identity, and version CAS; incumbent continuity holds by construction with a clock-free test; legacy session files with holder JSON load tolerantly under the unchanged codec version; session status is derived-only, verified by a kill-without-goodbye test; active/idle labels derive from stamp recency against the single 15-minute constant with injected clock, clamped against future skew. The review round surfaced and fixed a real regression the deletion introduced: a displaced writer's first advance was a phantom success because the engine's deferred sink stashed the typed ownership error — the engine now exposes the stashed error and every appending operation surfaces it synchronously on the same call, pinned by an immediate-typed-failure regression test with zero durable appends, re-verified adversarially across completing, non-completing, and chooser paths. Leave records the trigger cause always; release is idempotent for displaced teardowns; same-client re-attach skips the metadata append. go vet, go test ./..., and golangci-lint are clean on the worktree branch.
