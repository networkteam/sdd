Advertised the engine's already-present short-ID resolution on its read surface so agents resolve a pasted short ID through `show` rather than reading graph files off disk — closing the discoverability gap s-tac-4bq. Commit 69e9d8c.

Two changes landed, both minimal:
- `show`'s `ids` tool-schema description (internal/mcpserver/tools.go) now reads "entry IDs to show; accepts an unambiguous short ID ({type}-{layer}-{suffix}) and resolves it to the full entry." The resolver itself was already present via Graph.ResolveIDs — the same short-form resolution the CLI shipped in s-tac-mca — only undocumented on the MCP surface, so this builds on that finished work rather than adding capability.
- The dialogue-shell orientation (d-prc-dlg), revised in place per the base-procedure convention d-prc-25d, now tells the agent to resolve a short ID to its full form with `show` up front — reads are free — and never by reading graph files. That upholds the agent-agnostic foundations directive d-stg-dn6, since file paths don't exist for a remote or hosted graph.

Held to the scope confirmed in dialogue: no procedure branching, and the `/sdd` skill's separate "always use full IDs in CLI" rule was deliberately left untouched (a distinct determinism/collision concern; the new engine guidance duplicates no existing text, so no single-source drift). Verified clean on `go vet ./...`, full `go test ./...`, and `golangci-lint run ./...`; the rebuilt binary resolves a short ID via `show` to its full entry and serves the amended orientation. The gap is fully resolved — nothing left open.
