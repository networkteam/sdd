The public project-aware SDD application will ship through seven independently verifiable slices that preserve a working local server after every landing and culminate in one consumable shared runtime. This plan operationalizes the public API contract in 20260712-104530-d-tac-1mb as refined by the subsystem-shaped port directive 20260712-194427-d-tac-wjq; those two entries remain the normative architecture, while this plan defines implementation order, evidence, and closure.

Each slice is acted on through the implementation workflow and records its own commit-citing done signal against this plan. The final done signal closes this implementation plan and the parent public API plan once the full contract passes.

## Delivery slices

### Slice 1 — freeze parity and prove request identity

- Snapshot the existing MCP tool set, schemas, descriptions, core response shapes, served-once behavior, and a complete capture replay before moving boundaries.
- Build a real stateful Streamable HTTP test that changes scopes or sentinel metadata for the same MCP user across requests and proves the current values reach project resolution, an engine query, and mutation authorization; prove a changed user is rejected.
- Settle the narrow MCP-to-`RequestIdentity` bridge from that evidence. Authentication protocols, credential validation, roles, and policy remain outside SDD; initialization-time identity fallback is forbidden.

### Slice 2 — publish the contract without moving behavior

- Introduce the root `github.com/networkteam/sdd` package with public DTOs, opaque snapshots, typed errors, consolidated access and storage ports, separate embedding and search-index ports, and raw LLM execution.
- Introduce `github.com/networkteam/sdd/sddtest` conformance harnesses for every public port.
- Add `examples/extendingsdd` as a nested module with an external module path and a development `replace` to the repository root. It initially compiles fake port implementations against the root contract and is expanded to mount `mcpapp` when that package lands.
- Keep translations at the public boundary so internal packages never import the root package and no import cycle is opened.

### Slice 3 — converge local storage on the ports

- Implement the canonical `SnapshotData` and `EntryDocument` construction path, with filesystem loading delegating to it and a structured non-filesystem fixture proving no Markdown materialization or persistent host path is required.
- Adapt local filesystem graph authority, JSONL sessions, staged blobs, embedding execution, vector index, and LLM execution to the public contracts.
- Make `GraphStore` own snapshot reads, expected-revision apply, reconciliation, and canonical attachment paging. Replace file-shaped mutations with canonical document data plus SDD-rendered bytes.
- Run the same shipped conformance suites against every local adapter before any MCP extraction.

### Slice 4 — extract the protocol-neutral runtime

- Move free reads, rendering, procedure discovery, graph construction, authorization-aware dependency resolution, search semantics, engine orchestration, and typed results behind the root runtime.
- Keep SDD ownership of finders, handlers, commands, prompts, parsing, pre-flight, summaries, ranking, citations, and write-gate judgments.
- Route current request identity and operational context explicitly through every project-scoped operation; session bindings and cached runtimes never prove current access.
- Preserve existing local behavior through adapters while the internal MCP server continues to run.

### Slice 5 — make writes and sessions durable

- Implement storage-neutral prepared transitions and intent/apply/outcome across independently durable session and graph stores, including mutation ID/digest reconciliation and not-applied/applied/unknown outcomes.
- Keep every v1 codec and contract single-version and fail closed with typed migration-required errors for unsupported versions.
- Add optimistic session append plus exclusive holder metadata, history, typed session-in-use responses, explicit live takeover, recorded expired takeover, chooser-kind TTL defaults, and CAS fencing of displaced holders.
- Add failure-injection tests for stale graph revisions, orphaned intents, unknown apply outcomes, finalizer retries, staged-blob retention, concurrent advances, holder expiry, and takeover before exposing this behavior publicly.

### Slice 6 — extract the shared MCP application

- Move the existing MCP tool registration and transport surface into public `mcpapp` without duplicating schemas, procedures, instructions, engine transitions, or write gates.
- Make `cmd/sdd/serve.go` a thin local composition over root `sdd` and `mcpapp`; static bearer authentication remains in that local composition.
- Expand `examples/extendingsdd` to mount the shared Streamable HTTP handler behind external middleware and run it explicitly in CI, since root `go test ./...` does not enter nested modules.
- Prove stdio and HTTP parity against the Slice 1 snapshots.

### Slice 7 — prove multi-project composition and release

- Exercise at least two principals, two base projects, one connected dependency, differing read/write access, immutable project bindings, current-access loss, read-only dialogue, authorization-safe cross-project reads, local alias promotion, and ProjectRef results.
- Prove external mounting, session start/resume, every free read, capture through the write gate, reconciliation after failure, and holder takeover.
- Complete package documentation, the external composition example, unit and integration tests, lint, local stdio/HTTP smoke tests, and a release smoke from a temporary external module without a local `replace`.
- Publish a consumable version and record the final done signal closing both this plan and 20260712-104530-d-tac-1mb.

The order deliberately proves the SDK identity seam before stabilizing public types, proves local adapters before moving application behavior, and makes durable session/write semantics real before `mcpapp` becomes public. This avoids publishing temporary ports or a public transport facade whose persistence guarantees immediately change.

## Acceptance criteria

- [ ] Existing MCP tools, schemas, descriptions, response shapes, served-once behavior, and complete capture replay are characterized before extraction and remain compatible afterward.
- [ ] Stateful HTTP tests prove current per-request identity reaches project resolution, engine reads, and mutation authorization; a changed MCP user is rejected and initialization-time identity is never reused.
- [ ] The root package exposes no MCP SDK or internal types, internal packages do not import the root package, and `mcpapp` is the only MCP-specific public package.
- [ ] Public ports match the subsystem-shaped contract in 20260712-194427-d-tac-wjq, with `EmbeddingExecutor` and `SearchIndexStore` remaining separate.
- [ ] Every public port has a reusable `sddtest` conformance suite and every shipped adapter passes its applicable suite.
- [ ] Filesystem and structured stores converge through one canonical document-to-snapshot path, and mutation batches support both structured persistence and byte-verbatim filesystem/Git persistence.
- [ ] The root runtime owns all SDD read, search, procedure, rendering, pre-flight, summary, mutation, recovery, and write-gate semantics; external compositions supply infrastructure and authorization only.
- [ ] Every project-scoped operation resolves current access, every mutation separately resolves write access, and connected dependencies are independently authorized without leaking unknown-versus-denied distinctions.
- [ ] Session persistence uses optimistic append, pinned single-version material, fail-closed unsupported versions, exclusive holders, chooser-kind TTL defaults, visible liveness, explicit live takeover, and CAS fencing.
- [ ] Every mutation uses durable intent/apply/outcome with storage-neutral prepared data, idempotent ID/digest reconciliation, atomic canonical apply, distinct finalizer outcomes, and retained staged attachments through unresolved outcomes.
- [ ] Public `mcpapp` and local `sdd serve` use exactly one tool registration, procedure, served-knowledge, engine-transition, read, and write-gate implementation.
- [ ] `examples/extendingsdd` uses an external module path, compiles fake adapters, mounts the shared HTTP application, and runs explicitly in CI without relying on internal packages.
- [ ] Multi-project tests cover routing, immutable bindings, ProjectRef compatibility, local alias promotion, read-only use, current-access loss, authorized cross-repository reads, recovery, and holder takeover.
- [ ] Existing local tool names and non-project arguments remain valid, and local human-readable results remain byte-for-byte stable except for explicit project reorientation or error cases.
- [ ] Package documentation, example composition, full tests, vet, lint, stdio/HTTP smoke tests, and a temporary external-module release smoke pass.
- [ ] Each slice lands with a commit-citing done signal against this plan; the final done closes this plan and 20260712-104530-d-tac-1mb only after every criterion above and the amended parent contract pass.
