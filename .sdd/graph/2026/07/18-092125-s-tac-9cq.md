The view-layout base fact is harder to scan and less useful than the implementation-backed CLI help because it renders a dense terminal-style reference without Markdown structure or representative examples. The real-agent outer evaluation (s-tac-3cq) exposed the difference directly: the fact (s-prc-vwg) contains the necessary vocabulary, but `sdd view --help` made the same language easier to understand through a clearer hierarchy and examples such as participant filtering. The CLI-help implementation record (s-tac-its) explains the source of the mismatch: its shared host-neutral `ReferenceBody` carries grammar and vocabulary, while the CLI-only `Reference` adds usage and examples; the base fact currently receives only the former. The reference should retain host neutrality while rendering as native Markdown — headings for sections, fenced blocks for grammar and complete layouts, structured tables or lists for function descriptions, and representative host-neutral layout examples rather than CLI commands.
