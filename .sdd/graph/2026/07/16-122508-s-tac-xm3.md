Commit 270cfe9 removes the lazy-dimension spec failure that rejected every MCP phrase search before embedding began, closing the dimension-gate defect in s-tac-szl without weakening vector compatibility checks. The public EmbeddingSpec and index namespace now identify the model by fingerprint alone, so the Ollama adapter can make its first real embed call before dimensions are known; document batches reject empty or internally inconsistent vectors, and the index store rejects query vectors whose length differs from stored vectors. A regression test drives two phrase searches through a no-dimensions-before-first-response executor, while the adapted conformance fixtures preserve the subsystem-shaped boundary in d-tac-wjq: EmbeddingExecutor and SearchIndexStore stay separate and SDD enforces compatibility where vectors meet. Focused application/local tests, real loopback `cmd/sdd` server coverage, the external example module, `go vet ./...`, `go test ./...`, and `golangci-lint run ./...` pass. Live validation after restarting the MCP server confirms the invalid-spec gate is gone: the call proceeds into graph embedding. End-to-end MCP phrase search is still unusable on a cold server because s-tac-ex4 rebuilds the entire graph in process—minutes on this graph and potentially more than 30 minutes on a large graph—so that separate release regression remains open and release-blocking.
