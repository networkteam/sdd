The SDD documentation site will be built on Astro Starlight with the starlight-theme-nova theme and the @wave-rf/starlight-llm-tools plugin, published to GitHub Pages from markdown/MDX sources in this repo. This settles the tooling question the user-documentation gap (20260715-172002-s-cpt-i5a) deferred, judged against five candidates on open-source status, agent-native affordances (llms.txt manifests, per-page raw markdown, copy-as-markdown), GitHub Pages publishing weight, in-repo agent-writable sources, looks, and dependency surface — full comparison in the attached research record. Starlight wins on fit: static-first and framework-agnostic (this Go repo has no JS-framework allegiance to serve), plain MD/MDX content files with simple frontmatter that agents write naturally, an official deploy action for GitHub Pages, and a plugin ecosystem that includes a core-maintainer llms.txt plugin as fallback. Rejected: VitePress (lightest surface and its llms plugin is proven on Vue/Vite/Vitest's own docs, but no MDX and a stock look locked to the Vue-docs identity), Fumadocs (most modern aesthetic and the only built-in AI feature set, but Next.js/React is the heaviest dependency surface for this repo and its per-page markdown endpoints need extra wiring under static export), Docusaurus (versioning and plugin depth are not v1 needs; dated look), MkDocs Material (Python toolchain; MkDocs core maintenance question marks in 2026). The theme is Christopher's appearance pick from live demos: starlight-theme-nova (Tailwind-aware, cascade layers for predictable style overrides). The agent layer is @wave-rf/starlight-llm-tools — per-page .md twins with navigation headers, llms.txt/llms-full.txt/llms-small.txt per llmstxt.org, and Copy-Markdown plus open-in-AI buttons (MIT; requires Astro ≥5.0, Starlight ≥0.36). Known risk, accepted: that plugin is young (v0.3.1, June 2026, minimal adoption) — it is thin and replaceable by starlight-llms-txt (core-maintainer-owned) plus starlight-copy-button if it stalls. Maintenance surface opened: an npm/Astro toolchain alongside the Go toolchain, all dependencies MIT and vendorable, publishing in CI via the official action with no hosted service. Site scaffold, deploy pipeline, and the v1 information architecture follow as separate work.
