Local engine mutations will pin a concrete project-and-branch target in durable intent and route every write through one engine-owned apply-and-recovery path, so implementation captures follow the fate of their explicitly chosen Git branch without cwd authority or automatic replay. This tactical plan refines the explicit mutation-authority directive in 20260713-214050-d-cpt-65i and makes the base/work lifecycle in 20260713-214251-d-prc-pop implementable across in-place, same-directory branch, and worktree modes.

The durable transition gains a non-empty `MutationTarget{Project, Branch}`; the first delivery fixes project to the session project, resolves ordinary default branches before persistence, and requires the agent to supply implementation `baseBranch` and `workBranch`. Capture dispatch explicitly seeds `captureBranch <- workBranch`, following the explicit junction-seeding result in 20260706-093531-s-tac-xeq. WIP mutations target base, while implementation captures and the closing done target work. The session home project stays fixed, and cwd is at most a locator suggestion.

Handlers submit deterministic prepared facts to the shared engine and never operate a resolved target runtime. The engine briefly acquires the target for its snapshot, releases it before preflight or LLM work, persists structured documents plus canonical bytes, expected graph revision, batch identity, and `BlobOwner`/`BlobIDs`, then reacquires for structured revalidation, CAS apply, durable outcome, target-scoped finalization, and cleanup. This extends the durable intent/apply/outcome and staged-blob foundation in 20260712-104530-d-tac-1mb while preserving the storage-neutral, expected-revision-only `GraphStore` contract required by 20260712-194427-d-tac-wjq.

The local acquisition adapter validates the supplied branch, exact-matches it through `git worktree list --porcelain -z`, requires exactly one registered checkout, rechecks symbolic HEAD, loads that checkout's SDD configuration, and runs graph and Git finalizer operations against its explicit path. Checkout paths are rediscovered rather than persisted. Missing, ambiguous, detached, changed, or invalid targets fail loudly while durable workflow or recovery state remains. SDD does not create, switch, merge, or remove branches or worktrees.

Pending intents never replay automatically. A free read projection distinguishes outcome-unknown, not-applied-awaiting-decision, applied-finalization-pending, discarded, abandoned-unknown, and fully recovered states. Explicit recovery freshly resolves a distinct authorization request containing current actor, target, verb, and original owner/session, then reconciles batch ID and digest before any action. Apply reruns revalidation and CAS only after definitively not-applied; discard is then an audited terminal; finalize-retry handles applied mutations; abandon-unknown follows recorded failed acquisition or non-definitive reconciliation without claiming not-applied; and legacy version-1 intents require an authorized audited bind-target verb rather than inferred authority. Original ownership remains provenance, runtime wiring owns self/cross-principal policy, and every terminal records both actors.

An interactive local recovery command works without a live agent or workflow session. Actionable states appear in orientation, catch-up, and view through host-neutral served language; closed abandon-unknown records leave all action lanes immediately but remain in explicit audit history. Runtime recovery never creates graph entries automatically. The retained abandoned batch entry IDs preserve the input for a later event-driven grooming lens, without including that lens in this delivery.

The detailed contract, delivery slices, and verification matrix are attached. Remote connected writes remain outside scope under 20260713-214523-d-cpt-n8z, and logical non-Git fork/merge/abandon remains the separate future gap 20260715-113417-s-cpt-vxd; this delivery keeps their extension seams open without exposing unsupported capabilities.

## Acceptance criteria

- [ ] Every persisted mutation intent contains a session-project target and a concrete non-empty branch; defaults are resolved before persistence and cwd never selects authority.
- [ ] All application write paths use the engine-owned apply seam; acquisition is internal, short-lived, never spans preflight or LLM work, and releases on every path.
- [ ] Prepared mutations retain structured documents, canonical bytes, expected graph revision, batch identity, and home-staging blob references sufficient for deterministic revalidation and cross-branch attachment materialization.
- [ ] The local adapter exact-matches one registered worktree checkout, revalidates HEAD, constructs target-scoped graph/finalizer adapters, uses directory-bound Git operations, and fails loudly for every invalid or ambiguous case.
- [ ] Implementation workflow state persists explicit base/work branches, explicitly seeds capture branch, and routes WIP to base plus captures/done to work in in-place, same-directory, and worktree modes.
- [ ] No startup, resume, read surface, or unrelated mutation automatically replays a prepared intent.
- [ ] Durable recovery queries derive all six states and preserve the applied-versus-finalization-pending distinction across restart.
- [ ] Recovery authorization receives current actor, original owner/session, concrete target, and a distinct apply, discard, finalize-retry, abandon-unknown, or bind-target verb; engine invariants remain independent of resolver policy.
- [ ] Reconciliation precedes every recovery verb; applied forbids discard, not-applied apply reruns structured validation and CAS, and abandon-unknown requires recorded non-definitive evidence while retaining an unknown historical outcome.
- [ ] Discard, abandon-unknown, finalizer completion, and legacy target binding append immutable dual-attribution audit events and release staged blobs only when their durable state permits it.
- [ ] The local recovery CLI supports interactive actionable recovery and closed-history inspection without a live MCP/workflow session; served orientation, catch-up, and view notices remain host-neutral and show action only.
- [ ] `GraphStore` remains unchanged, no recovery path automatically captures a graph entry, remote write/branch capabilities remain unavailable, and the deferred grooming lens has the retained entry identities it will need.
- [ ] Application, local Git adapter, workflow, CLI, presenter, attachment, authorization, serialization, and crash-window tests cover the attached verification matrix; formatting, tests, vet, lint, and rendered-skill validation are clean where applicable.
