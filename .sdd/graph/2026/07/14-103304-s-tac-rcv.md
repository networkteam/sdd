The v0.16 session-store cutover lets any legacy JSONL session prevent all >=0.16 session listing and startup, so a user upgrading with historical sessions cannot enter the engine to recover. This was reproduced live: both session startup and session listing failed on an old, valid, already-abandoned session with `non-sequential version 0 at line 1`, while the server's free info read remained healthy.

Inspection found 52 persisted session logs: 51 used the earlier event shape with `v`, `seq`, and `event`; one used the current session-store envelope with `version`, `metadata`, and `events`. The current filesystem store attempts to load every JSONL file as the new envelope. A legacy line therefore decodes with an absent envelope version as zero, fails the line-one version check, and aborts the entire listing. Startup depends on that listing, so a single incompatible historical record prevents creating an unrelated fresh session. Moving the 51 legacy logs intact to a separate archive immediately restored startup, proving format coexistence—not malformed legacy data—caused the outage.

The compatibility failure spans more than the first upgrade. A pre-0.16 server can continue creating legacy logs after a >=0.16 server starts, so a one-time clean directory assumption can be invalidated later. The old reader is naturally fail-closed in the other direction: it silently derives no resumable work from a current envelope during listing and rejects an explicit replay because the decoded event version is zero. A >=0.16 reader therefore needs the symmetric ability to recognize and ignore legacy records during ordinary operation. Automatically rewriting them at read time would be unsafe because a still-running pre-0.16 process does not honor the new session-holder locks and may retain an open file descriptor.

The engine event payload format itself did not change between v0.15 and v0.16, so an explicit migration can wrap legacy events without losing their dialogue trajectory. Migration must also account for legacy per-session staging directories and attachment handles; converting only JSONL records could make a parked capture resumable while silently dropping its staged evidence.

This is the concrete second session format whose migration work was deferred by 20260712-194427-d-tac-wjq, and it was surfaced by the released application recorded in 20260714-095002-s-tac-4oj. The graph read-compatibility contract in 20260602-203349-d-cpt-i2x formally governs immutable graph entries rather than session state, but its requirement that format changes ship with a conversion path highlights the missing equivalent for durable session records.

The missing product behavior has two boundaries: ordinary >=0.16 runtime reads must ignore legacy or corrupt legacy sessions so healthy work and fresh startup continue, while an explicit user-confirmed migration path must process all legacy sessions independently. A failed legacy record must remain untouched, report its filesystem path, allow the remaining sessions to migrate, and make the overall migration exit non-zero so partial failure is visible and retryable. The attached live evidence preserves the exact failure, format comparison, causal code path, and successful non-destructive workaround.
