Graph reading in sdd follows one architecture: sources own their encoding, a single shared GraphFinder owns what the graph means, all read queries are pure intent, and load problems are data the finder serves — never a reason reading dies. The concepts, as realized by the graph-loading unification (20260723-113402-s-tac-g4v): a DocumentSource supplies storage-neutral documents — either raw canonical content or structured frontmatter plus body, mirroring the public DocumentChange union — together with unreadable-document issues for content the source could not decode; a filesystem walk, the snapshot document set behind the public GraphStore, or a future database each map their own storage format, and none knows what a ref or an index block means. The GraphFinder is the single semantic gate: it turns documents into typed entries through one validation path, records per-document failures as LoadIssues instead of aborting, merges embedded base entries, holds the resulting model graph and WIP markers, and executes read queries that carry only intent — no Graph, WIPMarkers, or GraphDir fields ride in query structs. Load errors and entry warnings surface through one health channel consumed by every surface: sdd lint, the session opening serve's graph-health block, and — via the additive public Snapshot.Health — any hosting implementation's own UI. The public API keeps local/remote parity: GraphStore remains the storage authority a hosted sdd implements, and this architecture changed it only additively. Two deliberate carve-outs bound the partial-read policy: embedded base entries stay build-time strict (a malformed embedded entry is a broken build, failing every load as a unit), and WIP-marker strictness is an explicitly open policy question, not covered by this directive. A full hard error on malformed content was rejected because hand-editable markdown is the graph's design surface — one bad file must never take down sessions or the CLI; strict rejection stays at the write paths, where invalid input can still be refused loudly.
