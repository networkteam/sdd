SDD files configuration and state by convenience of the moment rather than by whose fact each is, which is the single root behind the cross-repo evaluation's config, connections, and index findings. Two faces of the same error. First, config sits in the wrong layer in both directions: user/machine preferences — participant, llm, embedding — are trapped per-repo-local when they belong user-global (the config finding, 20260708-153545-s-cpt-m4j), while a repository's dependencies — which repos its graph references — are trapped per-machine-global when they belong committed per-repo (the connections finding, 20260708-164349-s-cpt-9ql). Second, per-machine derived state — the config.local overlay and the search index — is kept inside the working tree, which forces a harness-specific copy hack (.worktreeinclude, a Claude-Code-only mechanism) to share it across worktrees, at odds with the agent-agnostic foundation (20260628-123931-d-stg-dn6); moving that state out of the tree removes the dependency (the index finding, 20260708-164528-s-tac-eql). The unifying rule the findings converge on: place each kind of fact by what it is about — user/machine preferences go user-global; repository identity and dependencies go committed per-repo; per-machine derived state (the index) goes to a machine-global cache, never inside the working tree; the local overlay is reserved for genuinely machine-specific overrides. Getting the home right for each kind dissolves the config, connections, and index findings together and drops the harness copy hacks as a side effect — which is why they are better treated as one design thread than three.
