Slice 4 of the public project-aware application plan shipped in commit 9598a01, placing protocol-neutral read behavior behind the public root runtime while keeping the existing MCP server operational. The new Application owns current-access resolution for every call, project inference, info, show, view including WIP markers, text/vector/hybrid search, procedure discovery, attachment paging, and authorized connected-dependency reads; denied and unknown dependency lookups deliberately share a non-leaking error shape.

Canonical snapshots now carry storage-neutral WIP documents, and vector reconciliation validates embedding fingerprints and dimensions while rejecting stale indexed hits. Authorized dependency runtimes preserve their own graph and attachment authority rather than reducing them to snapshots. Repository tests, vet, and the nested external-module compile tests pass.

One small sequencing adjustment was made within 20260712-234500-d-tac-x1m: engine session orchestration remains in the internal MCP implementation until Slice 5 supplies durable write/session semantics and Slice 6 extracts the single public MCP registration. Moving it now would require a temporary duplicate session registry and undermine the plan’s one-runtime invariant. Slice 4 therefore completes the protocol-neutral free-read and search boundary; durable engine transitions remain next in Slice 5.
