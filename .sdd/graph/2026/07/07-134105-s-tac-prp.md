The groom procedure (20260706-171500-d-prc-grm) instructs the agent to remove a stale WIP marker via the `sdd wip done <marker-id>` CLI command — but the engine already exposes a `wipDone` command that removes a marker by arbitrary ID through the handler's `FinishWIP`, used today by the implementation procedure's closeout (20260706-170000-d-prc-imp). A served CLI instruction is unreachable whenever the graph is not mounted locally, so grooming an orphaned marker is impossible for a remote or hosted agent. The fix is spec-only (no new command): groom declares `wipMarker` in its state block and adds a `removeMarker` option on the walk step that collects the stale ID into `wipMarker` and calls the existing `wipDone` as its transition — mirroring how the setup step calls `wipStart`. The store's report trust boundary already permits this: `wipDone` reads the `wipMarker` slot whether `wipStart` (engine-written) or a report (state-declared) filled it.
