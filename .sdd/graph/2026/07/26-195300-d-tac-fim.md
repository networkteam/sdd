Bootstrap parity completion will preserve the adaptive orientation flow that already works while repairing identity composition and topic founding, then use a fresh live evaluation to decide legacy-skill retirement. This plan supersedes the original adaptive-bootstrap plan (20260718-222157-d-tac-k46) because its implementation has shipped and passed inner verification (20260722-084742-s-tac-3gl), while the subsequent greenfield and brownfield outer evaluation established a narrower, evidence-backed remainder (20260722-140955-s-tac-lgc). The state-machine and handoff behaviors remain explicit regression contracts; journalist posture, brownfield usefulness, and meaning-level recognition remain served-unit and live-evaluation criteria rather than being treated as mechanically provable.

Full type capture is the prerequisite, not duplicated bootstrap work. This plan depends on the full type-capture plan (20260726-193730-d-tac-zrh) for complete kind guidance, central draft validation, annotation capture, relevant diagnostics, and live-head resolution. Bootstrap composes those shared mechanisms through its procedure (20260719-140000-d-prc-bst); it does not reproduce required-field rules or kind prose in its own expressions and instruction units.

Identity dialogue keeps the established frame-before-self-description order (20260505-121556-d-prc-cgc) but restores the useful early attribution check from the legacy behavior. Project framing remains the first substantive conversation. Immediately before the first graph materialization, bootstrap lightly confirms the configured participant's canonical name; this is attribution, not the full actor interview. Zero-active-actor grace mode permits early framing captures without fabricating an actor. When the actor/role lens later opens, bootstrap resolves current actor heads and aliases from the graph and reuses an existing canonical. If no matching actor exists, it confirms canonical, aliases, and external identity or background, captures that actor first, then captures the role separately as the participant's stable contribution, authority, or domain weight in this project—not current tasks or a single sprint. The role binds to the active actor head.

The actor validator finding is handled regression-first rather than assuming the pre-merge observation still describes current code. Add the exact workflow from the evaluation gap (20260722-141835-s-tac-tom): capture an actor, supersede it with the same canonical, then capture a role referencing the new active head. If current shared validation passes, the test supplies evidence to close the gap without a code change; if it fails, repair the shared mechanical validator, never a bootstrap-specific exception.

Topic founding becomes user-approved and retroactive through annotation. Existing settled labels may still be reused inline, but newly proposed labels are withheld while the first cluster is captured; on an empty graph the founding entries therefore carry no new subject topics. After child capture IDs are known, a pure query/finder path loads their current live entries together with the existing topic vocabulary so the proposal is based on graph state rather than agent reconstruction. Bootstrap then presents a nested vocabulary and explicit label-to-founding-entry assignment map at a user chooser. The user may accept or reshape it. Only after acceptance does bootstrap dispatch one or more annotation captures referencing the founding IDs and carrying structured annotation-topic assignments. One coherent annotation is the default, not an exactly-one invariant; served guidance permits a split when it preserves meaning better. Later captures reuse the settled labels inline. This directly addresses the provisional-topic and missing-signoff gap (20260722-141942-s-cpt-ksz) without rewriting immutable founding entries.

The final slice is live parity evaluation, not an implementation assertion. Repeat the outer lens on an empty greenfield graph and a sparse brownfield repository. Confirm that the strengths from the prior run still hold; canonical attribution is confirmed without front-loading self-description; actor and role captures no longer require restarts, fabricated fields, or avoidable overrides; topic signoff is structurally user-owned and its accepted assignments actually apply to the founding entries; and catch-up receives a coherent foundation. The bundled and installed `/sdd` and `sdd-bootstrap` skill prose remains unchanged during this plan under the engine-primary transition decision (20260715-175731-d-cpt-p3k). A positive parity verdict records and triggers retirement; a negative verdict keeps the legacy surface and captures the remaining differences explicitly.

## Acceptance criteria

- [ ] The full type-capture plan (20260726-193730-d-tac-zrh) is completed before bootstrap parity implementation relies on its kind lanes, validator, annotation path, carried guidance, or live-head reads.
- [ ] Bootstrap state-machine regressions cover readiness injection; cold and brownfield routing; proposal accept, reshape, and defer; parented materialization with grounding and recognition seeding; dependency-ordered produced-ID reuse; cold resume; multiple clusters and repeated runs; refresh; and catch-up handoff. Tests change only where this plan deliberately replaces identity or topic-founding behavior.
- [ ] Served-unit tests preserve one-question journalist guidance, host-side repository inspection, meaning-level cluster playback, and recognition-mode handoff; the final live evaluation judges whether these still feel coherent in use.
- [ ] Project framing remains before self-description, while the configured participant's canonical name is explicitly and lightly confirmed immediately before the first graph materialization.
- [ ] With zero active actors, early framing capture uses the existing participant-canonical grace behavior; bootstrap does not invent aliases, identity prose, or a role merely to satisfy attribution.
- [ ] Opening the actor/role lens resolves active actor heads and aliases first, reuses an existing canonical when available, and otherwise captures canonical, aliases, and external identity as an actor before capturing a role.
- [ ] Role capture is separate from actor identity, describes the participant's stable project contribution rather than current tasks, and binds to the current active actor head.
- [ ] A workflow regression captures an actor, supersedes it with the same canonical, and captures a role against the new head without canonical-reuse or stale-head findings; only a failing regression authorizes a shared-validator fix.
- [ ] Existing stable topics may be reused inline, but newly proposed labels are withheld from founding captures until the landscape is accepted; an empty graph's first cluster carries no provisional subject topics.
- [ ] A pure query/finder path resolves the produced founding IDs to their live entries and returns the existing topic context used to construct and validate the proposed vocabulary and assignment map.
- [ ] Topic founding is a user chooser that presents a nested vocabulary plus explicit label-to-entry assignments and supports reshape before acceptance; an agent chooser cannot finalize it unilaterally.
- [ ] Acceptance dispatches one or more annotation capture moves over the founding IDs, with one coherent annotation as the default and splitting allowed when served grouping guidance justifies it; subsequent captures reuse the accepted labels inline.
- [ ] Greenfield and brownfield live outer evaluations demonstrate the retained strengths, corrected identity flow, relevant-only guidance, applied topic assignments, and coherent catch-up handoff.
- [ ] No bundled or installed legacy skill prose changes during implementation; the final evaluation records either a parity-backed retirement verdict or explicit remaining gaps while retaining the legacy surface.
