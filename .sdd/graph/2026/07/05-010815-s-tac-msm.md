The search surface should unify with the view pipeline: retrieval results rendered through the same layout vocabulary — brief lines, render terminators, filters, caps — instead of search's bespoke output format, with search acting as a source in the pipeline so one call can combine multiple probes into a single fused, de-duplicated, layout-controlled result. This widens the multi-probe search gap (20260702-204144-s-tac-4hh) in place: that entry records the N-probes-with-dedup half, while this adds the layout-unification half surfaced while deciding the drill-serve defaults — where search responses being model context makes size- and shape-control through the existing layout options the natural mechanism rather than search-specific flags.
