SDD's workflow engine is a move-instance runtime in the Go core — not an agent and not a session-owning controller. Playbook moves are declarative specs: small state graphs whose steps declare goal templates, evidence schemas, tiered checks, and named transitions, each typed by chooser — gate (taken on deterministic evidence checks), agent (a visible junction picked with rationale), or user (a handoff only the human's reply can exit, making dialogue-presence structural per s-cpt-p6f). Instructions, gates, and the junction map derive from the one spec, so guide and gate cannot drift; core specs ship in the binary as the single source (d-cpt-chi) that also renders today's skills, while project moves and rules extend from the graph, rules attaching binding or advisory constraints at move steps (d-tac-eho).

The engine drives move instances, never the conversation: the driving agent opens parallel instances behind handles (start, report, amend, abandon), the weave between them stays conversational, and activities without multi-turn state, gates, or writes are served as queries — data plus just-in-time guidance in one response, catch-up included (opt-in, with an ultralight delta at session open). The session root is itself a shell spec chosen by posture: interactive shells run open → workspace → close, with a goal-free workspace hosting the instances and a close gate deriving "anything uncaptured?" from held state; autonomous shells (intake, d-cpt-fbi) are corridors without user-chooser states, deferring dialogue to grooming. Enforcement follows surface ownership (s-cpt-1dz) and error cost: graph writes happen only as terminal effects of completed capture-family moves, while everything else is economically biased rather than policed (s-cpt-86s) — pre-fetched data makes discipline the cheapest path, evidence schemas demand what only the work yields, interview-style moves generate dialogue evidence by construction (s-cpt-qs2), and an engine-held read log turns grounding claims into deterministic lookups. The one LLM role is the judge at marked transitions — pre-flight, in-process per the Go verdict (d-cpt-8k5) — advisory unless graph-anchored.

This realizes the workflow-specialist direction (s-cpt-r57) with the spike's validated loop mechanics (s-tac-du6) and supersedes the two-phase MCP staging (d-cpt-313): the engine ships MCP-first into Claude Code — the dogfooding driver and the strictest guest-surface test — with Claude Desktop as the near-free second client and the hosted webapp (d-stg-6za) as a later in-process adapter over the identical engine. Deliberately open: the generic evidence-field form per surface (s-cpt-li1) is the first question the build answers empirically, and weave quality remains the host agent's ceiling — the engine guarantees the floor, never the conversation.
