This plan makes worktree-based dialogue sessions seamless by giving every session an explicit, declared branch binding and moving session storage into a machine-global per-project store, resolving the two sibling launch-context gaps (20260719-124038-s-tac-cwx, 20260719-133247-s-tac-c37) in one design pass. The two mechanisms are orthogonal: store locality decides where sessions are found; the branch binding decides which live checkout a session's captures and reads resolve against. The full spec — grounded in a code exploration with file-level citations — is attached; the committed working copy lives at docs/session-branch-binding-and-store-locality.md.

Branch binding: a dedicated `bind_branch` MCP tool sets or clears a session-level binding persisted in SessionMetadata via CAS append with typed events. Christopher explicitly rejected automated enter/leave coupling — the agent does the real worktree lifting, so procedures instruct the agent to declare; a procedure transition cannot own state that must outlive the procedure, and parameters on existing tools would conflate transport attach with a host-fact declaration. A session then has one effective branch — the binding when set, else the configured default branch — targeted by ordinary captures and session reads (procedure serves, ref validation, and attached free reads; vector search composes because the index reconciles against any snapshot). Explicitly seeded `captureBranch` still overrides; `baseBranch`/`workBranch` stay explicit with no default at all, and the currently silent default-branch fallthrough on an empty `baseBranch` WIP write becomes a loud error. This is the single deliberate revision of the ordinary-capture default clause of the explicit-mutation-authority directive (20260713-214050-d-cpt-65i): its never-ambient rule stays intact because every binding change is an explicit, session-logged, drift-validated event — declare-time and write-time resolution against exactly one registered checkout fails loud on every drift scenario the launch-context analysis enumerated (20260713-121507-s-prc-akz). Per the handover-fidelity invariant (20260719-124405-d-cpt-0tm), the binding projects into resume/door serves and session listings so a resuming agent never captures into a branch it does not know about.

Store locality: sessions and staged blobs move to a machine-global per-project store keyed by repo identity like the vector index, extending the placement directive's whose-fact rule (20260708-184318-d-cpt-6cq) — but deliberately under the XDG state root rather than the cache root, because sessions are not derivable and cache is deletable by contract. Identity-less repos key via the Git common dir, fixing the per-worktree key divergence for the index too (accepted one-time re-embed, no re-key migration). Migration runs on `sdd init` only, move-if-absent, never clobbering; `sdd serve` never refuses to start over leftovers — a failed MCP startup is invisible to the user — and instead serves a standing relocation notice in door, listing, and info responses. Everything store-related stays in the local composition; hosted deployments see only the optional metadata field, inert.

## Acceptance criteria

- [ ] Store locality: sessions and staged blobs live under the machine-global XDG state root keyed by stable repo identity (Git common dir for identity-less repos, index keying fixed the same way); `sdd init` relocates in-tree stores move-if-absent; `sdd serve` starts despite leftovers and serves a standing relocation notice in door, listing, and info responses; `list_sessions`/`resume_session` from a worktree see sessions created at the base.
- [ ] Binding core: `bind_branch` sets/clears the session binding persisted in SessionMetadata with typed events, validates at declare time that the branch resolves to exactly one registered checkout, errors cleanly where no branch concept exists, and the bound branch projects into door/resume serves and session listings.
- [ ] Binding consumption: ordinary captures and summary replacement target the session's effective branch with explicit `captureBranch` overriding; session reads (procedure serves, ref validation, attached free reads) resolve against the bound branch; WIP writes with an empty `baseBranch` fail loud instead of defaulting; acquisition failures name the session binding when it was the target's source.
- [ ] Procedure prose: the implementation procedure instructs declaring the binding on worktree entry and clearing it at closeout, with `workTarget` naming the binding as candidate default while the explicit report stays required; capture playback states the effective target branch.
