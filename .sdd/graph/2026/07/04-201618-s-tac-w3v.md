Reconnecting after a dropped connection double-pays the orientation text and burns rejected calls before finding the door. In the third dogfooding run, the agent tried next and then list_sessions after a client restart — both rejected, correctly pointing at start_session, but two wasted round trips — then the door serve delivered framing plus the shell orientation (~12.5KB), and the immediately following resume of the parked session re-injected both again (~12KB): the served-once contract keys its consumer memory to the session binding, so the same consumer on the same connection paid the full text twice within a minute. This exercises the reconnect path the session architecture shipped (20260703-232447-d-cpt-h99) and sits beside the teardown-resume framing cost (20260703-142336-s-tac-j25). Candidate directions: key served-once memory (framing and shell orientation) to the connection rather than the session binding, skip framing on a resume that follows a fresh door on the same connection, and let the unbound-call error name the parked session directly when one obviously matches.
