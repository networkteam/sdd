Agent conversation branching runs one dialogue session twice: after Claude Code's `/branch`, both conversation branches continue from the same context — same session handle, same instance handles, same pending junction — but each agent process spawns its own `sdd serve`, and the session stays bound to the first connection. Observed 2026-07-16 (myhogast-sdd graph): the original branch drove the session to a normal conclusion (captures, junction answer, completed shell) while the branched conversation's calls all answered "no session is open" — the session was neither listed as parked nor resumable by handle, `abandon` reaches only parked sessions, and the rolling holder heartbeat kept it held as long as the original tab stayed open. The branched agent operated on a stale session model — it believed its engage was still pending at the junction long after the other branch had concluded everything — with no way to see the session, take it over, or even detect the divergence. It resolved only when the user closed the original tab (serve drained, holder released) and the session log revealed the conclusion.

The graph itself stayed consistent throughout (append-only writes, single holder) — the failure surface is the agent-side session model after a branch loses the holder: no signal that its handles are dead, no path to reorient. Hypothesis: held sessions should be visible to other connections (`list_sessions` naming the current holder), and `resume_session` on a held session should either offer an explicit takeover or answer with the holder's identity, so a surviving branch can explain the situation instead of guessing.
