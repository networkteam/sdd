Implement target-class-aware ref-kind weighting in `sdd view` heat and coldness ranking so incoming refs count as current attention according to both the relationship kind and the class of entry receiving the ref.

This plan supersedes the earlier label-aware heat directive because the original idea is still right, but its vocabulary and process shape are stale: it predates the principle-based ref-kind vocabulary, the `surfaced-by` addition, the open-loop `coldness` lane, and the current expectation that implementation plans carry explicit acceptance criteria plus closure evidence. The replacement keeps the original response to the heat-conflation gap while bringing it into the current `sdd view` and ref-kind model.

The ranking model keeps decay and semantic weight separate. Decay continues to answer how quickly attention fades over time. The new weight answers how strongly one incoming ref should count as attention to the target. For heat, each incoming ref contributes `refWeight(refKind, targetClass) * decay(refAge)`, summed across incoming refs. For coldness, the denominator becomes weighted: `coldness = decay(entryAge) / (1 + weightedInDegree)`, so a weak background citation demotes an open loop less than a full action, refinement, dependency, or surfaced-work edge.

The first weighting axis is target class, not full entry kind. Reusing the existing ref-target classification — live decision, live signal, terminal done, retired — captures the important difference that the same ref kind can mean different attention depending on what receives it, without opening a broad `entry kind x ref kind` calibration surface. A full per-kind matrix remains a future option only if comparative findings show repeated wrong rankings that target class cannot explain.

The initial table is deliberately small and revisable: `grounded-in` is lightest for live decisions and retired targets, stronger for live signals and done evidence; `related` is medium everywhere; action-shaped refs such as `addresses`, `refines`, dependency pairs, and surface pairs are full strength for live work; `builds-on` is full strength for terminal done and slightly softer elsewhere; `unknown` stays full strength for legacy parity. The attached rationale records the full table and the reasoning behind each bucket.

The public CLI surface stays stable. `rank(heat(...))` becomes target-class-aware by default, and `rank(coldness(...))` uses the weighted in-degree denominator. This plan does not add a new public rank algorithm unless implementation needs a temporary internal comparison path for evaluation. It also does not change search ranking, topic derivation, ref-kind capture rules, pre-flight applicability, or the binary topic-membership constraint: scalar relationship strength belongs in ranking, while topics stay binary membership.

## Acceptance criteria

- [ ] `model.HeatScore` or its ranking equivalent weights each incoming ref by `targetClass x refKind` before applying the existing decay function and summing.
- [ ] `model.ColdnessScore` or its ranking equivalent uses weighted in-degree in the denominator, preserving the existing entry-age decay behavior and coldness default decay.
- [ ] The target-class axis reuses the existing live decision / live signal / terminal done / retired classification so ranking and ref-kind applicability reason from the same coarse target model.
- [ ] The initial weight table matches the attached rationale, including full-weight `unknown` for legacy parity and no weight for mechanically inapplicable cells.
- [ ] The public layout grammar remains stable: existing `rank(heat(...))`, `rank(heat)`, `rank(coldness(...))`, and `rank(coldness)` calls keep parsing without a new required argument.
- [ ] Existing composite rank algorithms that depend on heat (`mult`, `add`, `log`) either inherit the weighted heat behavior deliberately or have an explicit test documenting any narrower choice.
- [ ] `sdd view` focus-block stalled classification, topic count heat rows, catch-up active-and-hot, and catch-up open-loop lanes are checked as downstream presentation surfaces of the ranking change.
- [ ] Unit tests cover weight lookup by ref kind and target class, legacy `unknown`, mechanically inapplicable cells, heat ordering changes, and coldness demotion differences between weak and strong refs.
- [ ] A live-graph comparative findings attachment is produced at closure comparing old vs weighted heat top lists, old vs weighted coldness open-loop lists, and sensitivity for `grounded-in`, `related`, and retired-target damping.
- [ ] `go vet ./...`, `go test ./...`, and `golangci-lint run ./...` are clean.
