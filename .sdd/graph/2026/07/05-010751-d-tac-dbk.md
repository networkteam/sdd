The v1 workflow engine plan completes through four handoff-ready slices, governed by the mechanics settled in the completion interview: a session read log with a mechanical inspection gate on the write path, leaner drill serves with the compose lanes deliberately untouched, lighter session operations, out-of-the-box registration, and locale served as data. Each area below resolves one or more of the measured frictions this directive closes.

**Session read log + inspection gate.** The session event log gains read events — tool, entry IDs served, depth, timestamp; metadata only, never payloads. Serves distinguish full depth (a body served via show or as an injection's primary) from summary depth (chain bullets, search headers, snippets). Capture's assemble step gains the mechanical predicate refsInspected: every draft ref must appear in the session log at full depth — via show, an injected chain's primary, or seeded parent evidence in the same log. Failure is a plain rejection naming the un-inspected IDs; the agent reads them through the same free tools, which stay free and ungated — tracking is logging, not gating. Composition surfaces (briefs, catch-up) stay trust-based in v1 — already above skill parity, since the skill records nothing — and become auditable through the log. This resolves the fabrication gap (20260703-142356-s-cpt-be9) and answers the evidence-recorded-not-verified measurement (20260703-225033-s-tac-4ay).

**Serve sizes.** Of the oversized-serves gap (20260703-224930-s-tac-4hh): the framing share is already shipped; the drill share is fixed by defaulting the MCP search tool to header-only, hit-capped responses (snippet parameters remain available), with depth flowing through show as logged inspection; the compose serve is deliberately unchanged — its rich lane lines are accumulated fidelity fixes — with a recorded reopening condition: a read-log-instrumented side-by-side comparison of rich lanes versus lean-lanes-plus-drills, once drilling behavior is observable.

**Session operations.** abandon accepts a session handle directly, its response naming the discarded threads (20260703-142336-s-tac-j25). Served-once memory keys to the connection with content-hash dedup over rendered blocks — identical bytes are stubbed, changed content always serves in full (20260704-201618-s-tac-w3v). Unbound-call rejections inline the parked-sessions list; instance handles stay per-session counters, and the door remains the re-entry path. New affordance: a move can be parked back to the shell junction and surfaces in open_threads — mid-dialogue capture-worthy items become parked seeded drafts instead of agent promises.

**Registration and locale.** Registration rides the existing --scope flag (project default: .mcp.json and .codex/config.toml; user scope opt-in), with per-call graph resolution (worktree edge tested), a graceful no-graph door response, and drift-respecting writes that refresh stamped entries but leave user-modified ones. Claude Code entries set alwaysLoad: true, eliminating the schema ceremony (20260703-142428-s-tac-gt3); Codex does not defer schemas. The shell framing states the configured locale, and non-English graphs get the vocabulary table served as a data block, giving locale rendering its missing home (20260703-195207-s-tac-fgy).

**Slices and execution.** A: seeding contract and spec revisions per the dispatch directive (20260704-235517-d-tac-tlo). B: the three missing procedures — groom, implementation with WIP lifecycle, interview answering the resume-fidelity question. C: read log and gate, drill-serve defaults, session operations, park affordance, locale block. D: registration, freeze governance, and the side-by-side parity pass. A first; B and C parallelizable; D last. Each slice is handed to a dedicated agent session anchored on the graph entries — the graph is the handoff, no separate spec documents — with a done signal per slice; sessions after A run engine mode themselves, so implementation doubles as parity dogfooding. Sub-agents stay reserved for bounded read missions. See the [interview record](./05-010751-d-tac-dbk/completion-interview.md) for rejected alternatives and per-slice task detail.

This augments the engine plan (20260702-220449-d-tac-ry0) in place and settles the open design of the init registration directive (20260703-110919-d-tac-wfl).
