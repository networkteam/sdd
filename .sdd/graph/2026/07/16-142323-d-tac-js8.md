Amends the persistent MCP vector index repair plan (d-tac-9td) in place, binding four refinements and a two-slice delivery order that puts the release fix first.

**Slice 1 — the release patch** ships the plan's core as specced: the persistent local adapter over the machine-global store wired into base and dependency serve runtimes, monotonic entry-presence indexing with read-time filtering (no revision freshness, no request-shaped deletes), lock-before-load helpers, immediate v1-index reuse with no migration or rebuild, plus the embedded-entry index rules — included in the local store, excluded from connected stores per the base-facts coverage condition (d-cpt-dtv) — carried explicitly by the shared derivation contract. Load-per-operation is accepted for this slice: CLI parity, roughly a second per search on a 145 MB store, because the release pain is the 8-minute cold re-embed, not the reload.

**Slice 2 — versioned and fast** upgrades freshness to version-aware: StoredEntryRef carries the entry-state hash, presence is checked per (entry, hash) pair, new writes mint version-qualified chunk IDs while legacy IDs stay valid as the sole pre-existing version, the manifest becomes multi-version, and stale-version hits are filtered at read time — so on-demand summary regenerations (d-cpt-4qi) and mechanical fixes permitted by the immutability contract (d-cpt-e1i) re-index cleanly, and divergent branch versions of one entry coexist without flip-flopping over shared chunk IDs. Stale versions are collected by regular garbage collection inside write sessions — dropping versions that are neither the writer's current version nor recently indexed — accepting that revisiting a stale branch re-embeds its changed entries; request-driven deletes stay forbidden and explicit rebuild remains the full repair path. Slice 2 also adds a generation-checked snapshot cache to the persistent adapter (reload only when the store's write generation changed, counter-verified) so steady-state search drops from a full store reload to milliseconds, and folds in the connected-store force-repair fix (s-tac-chy) so the rebuild path covers every store the server uses.

Where these clauses touch the plan's attached specification (entry-manifest capability shape, presence check, cleanup rules), this amendment governs. See [design note](./16-142323-d-tac-js8/index-amendment-design.md) for the version-identity mechanism, GC policy, cache design, and rejected alternatives.
