`sdd view` hides its canonical layout reference behind the bare invocation while `sdd view --help` exposes only a generic flag synopsis, making the custom graph-view surface hard to discover and describing it too narrowly as “mechanical catch-up.” The original view plan placed the grammar, vocabulary, and examples on bare `sdd view` (20260506-151345-d-tac-uww), and the later help-drift repair kept that complete reference current (20260619-174118-s-tac-zwz), but neither made the conventional `--help` path authoritative. Since `sdd view` subsequently absorbed the filtered-listing and overview roles of `sdd list` and `sdd status` (20260625-150830-s-tac-sag), its command description should present it as the general tool for composing custom graph views with filters, ranking, transforms, and renderers—not as a catch-up-specific mechanism. The CLI help reference should not become another independently maintained vocabulary copy: the sibling MCP grammar-reach gap (20260717-095714-s-tac-lwi) already calls for an auto-generated reference from the executor’s vocabulary tables, and CLI help should consume the same implementation-backed source so both surfaces remain aligned. The expected CLI shape is: `sdd view --help` renders the full layout grammar, implemented vocabulary, macros, and examples; bare `sdd view` reports that `--layout` is required and directs the user to `sdd view --help`.
