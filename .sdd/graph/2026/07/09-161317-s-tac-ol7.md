`sdd repo add` (and the redefined `sdd repo remove`) write the committed `.sdd/config.yaml` but leave it uncommitted, inconsistent with `sdd init`, `sdd new`, and `sdd summarize`, which auto-commit their writes. Surfaced by the outer validation 20260709-160634-s-tac-tt8. `repo add`'s dependency declaration (part of plan 20260708-185833-d-tac-nhx) is a committed, shared artifact — the portable, go.mod-style record other clones read — yet the command tells the user to commit it manually, so it is easy to forget and the working tree is left dirty. The tension: `sdd repo add` is framed as environment configuration rather than dialogue, which may be why it doesn't auto-commit — but the artifact it writes is exactly the kind the auto-commit commands handle for the user. Either these config-writing commands should auto-commit the committed `.sdd/config.yaml` (consistent with `sdd init`), or the divergence needs an explicit reason.
