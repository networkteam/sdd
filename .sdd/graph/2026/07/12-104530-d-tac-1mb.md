SDD will expose its mature workflow application as one importable, project-aware Go runtime whose local CLI and external compositions share the exact MCP tools, procedures, served knowledge, engine transitions, and write gates. This extracts the behavior already shipped in the workflow MCP shell (20260703-002223-s-tac-kd2) rather than building a second CLI-parity server, implements the in-process engine architecture (20260702-174833-d-cpt-3yw) and Go-runtime direction (20260629-211231-d-cpt-8k5), and follows the CQRS planning contract (20260413-142536-d-cpt-ah1): SDD owns application semantics while integrations supply infrastructure and authorization only.

The public surface has two packages. `github.com/networkteam/sdd` is the protocol-neutral facade over the internal implementation; `github.com/networkteam/sdd/mcpapp` owns the single MCP tool and transport surface and depends on the root package. Root exports no MCP SDK or internal types, and internal packages do not import root facade types in ways that create cycles. The initial release remains one Go module; consumers of root avoid a compile-time MCP package dependency, while eliminating module-resolution of the SDK is explicitly not worth a second module's release surface yet.

The root package owns Show, View, procedure discovery and loading, rendering, text and hybrid search semantics, pre-flight, summary generation, NewEntry, ReplaceSummary, WIP behavior, write gates, engine transitions, session replay, and typed application errors; `mcpapp` owns their mapping to MCP results. External compositions can provide only narrow infrastructure ports: request identity and project/access resolution; canonical snapshot data; dependency resolution; session persistence; mutation persistence and finalizers; staged and canonical attachment storage; embedding execution and vector-index mechanics; and raw LLM execution. Policy wrappers may deny access but cannot replace SDD finders, handlers, commands, or domain judgments.

Snapshots have one construction path. Public canonical `SnapshotData` and `EntryDocument` carry stored document facts without exporting the model; filesystem loading parses into that representation, structured stores may supply it directly, and SDD alone validates, normalizes, constructs indexes and references, merges authorized dependencies, derives status, and builds the opaque `Snapshot`. This extends the finder-owned graph-currency seam already shipped in 20260707-181856-s-tac-50b. Dependency resolution receives current request identity and checks each declared target independently; unauthorized and unknown dependencies are indistinguishable to callers.

The MCP application resolves an explicit protocol-neutral `RequestIdentity` from current request metadata. A session stores immutable subject and project-binding identities, but neither a binding nor a cached runtime proves current access. Every project-scoped request resolves current read access, and every mutation separately resolves write access at the write gate. Slice A must prove, over two requests on one stateful MCP session, that changed scopes or sentinel metadata for the same MCP user reach project resolution, an engine query, and mutation authorization; a changed user must receive 403. Initialization-time context is forbidden. The spike may use SDK-supported per-request metadata, a narrow private bridge, or an upstream hook, but the public HTTP application is blocked until the observable security test passes.

Projects are selected explicitly in multi-project compositions and inferred only when exactly one accessible project exists. Sessions bind immutably to one project and reject switching. Every project-scoped structured result carries `ProjectRef{ID, DisplayName}`; capability and registry results do not, and local rendered text remains byte-for-byte stable except where project context is necessary for an error or reorientation. Local single-project composition uses canonical `repo_id` when present, otherwise the non-persisted, composition-scoped sentinel `local` with the repository basename as display name. Adding a canonical `repo_id` changes new bindings and results; stored legacy `local` bindings remain immutable aliases that resolve to the sole current project, and listed or resumed sessions display the canonical current ProjectRef without rewriting events. Only canonical repo IDs participate in cross-repository references.

Session persistence stores structured ownership/routing metadata plus ordered, versioned opaque events behind optimistic append. Every advance uses session-version CAS, structurally preventing the concurrent-claim corruption recorded in 20260709-174818-s-cpt-c2i. Every shell and submove pins its exact normalized procedure bytes, source entry, digest, procedure-spec version, and registry-contract version at instance start. Every stored event independently carries its event-codec version; replay verifies and executes the pinned material, never a current procedure with the same canonical name. SDD owns deterministic migrations. Load, list, and resume migrate only the in-memory replay view; the next authorized advance first appends a CAS-protected migration-acknowledgement naming source/target versions and a stable migration-chain fingerprint. Historical events remain immutable, retries recognize an existing acknowledgement, and unsupported versions or integrity failures stop without appending.

Mutating transitions use a durable intent/apply/outcome protocol across the independent session store and canonical project authority. After all nondeterministic work—including LLM calls—SDD creates a canonical `PreparedTransition` containing the exact engine-state delta, pinned registry operation, canonical mutation bytes, expected authority revision, staged-blob facts, ordered idempotent finalizer descriptors, their pinned contract versions, only the non-secret parameters required to resume them, and prepared result data. The envelope digest and mutation-batch digest are distinct. Intent is appended under session CAS before effects; `Apply` is idempotent only for the original mutation ID and batch digest; and the outcome records not-applied, applied, or unknown plus authority revision, finalizer status, and diagnostics. Orphaned intents reconcile before retry. Recovery may re-run current authorization and mechanical validation but never regenerates IDs, timestamps, semantic content, prompts, summaries, or LLM output. This also supplies first-class failed-transition and finalizer evidence for the silent-log gap in 20260707-170902-s-cpt-ev3.

`Apply` means durable in the adapter's canonical authority. Local filesystem writes are applied before the Git auto-commit finalizer, so commit failure is “applied, finalization failed”; a remote-Git authority includes commit and push in Apply, so failed push is not applied. Unknown results stop for reconciliation by mutation ID. The adapter atomically checks expected revision and persists the SDD-built batch of entries, attachments, and WIP changes; finalizers such as indexing, auditing, notifications, or local Git commit are separately idempotent. Incompatible mutation codecs, registry operations, or finalizers fail explicitly rather than substituting current behavior.

Attachments split session staging from canonical materialization. `StagedBlobStore` holds immutable owner/session-scoped blobs with stable ID, digest, size, and filename; mutation-ID retention protects referenced blobs until a terminal reconciled outcome. The prepared batch carries attachment materialization records, and Apply verifies digest and size while atomically materializing them with graph state. A path-free canonical reader serves authorized pages. `SweepUnretained` atomically deletes only expired, unretained blobs, avoiding list/delete races. A crash after retention but before intent may leak storage; generic cleanup preserves that hold, and only reconciliation or operator repair may release it after proving no durable intent exists. These mechanics also make the write gate reconcile every staged handle, directly addressing the orphaning gap in 20260707-175502-s-prc-lgu.

Search exposes `EmbeddingExecutor` for model execution and fingerprint/dimensions, plus `SearchIndexStore` for manifest, atomic reconciliation, and nearest-neighbor mechanics within explicit namespaces. SDD owns canonical chunks and hashes, embedding input, lazy reconciliation, text/regex matching, hybrid fusion, filters, authorized cross-project fan-out, ranking, stale-hit rejection, citations, and rendering. Shared-index queries receive the exact authorized namespace set and return raw metric-aware hits with revision and content hash.

LLM execution is similarly mechanical. SDD supplies purpose, fully rendered prompts, output schema, capability requirements, opaque routing metadata, prompt digest, and idempotency key; the adapter selects a provider/model and returns raw bytes, executor fingerprint, finish reason, and neutral usage. SDD validates declared capabilities and the actual fingerprint, parses output, classifies findings, performs mechanical checks, generates summaries, and alone decides whether a write gate opens. Capability mismatch, provider failure, timeout, or malformed output fails loud.

Transport authentication remains outside the shared application package: the handler consumes authenticated request metadata but does not implement an external authentication protocol. The local command keeps its standalone bearer wrapper, and the production-auth commitment in 20260610-232719-d-tac-47d remains a related transport-composition concern. Free reads remain outside the workflow write gate, never outside authentication, project authorization, or audit.

Delivery proceeds in six slices: freeze local parity and the public contract, including the stateful request-identity spike; extract the protocol-neutral root runtime and ports; extract the shared MCP application without duplicating registrations; add project routing, immutable bindings, versioned persistence, and identity promotion; prove authorization-aware dependencies, read-only dialogue, and durable recovery with a fake multi-project composition; then document, smoke, lint, test, and release a consumable version.

## Acceptance criteria

- [ ] Another Go module can import the root and `mcpapp` packages and mount the exact workflow MCP surface without importing internal packages.
- [ ] Local and external compositions use one tool registration, schema, procedure, served-knowledge, engine-transition, read, and write-gate implementation.
- [ ] Public ports supply infrastructure, execution, and policy effects only; SDD retains all read/write application semantics.
- [ ] Filesystem and structured sources converge through canonical SnapshotData into one validated opaque Snapshot construction path.
- [ ] Stateful HTTP tests prove current per-request identity reaches project resolution, engine queries, and mutation authorization; changed MCP user identity is rejected.
- [ ] Explicit/inferred project routing, immutable session binding, current-access resolution, and additive ProjectRef results behave as specified.
- [ ] Promotion of the `local` alias to a canonical repo ID preserves legacy replay without persisting a synthetic identity or enabling cross-repo use.
- [ ] Cross-repository reads resolve only declared, currently authorized dependencies and do not leak unauthorized project metadata.
- [ ] Session persistence uses CAS, pinned procedures, versioned opaque events, deterministic replay migration, and acknowledgement-on-next-advance.
- [ ] Every mutation follows prepared intent/apply/outcome with idempotent ID/digest reconciliation and typed not-applied/applied/unknown handling.
- [ ] Apply is atomic in the canonical authority, finalizer failures remain distinguishable, and recovery never duplicates applied mutations.
- [ ] Staged attachments are immutable, retained through unresolved outcomes, atomically materialized with graph state, path-free on read, and swept only when unretained.
- [ ] SDD owns search semantics over replaceable embedding and index mechanics, including authorized namespace filtering and stale-hit rejection.
- [ ] SDD owns prompt, parsing, pre-flight, summary, and gate semantics over a raw capability-checked LLM executor.
- [ ] Read-only principals can start, list, resume, and use dialogue/read tools but cannot cross the freshly resolved mutation gate.
- [ ] Existing local tool names and non-project arguments remain valid; local single-project text snapshots remain byte-for-byte stable except explicit reorientation/error cases.
- [ ] Package documentation, a minimal external composition example, parity/security/recovery tests, lint, stdio/HTTP smoke tests, and a consumable release version complete the handoff.
