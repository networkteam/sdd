The bootstrap procedure port has a settled, implementation-ready design, drafted and attached as the handover for its coding slices. This refines the bootstrap plan (20260718-222157-d-tac-k46) with the concrete engine spec the plan called for: the full procedure entry, the capture-procedure amendments, and the readiness view are attached in reviewed form, and the design decisions reached in dialogue are recorded here so the implementation can proceed against a fixed target.

State machine and units. Bootstrap is an eight-step persistent outer procedure: orient (agent chooser that push-injects the readiness view and branches inspect/proceed), brownfield (host-directed repository read into a synthesis), converse (the journalist loop: ask/cluster/finish/abort), propose (user junction playing the cluster back as a meaning-level replay: accept/reshape/defer), materialize (agent loop dispatching one parented capture per entry in dependency order, rolling produced IDs into state / clusterDone), foundTopics (agent chooser: found the nested topic landscape after the first meaningful cluster, or skip), refresh (user junction: continue/finish), and handoff (dispatch catch-up). Nine served instruction units carry the voice; the entry preamble is reader-facing only and is never served.

Grounding is push at first contact, pull thereafter. orient injects the readiness view so the agent is grounded before it opens. refresh does not inject: the agent's produced-ID record is the known delta, so it pulls the readiness view on demand through the free, host-neutral view capability (per 20260707-134311-d-cpt-476, served instructions reach graph reads through an engine capability, not the CLI), reserving a re-read for showing the user growth or re-grounding after a cold resume. The readiness view ships as a named `readiness` macro so orient's inject and refresh's pull share one definition; registering it requires superseding the view-grammar base fact (20260717-110000-s-prc-vwg) to list the new macro, since that fact is the agent's pullable grammar reference.

Capture amendments for actor/role/focus. involvement ships as a real structured engine type following the existing ref precedent, not list<text> — the JSON schema becomes the format contract, removing a separator convention, a hand parser, and runtime parse-error handling; the recognition-not-review playback softening is a seeded recognitionMode flag (explicit, chosen over parent-introspection); the assemble gate becomes kind-conditional so identity and focus kinds are no longer blocked by the refs-and-topics requirement; and write-gate validation failures re-serve actionably instead of wedging.

Two-slice cut. Slice 1 is actor plus role plus the shared gate infrastructure, the bootstrap entry itself, the readiness macro, and the s-prc-vwg update — carrying no new engine type, so bootstrap ships and is evaluable on its handoff dependency first. Slice 2 is focus: the involvement struct and its gate branch, which closes the focus capture wedge (20260707-162940-s-prc-g0j). Fidelity from the legacy sdd-bootstrap skill was deliberately re-adapted rather than dropped: the softened experience gauge driving an adaptive teaching/transparent register, plain-words-then-name concept teaching for newcomers, example anchors in every user-facing unit, the WHAT-first elicitation bias, whole-project scoping, contracts-not-sought, facts-point-at-docs, the actor/role split, and the single-sprint role guard. The three attachments carry the complete drafts.
