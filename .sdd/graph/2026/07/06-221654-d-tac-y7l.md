Rip out the summary-hash machinery and reshape `sdd summarize` and `sdd lint` to the on-demand, no-staleness-tracking model committed in d-cpt-4qi — a single slice. Today a summary skip-hash is stored per entry and recomputed over the full rendered summary prompt; because that prompt embeds neighbor summary prose and a read-order-dependent attachment list, the stored hash drifts on its own, so `sdd lint` flags a cascading treadmill of stale hashes (s-tac-pfn) and `--attach` entries are born stale (s-tac-gcd). Under entry immutability an entry's meaning is fixed at creation, so the hash guards against a change that cannot occur while generating false-staleness noise; d-cpt-4qi removes staleness tracking entirely rather than stabilizing the hash, and this plan implements that removal.

Decomposition (per the CQRS planning contract d-cpt-ah1):
- **model** (`entry.go`): drop the `SummaryHash` field, its `summary_hash` frontmatter tag, and the two constructor copies. Frontmatter parses via plain `yaml.Unmarshal` (no `KnownFields`), so the ~500 existing files that still carry `summary_hash` load cleanly — the now-unknown key is ignored and drops the next time that entry's summary is written. No migration; existing keys are left in place, per decision.
- **command** (`summarize.go`): keep `--force` but redefine it as “regenerate all” rather than “override the hash”; `OnSkipped` now means “already has a summary.”
- **handlers** (`handler_summarize.go`, `handler_new_entry.go`, `handler_rewrite.go`): remove all hash compute and set. `sdd summarize <id>` and `--text` regenerate/write the named entry unconditionally (the on-demand fidelity fix; the corrected-summary workflow otherwise lives in the MCP capture flow). `sdd summarize --all` fills only entries with an empty summary; `--all --force` regenerates every non-embedded entry.
- **finders** (`lint.go`): remove `validateSummaryHashes` and both hash warnings (stale hash, summary-without-hash); keep the hash-free missing-summary warning.
- **llm** (`summary.go`): stop computing/returning a hash and delete `ComputePromptHash` (dead once the callers above are gone).
- **presentation**: `sdd show` no longer renders `summary_hash`; the one doc surface that mentions the skip-hash, `references/cli-reference.md.tmpl`, is updated and re-rendered via `sdd init`.

A grep confirms no summary write path outside model/llm/finders/handlers sets the hash, so this removal also covers the MCP capture path. On completion the closing done signal closes both open gaps.
