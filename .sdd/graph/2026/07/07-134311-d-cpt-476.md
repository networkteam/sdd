Engine procedures must be host-neutral: their served instructions must never direct the agent to the `sdd` CLI surface (or any host-local command), and every operation a procedure needs must be reachable through an engine capability — a transition running a registered command, or a served query. Procedures run over the MCP surface against a graph that may be remote or hosted, where the CLI is not on the agent's path and does not point at the same graph; a served CLI instruction is simply unreachable there. This sharpens the agent-agnostic foundations directive (20260628-123931-d-stg-dn6) into a concrete authoring rule for procedure specs, and expresses the same discipline as the engine's narrow MCP surface, where graph writes exist only as procedure transitions (20260702-220449-d-tac-ry0). It governs the groom procedure's two current violations — CLI-based stale-marker removal (20260707-134105-s-tac-prp) and `sdd lint` fork detection (20260707-134223-s-tac-n5a) — and every future procedure spec. Skill prose runs in a local harness and is out of scope; this rule is for the engine's served procedure text.
