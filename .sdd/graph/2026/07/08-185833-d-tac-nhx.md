Implements the config-and-state placement directive (20260708-184318-d-cpt-6cq) end to end in four independently shippable slices: the unified config overlay with an `sdd config` surface, committed cross-repo dependencies with structural one-way enforcement, one machine-global content-addressed index store, and terminal-UX wiring for the long-running cross-repo operations (addressing 20260708-164711-s-tac-k50, the one evaluation finding the directive itself does not carry). Slice 1 factors the shared settings — participant, llm, embedding, and sync (whose home the dialogue pinned to BaseConfig as a preference, while language and skill_scope stay per-repo as properties of the repository) — into one BaseConfig embedded inline by GlobalConfig (plus `repos`) and PerRepoConfig (plus repo_id, graph_dir, language, skill_scope, supported_agents, and the new `dependencies`); model.Config is already the single schema both per-repo files parse into, so this is a factoring, not a format change, and YAML inline embedding keeps existing files parsing unchanged. Unknown or misplaced keys fail loud — the yaml.v3 KnownFields/inline-struct quirk is covered by scenario tests that prove both rejection and correct decoding across all three files. Slice 2 adds the committed `dependencies` declaration, `sdd repo add`'s dual write (committed declaration + per-user global resolution), the `sdd init` prompt-to-connect for declared-but-unconnected dependencies, and the resolve-or-block precondition (20260628-130400-d-cpt-uh0): a cross-repo ref resolves only if its target repo_id is a declared dependency. Slice 3 moves the index to one machine-global store keyed by (repo-key, embedder-fingerprint), where repo-key is the declared repo_id or, for identity-less repos, a hash of the absolute repo root — a moved identity-less repo re-embeds, accepted because `sdd init` migrate-if-absent covers the common case; minting synthetic IDs was rejected as inventing a second identity concept the directive just cleaned up. Multi-process safety (chromem-go writes per-document gob files with no coordination) comes from advisory file locking — exclusive write sessions, shared read opens, one small cross-platform flock dependency — centralized in a single seam in internal/index with no locking calls anywhere else, per the dialogue's explicit centralization requirement; swapping the store engine was rejected as a far heavier dependency change than serializing writers. Slice 4 wires `sdd repo add`'s clone and the connected-index build through the output coordinator per the terminal-experience architecture (20260628-131545-d-cpt-dgk) and adds `sdd index --repo/--all-repos` for eager, visible pre-indexing. Per the CQRS planning contract (20260413-142536-d-cpt-ah1) the decomposition is: config types, BaseConfig factoring, and merge logic in internal/model (pure); effective-config resolution in internal/meta consuming model; `sdd config set` as a command with a handler method (writes stay in handlers) and the effective-config view as a query through a finder; the repo-add dual write extending the existing Manager path in handlers; the dependency precondition extending the existing capture pre-flight/lint read path; and the index store plus its locking as one seam in internal/index behind the existing handler orchestration. Out of scope, sequenced deliberately: the documentation finding waits for these refined surfaces to land, and latency profiling stays deferred; the deferred second-round outer evaluation of cross-repo references is the natural closing evaluation once the slices ship.

## Acceptance criteria

- [ ] Shared user/machine settings (participant, llm, embedding, sync) set in the user-global config take effect in every repo; effective resolution is global → committed .sdd/config.yaml → .sdd/config.local.yaml → CLI flags.
- [ ] One BaseConfig struct is embedded inline by GlobalConfig and PerRepoConfig; .sdd/config.yaml and .sdd/config.local.yaml parse as the same PerRepoConfig schema; per-repo-only fields (repo_id above all) are not representable in the global schema.
- [ ] Unknown or misplaced keys in any of the three config files fail loud with an error naming the file and the key; scenario tests cover unknown-key rejection and correct inline decoding for all three files.
- [ ] `sdd config` creates the global file, gets and sets keys in the global and per-repo local files, and prints the effective merged config with per-value provenance.
- [ ] Cross-repo dependencies are a committed `dependencies` list in .sdd/config.yaml; `sdd repo add` writes both the committed declaration and the per-user global resolution.
- [ ] Capture blocks a cross-repo ref whose target repo_id is not a declared dependency, with a high-severity precondition finding.
- [ ] `sdd init` on a clone with declared dependencies detects unconnected ones and prompts `sdd repo add <clone-url>` for each.
- [ ] The vector index lives in one machine-global store keyed by (repo-key, embedder-fingerprint) — repo-key is the declared repo_id, else a hash of the absolute repo root; checkout, worktrees, and connected cache share it; neither .sdd/index nor the cache .index remains.
- [ ] `sdd init` migrates an existing .sdd/index into the global store (move-if-absent / merge-or-skip, never clobber) and stops emitting the .sdd/index gitignore entry; the .worktreeinclude index-copy recipe is removed.
- [ ] All index locking lives in one seam in internal/index — exclusive write sessions, shared read opens — with no locking calls outside it; concurrent writer/reader scenario tests pass.
- [ ] A repo that is both developed and connected is embedded exactly once per embedder fingerprint.
- [ ] `sdd repo add`'s clone and connected-index builds render transient progress through the output coordinator on a TTY and clean slog on non-TTY.
- [ ] `sdd index --repo <id>` and `sdd index --all-repos` eagerly build connected indexes with the same progress rendering.
