Fixed the `sdd index` and search lazy-fill progress bar so it tracks chunks and advances on completion, closing the progress-accounting gap (s-tac-hiy). The bar now measures chunks — the time-proportional unit, since an entry's embedding cost scales with its chunk count (the verifying run embedded one entry of 76 chunks alongside another of 2). `OnPlanned` sets the authoritative total from the same work set the skip pass produces, so the denominator can't drift from what actually embeds — fixing the `PendingCount`-vs-hash divergence that surfaced whenever a regenerated summary changed an entry's hash under a matching fingerprint. `OnEntryIndexed` advances the bar by each entry's chunk count as work completes, so it never reads 100% before the embedding round-trip returns, eliminating the perceived hang. `OnBatchStart` no longer moves the bar; it names the in-flight batch ("embedding N entries · K chunks") through a new footer note, so the long embedding call isn't silent. The fingerprint-only `PendingCount` launch gate is deliberately left as a cheap heuristic — the bar's total is authoritative regardless. Shipped in commit 7157b60; verified by unit tests (note propagation, footer render, planned == batch == indexed chunk accounting), a clean vet/test/lint gate, and a live end-to-end index run.
