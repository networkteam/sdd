The engine's evaluate procedure records evaluation findings ad hoc rather than as a done-with-findings, diverging from the evaluation-as-done model it should follow. The shipped evaluate procedure's junction turns each kept finding into a signal captured against the evaluated work; the evaluation-as-done model instead prescribes recording the evaluation itself as a done that references the move it followed, with findings surfaced-by that done. The two shapes are not equivalent: the ad-hoc route leaves no record of the evaluation as work, so an under-evaluation coverage map — recorded work × move, computed over graph entries — cannot be built, which is the model's whole point. Resolution: the evaluation-as-done shape should be built into the procedures — the evaluate procedure emitting an evaluation done and surfacing findings by it (with the typed move-reference the model calls for), and the same shape baked into the remaining procedures as they are specced, rather than each move recording findings ad hoc. Surfaced here when this evaluation's junction steered toward an ad-hoc fact and the user redirected to a done.
