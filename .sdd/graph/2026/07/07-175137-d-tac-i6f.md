Implements cross-repo references end to end in two independently shippable layers — a reference foundation, then cross-graph discovery — refreshed against the current codebase so the CLI and the MCP server are both first-class surfaces served from one read-side seam, realizing the augmented design (d-cpt-s6q). It supersedes the prior plan (d-tac-rpm) after a month of drift made four corrections necessary. Placement: the superseded plan had handlers building the MultiGraph, but reads never pass through handlers — the CLI and the MCP read tools call finders directly — so model.MultiGraph is assembled inside the finder-owned GraphSource whose introduction the graph-access gap (s-tac-jg8) commits to, giving cross-repo exactly one insertion point inherited by CLI commands, MCP free reads, engine serves, and capture-time resolution; side effects (cache clone/pull, remote index builds) stay in handlers that invalidate the source, mirroring the existing lazy-fill-before-search pattern — this plan depends on that refactor landing first. Surface: the MCP search and view tools gain repo selection equivalent to --repo/--all-repos (show resolves <repo-id>:<entry-id> through its existing ids parameter), while repo management (sdd repo add/list/remove/sync) stays CLI-only as machine setup; inside an engine session, cross-repo resolution always reads the live cache — cooldown pull, fetch-on-miss at capture — memoized per call/advance and never bound to session lifetime, so a mid-session capture cannot false-block on a stale snapshot. Invariant: resolve-or-block now grounds in d-cpt-uh0, which exempts the forward-class kinds (surfaces, required-by). Environment: base facts (d-cpt-dtv) merge embedded framework entries into every loaded graph, so member graphs load with the embedded set — keeping chains complete and per-graph status correct, including project-superseded base facts — while remote index builds exclude embedded entries and traversal dedups them by bare id, so exactly one copy ever surfaces; rendering builds on the shipped YAML-envelope show renderer (d-tac-z3k) with --up/--down bounds and owning-graph supersede head-walks; new operational output conforms to the terminal-experience architecture (d-cpt-dgk) via slog and reporter callbacks — the groundwork the old plan waited on has landed. The two-layer shape, repo-id identity auto-derived at init, sdd-managed read-only caches, and the single global embedding config with merged-by-cosine search carry over unchanged; the connected-repos configuration avoids the overloaded name "registry". Design deltas, code placement, and file-level changes are in the attached refreshed spec.

## Acceptance criteria

**Foundation**

- [ ] A cross-repo ref `<repo-id>:<entry-id>` stores verbatim and reloads identical (prefix + kind intact); it is not mistaken for a local id, not indexed as a local ref, and raises no dangling-ref warning; `sdd new --refs` and the engine capture path accept it with syntactic validation of both parts, and short-ID resolution never misclassifies the colon form.
- [ ] A cross-repo ref renders with the full canonical repo-id prefix and the remote entry's derived status read from the cached graph — in `sdd show`, `sdd view` expand(refs), and lists, identically through the MCP show and view tools; an unresolved repo renders `[unresolved: repo X]`.
- [ ] Capture blocks at high severity when a backward-class ref — local or cross-repo — fails to resolve, honoring the forward-class exemption (surfaces, required-by); cross-repo resolution auto-fetches on cache miss and blocks only if the target is absent from the other repo's default branch; behavior is identical via CLI capture and engine capture transitions, which read the live cache memoized per call — never the session snapshot.

**Discovery**

- [ ] `sdd init` derives and commits `repo_id` (host/path from the git remote, ssh and https forms normalized equal) when absent; it is not user-choosable.
- [ ] A user-global `~/.config/sdd/config.yaml` holds connected repos `{repo_id, clone_url}` and the shared embedding config; `sdd repo add <clone-url>` clones, verifies the repo declares that repo_id, and registers it; `sdd repo list` / `sdd repo remove` manage entries; the feature's code and docs avoid the name "registry".
- [ ] Connected repos cache read-only at `~/.cache/sdd/<repo-id>/` with lazy clone plus cooldown pull (`sdd repo sync` forces); the local repo keeps indexing itself at `.sdd/index/`.
- [ ] `sdd show <repo-id>:<entry-id>` resolves via the cache and renders the remote entry; cross-repo chains traverse fully, bounded by `--up`/`--down`, deduped by `(repo-id, entry-id)`, with supersede head-walks resolving within the owning graph.
- [ ] `sdd search` and `sdd view` accept `--repo <id>` (repeatable, additive to local) and `--all-repos`, and the MCP search and view tools accept equivalent repo parameters; results merge into one list by comparable cosine score with remote hits repo-id-prefixed; a repo indexed under a mismatched embedding config is excluded from cross-graph search and flagged by `sdd lint`.
- [ ] Member graphs load with embedded base entries so chains stay complete and a project-superseded base fact derives its per-graph status; remote index builds exclude embedded entries and traversal dedups them by bare id — exactly one copy surfaces in search results and show trees.
- [ ] Pre-flight runs the ref-meta consistency check against the cached remote entry for cross-repo refs.
- [ ] `model.MultiGraph` is assembled only inside the finder-owned GraphSource; cache clone/pull and remote index builds run in handlers that invalidate the source; connected-repos and cache machinery live in `internal/repos/`; all new operational output uses slog via `slogutils.FromContext` and reporter callbacks.
