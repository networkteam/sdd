The report-back gate in a goal-driving loop should bias the agent toward doing the work rather than verify that it did — evidence must be self-describing so it stands on its own for a judge that may run remotely. The mechanism is incentive, not policing: structure the required evidence so honest production is the cheapest path — verbatim specifics only the work yields, internal cross-coherence across the pieces, and for dialogue the trajectory to alignment rather than a bare "confirmed" — balanced against over-loading into busywork. Genericity lives at the principle level while the specific fields are declared per graph-resident unit: a playbook move is the workflow state machine, and rules attach binding/advisory constraints at its steps (enforcement/activation per d-tac-eho, the graph-resident-process direction s-cpt-r57 gives a home). The generic verification substrate is sdd plus the reported evidence — the judge is assumed to hold the graph, so graph-anchored evidence can be checked deterministically, while any check needing other tools (e.g. "site reachable after deployment") is scoped to a project rule that requires it and that the setup must provision the judge for, not part of the base. Fuzzy "is this good enough?" judgment must stay advisory and never block, or it re-triggers the oscillation pre-flight escaped by pulling fuzzy judgment out of the blocking tier (d-tac-tph). The limit this works within: no gate verifies the agent's process, only its artifacts (s-cpt-1dz).
