The engine surface leaves a cold session start undefined: the sdd-engine skill names no default move for arriving without stated intent, lists no available procedures (its only worked example is capture), and the server instructions don't name the set either. In the first dogfooding run the agent opened with engage "to get the framing block," abandoned it when the user asked for a briefing, then guessed "catchup" and learned the real procedure names only from the rejection message — seven tool calls to the first useful serve. A side finding: a rejected start_procedure still applies its label, because the label lands before the canonical resolves (the failed "catchup" call labeled the session). Candidate directions: name catch-up as the cold-arrival default in the skill and server instructions, surface the available-procedure list at session entry or in the start error, and apply labels only after the procedure resolves.
