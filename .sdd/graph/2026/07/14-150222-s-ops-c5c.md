`sdd init` does not add `.sdd/graph/.sdd-runtime/` to its managed gitignore set, so the durable local bookkeeping created by the v0.16 filesystem GraphStore appears as untracked repository content after the engine first accesses a graph. The directory contains the graph lock, applied-mutation records used for idempotency and crash reconciliation, and temporary transaction journals; the GraphStore itself excludes the directory from canonical graph revisions and prevents graph mutations from targeting it, so it is runtime state that must remain on disk but outside version control. Adding the path manually in this repository would only mask the product omission: `sdd init` must add it idempotently for both fresh and upgraded projects, with its existing fresh-project and gitignore-idempotency tests asserting the entry. This repeats the same init-housekeeping miss previously caught for `.sdd/index/` in 20260506-152056-s-ops-626 and `.sdd/stats/` in 20260608-135744-s-ops-qbl, now surfaced by the public runtime delivered in 20260714-095002-s-tac-4oj.
