Session-store relocation during `sdd init` is an explicit offline migration that proceeds only after user acknowledgement and rewrites `local` session identity to the repository ID in the same pass. This refines the automatic relocation clause of 20260722-112853-d-tac-ln1 because pre-upgrade servers have no fence hooks and cannot participate in a safe coexistence protocol; permanent online-migration machinery is rejected for a one-time transition.

The acknowledgement appears only when an in-tree session or staged-blob store exists and states the real precondition: stop running `sdd serve` processes and restart agent sessions. Fresh and already-migrated repositories remain silent. If the user declines, or init is non-interactive without acknowledgement, relocation is skipped, the source remains unchanged, and the standing notice keeps the pending migration visible for the next init. Serve startup behavior is unchanged: `sdd serve` never refuses to start over leftovers.

Once acknowledged, session logs and their staged state move as aggregates with move-if-absent behavior, `local` project identities are rewritten to the repository ID within the same offline pass, and a tombstone marks the abandoned in-tree location. New servers use only the machine-global store and never fall back. A pre-upgrade server writing after relocation fails on its next CAS read because the files have moved; any state it recreates under the tombstoned source is orphaned but visible through the relocation and recovery vocabulary, never silently merged.

Implementation must also make aggregate collision handling non-destructive, publish cross-device copies atomically after durable temporary writes, confine derived paths beneath an absolute XDG state root, and fail before mutation on invalid configuration. The done evidence must name this acknowledgement refinement explicitly so the original acceptance criterion does not drift silently.
