For agent-facing surfaces, outer validation means a real agent driving the real integration — an implementer-run simulated client is not a user. The slice-1 validation episode showed the gap concretely: a hand-rolled MCP client exercised the unfiltered happy path and passed everything, while a real Codex session — a genuine consumer with its own calling habits — hit the filtered path within minutes and found a defect that review, tests, and simulated smoke all missed (the silently no-op type filter, s-tac-wyu). The implementer simulating usage inherits the implementer's assumptions; a real agent brings foreign assumptions, and that difference is precisely what the outer lens exists to catch.

Practical rule: validation of MCP/engine surfaces should include at least one pass driven by a real agent session that was not shaped by the person or agent who built the change.
