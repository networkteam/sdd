The engine implementation procedure must persist explicit `baseBranch` and `workBranch` roles and route lifecycle mutations by phase: coordination on the base branch, implementation captures on the work branch, and marker removal only after host-reported landing. This refines the active implementation procedure in 20260706-170000-d-prc-imp, whose tracked setup currently creates WIP through one launch-bound handler and whose resolving `doneEntry` routes directly to `wipDone` without representing branch targets or the unmerged interval.

The agent supplies `baseBranch` before WIP creation and `workBranch` after the user chooses execution mode; neither is inferred from cwd, assumed to be `main`, or replaced by the repository's default branch. In-place work requires the two roles to be equal. Branch and worktree modes leave checkout creation and entry with the host, then resolve the reported work branch to an existing registered checkout. Both roles persist for resume under the explicit mutation-authority directive in 20260713-214050-d-cpt-65i.

Tracked runs create their exclusive marker through the base authority. Implementation-scoped captures—including one or more done signals—target the work authority unless the user deliberately selects another graph target. Commit hashes remain ordinary evidence; the procedure adds no checkout-cleanliness, code-HEAD, or ancestry gate.

A closing done signal is captured on the work branch before landing and advances the run to a landing junction, not marker cleanup. The landing read and merge decision therefore cover code and completion evidence together. If merge is deferred, the procedure remains resumable and the WIP marker stays visible on the base branch. After host landing succeeds, an explicit agent report authorizes the engine to remove the marker through the base authority and offer evaluation or finish. This restores the live-validated order in 20260608-102050-s-prc-ywh and preserves the coordination semantics established in 20260409-095950-d-prc-jzp. The attached lifecycle design specifies state, transitions, corrections, and resume behavior.
