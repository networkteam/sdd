SDD will support direct capture into an authorized connected repository and selected branch within one agent session, using the target graph's own rules and dependencies while keeping its read cache strictly read-only. This addresses the native-upstream-work gap in 20260710-233818-s-cpt-7y0: when dialogue in repository B discovers work owned by dependency A, the preferred path is a native A entry without requiring the user to open another session, transport context, or coordinate a manual handoff.

Target-aware capture scopes repository-and-branch authority to the capture submove under 20260713-214050-d-cpt-65i; the session keeps its originating project binding. An explicit target branch wins, otherwise ordinary capture resolves A's actual default branch rather than assuming `main`. Before drafting and playback, capture loads A's configuration, actors, graph, declared dependencies, rules, and pre-flight context. Playback names the exact destination, and confirmation writes through A's ephemeral connected-repository authority—not its cache.

Write authorization never grants reference permission. Every reference in the new A entry is validated from A's perspective under the resolve-or-block invariant in 20260628-130400-d-cpt-uh0, and may cross to B only if A independently declares B as a dependency; originating in B, possessing A credentials, or selecting A as a target cannot create an implicit reverse dependency. No dependency is auto-added. This refines the independent-write boundary in 20260529-131915-d-cpt-v8t by allowing deliberate authorized mutation of another graph while preserving its one-way reference and within-graph lifecycle rules, and refines the immutable project binding in 20260712-104530-d-tac-1mb by distinguishing a session's stable home project from a submove's explicit mutation target.

A guided `capture-upstream` procedure applies the primitive: confirm B declares A and that A owns the work; capture a self-contained native A entry first; then optionally capture meaningful source-side reasoning in B with the legal B→A reference; finally return to the originating move in B. A-first ordering prevents dangling provenance, and no B bookkeeping entry is created automatically. The optional B capture is a separate confirmed mutation rather than a distributed transaction. The attached design records the target-aware capture contract, procedure stages, failure ordering, and rejected alternatives.
