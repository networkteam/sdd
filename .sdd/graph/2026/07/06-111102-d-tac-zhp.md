SDD's auto-commit must fail fast and forward the error, never hang or silently swallow it. Across all auto-commit paths (`new`, `summarize`, `wip`, `init`, `lint --fix`, `rewrite`), run the `git commit` subprocess detached from any controlling terminal (a new session) and under a context timeout, so a signing or credential prompt that cannot be answered fails immediately instead of blocking on SIGTTIN. Commit failures then propagate as real errors to the caller (MCP tool result or CLI exit) rather than being printed as a stderr `warning:` and continued past. The written entry file stays on disk for durability, but the failure is surfaced and dealt with, not hidden — durable but loud. This closes the auto-commit hang gap by committing to a remedy, keeps what the graceful-degradation design (s-prc-1yb) actually cared about while dropping its silent-fallback behavior, and realigns the commit path to the CQRS discipline that handlers return errors (d-cpt-ah1).
