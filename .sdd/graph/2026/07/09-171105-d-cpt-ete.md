Bare cross-repo ID resolution drops local-first precedence and instead resolves against the union of the local graph and its declared dependencies as one flat candidate set, deduping framework-shipped embedded entries by bare id and erroring on any genuine ambiguity. This sharpens the resolution rule of the just-made bare-ID decision (20260709-164325-d-cpt-xbx): where that decision resolved local-first then across declared dependencies, resolution now treats local and declared-dependency matches as one candidate pool with no precedence — exactly one distinct entry resolves, more than one errors with the candidates listed (the local match in bare form, foreign matches in full repo-id-prefixed form), and zero is a not-found. Two coupled changes make this coherent. First, embedded/base entries — framework-shipped facts and procedures merged into every graph on load (20260707-140544-d-cpt-dtv) — are deduped by bare id in resolution, collapsing the copies that necessarily appear in the local graph and in every declared dependency into a single candidate resolved to the current graph's own instance (so a project-superseded base entry keeps its local status). This is the resolution-path twin of the by-bare-id dedup the cross-repo implementation already applies to traversal and search (20260707-175137-d-tac-i6f), where exactly one copy surfaces; without it, flat-set resolution would false-collide every base-entry id across the local graph plus N dependencies. Second, dropping local-first is deliberate and explicit: local-first would silently prefer a local match and hide a genuine cross-repo suffix collision — the opposite of the collision-avoidant, explicit posture the cross-repo design bought, and inconsistent with the 'honest rather than magic' collision handling the original bare-ID decision already applied across declared dependencies. Accepted cost: a local short id can begin erroring once a connected dependency carries the same type-layer-suffix, where local-first would have resolved it silently — tolerable because short ids stay unique within a single graph, so only a genuine cross-graph collision trips it, and the full or repo-prefixed form always disambiguates. Stored references remain full-prefixed exactly as before; this changes only how a typed bare id is resolved, at every surface the prior decision named — the `sdd show` CLI command, the `show` MCP tool, and move anchor resolution.
