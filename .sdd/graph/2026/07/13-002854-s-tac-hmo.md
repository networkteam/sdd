Slice 3 of the public project-aware application plan shipped in commit 75eeaa5, converging structured and filesystem storage on the public ports while the existing MCP server remains unchanged. BuildSnapshot is now the single in-memory validation and indexing path: structured EntryDocument inputs and LoadSnapshotFS both delegate to it, embedded procedures join exactly once, and tests prove the two inputs construct the same graph without requiring a host path or Markdown materialization for structured stores.

The local FilesystemGraphStore owns content-derived revisions, expected-revision Apply, storage-neutral document bytes, staged attachment verification and paging, and mutation reconciliation. FilesystemSessionStore retains the local append-only JSONL shape behind version-CAS Append, while FilesystemStagedBlobStore provides immutable owner/session-scoped bytes plus durable retention metadata. Functional adapters connect embedding, index, and raw LLM mechanics without exporting internal types. The reusable conformance suites now run against every one of these local boundaries.

Full repository tests, full go vet, and the external nested-module tests pass. Two durability details remain deliberately assigned to Slice 5 rather than hidden here: filesystem graph reconciliation is process-local and a multi-file OS failure may return unknown, while session CAS currently serializes within one process rather than fencing independent processes. This partially realizes 20260712-234500-d-tac-x1m; Slice 4 remains next.
