Removed the summary-hash machinery from the sdd CLI and moved summaries to the on-demand, no-staleness model: `sdd summarize <id>` now regenerates unconditionally, `--all` fills only entries that have no summary (`--all --force` regenerates every entry), and `sdd lint` flags only missing summaries. Dropped the `SummaryHash` field and its `summary_hash` frontmatter tag, `ComputePromptHash`, the summarize skip-by-hash logic, and lint's `validateSummaryHashes` (both the stale-hash and summary-without-hash warnings). The ~500 existing files that still carry a `summary_hash:` key load cleanly — the unknown key is ignored by lenient YAML — and shed it on the next regeneration; no migration, per d-cpt-4qi.

This closes s-tac-pfn (the cascading re-summarize treadmill) and s-tac-gcd (born-stale `--attach` entries) at the root: both were symptoms of a skip-hash computed over the full rendered prompt — which embedded neighbor summary prose and a read-order-dependent attachment list — and under entry immutability that hash guarded against a change that cannot occur. It completes the plan d-tac-y7l.

Beyond the plan's stated scope, and confirmed in dialogue with Christopher: with the hash gone, the summary prompt's on-disk-ref-kind rendering became vestigial (its sole purpose was hash stability across the grounds/evidence → grounded-in rename, s-tac-koz), so the summary prompt was unified onto the single canonical `FormatEntryForPrompt` render already used by pre-flight, and the now-dead `model.Ref.onDiskKind` field and `OnDiskKind` method were removed. Because `MarshalYAML` always wrote the canonical kind, this never touched serialization; the only observable effect is that a legacy grounds/evidence entry renders `grounded-in` in its summary prompt on next regeneration.

All eight acceptance criteria met, verified by `go vet ./...`, `go test ./...`, and `golangci-lint run ./...` (all clean, with new tests for legacy-key load, missing-summary lint, and all three summarize modes) plus live smokes on the 900-entry graph: `sdd lint` reports no issues and zero hash warnings; `sdd summarize --all` skips every already-summarized entry with no writes; `sdd show` renders no `summary_hash` on a legacy entry whose file still carries the key; the CLI reference was re-rendered via `sdd init` and the Codex skills validate.
