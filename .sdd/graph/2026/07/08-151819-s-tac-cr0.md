Outer validation of cross-repo references in first real multi-graph use finds the mechanism sound and useful, but not yet comfortable to live in for a real workflow. This evaluation (grounded in the evaluate procedure, 20260703-200000-d-prc-evl) covers the outer/validation lens only; the inner/verification lens was already carried by the PR #2 code-review round (20260708-090449-s-tac-vyq) and its remediation, so this run builds on the implemented work (20260708-010505-s-tac-94a) by exercising it in genuine use rather than re-reading code. Plan: connect a real second graph and judge whether cross-repo refs actually let reasoning reach across repository boundaries and serve someone working across two graphs. Evidence: Christopher connected a real second graph one-way to the sdd framework graph (the second graph referencing sdd, never the reverse); `sdd init` derived and stamped sdd's repo_id from its git remote and `sdd repo add` resolved it cleanly (both worked first time), and merged cross-repo search returned results across both graphs with relevance ranking that looked reasonable across repositories — the core promise validated. But usability gaps the two-repo lab fixture never exercised surfaced in use: the user-global config is a cross-repo-only schema that silently drops participant/llm placed there (proven by `sdd lint` reporting no participant), forcing per-repo duplication; the vector index is embedded a second time per machine when a repo is both developed and connected (129 MB local plus a separate cache index), with worktree sharing riding on a Claude-Code-only file copy; long operations run with no progress — the first cross-repo search's index build took ~35 minutes of silence — despite the done's claimed conformance to the terminal-experience architecture; and connections live only in the per-user global config, with no committed per-repo declaration of which repos a graph depends on, so a cloner cannot know what to connect. Verdict: the mechanism is right and works; ship-usable for a motivated dogfooder, not yet for the non-developer / hosted audience the strategic aspirations target. Seven findings are surfaced by this evaluation — config overlay, connections as committed directed dependencies, index storage, terminal UX, latency, docs, and a unifying insight that config sits in the wrong layer in both directions; notably the connections finding would also make the one-way guarantee structural rather than a discipline. The capture-time resolve-or-block, cross-boundary show traversal, and remote status rendering were not exercised and are deferred to a second round.
