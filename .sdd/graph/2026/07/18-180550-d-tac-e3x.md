The session-model contract (20260718-131626-d-cpt-9of) is realized in five code-grounded slices — merge-clean graph applies, handle-addressed tools with free discovery, holder-machinery deletion with attachment stamps, structural consent with informative conflicts, and converging reorientation with a shell-composed slim door — a net deletion that removes the lease branch matrix, the time-dependent test class, and one CAS append per engine operation while adding only a required session argument, a consent check, a cause enum, a lane-declaration spec surface, and a bounded retry loop. Every design decision is settled here and in the attached register; implementing sessions inherit decisions, not guesses.

Slice 1 (independent, first — it stops the recovery-queue pollution hurting live dogfooding): `applyOnAcquired` currently revalidates a prepared write against a fresh snapshot and then applies against the minutes-old prepare-time revision pin with no retry, filing every lost race into explicit recovery. It changes to apply with the revalidated fresh revision, keeping the pin as provenance in the durable intent, plus a bounded mechanical retry — three attempts, engine-internal, invisible to the agent, never re-running pre-flight or summary — because the filesystem adapter's lock is per-call, so a concurrent process can still write in the milliseconds between the fresh read and the apply. Exhausted retries fail typed as the existing graph-conflict error inviting a plain re-try; the recovery queue becomes reachable only for unknown outcomes and non-conflict failures. Both write paths (entry creation and summary replacement) and the recovery replay verbs get the same treatment.

Slice 2: the session handle becomes required on every work tool (next, start_procedure, park, stage_attachment, abandon-by-instance) — the agent carries the handle always, identically over stdio and remote, with no connection-default resolution; the deliberate exception is resume_session, whose optional handle is the compaction escape (no-args on an attached connection re-serves its own session, no-args unbound returns the session list). Connection state shrinks to two reconstructible caches: served-block dedup and consent memory. A connection holds one attached session at a time; attaching to another applies the existing leave rule to the previous with cause switch. A stateful call naming an unattached session fails typed into the attach funnel (resume_session) from this slice on; list_sessions and named attach work on fresh unbound connections; listings show every session with open work, labeled active or idle by attachment recency instead of hiding held ones; server instructions and tool descriptions are rewritten to the handle-carried model so description and implementation match exactly, pinned by the tool-contract snapshot test.

Slice 3: the holder lease is deleted — TTL table, expiry, liveness flag, generation fencing, and the per-operation bind append — and replaced by an informational attachment stamp (subject, client, MCP session id, last activity) riding each event append's metadata, with an attachment history whose causes form a closed six-value enum (disconnect, switch, shutdown, claim, conclude, abandon) and whose claim records carry the consenting user words for auditability. Serves become pure reads; recency stays truthful because read-log appends stamp. Binding verification reduces to subject/project immutability plus version CAS; legacy session files with holder JSON load tolerantly under the unchanged codec version (in-place store evolution); session status becomes derived-only, so a server killed without a leave event still classifies correctly.

Slice 4: attaching to a session this connection did not open requires the user's verbatim ask, and attaching to one whose stamp is recent (15-minute constant, one definition for both the takeover requirement and the listing label) additionally requires an explicit takeover flag, with the current attachment named in refusal and success. Cross-device hot handoff mid-move is an explicit non-goal — what survives an attach is the session log only (step position, state fields, staged blobs, label), never the other agent's conversational context — so attach-from-elsewhere targets idle or parked sessions, where junction-parked work resumes with near-full fidelity, and takeover is a sovereignty escape hatch (hung client, runaway autonomous session) whose response states the fidelity limit honestly. A displaced writer's append fails typed as session-displaced, naming who advanced the session and when, distinguished from the benign same-writer version race that reloads and retries invisibly; an abandoned session's still-attached client is told actor, time, and reason through the same interpreted-conflict path.

Slice 5: the clear-and-replay on same-session resume is replaced by natural dedup convergence plus an explicit one-shot fullReplay for agent-declared context loss, preserving the compaction recovery capability. Framing composition moves from a hardcoded Go constant into the shell procedure's spec: the engine always supplies the info block (participant, language, search modes), and all other lanes — aspirations, guiding directives, focus, participants, a byte-capped recent-moves lane, the open-work count — are declared by the shell entry and rendered through the existing injection mechanism, so autonomous shells can declare less and projects can reshape framing without touching Go. Other dialogues are never pushed on any serve: session entry carries a one-line open-work count, junction serves (move-end, resume, conclude) list this dialogue's own threads only, and the full labeled listing exists solely on demand via list_sessions.

Ordering: 1 independent and first; 2 → 3 → 4 sequential (3 removes what 2 routes around, 4 needs 3's stamp for attribution); 5 after 2, parallel to 3/4. Each slice lands with vet, lint, full tests, and a commit-citing done signal; implementation sessions run engine mode so the work dogfoods the surface it changes. Deliberately out of scope: a dialogue fork tool, observer mode, a door verb merge (semantics change, tool names stay), resume-fidelity improvements beyond honest surfacing, and grooming the existing pending-recovery backlog. The attached implementation notes carry the seventeen-entry settled-decision register, file-level mappings per slice, the retry design, the metadata schema change with compatibility notes, and per-slice test lists.

## Acceptance criteria

- [ ] Two sessions capturing interleaved with an artificially slow LLM stage both land: no recovery entries, pre-flight runs exactly once per capture; a genuine logical-path collision (same WIP marker path) still fails typed.
- [ ] A graph revision conflict can no longer produce a recovery-required outcome; the recovery queue is reachable only for unknown apply outcomes and non-conflict failures.
- [ ] Every work tool requires an explicit session handle and succeeds on a fresh, unbound connection presenting one, identically over stdio and Streamable HTTP; a call without a valid handle fails typed naming both doors; list_sessions works unbound and lists every session with open work, active ones labeled with client and recency, never hidden.
- [ ] The holder lease machinery is gone — no TTL table, no expiry, no liveness flag, no per-operation bind append: each engine operation performs at most one session-store append, carrying the attachment stamp, and serves perform none. Legacy session files with holder metadata still load.
- [ ] Incumbent continuity holds by construction: with any elapsed time and no competing claim, the driving client's next operation succeeds — verified clock-free because no expiry exists to inject.
- [ ] Attaching to a session this connection did not open without the user's verbatim ask fails typed (the mwd regression); attaching to a session stamped within the 15-minute recency window additionally requires the takeover flag; refusal and success name the current attachment, and the takeover response states that only recorded state resumes.
- [ ] A displaced or raced writer's session append fails typed naming who advanced the session and when, and a subsequent reorientation succeeds (the 2sp regression); the benign same-writer version race retries invisibly; an abandoned session's still-attached client is told actor, time, and reason.
- [ ] Repeated resume calls converge — identical blocks stub and payloads are monotonically non-increasing — while an explicit fullReplay serves the complete position exactly once; no-args resume on an attached connection re-serves its own session (compaction escape preserved); a reorientation response never exceeds the original serve.
- [ ] Every attachment lifecycle record carries a specific cause from the closed enum and claim records carry the consenting user words; the bare "released" reason no longer exists; session status is derived from the store alone, verified by killing the server without a leave event and classifying correctly on next start.
- [ ] Framing lanes are declared by the shell procedure's spec and rendered through the injection mechanism, with the engine-supplied info block the only fixed part; the hardcoded framing layout constant is deleted; the default shell's door payload — info block, declared lanes, open-work count line, no session listing — is asserted ≤ 25KB in a test.
- [ ] No serve pushes other dialogues: session entry carries the count line only, junction serves list own threads only, and the full labeled listing is reachable solely via list_sessions.
- [ ] Tool descriptions and server instructions match implemented behavior exactly, pinned by the tool-contract snapshot test; wording stays host-neutral.
- [ ] go vet, golangci-lint, and the full test suite are green; the sddtest session-store and graph-store conformance suites are updated to the new metadata shape and merge-under-append behavior and pass for all shipped adapters.
