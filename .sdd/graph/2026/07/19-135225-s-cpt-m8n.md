How should procedure state become generically servable — projected into serves by declared policy at one seam instead of a hand-added Go field per element — and is the engine-owned typed state model itself the right long-term shape for what procedures can express? Raised by Christopher while accepting the contained resume-projection slice for the handover-fidelity invariant (20260719-124405-d-cpt-0tm): the slice stops the observed asymmetry (20260719-123350-s-cpt-hkx), but its implementation shape exposes a recurring pattern — every agent-visible element of a serve is a specific Go field threaded by hand through three stacked mappers (engine serve → workflow serve → MCP result), so each future addition needs its own careful handling of size capping, served-once dedup, trust-field exclusion, and projection timing, and the same question will be re-answered field by field. Two directions are bundled here. First, generic projection: the instance store is already a provenance-tagged map that survives replay, so serves could carry durable state declaratively — one projection seam applying uniform policies (per-value truncation with omission notices, dedup blocks, trust-machinery exclusion, resume-only vs. every-serve timing) driven by the state declaration rather than by Go plumbing; the attached sizing study maps the three mappers and the option space this reasoning comes from. Second, the state model itself: procedures declare state fields in spec frontmatter against an engine-owned type vocabulary, and whether a value reaches the agent depends on engine plumbing — does that ceiling limit what procedure authors (including project-local procedure authors) can express, and would an opened model — richer or extensible value types, author-declared per-field serve visibility and policy — be the right refactoring? Acknowledged as a larger engine-refactoring topic, deliberately captured as a question rather than a commitment: the full d-cpt-0tm projection-boundary design (filtered trajectory, completed ancestors, compression labeling) should start from this question instead of rediscovering it, and any answer must keep serve-size discipline and host-neutral operation intact.
