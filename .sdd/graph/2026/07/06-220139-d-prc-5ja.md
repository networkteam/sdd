All static base procedures shipped in the binary carry the topic `engine/base-procedures`. The embedded base procedure set that `LoadGraph` injects into every graph currently carries no topic at all, so it can't be surfaced as a family through topic filters or heat in `sdd view`, even though the procedures appear in the graph like any other entry. This directive clusters them under `engine/base-procedures` — the label coined while capturing the plan-authoring-procedure gap (s-prc-38f) — so the static base set is discoverable as a group. Because these procedures are embedded and regenerated from source, shipped by the engine build (d-tac-ry0), applying the topic means editing each embedded definition and re-shipping. Adding a topic is a mechanical, non-semantic change under entry immutability, so no supersession is required: the definitions are amended in place rather than superseded.
