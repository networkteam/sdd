The bootstrap flow lives only as a Claude Code skill that contradicts itself, and it has no engine procedure — an open blocker for retiring the /sdd skill family. The contradiction is concrete: the sdd-bootstrap skill's frontmatter description orders actor capture before the Golden Circle strategic seeding, while its playbook body runs the Golden Circle first (experience gauge → identity → what → how → why → actors → hand-back) — an agent following the skill must silently pick one. It surfaced during the docs example-world pilot (20260715-183740-d-cpt-jrt), where scripting the bootstrap dialogue required reading the skill closely and both production rounds tripped over the mismatch: the first followed the description's order, the review-driven revision re-ordered to the body and had to rename five fabricated entries to keep timestamps coherent. The deeper half is structural: bootstrap is part of the base experience — a fresh project's first contact with SDD — yet the engine serves no bootstrap procedure, so in engine mode the arc (readiness sweep, context gather, actor capture, strategic seeding, catch-up hand-back) exists nowhere. The engine-main-mode directive (20260715-175731-d-cpt-p3k) commits /sdd and its sibling skill renders to deprecation, and that retirement cannot complete while bootstrap remains skill-resident. Resolution direction per Christopher: a follow-up session that fixes the skill's internal contradiction and ports bootstrap to a procedure — the same skill-to-procedure move already committed for the release workflow (20260707-143547-s-prc-tso), with the difference that bootstrap belongs to the base procedure set, so host-neutrality applies to its served instructions.
