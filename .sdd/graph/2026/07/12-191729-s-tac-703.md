Cross-repository attachments cannot be read through the MCP `read_attachment` surface even when the owning foreign entry resolves successfully. This was observed from another repository while consuming the detailed plan attached to 20260712-104530-d-tac-1mb: `show` returned the full entry and reference chain for the qualified ID, while `read_attachment` reported `entry not found` for both the qualified and bare forms. Source inspection confirms the mismatch: `show` resolves typed IDs across the local graph and declared dependencies, but `ReadAttachment` looks up the caller-supplied ID directly in the local graph's `ByID` map and always joins the attachment path against the local graph directory; the MCP attachment handler also omits the qualified-repository cache refresh performed by `show`. The failure leaves the attachment-read commitment in 20260606-004059-d-tac-d21 incomplete across repository boundaries, contradicts the usable cross-graph read direction in 20260606-003344-d-cpt-s6q, and misses the uniform typed-ID resolution rule established by 20260709-164325-d-cpt-xbx. A correct read must resolve the entry across the graph union, retain its owning repository and graph directory for path access, and cover both qualified and uniquely resolvable bare IDs without bypassing declared-dependency or ambiguity rules.
