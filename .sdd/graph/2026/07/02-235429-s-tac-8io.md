Slice 2 of the v1 workflow engine plan is complete: the engine core shipped as `internal/engine` — typed spec parsing of `params`/`state`/`steps` at engine load (the boundary the type-system revision contract set, with the model retaining the raw frontmatter for lossless round trips), the typed variable store with the report trust boundary (reports write declared state only; trust-bearing values are engine-written per command contracts), the predicate-only guard grammar, the closed registry with built-in pre-flight predicates and the confirmPlayback/playbackConfirmed staleness pair (edit-after-confirm reopens the recording chooser), gate-transition cascade with sequence-validated choosers (no early, late, or double answers), JSON report schemas generated from collect lists and variable declarations, and append-only JSONL session logs whose replay re-validates logged values and never re-runs side effects. Shipped in commit 79ee276; per-procedure table tests drive a capture-shaped fixture through one-shot batch drafting, revise/override routing, edit-after-confirm reopening, abort, and restart-by-replay. This satisfies the plan's second acceptance criterion and the log-replay half of the third; list_sessions and resume_session land with the MCP shell (slice 3).

Two spec-authoring findings carried forward to the base capture procedure (slice 4): the optional-field marker (`intent?`) is invalid YAML inside flow lists and must be quoted or written in block form (the engine parses the marker regardless of YAML form), and chooser-collected evidence fields (fidelityNote, correctedSummary) must be declared in state per the reports-write-only-state rule — the surface spec's illustrative fixture omits both. Graph-coupled queries (viewLayout, entryChains, sessionInfo, generatedSummary) and effectful commands (newEntry, replaceSummary, wipStart, wipDone) deliberately register with the shell that owns their dependencies, keeping the engine core free of side effects and the write path single (slices 3 and 4).
