Engine sessions get a human-meaningful label so a user offered several parked dialogues can tell them apart: agent-supplied with a derived fallback. The loop tools `start_procedure` and `next` accept an optional single-line `label` field (length-capped) the agent may supply on any turn and update as the dialogue's subject sharpens; the shell appends it as a session-scoped labeled event, and the descriptor fold takes the last one. When no label was ever supplied, the descriptor falls back to the first line of the most recent drafted body in the log; when neither exists, the label stays blank — an honest signal that nothing was drafted. Labels are session-scoped, not per instance: resume operates on sessions, and open instances already carry procedure and step. The instruction side stays agent-agnostic and procedure-free: the tool schema documents the field, and the framing block carries the base line (label the session, update when the subject sharpens) — no per-procedure prose. `list_sessions` and the `resume_session` briefing surface the label.

The naming is pinned alongside, because the label design forced the question of what the user-facing unit is: an sdd session is one dialogue — that it can outlive the agent session that started it is a tooling accident (crash, closed window), not the concept — and procedure instances are narrated in dialogue as threads, the strands within a dialogue (this capture, that interview), following the procedure/move vocabulary-register pattern. The formal vocabulary keeps `session` and `instance` in tools, log, and spec; no tool renames — a considered rename of the session surface to "threads" was rejected because it would relocate the overload, not remove it. The framing prose teaches the distinction once.

This sharpens the v1 workflow engine plan's MCP-shell commitment (20260702-220449-d-tac-ry0) and deliberately widens the surface its spec declared exact (§5): two tool inputs gain an optional field, recorded here rather than slipped in. It extends the shipped descriptor machinery — the fold over the append-only session log (20260703-002223-s-tac-kd2) — so persistence, restart survival, and update history come free from the log. It closes the session-descriptor gap (20260703-111915-s-tac-wy7) by settling its open question: agent-supplied and derived are combined, supplied winning over derived. For the implementing agent: a session-scoped labeled event constant in the engine (replay-neutral — session metadata, no instance state), the two tool inputs plus fold and fallback in the shell, one framing line, and tests for the fold (set, update, fallback, blank), the MCP round trip, and restart replay with the label intact.
