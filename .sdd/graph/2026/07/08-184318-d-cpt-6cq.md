Every kind of SDD configuration and state is placed by whose fact it is — user/machine preferences go user-global, repository identity and dependencies go committed per-repo, per-machine derived state goes to a machine-global cache — replacing the placement-by-convenience that the cross-repo outer validation exposed. This commits the rule synthesized by the unifying insight (20260708-170802-s-cpt-une) across three findings, giving each fact its target home. First, user/machine preferences — participant, llm, embedding — live in the user-global config as the base of a unified overlay: global base, overridden by the committed per-repo .sdd/config.yaml, refined by the per-machine .sdd/config.local.yaml, CLI flags last. The schema shape makes sharing and distinctness explicit: the shared settings form one BaseConfig embedded by both location schemas — GlobalConfig is BaseConfig plus the global-only fields (the `repos` per-user resolution), PerRepoConfig is BaseConfig plus the repository's own fields (repo_id, graph_dir, supported_agents, skill_scope, language, and the `dependencies` declaration) — and .sdd/config.yaml and .sdd/config.local.yaml both parse as the same PerRepoConfig schema, the local file overlaying the committed one with genuinely machine-specific overrides. Unknown or wrong-file keys fail loud instead of being silently dropped, and an `sdd config` surface creates the file, gets/sets keys, and prints the effective merged config (addresses 20260708-153545-s-cpt-m4j). Second, repository identity and dependencies are committed per-repo: repo_id (never user-chosen, never inherited from a global default) plus `dependencies` — the directed list of repo_ids this graph references, declared in .sdd/config.yaml the way go.mod declares modules — while the global `repos` field stays the per-user resolution (clone URL, homedir cache) for how this machine reaches each dependency (addresses 20260708-164349-s-cpt-9ql). Directedness thereby becomes structural: resolve-or-block (20260628-130400-d-cpt-uh0) gains the precondition that a cross-repo ref resolves only if its repo_id is a declared dependency of the referring graph, so the one-way guarantee holds by construction rather than by registry discipline; `sdd repo add` writes both records, and `sdd init` reads the declared dependencies on a fresh clone and prompts to connect each missing one. Third, per-machine derived state — the vector index — lives in one machine-global, content-addressed store under the cache root, one index per (repo-id, embedder-fingerprint), shared by the checkout, its worktrees, and the connected cache, with no .sdd/index in the working tree (addresses 20260708-164528-s-tac-eql); this ends the double embedding of a repo that is both developed and connected, and drops the Claude-Code-only .worktreeinclude index copy, honoring the agent-agnostic foundations (20260628-123931-d-stg-dn6) and leaving the worktree lifecycle fully outside the CLI per its standing scope boundary (20260628-130403-d-cpt-h4l) — the skill-recipe index carry-over that boundary's chain carries becomes unnecessary. This refines the cross-repo design (20260606-003344-d-cpt-s6q) in place: sdd-managed homedir caches, cross-graph discovery scope, and the single shared embedder stand; what changes is where connections are recorded (committed per-repo dependencies rather than only the flat per-user registry) and where indexes live (one machine-global store rather than the local-index-plus-cache-index split). Alternatives rejected: keeping the narrow cross-repo-only global schema (silently drops shared settings, violating fail-loud); connections only in the per-user registry (a fresh clone cannot know what to connect, and one-way holds only by discipline); and per-repo local indexes (their per-participant embedder-freedom rationale is undercut by the single shared embedder cross-repo already committed to). Deliberately left to the implementation plan: keying identity-less repos in the global store, safe concurrent multi-process index writes, and the global-vs-project homes of language, skill_scope, and sync.cooldown.
