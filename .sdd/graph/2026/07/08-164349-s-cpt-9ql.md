Cross-repo connections are recorded only in the per-user global config, with no committed per-repo declaration of which repositories a graph depends on — connections should instead be committed, directed dependency declarations, which also makes the one-way reference guarantee structural rather than a discipline. Surfaced during the outer validation of cross-repo references (20260708-151819-s-tac-cr0): `sdd repo add` writes the connection only into ~/.config/sdd/config.yaml, and neither the current repo's committed .sdd/config.yaml nor model.Config records anything about it, so a fresh clone of a dependent graph carries no list of what it needs connected. Two concepts are being conflated. `repos` is the per-user resolution — for each repo_id, the clone URL (ssh vs https, per user) and homedir cache; it is genuinely global and stays in the GlobalConfig. `dependencies` is a distinct, per-repo concept: the committed, directed list of repo_ids this graph references, declared in .sdd/config.yaml the way go.mod declares modules — portable, so a cloner sees exactly what to connect. The payoff beyond portability: directedness becomes structural. Resolve-or-block (20260628-130400-d-cpt-uh0) gains a precondition — a cross-repo ref resolves only if its repo_id is a declared dependency of the referring graph. A graph that does not declare a given repository therefore cannot capture a ref into it: the block fires mechanically, so the intended one-way direction (a dependent graph may reference the repository it declares, never the reverse) holds by construction rather than by the discipline of not adding the reverse to a flat registry. `sdd repo add` should then do two writes: declare the dependency in the current repo's committed config, and record the per-user clone_url/cache resolution globally. Resolution for a fresh clone rides on `sdd init` — the post-clone / post-update surface every user already runs — rather than a new command: init reads the declared dependencies, checks which the user has not connected, and prompts `sdd repo add <clone-url>` for each missing one; the prompt is required because the clone_url is per-user and not committed, so init knows the repo_id to fetch but not how this user reaches it. This bears on the connected-repos design (20260606-003344-d-cpt-s6q), which placed connections in a flat global registry, and pairs with the config finding (20260708-153545-s-cpt-m4j) that separates the global `repos` field from per-repo `dependencies`.
