An outer validation of the session branch-binding and store-locality plan (20260722-112853-d-tac-ln1), run live against this repository's own accumulated session store, judges the delivered store-relocation and acknowledged-migration slice unusable in real use — though not unsafe. Two blocking defects, folded into one finding at Christopher's direction with fixing treated as urgent. First, the migration cannot read the data it exists to migrate: `sdd init --migrate-sessions` aborted the whole sweep on the first pre-existing session log with `json: unknown field "Holder"`, before any of the 145 in-tree payloads moved. Session logs are bucketed solely on presence of a top-level `version` key — absent means legacy and the file is copied byte-for-byte untouched, present means current and every line is strictly decoded with `DisallowUnknownFields`. The `Holder` field was deleted from the session model on 2026-07-18 (commit c80af3a) without bumping the codec version, so every session written before that commit sits inside the tolerated current bucket while being structurally unreadable, and the codec-version gate cannot distinguish it. The tolerance boundary was drawn once at the pre-0.16 legacy line and then treated as permanent while the format moved underneath it. This regresses against the permanent read-compatibility contract (20260602-203349-d-cpt-i2x), whose conversion-path clause was already invoked once for session persistence, and is a step back from the earlier legacy-session migration (20260714-140424-s-tac-fco), which tolerated old logs and was proven by an isolated end-to-end run over 51 real ones. Second, the committed acknowledgement gate is implemented and unreachable: the confirm does fire on an interactive stdin and does render `[y/N]`, but its prompt string concatenates a two-clause payload census, the instruction to stop every `sdd serve` process and restart agent sessions, and the question into a single ~330-character sentence, which bubbletea's inline renderer truncates at terminal width — the affordance and cursor never reach the screen, the user reads a status line, and the always-default-N resolution silently routes to the declined branch. Christopher's attestation confirms he saw no prompt and no indication a keypress was expected. That defeats the directive committing relocation to run only after explicit user acknowledgement (20260723-192701-d-tac-g7r) and breaches the terminal-experience architecture's per-command UX commitment (20260628-131545-d-cpt-dgk); the machine-shaped prompt text is folded in as the same surface and the same fix. What held is worth recording: the failure was loud, occurred during manifest planning before any payload moved, and left the store intact; detection and counting worked; `sdd serve` started over the leftovers as committed; and the standing relocation notice is present in every serve response. The more valuable half is what the run teaches. The inner verification (20260726-195621-s-tac-0hg) judged this same work merge-ready with zero blockers across four lenses including a data-safety code review, and the first outer run broke on the primary path within seconds — not a lens run badly but a lens never run, since nothing was ever executed against a real historically accumulated store. The graph already held that lesson twice and applied neither: real-tool smoke tests are load-bearing precisely when domain logic is well unit-covered (20260423-145830-s-prc-lgz), and implementer-shaped simulation inherits the implementer's assumptions (20260716-155256-s-prc-686) — a synthetic fixture encodes what the implementer believes a session log contains, and only the real store knew otherwise. This compounds the find-something review-bias insight (20260726-200257-s-prc-cbl): the review regime generated the strict decoding as defensive machinery and then verified that machinery as sound, with the strictness itself being the defect. This run covers the outer lens only; the branch-binding half of the plan is not validated here, as no worktree session was driven end to end. The full evidence record — verbatim run output, code-path citations, the failing payload shape, and the defect analysis — is attached.
