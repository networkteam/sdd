The engine session model is reduced to a two-layer behavioral contract — a durable, CAS-versioned session addressed by an explicit handle that the agent conversation carries, with the MCP connection demoted to transport plus payload cache — deleting holder leases, TTL-derived liveness, connection-gated tools, and revision-pinned graph applies in favor of informational attachment stamps, structural user consent, and cleanly merging appends.

Two live traces ground this. The continuity trace (20260718-112133-s-tac-eqv) established the unbound trap (list_sessions and named resume both require an in-memory connection binding, so a connection that lost it can only mint a new session), replay amplification (resume clears served-once memory and re-serves 55KB+ per reorientation), and the lease anomaly (the TTL is chosen from the pre-transition step, leaving a 2-minute gate lease on a user junction). The consent trace (20260718-113056-s-tac-mwd) established that one resume call switches dialogues with no structural consent — "recommend, never auto-run" lived in prose only. Source reconstruction added two more: an expired-but-active session is advertised as parked to every other connection while its incumbent keeps working, and a held session is entirely invisible to a branched or second client (20260716-122358-s-tac-2sp) — the filter that resolved the live-versus-parked ambiguity (20260706-231416-s-tac-y2z) deleted the information instead of labeling it. On the graph side, a prepared write pins the snapshot revision before its 1–3-minute LLM window and applies against that stale pin with no retry, filing concurrent sessions' writes into the explicit-recovery queue even though revalidation against the fresh snapshot already proved them valid.

The diagnosis repeats three times: a guarantee already supplied by a simpler mechanism was duplicated by a stricter one whose false positives became the regression. Session-log integrity is fully supplied by CAS on append — the holder lease adds attribution, not safety, so the concurrent-hijack gap (20260709-174818-s-cpt-c2i) is answered by CAS plus consent rather than the exclusive hold it pointed toward: corruption is impossible (a raced append fails typed), and a foreign advance is detected at the write and turned into dialogue. Write validity is fully supplied by revalidation under the acquired-target lock — the stale revision CAS adds only false conflicts. And dialogue coherence is a consent problem keyed to the wrong identity: MCP offers no stable carrier for an agent conversation (stdio has no session id; Streamable HTTP re-mints on client restart), so the durable session handle is the cookie — engine-minted, subject-scoped when hosted, carried in the agent's context through compaction-durable channels, presented explicitly on every stateful call.

Eight invariants form the contract. I1: a dialogue's identity is its durable handle, never a transport connection. I2: log integrity comes from CAS and only CAS. I3: time passing never takes a session from the client driving it — staleness changes what others are offered, never what the incumbent can do. I4: discovery is a free read; every session with open work is listed, active ones labeled with client and recency, never hidden. I5: crossing into another dialogue requires the user's verbatim ask, and attaching to an actively driven one additionally requires an explicit takeover flag — a fresh user request is never consent. I6: reorientation converges — repeated resumes shrink to stubs; a full replay is a one-shot, agent-declared request preserving the compaction recovery shipped by the reorientation plan (20260709-160621-d-tac-zm2). I7: every lifecycle change records its specific cause, and session status is derivable from the store alone — a server that died without a goodbye still classifies correctly. I8: concurrent graph appends merge cleanly — entries are immutable, so a write is never failed or sent to recovery because another session appended meanwhile; the recovery queue is for unknown outcomes, never lost races. The governing distinction: the graph is a shared ledger where concurrent appends are the normal case and merge silently; the session log is one dialogue's spine where a concurrent append is the anomaly and surfaces as dialogue.

The user stories the contract serves, refined in dialogue: A1 fresh start — a slim door (recent graph movement in headline form, open work as one line, catch-up and listings as choices; the door must not eagerly advertise other sessions). A2 continue-where-we-left-off — the agent disambiguates what the user means, and the user's words authorize the attach. A3 fresh-by-default when a request merely resembles parked work. B1–B5 survival — client restart, crash, remote transport blips with re-minted MCP ids, hours-long junctions, compaction (one declared full re-serve), and server death without a leave event ever being written. C1–C4 concurrency — parallel sessions in one repo are normal and must not confuse agents; stale-session takeover from another machine with honest fidelity expectations (recorded state transfers, the other agent's conversational context does not); a branched conversation carrying the same handle learns of divergence informatively at its first write instead of a silent lockout, with no dedicated fork tool until a need shows; racing clients never corrupt and the loser is told immediately. D1–D3 stewardship — housekeeping without resuming, abandon as an appended marker whose still-attached client gets told who and why, cause-specific auditability, and every story holding for hosted non-developer participants with subject-scoped sessions and no filesystem assumptions.

This refines the port-contract directive (20260712-194427-d-tac-wjq) in place — expected-revision Apply stays the sole graph concurrency primitive but CASes on the revalidated fresh revision rather than the prepare-time pin, and the exclusive-holder-with-chooser-TTL commitment is replaced by the attachment stamp — and refines the session-operations directive (20260705-010751-d-tac-dbk) by ungating discovery and attach-by-handle while keeping connection-keyed served-once dedup, which genuinely belongs to the pipe. It builds on the closed lifecycle rules (20260704-000621-d-tac-bfc), keeping door-opens-fresh and the shell model while replacing the parked-only listing and binding-gated loop rules. Alternatives rejected: point-fixing the current machinery keeps two ownership models and reproduces the lockout at every future connection/dialogue divergence; a hard single-writer lock wedges sessions behind crashed clients until a force path reintroduces takeover anyway; a fully sessionless surface has nowhere honest to keep payload dedup. Accepted trade-off: two clients that both obtained consent can interleave a dialogue — the log stays consistent, and mitigation is detection at the write, not prevention.
