User-facing config messaging still points users only at `.sdd/config.local.yaml` for participant, LLM, and embedding settings, lagging the settled placement model where those user/machine preferences are canonically user-global. The config-and-state placement directive (20260708-184318-d-cpt-6cq) made the user-global config the base of the overlay and the canonical home for participant/llm/embedding/sync, reserving `.sdd/config.local.yaml` for genuinely machine-specific overrides. But several “not configured” error and help strings, and a couple of skill-template lines, still name only `.sdd/config.local.yaml` as the place to set these — surfaced while documenting the config model for the cross-repo release. Concretely, the “set embedding.provider / llm / participant in .sdd/config.local.yaml”-style messages across internal/llm/embed, internal/llm/factory, internal/llm/gollm, and internal/finders/search, plus the participant-inference guidance in the bundled `sdd` skill template (SKILL.md.tmpl), all frame the local file as where to configure these. They should lead with the user-global layer (or `sdd config set`), naming the local file as the per-machine override — matching what the README now documents. Left as a gap rather than fixed inline: the fix spans several packages and the skill templates (with a re-render), beyond the docs work that surfaced it, and wants its own small sweep so the CLI's own messaging, the skill guidance, and the README all tell one story.
