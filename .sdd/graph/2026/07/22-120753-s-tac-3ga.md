The `factIndex` workflow query shipped with the base-fact index (20260721-152753-s-tac-31o) returns an internal model type through the application composition boundary, the one unclean spot in an otherwise transport-agnostic change. The query hands back `[]model.FactIndexRow` whose `Topic` field is a `model.TopicPath` — a bare `Components []string` with no JSON or YAML tags — while every other public-API surface deliberately uses application-owned DTOs to keep model types off the boundary. The leak is latent today: inject results are rendered only through Go templates, and the dialogue procedure touches only `.ID` and `.Title`, never `.Topic`. But if a served or remote engine ever surfaces inject or query results structurally, the topic would serialize as `{"Components":["cli","view"]}` with capitalized keys instead of the `cli/view` string form used everywhere else — exactly the kind of local/remote-split hazard the inner evaluation (20260722-115503-s-tac-a0o) was scoped to catch. Either of two small fixes suffices: map the query result to an application-level DTO with a string topic, or give `TopicPath` MarshalJSON/MarshalYAML emitting the slash-joined string. The rest of the change keeps the boundary clean — base facts route through the existing embedded-merge path and graph access stays behind the engine's provider abstraction.
