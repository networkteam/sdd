Four architecture remediations are committed for the cross-repo references branch (PR #2) before merge, paying the layering debt the review round surfaced (20260708-090449-s-tac-vyq): a shared model-level cross-repo ID helper, an explicit-locations rework of internal/repos split into a pure Registry and a side-effectful Manager, a new internal/git adapter package absorbing every raw git-execution site, and the index-lint computation moved from the CLI into the finder. (1) The duplicated collectors — crossRepoIDsIn in the CLI, crossRepoIDsOf in the MCP server — collapse onto one pure function in internal/model beside SplitCrossRepoID, restoring push-down and single-path. (2) internal/repos stops reading XDG env vars as hidden globals: a Locations value carries ConfigPath and CacheRoot, and repos.DefaultLocations() keeps the XDG convention inside the package as the documented, testable default while the composition roots (CLI and MCP bootstrap) decide when to apply it — deliberately not moving the env reads into cmd/sdd. On top of Locations sit two abstractions rather than one registry object, following the read/write seam: repos.Registry exposes only pure reads (Connected, CacheDir, IsCloned, GraphDir, IndexDir, DeclaredRepoID, config load) and is injected into finders.Options; repos.Manager wraps the Registry plus the git dependency and owns the side-effectful lifecycle (EnsureCloned, CooldownPull, ForcePull, add/remove-with-save), injected into handlers.Options. The reason for the split: finder purity becomes type-enforced rather than discipline-enforced — a finder physically cannot clone or pull because its dependency has no such method. Config reads stay lazy per call inside the Registry so a long-lived MCP server sees a repo connected from another terminal without restart; tests construct Locations over temp dirs and the t.Setenv workarounds go away. (3) A new internal/git package becomes the single git adapter: the low-level run-git helper (stderr folded into errors) plus the concrete implementations of the consumer-defined interfaces — handlers' Committer/Brancher/Mover/Puller, finders' GitSyncer, and a new narrow repos-side interface (Clone, PullFFOnly) held by the Manager. Interfaces stay defined with their consumers; a single universal Git interface was rejected because sync predicates, committing, and cache clone/pull serve different consumers. The accumulated raw exec code in cmd/sdd/main.go and sync.go migrates into the adapter in the same sweep — folded into this branch deliberately rather than deferred. This confines a possible future swap to go-git to one package with every interface unchanged, potentially partial (clone/pull plumbing first; merge-tree may stay a shell-out); go-git's heavy dependency tree against dropping the git-binary-on-PATH requirement is a cost call explicitly not decided here. (4) populateIndexLint and populateRepoIndexLint move beside Finder.Lint; the CLI keeps only flag-to-EmbeddingConfig resolution, and the deliberate degrade-silently posture (lint never blocks on absent index machinery) moves with the code — with the Registry injected into the finder, the cross-repo lint section needs no CLI-side wiring. Scope is deliberate: this directive moves the new cross-repo surface onto composition-root dependency ownership per the CQRS contract (20260413-142536-d-cpt-ah1) without migrating the six legacy read queries — the open read-side leak (20260507-130356-s-tac-m09) is the same drift family but stays separately scoped.
