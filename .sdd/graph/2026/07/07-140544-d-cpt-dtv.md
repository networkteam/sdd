SDD gains a pull layer for reference knowledge by shipping *base facts* — framework process knowledge bundled in the binary as embedded `fact` signals, merged into every graph exactly as base procedures are, and reachable on demand through search, links, and refs. This is the committed answer to the engine's push-only knowledge gap (s-cpt-7wc): rather than re-introducing skill-style on-demand reference files — the push/skill lineage we are retiring, and Claude-only besides — the reference material lives in the graph itself, so it is agent-neutral, discoverable by the same read tools as every other entry, and one uniform corpus rather than per-harness prose. Base facts reuse the base-procedure pattern wholesale (d-prc-5ja): embedded framework artifacts with no participants and no project refs, injected into every graph, always loaded. Because a base fact is just a graph entry it is linkable from a procedure's instruction units and from other entries, citable as a ref, and — crucially for reach — a project can record a superseding fact to bend the process knowledge for itself, so "how to tweak the process" becomes the same move as tweaking a procedure. The shell's opening serve carries only a small index — a pointer that facts exist and how to reach them, mirroring how the live move list is already served — never the fact bodies, so the served minimum stays small and the knowledge is pulled, not pushed. Two conditions make this real. First, the split between the three knowledge homes is a discipline, not just a layout: facts hold reference knowledge you look up and cite, step instructions hold what-to-do-now and stay disposable, the shell serve holds the irreducible minimum — and guidance must not be duplicated across them, or they drift apart the way the skill and its reference files once did. Second, the finders must treat embedded and on-disk entries identically: `sdd view` already sees base entries through the in-memory graph, but embedded entries have no on-disk file for the search index to build from, so making base facts (and base procedures) findable by vector and text search means the indexer must cover embedded entries too — to a reader there is no difference between a static and an on-disk entry, and the finders must not introduce one. Implementation — the base-facts package and initial fact set, the shell index, and the indexer change — follows as its own plan.
