# Bootstrap parity completion design record

## Relationship to the existing plan

The adaptive bootstrap plan shipped its procedure and passed inner verification, then a two-run outer evaluation found it useful but not at parity. This completion plan supersedes the old active plan so the graph has one current bootstrap commitment. It carries forward the flow that held — adaptive journalist dialogue, brownfield host inspection, meaning-level cluster playback, dependency-ordered materialization, and catch-up handoff — and replaces the assumptions invalidated by live use.

Full type capture is a hard prerequisite. Bootstrap composes the shared capture capability and does not recreate kind validation or composition guidance locally.

## Canonical, actor, and role sequence

Keep frame-before-self-description. The cold opener and early project framing still come first. Immediately before the first graph materialization, confirm the configured participant's canonical name lightly for attribution; this is not the actor interview. A graph with zero active actors already operates in participant-canonical grace mode, so framing entries can be recorded without inventing an actor first.

When dialogue opens the actor/role lens, resolve active actor heads and aliases from the graph. Reuse a matching canonical rather than reconfirming known identity. If no actor exists, ask for the stable canonical, aliases, and external identity/background, then capture the actor. Capture the project role separately: the stable contribution, authority, or domain weight held here, not current tasks or the present sprint. Role binds to the active actor head.

Add an exact workflow regression: capture actor, supersede it with the same canonical, then capture a role referencing the new active head. The current source appears already to exempt same-chain canonical reuse and require active actor heads. Therefore the test comes first; if it passes, close the evaluation gap as already resolved, and if it fails, repair the shared validator rather than adding bootstrap-specific exceptions.

## Topic founding

Existing stable labels may be reused inline. Newly proposed labels are withheld while the first cluster is captured; on an empty graph those founding entries therefore carry no new subject topics.

After child captures return their IDs, the founding step obtains the current live entries and existing topic state through a pure query/finder path, not agent reconstruction. It serves a proposed nested vocabulary plus an explicit label-to-founding-entry assignment map at a user chooser. The user may accept or reshape it. Only after acceptance does bootstrap dispatch annotation capture moves referencing the founding IDs and carrying structured annotation-topic assignments. One coherent annotation is the default, but the procedure may split the landscape into multiple annotations when that better preserves meaning. Subsequent captures reuse the accepted labels inline.

This design accepts a small post-capture founding beat because immutable entries must not receive provisional labels that later change. Annotation is the domain's retroactive clustering mechanism, so no entry rewrite is needed.

## Parity and retirement

Repeat live outer evaluation on an empty greenfield graph and a sparse brownfield repository after full type capture and bootstrap changes ship. Verify that the strengths from the first evaluation remain, actor/role composition no longer causes restarts or overrides, only relevant capture guidance appears, canonical attribution is confirmed without front-loading self-description, and topic signoff produces assignments that actually apply to founding entries.

If the live comparison establishes parity, record the retirement verdict and phase the legacy surface out under the engine-primary directive. If not, retain it and surface the remaining differences as explicit gaps.
