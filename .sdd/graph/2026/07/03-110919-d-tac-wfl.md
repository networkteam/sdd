`sdd init` should make engine mode work out of the box for each supported agent: register the SDD workflow MCP server and pre-allow its tools, so a fresh session can drive procedures without manual setup or per-tool permission prompts. The first engine dogfooding session (slice 4 of the v1 workflow engine plan, 20260702-220449-d-tac-ry0) was blocked before the loop started: the engine bootstrap skill assumes the procedure tools are present, but no setup step registers the server — the fix was manual. For this repo the setup now ships committed: a project-scope `.mcp.json` invoking bare `sdd serve` (resolving through the devbox PATH to each user's dev build) and an `mcp__sdd__*` allow rule in the shared `.claude/settings.json`. `sdd init` should generalize exactly that pair: per supported agent, install or refresh the project-scope MCP registration and tool allowance alongside the skill render — `.mcp.json` plus settings for Claude Code, the equivalent config for Codex and future harnesses — following the standing pattern that agent-specific config is a cheap per-agent layer rendered from neutral intent (20260628-130414-d-cpt-kvb). Open design for implementation: the per-agent config formats, and how init treats registrations or permission entries the user has modified.
