Both defects that made the acknowledged offline session-store migration unusable on a real store are fixed, verified against copies of this repository's actual store, reviewed, and committed on branch worktree-relocation-readcompat (c058406, d75158a, 8697ee6). This retires 20260726-203525-s-tac-q8r: the migration now reads every session shape sdd has written, and the acknowledgement is visible and navigable on a real terminal. One clause of that gap does not close with it and is named below rather than quietly absorbed.

Read-compatibility (c058406). The codec now records its own history in one place: RetiredSessionMetadataFields names, per codec version, the top-level metadata fields that version wrote and the model has since dropped — for codec 1, the Holder and HolderHistory pair the holder-lease deletion removed in c80af3a. A single decodeSessionLine skips exactly those before the strict decode; every other unknown field still fails, so strictness keeps working as a drift alarm instead of being deleted wholesale. SupportedSessionCodecVersion replaces equality on the seven read gates (session_runtime ×2, recovery, workflow ×2, sessionrelocate ×2) so a future bump converts old shapes rather than rejecting them, while the two assertions in local_sessionmigration.go stay strict equality — they verify a session sdd has just prepared, which is a write-path claim, not a read-compat one. This restores for session persistence the conversion-path rule the permanent read-compatibility contract (20260602-203349-d-cpt-i2x) states, following the tolerate-and-convert shape of the earlier legacy-session migration (20260714-140424-s-tac-fco). Deliberate deviation from the dialogue's first instinct: SessionCodecVersion is not incremented. A codec-2 log would be byte-identical in shape to a post-c80af3a codec-1 log, so the increment would carry no information; the version that should have moved was at the deletion commit and is not retroactively available. The retirement table's doc comment makes the bump a requirement at the next real field removal, and states plainly that the table reaches top-level metadata keys only — a field retired from a nested type would need decode traversal that is deliberately not built for a case that has not occurred.

Visible acknowledgement (d75158a). Wrapping is fixed once, in the shared TUI layer, not per prompt: wrapPromptText is applied by the confirm, select and multi-select views once a WindowSizeMsg reports the width, closing the truncation class for every prompt rather than this instance, per the terminal-experience architecture (20260628-131545-d-cpt-dgk). The confirm's affordance moves to its own line. The relocation prompt itself becomes a select whose options are always on screen, cancel maps to decline, and heading, one line per pending item, precondition and question each occupy their own line — so the acknowledgement the directive requires (20260723-192701-d-tac-g7r) is reachable in practice and not merely present in the code path. Both the prompt and the non-interactive notice render from one pendingItems list, so the two surfaces cannot drift.

Proven the way the defect was found (20260726-204112-s-prc-ogp), not by tests alone. Against a copy of the real store isolated by XDG_STATE_HOME and HOME so the machine-global store was never touched: one `sdd init --migrate-sessions` relocated all 145 payloads and exited 0; a second run did nothing, idempotent; every source payload reconciles against the destination with none missing and none extra; no migrated log retains Holder; project identity is rewritten, participant preserved, the tombstone left, and `sdd info` no longer reports a pending transition. On a real pty, arrow-up plus Enter performed an actual migration and Escape declined — the prompt is live and navigable. Gates clean throughout: go vet, golangci-lint (0 issues), and go test across local, application, cmd and internal/cliout.

The same discipline corrected two wrong conclusions of mine mid-run, which is the point of it: an apparent copy-without-delete bug was my own harness SIGPIPE-ing sdd through `head`, and the retired-field set turned out to be a pair rather than just Holder only because the real store was scanned instead of the diff read.

An independent review returned no blockers, and checked rather than accepted the load-bearing claims: that the intermediate re-encode never reaches disk because copySessionLog re-marshals the decoded line anyway, that json.RawMessage payloads survive byte-identical, that tolerance is genuinely scoped per codec version, and that the real store decodes under the new reader. Its findings produced 8697ee6, which pins the prompt's safety property — nothing had asserted that enter preselects declining, and dropping that cursor would make relocating the enter-key default, the same silent-default failure in the opposite direction — drops a tautological assertion comparing description() against its own input, and corrects the retirement table's overstated reach. One review note was declined rather than fixed: the relocation header omits the navigation hint its sibling prompts carry, which is real but is polish on a surface the promptkit adoption (20260727-011759-d-tac-nq7) will replace.

What stays open, deliberately. The gap also stated that one unreadable payload must not abort the whole sweep. This repair removes the cause that was aborting it, but not the general property — a different unreadable payload would still stop the run. Adding per-payload resilience means writing it into transaction machinery that 20260726-195959-s-tac-wg5 is already committed to collapsing, so it is deferred there by explicit decision rather than dropped, and belongs in that consolidation's scope. Also recorded during this run and not implemented here: the promptkit adoption, which is expected to delete the width plumbing this repair added — landing it inside a data-migration fix was refused on the compounding grounds this repair otherwise follows.
