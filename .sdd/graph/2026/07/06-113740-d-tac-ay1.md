When `sdd init` registers the SDD MCP server for Codex, the generated `.codex/config.toml` must forward `SSH_AUTH_SOCK` to the server via `env_vars = ["SSH_AUTH_SOCK"]`. Codex launches stdio MCP servers with a filtered environment that drops `SSH_AUTH_SOCK`, leaving `sdd serve` unable to reach the ssh-agent — the environment-side trigger of the auto-commit signing hang (s-tac-cam). Whitelisting the variable (rather than hardcoding the dynamic launchd socket path) lets the server sign commits through the agent as it does under Claude Code. This sharpens the per-agent registration commitment (d-tac-wfl) with a Codex-specific env requirement; it is a convenience mitigation, not a substitute for the code-side fail-fast fix. Verify `env_vars` is honored by the targeted Codex build — the flag was not visible in 0.142.5's `codex mcp add --help`.
