An adaptive bootstrap procedure will establish enough shared understanding of a fresh or sparse project's world for meaningful SDD work, using user-paced dialogue and dependency-ordered capture clusters instead of a mandatory onboarding sequence. It addresses the open bootstrap-port gap (20260716-144333-s-prc-7ku) while retaining the later legacy ordering insight (20260505-121556-d-prc-cgc) only as a set of optional conversational lenses: readiness, brownfield context, WHAT/HOW/WHY, and actors/roles adapt to what the graph and user already cover.

Bootstrap will be a persistent outer procedure built on the engine procedure model (20260702-220449-d-tac-ry0). Every run injects a slim capped view of active actors/roles, conceptual guiding framing, strategic guiding direction, and aspirations; the agent summarizes established context and apparent gaps before recommending a warm line of inquiry. Brownfield repository inspection remains host-agent work under served instructions. The interview posture builds on the active interview procedure (20260706-180000-d-prc-int), but its question stock is a reservoir rather than a checklist: the user controls depth, concise answers are valid, and no lens is required merely for completeness.

As soon as the agent can explain a coherent cluster of standalone candidate signals and decisions, it pauses questioning and proposes their SDD kinds, layers, topics, participants, and typed references. Once accepted, the whole stable cluster is recorded while context is fresh through separate parented instances of the shared capture procedure (20260703-094500-d-prc-cap), in dependency order; each generated ID becomes available to later captures, preserving the resolve-or-block reference invariant (20260628-130400-d-cpt-uh0). Unsettled candidates remain in outer synthesis. Parking is reserved for interruption of one capture already in progress, not used as a draft backlog.

There is no readiness score. One actor and at least one framing signal or decision are the indispensable foundation for handoff; identity, direction, and aspiration may deepen across an indefinite number of clusters and repeated bootstrap runs. After each cluster, bootstrap refreshes graph context and lets the user continue, deepen, redirect, or finish through the active catch-up procedure (20260703-194500-d-prc-cat). Supporting actors and roles also requires closing the shared-capture kind-field limitation exemplified by (20260707-162940-s-prc-g0j): actor canonical identity and aliases, plus role-to-actor linkage, must flow through capture state, playback, validation, and the new-entry command.

The attached design record preserves the user stories, dialogue shapes, rejected alternatives, engine-mechanics analysis, and tone contract behind this plan.

## Acceptance criteria

- [ ] A canonical, discoverable `bootstrap` procedure can be started as a long-lived outer move and retains its current lens, readiness synthesis, brownfield synthesis, interview transcript, unsettled candidates, produced entry IDs, and user direction across loops and park/resume.
- [ ] Each fresh run injects a capped graph view covering active actors/roles, conceptual guiding directives, strategic guiding directives, and aspirations, then serves a concise summary of what is established and what appears missing; it does not inject the full graph or compute a numeric completeness score.
- [ ] Repeated runs reconstruct coverage from current graph state, skip already-covered areas, and may deepen any incomplete area without replaying a fixed sequence; resumed runs additionally preserve their conversational synthesis.
- [ ] Brownfield guidance instructs the local host agent to inspect and synthesize relevant repository instructions, README material, stack/manifests, structure, and recent activity as appropriate; the engine performs no repository or Git inspection.
- [ ] Readiness, brownfield context, WHAT, HOW, WHY, and actors/roles are optional lenses selected from graph gaps and dialogue, not mandatory ordered gates; the agent recommends a warm direction while the user can continue, deepen, redirect, skip, or finish.
- [ ] Interview instructions use journalist posture, ask one balanced question at a time, accept sufficient concise answers, and treat possible questions as a reservoir rather than requiring exhaustive traversal.
- [ ] When a coherent cluster forms, bootstrap pauses further questioning and proposes one or more standalone signal/decision candidates with body intent, kind, layer, topics, participants, and grounded typed references; the user can reshape, defer, keep exploring, or accept the cluster.
- [ ] An accepted stable cluster dispatches one parented `capture` sub-move per entry and completes the whole cluster while context is fresh, in dependency order; produced IDs from earlier captures can seed resolvable references in later captures, and every child retains exact playback, explicit confirmation, pre-flight, and summary verification.
- [ ] Unsettled candidates stay in the outer bootstrap synthesis. A parked child represents only an interrupted in-progress capture and is not used as the default phase backlog.
- [ ] After every captured cluster, bootstrap refreshes its slim graph grounding and returns to dialogue with a lightweight choice to continue, deepen, redirect, or finish.
- [ ] Bootstrap may recommend catch-up handoff once the graph contains at least one actor and at least one framing signal or decision, without requiring direction or aspiration gates; catch-up re-reads the updated graph.
- [ ] Shared capture and `newEntry` support actor canonical identity and aliases plus role-to-actor linkage end to end, including kind-specific assemble guidance, exact playback, validation errors, command transport, persistence, and generated-summary verification.
- [ ] Actor and role entries created through the procedure render correctly through existing `show`, `view`, and catch-up presentation surfaces; no new rendering semantics are introduced unless testing exposes a concrete gap.
- [ ] Procedure tests cover empty and partially bootstrapped graphs, skipped lenses, shallow and deep user-directed interviews, multiple clusters within one lens, dependency-ordered references, cluster deferral, child interruption/resume, repeated fresh runs, resumed runs, actor/role capture, and catch-up handoff.
- [ ] A live local-agent evaluation demonstrates that bootstrap feels like shared orientation rather than a questionnaire, that repository inspection stays host-side, and that the legacy `sdd-bootstrap` skill is not retired until procedure parity is evidenced.
