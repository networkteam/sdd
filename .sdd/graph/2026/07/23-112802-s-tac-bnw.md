`sdd repo add` scrolls the whole terminal away when it actually clones a connected repo, leaving the command's output stranded at the top of a blanked screen — a jarring "fullscreen jump" that the already-connected fast path (no clone) never shows.

Traced end to end via PTY captures of the real output coordinator: it is not the alternate screen buffer and not a screen clear — no `?1049h`, no `2J`, no cursor-home is ever emitted. The jump is a single cursor-down of exactly the terminal height (`ESC[<rows>B`, confirmed scaling 10→10 … 60→60), emitted by bubbletea v2's `tea.Printf` — the mechanism the coordinator uses to stream a durable log line above the transient footer when `StreamLogs` is true. The bubbletea frame starts sized to the full terminal height; if the first streamed line prints before the footer's first render shrinks the frame to one line, bubbletea scrolls a full screen to make room. It is a race, proven directly: logging immediately reproduces the full-height scroll, while delaying the first log by 250ms so the footer renders first eliminates it entirely.

The clone path loses this race every time because the very first statement on it — `logger.Info("cloning connected repo", …)` in `internal/repos/manager.go` — fires instantly, before any spinner frame. The already-connected path never starts the coordinator (`willClone=false`), so there is no log and no scroll. `sdd index`, on the identical coordinator with `StreamLogs` true, does not jump only because its first per-entry log arrives after embedding setup, by which point the footer has already rendered and shrunk. Git is not implicated: the clone subprocess runs fully detached from the terminal (`internal/git/cache.go` — stdin /dev/null, stdout nil, stderr buffered), so it cannot touch the screen; the correlation with cloning is entirely because the coordinator runs only when a clone is needed.

This lives in the terminal-experience architecture (d-cpt-dgk) and is a distinct facet of the coordinator-lifecycle gap already recorded for `sdd repo add` (s-tac-bg7): that one is the escape-sequence leak on the fast no-clone path; this is the full-height scroll on the clone path. Two smaller adjacent defects surfaced while tracing: `sdd repo add`'s view is spinner-only with no progress, reading as less finished than `sdd index`; and the comment at `internal/cliout/tui/interactive.go` still asserts the coordinator runs in "alt-screen," which the code contradicts (the model's `View()` never sets `AltScreen`) — an actively misleading comment worth correcting. Fix direction: ensure the footer renders (frame shrinks) before the first streamed line, or hold the pre-clone log until the view is established, or size the initial frame to content rather than the full terminal.
