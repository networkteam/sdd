The transient output coordinator has two unhandled program-lifecycle edges surfaced during outer validation (20260709-160634-s-tac-tt8), both grounded in the terminal-experience architecture (20260628-131545-d-cpt-dgk). First (slice-4 regression, fix-soon): `sdd repo add` on the fast already-connected path starts the coordinator view for a near-instant no-clone operation, and the program quits before the terminal's mode-query (DEC 2026/2027 synchronized-output) responses drain — so those escape sequences leak into stdout and onto the next shell prompt. The fix is to gate the view on a clone actually running, mirroring how `sdd index` skips the view when there is no work. Second (pre-existing, low): Ctrl-C during a long embed cancels the work context and tears the footer down cleanly, but the in-flight call surfaces a raw `context canceled` error and a nonzero exit rather than being recognized as user cancellation. Both are edges of the same coordinator lifecycle — too-fast startup drain, interrupt teardown — and they sit alongside the concurrent inner run's related footer-labeling finding (20260709-152943-s-tac-jbm), the text-only-search facet of the same surface.
