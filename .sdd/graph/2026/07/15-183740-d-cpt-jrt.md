The docs example world is fabricated deliberately — scenario-scoped partial graphs and written dialogues, authored directly and validated against the real tool — with fidelity to real sessions as the hard requirement and production ceremony explicitly dropped. The roastery example world lives in its own repository (sdd-example), keeping the SDD-building-SDD dogfood graph entirely out of the docs; scenarios share the story's world and personas so the docs read as one place, but each docs scenario gets a small purpose-built graph slice (a fresh quickstart graph, a lived-in graph for catch-up and engage, a supersede chain, a grooming candidate set) rather than one continuous history. Entries are authored straight to disk as valid graph files, with story-time IDs and timestamps correct from birth and coherent refs; summaries are written in the register the real summarizer produces. Fidelity is guaranteed three ways: content is modeled on the project's abundant real session material (how captures play back, how catch-up briefs, how engage lands); every fabricated graph must load, index, and render through the real sdd, making loader strictness the validation gate; and all CLI output shown in the docs is genuine output from really running sdd over these graphs. Dialogues, not graph entries, are the docs' primary example surface: users experience SDD as conversation, so entries appear as supporting artifacts inside rendered dialogues — a Dialogue component renders written transcripts as a conversational UI with typed agent actions (playback cards, recorded-entry moments, junction choices), deliberately unlike a coding-agent terminal, and doubling as a static preview of the hosted webapp's future surface; a disclosure line states that dialogues are authored with the story's characters, modeled on real sessions. Working process: scenarios are designed as dialogue scripts with Christopher first — which graph case each demonstrates and how the conversation should go — then tried by sub-agents: a sub-agent constructs the scenario graph, runs the real tool over it, drafts the dialogue transcript, and returns the result for review, keeping Christopher's involvement to scenario design and spot-review. Rejected alternatives: one continuous eight-month world graph (heavy, unnecessary — partial graphs demonstrate the cases); and producing graphs through real engine or CLI capture runs with IDs and timestamps rewritten afterwards — the rewrite fights the tooling (refs embed full IDs, auto-commits stamp production time) and adds ceremony without adding fidelity, given the real-behavior reference material already at hand. This refines the real-mechanics example principle of the v1 docs structure plan (20260715-181235-d-tac-c7b): fidelity to real sessions is the hard requirement; fabrication with real-tool validation is the route.
