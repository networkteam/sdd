Teardown of parked engine sessions is heavy: `abandon` requires a live instance handle, so clearing a stale session means resuming it first — six calls to clear three sessions on the first live run — and each of those resumes injects the full ~28KB framing block although its only purpose is teardown. The friction was observed while clearing the three false-start sessions the first dogfooding run of the v1 workflow engine plan (20260702-220449-d-tac-ry0) found parked; the shipped shell (20260703-002223-s-tac-kd2) established the resume-then-abandon path and per-consumer framing injection this critiques. Fix directions for dialogue: `abandon` accepting a session handle directly (or a lightweight discard operation), and framing suppressed when a resume exists only to tear down.
