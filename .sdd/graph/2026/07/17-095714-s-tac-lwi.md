The MCP `view` tool mechanically strands an agent that does not already know the layout grammar: the tool schema teaches only two examples, and every recovery surface the agent hits from there fails in its own way — observed live in an engine-mode session on a separate project's graph (content kept out of this record), the third reproduction of the grammar-reach failure (20260707-142811-s-prc-3kh), where the agent burned six `view` calls guessing layouts, abandoned the tool for host-side git history, and only recovered via `search`. Code inspection confirms each failure is structural, not agent error. (1) The unknown-function error lists only the primitive functions and omits all eleven macros (`top`, `focus`, `done`, `wip`, …) — contradicting the tool schema's own `top(15)` example. (2) Unquoted multi-word, date, and duration arguments (`participant(Jonathan Philipp)`, `since(7d)`, `since(2026-07-14)`) die in the grammar parser with a positioned but uninstructive `expected ')'`; the helpful quoted-form examples live in executor-side validators that are unreachable for exactly the inputs that need them. (3) An empty result renders as a bare empty `sections` string — a `participant()` miss (exact canonical-name match, no alias resolution) is indistinguishable from genuinely no data, though the graph could name the participants it knows. (4) `as-list` has no default page cap or server-side size guard over MCP, so a plain `active:as-list` dumps the entire open graph and blows the client's token budget. The improvement direction agreed in dialogue has three parts. First, the mechanical fixes are cheap and independent: macros in the unknown-function error, a "0 entries matched (known: …)" empty-result message, a quote-your-argument hint on the parser's argument errors, and a default cap or size guard for MCP view output. Second, the grammar reference itself ships as a base fact under the committed pull layer (20260707-140544-d-cpt-dtv) — auto-generated from the executor's own vocabulary tables (known functions, macros, rank algorithms) rather than hand-written, because the hand-synced `viewHelpText` already drifted once and caused a real misdiagnosis before its rewrite (20260619-174118-s-tac-zwz); generation makes drift impossible instead of remembered-against. Third, the fact is paired with a first-hit hint on the `view` tool: the existing per-read hint plumbing gains per-session dedup so the first `view` call in a session carries a one-line pointer to the fact's entry ID — the knowledge is discovered at the moment of need without creating a duplicated fourth knowledge home, honoring the no-duplication discipline of the base-facts direction. A served index over all base facts remains out of scope here as its own story. The general push-only knowledge gap this instantiates is 20260707-135618-s-cpt-7wc.
