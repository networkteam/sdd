An engine-mode agent, shaping a capture in dialogue, could not survey the graph's topic vocabulary and fell back to layout-guessing and grep — a concrete, reproducible instance of the engine's push-only knowledge gap (s-cpt-7wc), retained as the before-state benchmark for the base-facts fix (d-cpt-dtv). In the observed session the agent was still in pre-capture dialogue, agreeing refs and topics before starting the move; asked for the topic landscape, it guessed an `sdd view` layout (`topics:as-counts`, rejected by the parser), fell back to a raw `grep` over `.sdd/graph` frontmatter that returned parse noise (full IDs from adjacent `closes:`/`refs:` blocks, `label:`-prefixed lines), and recovered the working form (`active:as-counts`) only by trial-and-error against error messages — because the `sdd view` grammar, exactly the reference knowledge s-cpt-7wc names as homeless, has no surface the agent can pull from mid-dialogue. It is the same wall s-cpt-7wc records for procedure-authoring, hit independently in a second situation. This is filed as a gap rather than a fact so it can be closed by demonstration: once base facts ship the pull layer (d-cpt-dtv), an agent in this exact spot should pull the view-grammar / topic-survey fact and run `active:as-counts` in dialogue — no grep, no layout guessing. Until that behavior is observed the reach failure stands open, and its closing done signal is the evaluation metric that the pull layer changed agent behavior, not merely the served text.
