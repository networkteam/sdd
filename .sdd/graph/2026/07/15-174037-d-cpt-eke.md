A dedicated planning session will define the v1 information architecture and content plan for the SDD documentation site, landing a structure the site build can execute against. This dispatches the second half of the docs initiative: the user-documentation gap (20260715-172002-s-cpt-i5a) left which documentation belongs in v1 an open question, and the stack directive (20260715-173844-d-cpt-o0r) settled tooling, so structure planning gets its own session rather than riding along the site build. The candidate shape to walk in dialogue: quickstart, concepts and philosophy (the ideas behind SDD), guides, how-tos, reference, and a clearly separated work-in-progress/outlook section — which of these make v1 is the session's call. Two hard requirements from Christopher are set now: first, the vocabulary must become learnable — readers should, after some time with the docs, understand SDD's vocabulary and see what SDD offers as types and kinds, which means a proper reference treatment woven into the concepts track, not a glossary afterthought; second, advanced users get the process-customization story — procedures, and the upcoming rules, documented as how the working process itself is adapted. The scope constraint inherited from the gap holds: v1 documents the current working state only, with the outlook section carrying planned and in-discussion features, fed directly by the graph's open decisions and focus entries. Content is sourced from the graph's rich history (decisions carry rationale, done signals carry what shipped), the README, and the narrative docs (docs/story.md, docs/signal-dialogue-decision.md), iterated with user feedback. Expected landing: a v1 structure plan with page-level acceptance criteria plus a content-sourcing map, captured from that session.
