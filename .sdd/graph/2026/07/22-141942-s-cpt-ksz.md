Bootstrap's topic-landscape founding assigns provisional topics during capture and never applies the agreed vocabulary back, leaving the founding entries mis-tagged. In both live runs the agent minted provisional topic labels while capturing the first cluster, then founded a landscape afterward; because the entries were already immutable, the agreed vocabulary became prospective-only — in one run the founded bases tagged nothing retroactively and an entry sat under the wrong base. A compounding factor: the founding step is an agent chooser, so signoff on the vocabulary is not structurally required — in one run the agent chose the landscape unilaterally and never put it to the user. Fix direction: withhold topic assignment until the user signs off the landscape (which needs a few captured entries for perspective), make that signoff a structural user junction rather than an agent chooser, then attach the agreed topics to the founding entries via annotation — which depends on the engine gaining annotation capture (20260722-141909-s-tac-6rd). Surfaced by the outer evaluation of the bootstrap port (20260722-140955-s-tac-lgc).
