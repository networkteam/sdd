Slice 2 of the persistent MCP vector index repair is implemented, verified, and merged (merge ae4042b), completing the repair plan and its amendment: the machine-global store is version-aware end to end. Commit ffc7053 delivers version-qualified chunk IDs, the multi-version manifest with byte-compatible legacy round-trip, per-(entry, hash) presence on both CLI and MCP paths, and read-time stale-version filtering — added to the CLI finder as well, since additive versioning makes filtering a correctness requirement on every reader. Commit f8a4411 adds retention-window garbage collection: a pure decision function with the 14-day window as a named constant, its delete side-effect confined to CLI write sessions under the exclusive lock. Commit 5da647d adds the generation-checked snapshot cache — write sessions bump a generation marker only when the index actually changed, and reads reuse the held snapshot until it moves.

Verification: full gates green (vet; tests across 26 packages including the new legacy-store, summary-regeneration, and branch-divergence scenarios; lint; the extendingsdd example module). Post-merge live smoke against the real 145 MB store: a fresh server topped up only entries captured since the last fill, two further fresh servers answered filtered and unfiltered phrase searches in 0.9–1.2s with zero document embeds, shorthand type filters resolve, and an unknown layer value errors loudly. The landing without directory isolation was cleared by the format-compatibility scoping (d-cpt-vri); the amendment's connected-store force-repair clause was found already delivered by an earlier commit and is closed by its own record. One boundary is recorded for the remote-runtime lifecycle design (s-cpt-e8x): GC triggers only in CLI write sessions, so a serve-only deployment accumulates versions until a CLI touches the store. Details in the attached [verification note](./17-000200-s-tac-eyc/slice-2-verification.md).
