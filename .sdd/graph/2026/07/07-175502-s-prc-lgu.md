A capture can silently orphan staged attachments: stage a file, get a handle back, and if the report never lists that handle the write gate materializes the entry without it — no warning at any step, no trace of the dropped file. Observed first-hand in this session: the architecture-review record staged for the graph-access gap (s-tac-jg8) was never carried into the attachments field, and the entry landed with a body asserting "the attached review" while carrying no attachment; the implementing session discovered the hole only when it went looking for the review and found nothing to read. Three holes lined up. First, no reconciliation between session scratch and report: attachments are an optional assemble field, and the write gate does not check for staged-but-unreferenced files — while the staging tool's own description, "the write gate materializes staged files with the entry", reads as automatic inclusion and invites exactly this omission. Second, the playback adjust chooser collects body, refs, topics, confidence, and intent but not attachments, so the omission cannot be repaired at the verification step even when noticed — the same unreachable-field shape the write-gate opacity gap (s-prc-0p1) records for the frozen closes parameter. Third, pre-flight passed a body that asserts an attached record on an entry with zero attachments: the body↔edge consistency discipline that exists for refs has no attachments counterpart. Recovery required an out-of-band mechanical fix — writing the file into the entry's attachment directory, adding the frontmatter line by hand, and committing — possible only on a locally mounted graph and unavailable to any agent working over MCP alone. Session-scoped staging shipped under the v1 engine plan (d-tac-ry0); the capture procedure (d-prc-cap) owns the flow where the holes sit. The fix direction: reconcile staged handles against the report at the write gate (warn or hold when staged files are unlisted), add an attachments slot to the playback adjust chooser, and consider an attachment-mention consistency check in pre-flight.
