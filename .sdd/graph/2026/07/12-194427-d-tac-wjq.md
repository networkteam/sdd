The public project-aware SDD application will expose subsystem-shaped ports instead of mirroring SDD’s internal pipeline, reducing the API while keeping invariants in SDD-owned orchestration and conformance tests. This directive refines the active public-API plan (20260712-104530-d-tac-1mb) without changing its central commitment to one shared importable runtime and MCP surface.

The public boundary is amended as follows:

- Consolidate identity, principal, project-access, and dependency authorization behind one access-resolver family. Consolidate snapshot reads, canonical mutation apply/reconciliation, and canonical attachment paging in `GraphStore`; the adapter owns cache invalidation from the revision returned by its own apply. Keep `SessionStore`, `StagedBlobStore`, and raw model execution aligned with the subsystems a composition actually owns. Session ID generation is an option rather than a port, and staged-blob sweeping is composition-side operations work rather than an SDD-facing method.
- Keep `EmbeddingExecutor` and `SearchIndexStore` separate in v1. Although merging them would hide vectors and shrink the method surface, separation lets SDD centrally verify that indexing and query execution use compatible fingerprints and dimensions.
- Remove `Begin`, `Abort`, and any public lease spanning validation or LLM work. `GraphStore.Apply(expectedRevision, ...)` is the only concurrency primitive: a stale revision is definitively not applied and starts a new prepare cycle. An adapter may serialize storage operations internally during `Apply`; the accepted trade-off is rare repeated pre-flight work under human-paced contention.
- Ship reusable `sddtest.Run<Port>Tests` conformance suites for every public port, and require every shipped adapter to pass its applicable suite. The same suites exercise local and external adapters, making behavioral invariants rather than lifecycle-heavy method shapes the parity mechanism.
- Make `MutationBatch` storage-neutral. Changes carry canonical document-shaped data where one exists plus the exact canonical bytes rendered by SDD; structured stores persist documents directly, while filesystem and Git adapters write bytes verbatim. Logical-path-plus-bytes covers WIP markers and other canonical non-document artifacts.
- Retain event, procedure, registry, finalizer, and prepared-envelope version fields, but implement no migrations in v1. Unsupported versions fail closed with a typed migration-required error. Migration acknowledgements, chain fingerprints, and envelope migration rules enter scope only when a second concrete version requires them.
- Require durable intent/apply/outcome whenever session persistence and the canonical graph authority are independent durable stores. Do not publish a speculative atomic-transition capability until a concrete composition needs one. Session-side outcome bookkeeping and finalizers remain retryable and idempotent because they cannot be atomic with canonical apply across that split.
- Treat session CAS as fencing, not the user-level ownership model. Add an exclusive holder recorded through CAS with subject, MCP logical session, client information, bind generation, and last activity; listings expose holder history and liveness. A live holder yields a typed session-in-use response, takeover is an explicit user decision, expiry takeover is silent but recorded, and a displaced holder is reoriented when its stale append fails. Activity expiry is authoritative, while transport lifecycle events only accelerate release. V1 uses chooser-kind TTL defaults; per-step overrides are deferred.

The exclusive-holder semantics directly address the concurrent session corruption gap (20260709-174818-s-cpt-c2i) and its liveness-visibility sibling (20260706-231416-s-tac-y2z): CAS prevents corrupt append claims, while holder semantics make ownership and takeover intelligible to users.
