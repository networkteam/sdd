Slices 2 and 3 of the session-subsystem rebuild (20260730-093011-d-tac-k4q) are delivered in commits `4a97314c`, `a9a80535` and `580f6407`, continuing the slice-1 delivery (20260730-105153-s-tac-tia). The ports gained enumeration and deletion, and one command with one handler now removes sessions that have ended and are past their retention, taking their staged blobs with them and draining declarations that can never converge. `sdd serve` startup is its trigger; the exported API is the other caller. This settles the mechanism 20260728-004924-s-tac-gtx deliberately left to a separate dialogue — the port grows enumeration and deletion rather than reclamation staying inside the local composition, and the trigger is an automatic pass rather than a command.

One concept was removed that the plan did not name. There was never a blob owner: `BlobOwner` was the composite key addressing a staged-blob directory, and naming it an owner invented an entity where there is only a subject and a session. It is now `SessionRef`, and staged blobs live under `<subject>/<session>/` rather than under a hash of the pair. Because the path states whose they are, enumeration became a directory walk and the store no longer opens a file inside a directory to learn what it is looking at. That also removed a class of directory the sweep could not attribute, and two writes that created them: a retention over an empty ID list, which every capture without attachments was performing, and a release for a session that had staged nothing.

Retention is `sessions.retention` on the existing config overlay, defaulting to fourteen days. Proven against copies of this machine's real accumulated store: setting it through `sdd config` needed no change to the config surface, the pass removed only the session that had ended outside the window and left the rest untouched, a second run found nothing to do, and two simultaneous starts both completed with nothing half-removed.

Collection failure is not fatal, reversing a decision taken earlier in this run. Propagating it would stop `sdd serve`, and over stdio that leaves the agent a closed pipe with no readable error and no way forward — worse than the unreclaimed disk it reports. The exported API still returns the error, since a scheduled caller can act on one.

The conclude rate is what limits this in practice, and on this store almost nothing is ever concluded: most sessions carry labelled work whose moves completed, and their last attachment record is a socket closing rather than a participant ending the dialogue. Only `conclude` and `abandon` count as ended, which is why the pass reclaims little — and why slice 4's teaching half is load-bearing rather than polish.

That also surfaced an open question this plan does not settle. `AttachmentCause` mixes two unrelated things: acts on the dialogue (`conclude`, `abandon`, `claim`) and transport events (`disconnect`, `shutdown`, `switch`). The transport causes are written into the session log and read by nothing, which puts connection lifecycle inside the session record and cost this work an explicit cause filter to define what ended means. Clearing the live attachment stamp on disconnect is the useful half and should stay; appending a history record for it is the half to reconsider. Left for a deliberate decision rather than changed here, since the vocabulary belongs to the session-model contract.

Slice 4, the branch-precedence consolidation, and the live binary swap remain; the plan is not closed.
