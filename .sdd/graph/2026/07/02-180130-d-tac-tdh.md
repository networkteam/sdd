Produce the v1 implementation plan for the workflow engine (d-cpt-3yw), targeting full parity with the skill-based SDD experience so dogfooding replaces it outright rather than running alongside it. The path, over one or more sessions: (1) **Parity inventory** — enumerate the current experience surface (catch-up, capture, engage, explore, groom, evaluate, interview, topics procedure, pre-flight, summary verification, WIP/worktree recipe, sync reactions, language handling) and sort each into move, query, stays-host-side, or deliberately dropped; the inventory is the plan's scope contract. (2) **Spec through interview** (s-cpt-qs2) — settle the concrete unknowns with user decisions: move-spec format, session-state persistence, MCP tool surface, evidence fields per move (concrete per-move first, generalize after use), and the sequencing call on the rule system (d-tac-eho): checks declared in move specs for v1 with graph-resident rules integrating later, or folded in. (3) **Capture the plan** with acceptance criteria, sliced so dogfooding starts early inside full scope — spine first (engine core, session shell, capture, engage), then explore/groom/evaluate, then interview and the close gate, then Desktop as second client. The plan carries addresses-refs to the alignment directives (d-prc-1ob, d-prc-e2y), which ship as shell junctions and the interview move spec rather than skill text. (4) **Transition mechanics** — ship a second thin skill (engine bootstrap + MCP wiring) alongside the untouched /sdd; the user chooses per session, every engine session is a live comparison, and findings are captured as signals. Authority rule: once a move ships in the engine, its spec is authoritative and the corresponding skill prose is frozen — changes land in the spec only. Endgame: the thin skill replaces /sdd and the full renders retire. Closes when the v1 plan is captured.
