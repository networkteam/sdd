The recovery projection's single overloaded state field is split into three — delivery state, reason, and provenance — in commit `295661c`, retiring the conflation gap (20260728-010206-s-tac-gjr) by implementing its settled direction exactly, including its rejection of keeping `recovered` as a state value. `State` now carries only delivery: `delivered`, `pending`, `abandoned`, where abandoned is a participant's decision rather than a delivery result. `Reason` names what delivery waits on (`outcome-unknown`, `not-applied`, `finalization-owed`) or which decision ended it (`discarded`, `abandoned-unknown`). `Recovered` is a flag set from a recorded recovery attempt — the only evidence that carries provenance. `Actionable` becomes a method deriving from `pending`, so actionability and state can no longer disagree. This is the two-durable-conditions standard of 20260727-230506-d-cpt-msg expressed in the field that was supposed to express it, and it absorbs the `applied-finalized` state that 20260728-005407-s-tac-1kr had to invent because no existing value could say "delivered without a terminal".

Measured on the live store with the rebuilt binary: 122 history rows, all `delivered`, none `recovered`, none actionable. Before the change every one of those 122 read `recovered`, including entries captured minutes earlier by healthy sessions.

The honest accounting on complexity, since the stated goal was simplification: by raw count this is slightly larger, not smaller. `recoveryItem` went from 45 to 48 lines with 11 branches unchanged; the vocabulary went from six constants to eight; `RecoveryItem` gained a field on net; the production diff is +158/-61 across the projection, the CLI and the docs. What improved is not size but the elimination of a defect class — no value can encode a combination, which was the pressure that produced the seventh state, and no derived flag can contradict the state it was derived from. Whether more names each meaning one thing beats fewer names carrying several is a judgment rather than a measurement, and it was taken deliberately with the numbers in hand. The real mass in this subsystem is untouched: five verbs, the legacy target-binding path, the authorization port and the audit events, most of which 20260727-230506-d-cpt-msg implies should not exist. That reduction is separate work; the state vocabulary was the symptom, not the bulk.

One defect was self-inflicted during the change and is worth recording because of what caught it. The first implementation set the provenance flag from terminal presence — but the ordinary write path writes a terminal, so every one of the 122 rows came out `delivered · recovered`: precisely the error this change exists to fix, reproduced in the field designed to prevent it. `go vet`, the full suite and the reviewer's own reasoning all passed it, because the stranded fixture carries no terminal and so never exercised the branch. What caught it was building the binary and reading its output — the same mechanism that surfaced the original mislabelling, and the second time in one session that output-reading beat analysis, which is the discipline of 20260726-204112-s-prc-ogp applied to a code change rather than a release. A test now constructs the ordinary-write shape — a terminal with verb `apply` and no attempt — and asserts `delivered` with the flag unset.

Several test assertions were strengthened rather than merely migrated: the bulk rename collapsed `discarded` and `abandoned-unknown` into `abandoned` and both pending states into `pending`, which would have silently weakened five assertions and made the verb-menu table two identical rows. Each now asserts its reason alongside its state, restoring the distinctions the old constants carried implicitly. Verification is clean in both modules — `go vet ./...`, `go test ./... -count=1`, `golangci-lint run ./...` with zero issues, `git diff --check` — and the CLI result print no longer casts an `ApplyState` into a `RecoveryState`, which had been manufacturing values outside the declared set.
