The engine store's clone machinery, shipped with the base-fact index hardening (20260721-152753-s-tac-31o), carries a confirmed latent panic and roughly 150 lines of speculative surface around an otherwise-correct atomicity fix. The recursive clone's unexported-mutable-field guard rejects `time.Time` (its unexported `loc` pointer) and anything containing one — `cloneStoreValue(time.Now())` panics — even though `time.Time` is JSON-persistable per the function's own contract; no store value carries a timestamp today, but the panic sits on hot read and commit paths with no recover, so the first op that stores a timestamp crashes the engine. Around it, a `StoreValueCloner` extension point with zero production implementers, concrete-type-preservation panics, unexported-field reflection, cycle detection, and five test-only types defend value shapes that cannot occur — production store values are entirely JSON-shaped — while `commit` deep-clones the whole candidate a second time on every write and reads deep-clone on every access. The transact/validate-all-then-commit structure itself is correct and was verified behaviorally in the inner evaluation (20260722-115503-s-tac-a0o): rejected batches leave store and log byte-identical, and the Start() reorder fixes a real half-update — the original intent (multi-field writes must fail atomically, with clean copies for immutability) is sound; the cloning half overshot it. The agreed simplification direction: keep transact/commit, make the store contract literally "values are JSON documents", clone by JSON marshal/unmarshal at the write sites (matching WriteEngine), and let commit become a plain swap — self-enforcing (non-serializable values fail loudly at write time instead of panicking on a later read), normalizing every value to its persisted form so pre- and post-restart behavior cannot diverge, and dissolving the time.Time landmine as a side effect. The cloner interface, reflection guards, panics, and test-only types get deleted.
