Open dialogues and their threads get surfaced at junction points, structurally: the shell attaches an open-threads block to junction payloads only — procedure completion, session entry and resume, abandon — and never to mid-procedure serves, so the property that a user is not reminded of other work after every interview answer holds by construction rather than by agent judgment, the same principle that carries dialogue presence. Presentation follows the served-instruction memory pattern: a base instruction the first time a block appears (present the open work as continuation options, in the user's language), a one-line reminder after. Ordering at a thread's end: the current dialogue's other open threads first, then other open dialogues. This also hands the agent its lead-following material at exactly the moment a finished thread otherwise drops it back into its own momentum. A Claude Code statusline surface stays an optional agent-specific extra reading the same session list, never the primary mechanism. This refines the v1 workflow engine plan's MCP-shell commitment (20260702-220449-d-tac-ry0) — the second deliberate widening of the loop's return payloads after the session labels — and depends on those labels (20260703-140618-d-tac-2ez): an unlabeled thread list is not presentable as choices.
