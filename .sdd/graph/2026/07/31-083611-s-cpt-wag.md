Capture's lifecycle fields are start-only, so an author who discovers mid-draft that an entry closes something has no legal way to say so — and the graph silently records a false relationship instead of blocking. The engine enforces the start-only property: a step's `collect` may only name fields declared under `state:` (naming a param fails spec validation at load), and `setParams` is reachable only from `SetStart`. But that constraint belongs to params, not to `closes`. `SetStart` splits its inputs — declared params become params, declared state becomes a seed — and the capture procedure (20260703-094500-d-prc-cap) already exploits this: `captureBranch` is declared under `state:` and seeded at start by the dispatching workflow. Moving `closes` and `supersedes` to `state:` would keep every existing start-time call working identically and additionally make them collectible at assemble. The current split is a declaration choice, not an engine limitation.

The friction hypothesis — reasoned here, not validated — is that the observed failure was not an author forgetting a parameter, but the procedure shaping a false entry. Reported externally by Benno against v0.16.2: a done signal whose body and generated summary both state „Schließt den Gap …" was written with the target in `refs` under `kind: addresses` and no `closes` key, so the gap still reads open. The closure was the substance being captured, surfacing while drafting rather than before starting the move. At assemble the only field open for that target ID was `refs`, and `addresses` is explicitly sanctioned there as responding to a gap — so the author picked a legitimate kind from the only field it was permitted to write, and the body said what had actually happened. The same step's instruction then names `closes` among the IDs that must have been served in full, pointing at a field the schema does not offer there. The only escape is abandon-and-restart; a restart could re-seed the drafted fields as state, but nothing documents that and no author would guess it.

Nothing downstream catches the result. `sdd lint` compares fields against fields only — no check in the codebase reads body prose against frontmatter, so this is an absent category rather than a missing rule. Pre-flight gates every lifecycle-aware rubric behind the entry carrying `closes`, so a done signal without it falls through to the generic classification check: the check that would catch the omission is gated behind the field being present. And a done signal carrying refs but no closes is deliberately legal, so two valid shapes exist and only the prose distinguishes them.

This sits one notch finer than enforcement already promised. The body↔edge consistency rule (20260604-164606-s-prc-ema) requires every ID typed in a body to be one of its edges; the reported entry passed it, because the ID was in `refs`. Its mechanical half (20260611-113656-d-tac-b7f) diffs body IDs against refs ∪ closes ∪ supersedes and was never built (20260614-225650-s-tac-dxh, verified still absent at HEAD) — but even fully built it would not catch this case, since the union it diffs against includes `refs`. The failure is edge *kind*, not edge presence.

The precedent for a fix shape is (20260707-162940-s-prc-g0j): the same class of defect, where assemble collected no involvement and a focus decision therefore could not be written, closed by adding the fields to `collect`. The failure modes differ in the way that matters — that one wedged loudly at the write gate, this one succeeds quietly with a degraded entry, and silent conformance is the worse failure because only a human re-reading the target ever notices. Which remedy to take is left open: a declaration move, a wording fix that names the dead end without removing it, or a pre-flight check that cannot route on absence and so must widen the generic checks most prone to false positives. The param/state split belongs to the authoring contract that the procedure-language ceiling (20260726-195739-s-cpt-hcp) already frames as one connected problem, so a redesign should absorb this rather than patch it twice.
