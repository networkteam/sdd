Twenty-nine of the thirty-four pending-write notices in this repository's session store can never be cleared, because the only recovery verb that admits a prepared-transition v1 intent — bind-target — rejects every one of them, exposing both an unreachable recovery path and a wider complexity-creep gap in the recovery design. The underlying writes all succeeded, so these are bookkeeping residue, not pending work; but they head every orientation, catch-up, and view serve with an actionable notice that no available action removes.

The evidence is a full replay of the live store (100 session logs): 109 mutation intents, 109 outcomes — every one recording `applied` — and only 75 terminals. The 34-item difference is exactly the notice set. Each stranded intent carries `Version: 1`, a null target, no binding event, and `Document: null` on every change, because v1 persisted only canonical bytes. Every corresponding file is present and committed under `.sdd/graph/2026/07/`, with matching `.sdd-runtime/applied/` records, and the WIP markers those intents deleted are indeed gone.

Three things compose into the trap. The success terminal appended after a definitive apply is younger than these sessions and nothing back-filled it, so the intents have no terminal. The projection treats terminal-absence as actionable regardless of recorded outcome. And the legacy branch in the projection short-circuits before it reads the apply state at all, so each item is rendered `unknown · target binding required` when the store plainly records `applied` — the notice is wrong about both its state and its need.

The escape hatch itself is the substantive defect. The mutation-target and recovery plan (20260715-170623-d-tac-2ko) committed that "legacy version-1 intents require an authorized audited bind-target verb rather than inferred authority", and its closing done (20260716-153108-s-tac-spx) reports focused proofs for legacy bind-target and legacy-v1 audit among the completed matrix. But `bindLegacyTarget` refuses any change that is neither a delete nor a `wip/` path when its `Document` is nil — and no real v1 intent has a document, because Slice 5 (20260713-005437-s-tac-paq) shipped the v1 shape carrying canonical bytes alone. The verb is therefore reachable only for the 5 `wip/` items; the 29 entry and summary items have no verb sequence that terminates them. The proofs necessarily constructed v1 intents with documents attached, which the v1 writer never produced: the guard and the actual legacy corpus were never brought together. That is precisely the failure shape recorded in the run-it-once insight (20260726-204112-s-prc-ogp) — an artifact reviewed and tested against a model of what it would meet, never against the accumulated store that holds what the format actually wrote.

The failure also exposes a proportionality problem in the recovery architecture. The plan grew a six-state projection, five specialized recovery verbs, reconciliation rules, dual-attribution audit events, and a legacy binding path, yet the real corpus's dominant legacy case is simpler: the durable outcome already says the write was applied. Instead of resolving that fact directly, the machinery routes it into a target-binding action that cannot succeed. This is the complexity-creep pattern identified in 20260726-200257-s-prc-cbl: individually defensible safeguards compound into machinery nobody explicitly judged necessary, and the machinery can obscure the primary case it exists to handle.

The error the guard returns compounds it by naming an escape that would cause harm: "recapture explicitly" is wrong advice when the entries are already in the graph, since recapturing would duplicate them. Whatever the fix, this is the same class the read-compatibility contract governs (20260602-203349-d-cpt-i2x) — a durable record in a retired format with no conversion path — and the second time session persistence has lacked that equivalent, after the startup outage recorded in 20260714-103304-s-tac-rcv, which is itself one of the stranded intents.

The shape of the remedy is open and belongs in dialogue. Before choosing among patches, that dialogue should reduce the recovery contract to what is actually necessary: which states represent real user choices, which definitive outcomes can reconcile without intervention, and which safeguards have a credible threat model proportionate to their maintenance surface. Candidates worth weighing against that reduced contract include relaxing the document guard for intents whose recorded outcome is already definitive; teaching the projection to read the apply state before the legacy short-circuit; or a one-off sweep that writes terminals for legacy intents whose outcome is `applied` and whose logical paths are all present. The attached audit carries the per-session inventory, the census, the exact code paths, and the reachable end state for each of the two groups.
