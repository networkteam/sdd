Cross-repo entry-ID resolution accepts bare IDs — short or unprefixed-full — resolving them local-first and then across the referring graph's declared dependencies, accepting a unique match and erroring with the full-prefixed candidates on collision, while stored references always remain full-prefixed. This resolves the open question (20260709-161345-s-cpt-bae) of whether cross-repo resolution should stay strictly prefixed or open up, surfaced when a foreign short ID failed to resolve during outer validation while its full prefixed form worked. The rule extends the de-ambiguation that already resolves local short IDs within one graph: the same lookup simply widens from the single local graph to the local-plus-declared-dependencies set, covering both short IDs and unprefixed full IDs. It applies uniformly at every surface that turns a typed ID into an entry — the `sdd show` CLI command, the `show` MCP tool the engine serves to agents, and anchor resolution for moves such as engage and capture — because the motivating case is agent-facing: a user copies a short ID out of some output and hands it to the agent, whose first act is to resolve or anchor on it, so fixing only the CLI read commands would leave the papercut half-open. The collision rule is honest rather than magic: when the same suffix exists in more than one declared dependency, resolution refuses and lists the candidates in full prefixed form rather than guessing. Two properties are held invariant. First, stored references are never a bare-ID shortcut — the moment a resolved ID becomes a ref (a capture anchoring on a foreign entry), it is expanded to the full canonical repo-id-prefixed form, so the committed graph stays exactly as explicit and portable as the cross-repo design (20260606-003344-d-cpt-s6q) requires; this refines that design's resolution rule in place while leaving its full-prefix rendering and storage untouched. Second, the resolution scope is bounded to declared dependencies — precisely the set the declared-dependency precondition already governs (20260708-184318-d-cpt-6cq): a bare anchor that resolves uniquely across declared deps is exactly one that would satisfy resolve-or-block's dependency precondition when captured, so resolution never reaches a repo a ref could not legally point at, and stays deterministic per checkout rather than depending on the machine-global connection registry. Alternatives rejected: staying strictly prefixed (safe and zero-code, but leaves the copy-paste friction validation hit and forces the agent to know which repo an ID lives in); and full auto-resolution across the whole connected registry or into stored refs (machine-dependent, collision-prone, and erodes the explicit-dependency guarantee prefixing bought).
