Shipped a fully explicit per-junction grounding handoff for the workflow engine (commit c8fba6c), resolving the silent-loss gap without the no-declaration default its recorded resolution proposed. A dispatching junction option carries `dispatch: {procedure?, seed}` — seed maps child field ← parent field, written entirely in the parent's spec. Answering that option stashes the mapping on the parent instance; the next child started under it inherits exactly that mapping, re-derived on replay from the logged chooser answer. There is no engine-wide default: a handoff happens only where a junction declares one, so every inheritance is readable at the junction that grants it. This diverges from lbc's recorded resolution (which kept the shipped {widenReport, anchor} set as a no-declaration default with a serve note); it was re-decided in dialogue because a fallback reintroduced implicit name-coincidence behavior and reached into explore, whose fresh-widen gate the default silently pre-satisfied. engage's move and evaluate's record junctions now declare their handoffs explicitly; explore, dispatched from a gate that answers no seed-bearing option, widens fresh. A seed sourcing an undeclared parent field fails at load; an optional procedure guards a seed to a named child. The two `next` serve misfires are fixed: pending_chooser names its step id, and chooser steps serve an answer-envelope report_schema with collected fields nested under `fields`. The task fork hint is structural: task-class serves carry `execution: fork-preferred`. Verified with go vet, the full test suite, and golangci-lint green, plus an MCP end-to-end run confirming the evaluate→capture handoff, the chooser step id, and the fork-preferred hint on the real serve surface. New tests cover declared-remap handoff, seedless-option and procedure-guard inheriting nothing, the load-time source guard, anchor inherit, the seed-never-skips-a-chooser invariant, and answer-schema field nesting.
