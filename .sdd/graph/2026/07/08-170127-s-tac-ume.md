Cross-repo references ship undocumented — the README and skills carry nothing on connecting repos, and one non-obvious mental-model point in particular needs stating plainly: a connected-repo cache is a git clone of pushed state, not the working tree. Surfaced during the outer validation of cross-repo references (20260708-151819-s-tac-cr0), where the whole onboarding path had to be worked out from source. The closing done (20260708-010505-s-tac-94a) explicitly deferred 'the skill and reference-doc updates named in the plan's attached spec' as follow-up outside the acceptance criteria, and the README has never covered the feature. What needs documenting, end to end: giving a repo an identity (repo_id derivation via `sdd init`), connecting a repo, the user-global config and shared embedder, and eager indexing. The sharpest single point to call out: because a connected cache is a clone of the remote's pushed branch, a freshly captured entry resolves across repositories only after it is committed and pushed — not merely saved locally — and the cache refreshes on `sdd repo sync`; this is easy to miss and fails silently. Sequencing matters: this documentation should be written against the refined surface these findings propose — the unified config overlay and `sdd config` (20260708-153545-s-cpt-m4j), and connections as committed directed dependencies with the `sdd init` prompt-to-add resolution (20260708-164349-s-cpt-9ql) — not the as-shipped surface, which is about to change; documenting current behavior now would document a moving target. Proposed direction (not yet a committed decision): once that refined surface lands, document the cross-repo onboarding end to end in the README and the skills, stating the pushed-state cache model explicitly. This is the seed for the README improvement work already on the table.
