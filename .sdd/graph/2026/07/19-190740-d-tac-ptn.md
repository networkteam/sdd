The derived base-fact index, its `indexed` view filter, and the Markdown reference will be implemented end to end across the graph model, ordinary authoring and inspection surfaces, the view pipeline, the user-dialogue shell, and a fresh-agent evaluation anchored on the done signal that ships the change.

The work lands in three independently verifiable slices:

1. **Metadata and derived read.** Add a nested fact-only `index` value object with required `title` and `topic`; round-trip and validate it; expose it through capture, the application/command paths, a single JSON-object CLI flag, and `show`. Add a pure model read over active local-plus-embedded facts, ordered by topic/title/full ID. Enrollment is explicit on each active entry and does not inherit across supersession.
2. **View filtering, opening discovery, and Markdown reference.** Add a zero-argument `indexed` view filter that selects entries carrying the metadata and composes with `active`, `topic`, ranking, paging, and ordinary renders; it neither implies active state nor adds special title rendering. Register a graph-derived `factIndex` workflow query and inject it into the user-dialogue opening serve, rendering full canonical IDs and standalone titles from data rather than hard-coded IDs. Refactor the view-layout reference around shared semantic data so terminal help stays terminal-shaped while the indexed base fact becomes native Markdown with grammar and example layout specifications.
3. **Behavioral closure.** Verify unit, integration, and binary smoke surfaces, then capture the implementation done signal and run the outer evaluation against that done signal in a fresh agent context. The benchmark is discovery before the first view call: the agent must use the opening cue to pull the fact and compose a nontrivial layout without grep, source inspection, or syntax guessing.

Implementation details, resolved boundary questions, and the verification matrix are attached.

## Acceptance criteria

- [ ] Entry frontmatter supports `index: {title, topic}` as one nested value; it round-trips through parse/format, is valid only on `kind: fact`, requires both trimmed values, and requires `index.topic` to be a valid member of the entry's ordinary `topics`.
- [ ] The same nested value is supported through engine capture, application `EntryDraft`, command construction, and `sdd new --index '<JSON object>'`; capture playback and `sdd show` expose it exactly, and invalid/partial/non-fact use fails loudly.
- [ ] A pure model-derived index selects only active indexed facts from the current project graph after embedded/project merge and lifecycle resolution, excludes connected dependency graphs, does not inherit metadata to a successor, and sorts deterministically by topic, title, then full ID.
- [ ] The view language accepts a zero-argument `indexed` filter that selects entries carrying `index` metadata, rejects arguments and `source(wip)` use, and composes with `active`, `topic`, ranking, paging, grouping, and ordinary render terminators; `active:indexed:as-list` selects the same population as the shell index without introducing a special render shape.
- [ ] The user-dialogue opening serve injects the derived index and renders each row as a compact Markdown pointer containing the full canonical ID and standalone title; the procedure contains no fact IDs and omits the block when no entries qualify.
- [ ] The shipped view-layout fact enrolls with topic `cli/view` and title `How to compose graph views (view tool): layout grammar, filters, ranking, quoting, and examples`.
- [ ] The view-layout fact body uses host-neutral Markdown headings, fenced grammar and example layout specifications, and readable tables or lists; it removes the “debugging” framing, documents `indexed`, and names no CLI or MCP command.
- [ ] Terminal `sdd view --help` and the Markdown fact are rendered from one shared grammar/vocabulary/example model; both retain complete live vocabulary coverage—including `indexed`—while preserving their distinct host-specific versus host-neutral presentation contracts.
- [ ] Tests cover serialization and validation, authoring propagation, active/superseded/overridden selection, deterministic ordering, `indexed` filter parsing and composition, show output, shell injection, Markdown structure, host neutrality, vocabulary completeness, and unchanged terminal-help behavior.
- [ ] The rebuilt binary passes targeted tests, `go test ./...`, `go vet ./...`, `golangci-lint run ./...`, plus smoke checks for `sdd view --help`, `sdd view --layout='active:indexed:as-list'`, `sdd show` of the indexed fact, and a fresh session opening.
- [ ] After an implementation done signal is captured, a fresh-agent outer evaluation anchored on that done signal demonstrates that the agent notices the opening title, pulls the full-ID fact before its first view call, and composes a nontrivial layout without grep, source inspection, or syntax guessing; failures are captured as new signals.
