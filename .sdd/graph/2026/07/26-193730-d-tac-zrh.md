Full type capture will make the shared engine capture path construct, validate, guide, and render every current SDD entry kind before bootstrap parity work resumes. The plan is grounded in the live bootstrap evaluation that exposed actor/role, annotation, and kind-routing failures (20260722-140955-s-tac-lgc), implements the current 7+8 kind contract as an actual capture capability rather than only a storage model (20260702-222259-d-cpt-7iy), and refines the existing capture procedure whose flat alternative gate produced irrelevant instructions (20260703-094500-d-prc-cap). It directly addresses the kind-conditional diagnostic failure (20260722-141852-s-tac-dhn) and the missing annotation capture path (20260722-141909-s-tac-6rd).

The knowledge layer follows the graph-local pull architecture: ship one indexed overview fact for the complete type system and one unindexed detail fact for each current kind. The overview names the closed kind-to-type mapping, common entry structure, and references to every detail fact; the detail facts carry kind-specific composition guidance and examples. This realizes the base-fact pull-layer directive (20260707-140544-d-cpt-dtv) while preserving the derived active-fact index contract (20260719-133529-d-cpt-qhn). Exact fact prose is implementation-owned and may improve through ordinary supersession; the overview/detail topology and indexing behavior are the stable mechanism.

The capture procedure becomes structural. An agent reports `entryKind` and may batch every already-known draft field at the same time; classification enters a concrete kind assembly lane, which serves concise guidance plus the relevant detail-fact pointer. A generic carried-instruction facility accumulates ordered instruction units traversed during a successful cascade and returns them alongside the final current unit, with per-block content-hash deduplication at the host boundary. A knowledgeable agent can therefore start capture and then report kind plus a complete draft in one second call, receive the lane guidance, and land directly at playback. A stalled lane remains the current serve and is not duplicated as a carried block.

Required-field rules are not copied into procedure expressions. A single reusable new-draft construction and structural-validation boundary owns common requirements and every kind-specific invariant; the engine exposes that boundary as `reportedDraftValid` for this plan. Graph-dependent validity such as reference resolution, current actor/canonical binding, and involvement targets stays in separate graph helpers, while session evidence such as inspected references remains a separate predicate. Reports remain incremental patches under the present engine: lane fields use optional collect markers so corrections need not resend the whole draft, while `reportedDraftValid` decides completeness over accumulated state. The overloaded collect semantics are accepted here and carried into a separate engine-design gap rather than blocking this plan.

Strict capture validation applies only to new drafts and writes. The shipped GraphFinder continues loading all parseable historical entries and returning document problems and structural drift as health data; this plan introduces no compatibility read mode and no new load blocker. The implementation extracts and reuses the existing application/model draft-validation boundary so CLI/application writes and engine capture cannot drift.

The read side gains a live-head contract. Default `show` resolves the requested primary transitively through supersession, preserves the requested-origin to resolved-head breadcrumb, and resolves every relationship-tree node to its live head. An `exact` option keeps only the requested primary literal; relationship nodes still follow live heads. Pure resolution and tree construction live in the model, finder orchestration returns origin, resolved primary, and breadcrumb, and the query, CLI flag, application mapping, and MCP argument expose identical semantics.

Presentation scope is explicit. `show` is directly covered for every structured kind and for live-head/exact rendering. `view` receives regression coverage for kind counts, filters, topics, and participant behavior. Catch-up receives regression coverage, especially that annotation signals do not leak into narrative lanes. The frozen legacy `/sdd` skill remains unchanged under the engine-primary transition decision (20260715-175731-d-cpt-p3k); bootstrap parity evaluation, not this plan, decides its retirement.

## Acceptance criteria

- [ ] One indexed overview fact describes the active type system, maps every current kind to signal or decision, and references one unindexed detail fact for each current kind; the compact fact index remains derived from active fact metadata.
- [ ] Every current kind has a concrete capture assembly lane with concise served guidance and a pointer to its detail fact, including full annotation capture.
- [ ] Kind-specific fact prose is authored during implementation and covered for required structure without making its initial wording an immutable plan artifact.
- [ ] One reusable new-draft validator owns common and per-kind structural requirements; procedure expressions do not duplicate required-field lists, and graph checks plus session-inspection evidence remain separate.
- [ ] CLI/application writes and engine capture use the same strict new-draft construction and validation boundary, while GraphFinder historical reads retain their current partial-load and health-reporting behavior.
- [ ] Generic carried instruction units preserve ordered guidance across successful cascades, are deduplicated independently by content hash, and do not duplicate the current stalled unit.
- [ ] A table test proves the ideal path: start capture, report kind plus a complete draft, receive the traversed lane guidance, and arrive at playback without another report call.
- [ ] Table-driven capture coverage exercises valid and invalid drafts for every current kind and returns only diagnostics relevant to the selected kind.
- [ ] Default `show` resolves the primary and every relationship node to live supersession heads and returns an origin-to-head breadcrumb; primary-only exact mode preserves the requested historical primary while keeping relationship nodes live.
- [ ] Model, finder, query, CLI, application, and MCP tests prove identical live-head and exact behavior.
- [ ] `show` renders all structured kinds; `view` regressions cover counts, filters, topics, and participants; catch-up regressions keep annotation out of narrative composition.
- [ ] No bundled or installed `/sdd` skill prose changes as part of this plan.
