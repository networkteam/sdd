Commit 990b1d9 completes the opt-in legacy-session compatibility plan: >=0.16 runtime scans now ignore legacy and unreadable legacy records without blocking healthy sessions, while direct legacy access returns a typed, host-neutral migration-required error. This retires 20260714-105448-d-tac-kag because every acceptance criterion is implemented, and closes the reproduced startup/migration gap 20260714-103304-s-tac-rcv.

The local filesystem converter preserves every legacy engine-event payload byte-for-byte inside the current envelope, synthesizes routing metadata from the historical log, restores participant, label, timestamps, and parked instance state, and moves legacy staging files into session-owned staged-blob storage with their original attachment handles. Replacement is same-directory atomic and idempotent; pre-replacement failures clean up newly staged blobs and leave the legacy log untouched.

`sdd init` detects remaining legacy records on every run. Interactive users must confirm that no session server is active; declining leaves all sessions unchanged while normal init continues. Non-interactive migration requires the explicit `--migrate-sessions` acknowledgement. The handler migrates sessions independently, logs each failed path, continues the sweep, and returns a non-zero joined error after the normal init lifecycle completes. The runtime therefore also remains healthy if a pre-0.16 server creates another legacy record later. This realizes the migration point deliberately deferred by 20260712-194427-d-tac-wjq without automatic read-time rewriting or liveness heuristics.
