An adaptive bootstrap procedure will establish enough shared understanding of a fresh or sparse project's world for meaningful SDD work, using user-paced dialogue, optional lenses, and dependency-ordered capture clusters instead of a mandatory onboarding sequence. It supersedes the first version of this plan (20260718-175730-d-tac-3y2) after a dedicated review of its user stories, UX, and engine mechanics: the structure stands, while the review reshaped the cluster-confirmation surface, specified the cold open, honest-scoped the resume promise, folded focus support and deliberate topic-landscape founding into scope, and verified every engine claim against the engine source.

Bootstrap addresses the open bootstrap-port gap (20260716-144333-s-prc-7ku) by dissolving the ordering contradiction it records: readiness, brownfield context, WHAT/HOW/WHY, actors/roles — and now focus — are optional conversational lenses, not gates. The legacy ordering insight (20260505-121556-d-prc-cgc) is retained concretely as an encoded default recommendation bias: on a sparse graph the agent warms up project framing before inviting self-description, rather than leaving that to judgment. The cold open is specified: on a truly empty greenfield graph the fixed opener is the briefing frame — "imagine you're bringing someone on board to help with every aspect of this project; what's the one thing they need to understand first?" — whose answer is a pointer the agent classifies against the lenses and follows; when brownfield synthesis exists, a grounded opener replaces it ("here's what I read from the repo — does it match, what does it miss?"). Bootstrap is auto-recommended only on a truly empty graph; every later, deepening run is user-initiated, so re-offering skipped lenses cannot become nagging.

Bootstrap runs as a persistent outer procedure on the engine model (20260702-220449-d-tac-ry0); every serve injects a slim capped view (active actors/roles, conceptual guiding directives, strategic guiding directives, aspirations), fresh per serve, so loop-backs re-ground automatically. The interview posture builds on the interview procedure (20260706-180000-d-prc-int): journalist stance, one balanced question per turn, question stock as reservoir, concise answers valid. Brownfield repository inspection remains host-agent work under served instructions.

The review reshaped cluster confirmation: the cluster proposal is a meaning-level replay — the agent plays back its understanding as the prose that would be captured, and the user verifies framing and words, since bootstrap users may be at their first SDD touchpoint and cannot meaningfully review field taxonomy; field structure (kinds, layers, topics, refs) is the agent's job. Each accepted entry still writes through a parented shared capture (20260703-094500-d-prc-cap) — exact playback, explicit confirmation, pre-flight, and summary verification all retained — but playback fidelity instructions adapt to recognition of already-approved words, not a second field review. Captures run in dependency order per the resolve-or-block invariant (20260628-130400-d-cpt-uh0). The engine deliberately gains no child-to-parent produced-ID mechanism: the agent reports each produced ID and the refreshed synthesis into outer state at the beats where it already talks to the engine (cluster proposal, capture completion, direction junction). Outer state exists because beats are free carriers, guards need a few fields, and the state machine rails the agent into the sequence more reliably than prose instructions; the honest resume promise follows — a resumed run recovers the graph plus state as of the last beat, and dialogue-only material since then is re-derived, which capture-while-fresh makes acceptable. Unsettled candidates stay in outer synthesis; parking is reserved for one interrupted in-progress capture. On a fresh graph the first captured cluster also founds the topic vocabulary deliberately — taxonomy talk before any entry exists is friction and after-the-fact annotation is ceremony, so the agent mints labels during capture and, once the cluster lands, proposes a small nested topic landscape with stable bases for discussion, which later captures reuse. There is no readiness score: one actor and at least one framing signal or decision are the indispensable foundation for handoff via the catch-up procedure (20260703-194500-d-prc-cat), which re-reads the updated graph.

Engine scope, verified against source: the engine write path cannot currently produce actor, role, or focus entries — the engine's entry draft and newEntry command carry no canonical/aliases, actor linkage, or involvement fields (the CLI-side command already does), capture declares no such state, no presence predicates exist for them, and the assemble gate's refs-and-topics requirement structurally blocks kinds without natural refs. This plan folds all three kinds into scope, addressing the focus wedge (20260707-162940-s-prc-g0j) rather than rebuilding the same wall beside it, in two slices: actor/role first (bootstrap's hard dependency — handoff needs an actor), focus second (heavier: involvement triples, per-involvement overrides, when ranges), with focus as an optional lens captured only when the user describes a next-steps direction. Write-gate validation failures re-serve actionably instead of wedging. The capped readiness view is a new layout string over existing filter vocabulary; the procedure itself is a base entry needing no Go registration. The attached design record (v2) preserves the user stories, dialogue shapes, opener candidates, rejected alternatives, corrected engine-mechanics analysis, and tone contract.

## Acceptance criteria

- [ ] A canonical, discoverable `bootstrap` procedure can be started as a long-lived outer move and retains its current lens, readiness synthesis, brownfield synthesis, interview transcript, phase synthesis, unsettled candidates, produced entry IDs, and user direction across loops and park/resume, with state current as of the last report beat.
- [ ] Each serve injects a capped graph view covering active actors/roles, conceptual guiding directives, strategic guiding directives, and aspirations, then serves a concise summary of what is established and what appears missing; it does not inject the full graph or compute a numeric completeness score.
- [ ] On a truly empty graph the served opener is the briefing frame; when brownfield synthesis exists the grounded repo-synthesis opener replaces it; the instructions direct the agent to classify the answer against the lenses and follow it.
- [ ] The frame-before-self-description bias is encoded as the default recommendation on sparse graphs: project framing warms up before the user is invited to self-describe.
- [ ] Bootstrap is auto-recommended only on a truly empty graph; repeated runs are user-initiated, reconstruct coverage from current graph state, skip already-covered areas, and may deepen any incomplete area without replaying a fixed sequence.
- [ ] Brownfield guidance instructs the local host agent to inspect and synthesize relevant repository instructions, README material, stack/manifests, structure, and recent activity as appropriate; the engine performs no repository or Git inspection.
- [ ] Readiness, brownfield context, WHAT, HOW, WHY, actors/roles, and focus are optional lenses selected from graph gaps and dialogue, not mandatory ordered gates; focus is engaged only when the user describes a next-steps direction; the agent recommends a warm direction while the user can continue, deepen, redirect, skip, or finish.
- [ ] Interview instructions use journalist posture, ask one balanced question at a time, accept sufficient concise answers, and treat possible questions as a reservoir rather than requiring exhaustive traversal.
- [ ] When a coherent cluster forms, bootstrap pauses questioning and proposes it as a meaning-level replay — the understanding in the prose that would be captured; the user can reshape, defer, keep exploring, or accept; field taxonomy is not duplicated into the proposal for user review.
- [ ] An accepted stable cluster dispatches one parented `capture` sub-move per entry in dependency order while context is fresh; every child retains exact playback, explicit confirmation, pre-flight, and summary verification, with playback fidelity instructions adapted to recognition of the already-approved words.
- [ ] After each child capture completes, the agent reports the produced entry ID and refreshed synthesis into outer state at that beat, so later captures can seed resolvable references and a cold resume reconstructs the true picture from last-beat state.
- [ ] Unsettled candidates stay in the outer bootstrap synthesis; a parked child represents only an interrupted in-progress capture and is not used as a phase backlog.
- [ ] After every captured cluster, bootstrap refreshes its slim graph grounding and returns to dialogue with a lightweight choice to continue, deepen, redirect, or finish.
- [ ] On a fresh graph, bootstrap raises the topic landscape after the first captured cluster, not before: the agent proposes a small set of nested topic bases (family/member) derived from the captured entries and dialogue, the user reshapes or accepts it, and subsequent captures reuse those bases rather than minting flat ad-hoc labels.
- [ ] Bootstrap may recommend catch-up handoff once the graph contains at least one actor and at least one framing signal or decision, without requiring direction or aspiration gates; catch-up re-reads the updated graph.
- [ ] Slice 1: the engine write path and shared capture support actor entries (canonical identity, aliases) and role entries (role-to-actor linkage) end to end — engine entry-draft and newEntry command wiring, capture state fields, presence predicates, a kind-conditional assemble gate that does not demand refs/topics for kinds without them, kind-specific assemble guidance, exact playback, validation, persistence, and generated-summary verification.
- [ ] Slice 2: focus entries (involvement triples, focus actors, when ranges) flow through the same surfaces, closing the focus capture wedge (20260707-162940-s-prc-g0j).
- [ ] Write-gate validation failures re-serve actionably — naming the violated rule and missing field and routing back to a step that can fix it — instead of wedging the instance.
- [ ] Actor, role, and focus entries created through the procedure render correctly through existing `show`, `view`, and catch-up presentation surfaces; no new rendering semantics are introduced unless testing exposes a concrete gap.
- [ ] Procedure tests cover empty and partially bootstrapped graphs, skipped lenses, shallow and deep user-directed interviews, multiple clusters within one lens, dependency-ordered references, cluster deferral, child interruption/resume including cold resume from last-beat state, repeated fresh runs, resumed runs, actor/role/focus capture, topic-landscape founding, and catch-up handoff.
- [ ] A live local-agent evaluation demonstrates that bootstrap feels like shared orientation rather than a questionnaire, that repository inspection stays host-side, and that the legacy `sdd-bootstrap` skill is not retired until procedure parity is evidenced.
