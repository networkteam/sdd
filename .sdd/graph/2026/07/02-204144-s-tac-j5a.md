Agents running the widen discipline make several search calls from different angles — separate queries and terms — and the result sets overlap, so the same entries come back and get re-read across calls: wasted tokens and slower grounding, precisely on the discipline the framework prescribes. A multi-search call accepting a list of probes (query phrases and term patterns) in one invocation and returning a single fused, de-duplicated result set would make honest widening the cheap path. The shipped search already fuses one query+term pair via RRF in hybrid mode; multi-search generalizes that fusion to N probes. Open design questions: ranking across heterogeneous probes, and how citations attribute hits to the probes that found them.
