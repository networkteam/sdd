Make post-compaction reorientation reachable and self-triggering through three changes to the MCP session surface, realizing the reorientation-guarantee directive (d-cpt-xgq) and closing the reach gap (s-cpt-h31). The core change is cheap because the machinery already exists: resume_session already receives the connection and already holds the currently-bound session, and its resumeResult already computes the exact recovery payload — framing plus every running move's current serve with its report schema. Today two guard lines reject the case we need (an empty session, and a session equal to the current one); relaxing them so an omitted session re-serves the current bound session — no rebind, no leave — is the whole capability, and it is strictly better than start_session's re-serve because it returns each running move's step schema rather than only the shell junction. The second change is the durable-channel half: rewrite the resume_session tool description so it triggers on the symptom an amnesiac agent can recognize in itself — it no longer holds its session or instance handle, or its context was compacted or summarized mid-session — states the handle-free "re-serve the session this connection is already in" operation, and makes clear it returns each running move at its current step with the schema to continue it. The third change routes any agent home regardless of what it remembers: every serve that carries open running moves foregrounds a short reorientation breadcrumb naming the open move(s) and how to continue (next) or reorient (resume_session), so a compacted agent is guided by whatever call it happens to make next rather than having to rediscover the recovery tool on its own. Wording stays host-neutral throughout (no harness names). The unbound-connection bootstrap already works and is left intact: a call on a connection with nothing bound returns the parked-session list by handle and label.

## Acceptance criteria

- [ ] resume_session accepts an omitted session: on a connection already bound to a session, it re-serves that session's live position — framing plus every running move at its current step, each with its report schema — without rebinding or parking; passing the current session's own id behaves identically instead of erroring.
- [ ] On a connection with no bound session, a no-session resume_session returns the parked-session list (handle + label) so the agent can pick one to resume (existing bootstrap path preserved).
- [ ] The resume_session tool description leads with the recognizable symptom (no longer holding the session/instance handle; context compacted or summarized mid-session), names the handle-free re-serve-current operation, and states that it returns each running move's current-step schema; wording is host-neutral.
- [ ] Every serve carrying one or more open running moves includes a reorientation breadcrumb that names the open move(s) and how to continue (next) or reorient (resume_session).
- [ ] A regression test drives the post-compaction path end to end: a no-session resume on a bound connection returns the running move's current-step report schema — the field the observed thrash had to reconstruct from memory.
