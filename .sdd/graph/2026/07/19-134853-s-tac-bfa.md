The binding-wipe defect is fixed in commit 0741332 on the session-model worktree branch: `runWorkflowNewEntry` now adopts `result.Binding` only on success (`if err == nil`), matching the guard all four sibling mutation commands already carried, so a validation-rejected capture write leaves the connection's session binding fully intact instead of wiping it to an empty session ID. The commit closes the gap it retires (20260719-123145-s-tac-tq7) with the exact fix direction recorded there. The regression is pinned by a connection-level test (`TestRejectedWriteKeepsConnectionUsable` in mcpapp): a capture-shaped probe procedure drives a real dangling-ref rejection through the production MCP surface, then asserts the same connection's `show` still answers and a no-args `resume_session` re-serves the same session handle — verified red against the unfixed code (failing with the live incident's exact `sdd: invalid session ID ""` symptom) and green with the fix. An independent review traced every `CreateEntry` error path before approving: the one behavioral delta — error paths that return an advanced store version whose binding is now discarded — is self-healing, because the next session append catches the version conflict and resyncs before retrying, the identical convention the sibling commands already rely on; the high-severity-findings path is a no-op change since it returns a nil error with the binding unchanged. Findings storage on a failed write is deliberately untouched. go vet, the full test suite, and golangci-lint are clean. Implementation and review were run by delegated agents with the fix applied during the same live evaluation session (20260718-180550-d-tac-e3x) that surfaced the defect. Deployment note: long-running `sdd serve` processes keep the unguarded binary until restarted — restart them when this branch lands.
