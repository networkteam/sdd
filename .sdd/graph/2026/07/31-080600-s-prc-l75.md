Working on SDD through SDD collapses the boundary between subject and instrument, and dialogue in this repo degrades into framework-referential circling that produces bad reasoning instead of movement. Christopher stopped a long session to name it: the work had been going in circles inside the repo for some time, and the dialogue had to change angle or end.

The symptoms are specific. Reasoning reaches for the framework's own structures as substitutes for thinking — a countable metric, an existing entry that resembles the point, a classification slot, the current arrangement of things — and each substitution feels like grounding while adding nothing. Corrections land on instances rather than classes, so the same error repeats after being named; in the session that surfaced this, five corrections on one entry addressed one recurring error. Existing entries get cited as confirmation on the strength of resemblance, which is worse than citing nothing because it supplies a false floor to reason from. And the participants' stated positions go unused while the agent works its own instrument instead, which is the alignment failure underneath the rest.

The cost is the dialogue itself, not the artifacts. Entries still get produced, correctly shaped, passing every mechanical gate — and that is what makes the failure hard to see from inside. What degrades is the reasoning: sessions generate work about how the framework records things while nothing changes outside the repo, and the graph feeds itself. The audience boundary between project-specific and framework-generic content is already committed for authored artifacts (20260730-101601-d-cpt-r99); this is the same boundary missing one level up, in how the work is thought about rather than in where its output lands.

This sits beside the cross-project agent-discipline thread (20260528-170354-s-prc-uq8) without being an instance of it: the shallow-on-pushback mode it documents is precisely what recurred, but its generative-mode shortcut describes pattern-matching against training-data shapes, where the failure here was the opposite — over-grounding in this project's own material. What causes the circling is recorded separately as an insight; this entry records that it happens and what it costs.
