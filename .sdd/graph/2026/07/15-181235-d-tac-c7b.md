The v1 SDD documentation site ships seven sections — The idea, Quickstart, Concepts, Guides, Reference, Customizing the process, What's ahead — presenting engine mode as the way SDD works, with every example produced by genuinely running sdd against a purpose-built roastery example graph grown from the founding story. This is the structure plan and content-sourcing map the planning activity (20260715-174037-d-cpt-eke) committed to as its expected landing — its completion is recorded by a separate closing done signal now that this plan exists — and it responds to the user-documentation gap (20260715-172002-s-cpt-i5a), which stays open until the docs actually ship. The full page tree with per-page sourcing is in the attached record; the plan hands the content spec to the site-stack implementation already running against the stack directive (20260715-173844-d-cpt-o0r). Four design principles govern the work. First, every explanation earns a visualization — a prose-only concepts page is not done — and because the visual language cannot be specced in prose, an early style spike gates the bulk of authoring: one concepts page fully designed, approved by Christopher on the rendered site. Second, real mechanics in a distinct example world: docs examples are never mocked up and never meta — a real .sdd graph is built for the story's coffee roastery and all example output is genuinely produced against it, keeping the SDD-building-SDD dogfood graph out of the learning path; this rests on the insight that produced artifacts are trivially generated while usage evidence is the credible signal (20260420-163550-s-cpt-l2q), and on the observed meta-confusion of readers seeing SDD described through SDD building itself. Third, people first: communication leads with people, dialogues, and knowledge curation — the technical part is learnable step by step below. Fourth, v1 documents the current working state only, with planned and in-discussion work confined to a clearly marked outlook. Settled calls folded in: engine mode is documented as the primary flow with /sdd at most a legacy note (20260715-175731-d-cpt-p3k); the contract kind is omitted from the vocabulary reference since the rules plan deprecates it (20260622-084244-d-tac-eho); the story ships as a light edit of docs/story.md explicitly framed as founding vision; the single-loop framing is replaced by "How the graph moves" — moves as interleaved mini-loops with an honest current-vs-planned split on human and agent roles. The connecting-repositories guide absorbs the open cross-repo docs gap (20260708-170127-s-tac-ume), stating the pushed-state cache model plainly. The outlook is anchored by the knowledge-flow narrative — knowledge goes in, gets used, enhanced, shaped, and goes out — built from the decided intake model (20260603-172628-d-cpt-fbi) and the open outbound emit-and-mirror gap (20260617-182152-s-cpt-yve), alongside rules v1, base facts, and the hosted-webapp direction.
