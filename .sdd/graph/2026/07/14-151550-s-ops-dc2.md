Commits cfc755b and e23a8c8 make `sdd init` own the filesystem GraphStore runtime ignore rule, closing 20260714-150222-s-ops-c5c without treating durable runtime state as disposable. The init handler now derives `<graph_dir>/.sdd-runtime/` from the configured graph directory and adds it through the existing idempotent managed-entry path, so the default `.sdd/graph/.sdd-runtime/` and custom graph locations are both covered on fresh and upgraded projects. The fresh-project and idempotency tests assert the new entry, and a dedicated custom-graph test prevents regression to a hardcoded default. `go test ./...`, `go vet ./...`, `golangci-lint run ./...`, and the local build pass. Running the rebuilt `sdd init --scope project` then added the rule to this repository through the product path and auto-committed it; `git check-ignore` confirms the existing `graph.lock` is ignored by that exact rule. This extends the canonical idempotent readiness behavior established by 20260428-125737-d-tac-kud.
