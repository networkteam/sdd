The capture procedure's playback unit is written for a single full presentation and gives no guidance for re-serves: on the first live run, after each adjust the agent improvised a delta view — showing only the changed field with "rest unchanged" — drifting from the unit's "show the description verbatim" contract. The improvisation was sensible UX, but what to re-show after a one-field adjust should be the prose's call, not the agent's. Engine correctness is untouched: the confirmation-staleness pair already reopens playback on any edit after confirm, so the write can never bind to an unseen state. The fix is prose in the embedded capture entry — explicit re-playback guidance (full presentation on first serve, delta with an offer to re-show in full on re-serves, always the full body again before a confirm that follows adjustments to it) — editable in the entry source pre-release, surfaced by the first dogfooding run of the v1 workflow engine plan (20260702-220449-d-tac-ry0).
