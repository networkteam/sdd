This plan repairs the MCP view tool's four agent-stranding surfaces with independent mechanical fixes and ships the first base fact — a view-grammar reference rendered at graph load from the executor's live vocabulary tables, paired with a first-hit hint on the view tool — as the first concrete slice of the base-facts pull layer. It implements the improvement direction recorded in the tool-usability gap (20260717-095714-s-tac-lwi) and realizes part of the base-facts commitment (20260707-140544-d-cpt-dtv): the embed-and-merge mechanism for `fact` entries plus the first shipped fact, while the served facts index and vector-index coverage of embedded entries stay with d-cpt-dtv as future work. Two shaping choices. First, the fact body is rendered at load from the same Go tables the executor dispatches on (known functions, macros, render terminators, rank algorithms, plus the grammar's quoting rules and pipeline shape) rather than hand-written or produced by a go:generate step — a hand-written fact repeats the viewHelpText drift already observed, and a generate step is a forgettable sync discipline, drift by another name; load-time rendering leaves exactly one source. Second, the first-hit hint carries only a pointer — the fact's entry ID and a one-line cue — never grammar content, so no fourth knowledge home opens up; text search already operates on the in-memory graph, so the fact is findable today without indexer changes. Explicit carve-outs: the served index over all base facts (its own story per the gap dialogue), participant alias resolution (observed in the gap, not committed here), and regenerating the CLI `viewHelpText` from the same tables (subject of a separate capture in flight).

## Acceptance criteria

- [ ] The unknown-function error lists macros alongside primitives, labeled as such, so a failed guess like `recent(15)` teaches the full vocabulary including `top`, `focus`, `done`, `wip`.
- [ ] Parser errors caused by unquoted multi-word, date, or duration arguments carry a quoting hint with a concrete example (e.g. `since("7d")`, `participant("Jonathan Philipp")`).
- [ ] An empty view result over MCP never returns a bare empty string: it states that 0 entries matched the pipeline, and when a participant filter was active it names the participants the graph knows.
- [ ] MCP view responses have a default size guard: over-limit output is truncated with an explicit notice naming `n()` paging as the recovery.
- [ ] A base-facts mechanism ships embedded `fact` signals merged into every graph on load, mirroring the base-procedures pattern (Embedded-marked, no participants, no project refs, stable IDs).
- [ ] The view-grammar fact's body is rendered at load from the executor's live vocabulary tables — no hand-maintained duplicate exists, and a vocabulary change in code changes the fact with zero manual sync.
- [ ] The view-grammar fact resolves via `show` by its stable ID and surfaces in text search.
- [ ] The first view call in an MCP session carries a one-line hint pointing to the view-grammar fact's entry ID; subsequent view calls in the same session omit it.
