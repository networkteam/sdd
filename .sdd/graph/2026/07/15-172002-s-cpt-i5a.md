SDD lacks a coherent user-documentation surface: external feedback reports that people cannot build a working understanding of the framework from the material that exists today. What exists is a positioning-focused README (rewritten for outcome-first framing and workflow coverage, 20260417-194635-s-prc-b9y), insider-oriented narrative docs (docs/story.md, docs/signal-dialogue-decision.md), and agent-facing skills — none of which form a deliberate learning path. The feedback named step-by-step material as the missing piece, but the gap is broader: documentation for SDD means introducing the ideas and philosophy, explaining the concepts, guiding first steps, and providing reference — and which of these belong in a v1 set is itself an open question to settle. Scope constraint set at capture: v1 documents only the current working state, with a clearly separated outlook on features that are planned or in discussion — the graph's open decisions supply that outlook directly. Proposed direction (not yet committed): publish a documentation site from markdown/MDX sources living in this repo — an open-source, agent-writable generator with modern layout, agent-native affordances such as copy-page-as-markdown, and lightweight GitHub Pages publishing; tooling choice and information architecture follow as separate decisions. This generalizes the narrower feature-scoped docs gap on cross-repo onboarding (20260708-170127-s-tac-ume), which already flagged README improvement as being on the table, and sits beside the MCP setup-friction gap (20260611-092625-s-cpt-4v3) as an adoption concern: the non-developer-reach aspiration (20260422-122523-d-stg-x0l) presupposes material people can understand without a developer translating.
