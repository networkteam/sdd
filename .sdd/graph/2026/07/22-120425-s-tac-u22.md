The shipped base-fact index (20260721-152753-s-tac-31o) treats a malformed index block with two contradictory strictness policies, and the stricter one can prevent every session from opening. Graph load records an invalid `index` (for example an `index.topic` missing from the entry's `topics`) as a soft warning and admits the entry, consistent with how all other frontmatter drift is handled; but `Graph.IndexedFacts` re-validates and hard-fails the whole derived read on the first offender, and because the `factIndex` query is injected into the user-dialogue opening step and inject errors abort the serve, one hand-edited malformed indexed fact in the project graph makes session opening fail entirely. The same split breaks the plan's population-parity promise: the structural `indexed` view filter (`Index != nil`) includes the very entry the shell index errors on. Exposure is limited to hand-edited entries — all write paths already hard-reject, and embedded base facts are build-validated — but hand-editable markdown is exactly the graph's design surface. Confirmed independently by two reviewers in the inner evaluation (20260722-115503-s-tac-a0o), with the severity verified by tracing the inject error path. The agreed remediation direction: make validity part of enrollment — one rule everywhere, a fact is indexed only if its `index` block is valid; both `FilterIndexed` and `IndexedFacts` select on valid enrollment via a shared check, malformed means load warning plus quiet exclusion (never an error, never inclusion), and hard rejection stays at the write paths. That restores population parity, keeps session opening robust, and collapses the duplicated strictness policy. A full hard error was rejected as not robust for this surface.
