The public root package is no longer a facade: it combines multiple independently meaningful surfaces into 23 production files and 4,501 lines under one namespace. The inner evaluation (20260713-165141-s-tac-78g) found identity and access contracts, application orchestration, project runtime, read and write DTOs, graph/session/blob ports, filesystem adapters, vector search, workflow execution, transition recovery, and registry rendering together in the root implementation governed by (20260712-234500-d-tac-x1m). The current import graph is acyclic but lopsided: mcpapp imports the root plus internal engine/query packages, sddtest imports the root, and the root reaches into ten internal subsystems. The desired boundary is a root sdd package containing only a very small facade—one or a few files—over cohesive nested public packages for the actual surfaces. A candidate direction is application for protocol-neutral behavior, ports for host contracts and canonical DTOs, and local for bundled filesystem/mechanical adapters, with mcpapp depending on application and sddtest on ports; nested packages must not import the root facade. The exact package count and type placement should follow a dependency audit of the cross-surface types so the split creates a clean directed graph rather than an arbitrary folder taxonomy.
