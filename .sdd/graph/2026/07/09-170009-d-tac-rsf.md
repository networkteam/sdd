Cross-repo references reach release readiness through structured follow-through on the inner and outer evaluations, executed as two batches — a code pass, then a documentation-and-coverage pass — after which the release tag can be cut. This plan pulls together the still-open findings from the cross-repo evaluation rounds (the outer validations 20260708-151819-s-tac-cr0 and 20260709-160634-s-tac-tt8 and the inner code evaluation 20260709-152356-s-tac-6n3), scopes which are release-critical, and defers the rest explicitly. It realizes two decisions already made — the redefined `sdd repo remove` (20260709-161424-d-tac-g8z) and bare-ID resolution (20260709-164325-d-cpt-xbx) — and grounds in the cross-repo design (20260606-003344-d-cpt-s6q) and the config-and-state placement directive (20260708-184318-d-cpt-6cq) whose surfaces these fixes extend.

Batch 1 is one cohesive Go pass across model, finders, handlers, CLI, and the MCP server: the dependency-lifecycle commands and their config-commit consistency (20260709-161317-s-tac-ol7) plus standing lint enforcement (20260709-161217-s-tac-dt0), bare-ID resolution, index reliability (the CLI/MCP embedder divergence 20260709-152514-s-tac-qbk and the `--force` repair path 20260709-152616-s-tac-chy), and the terminal-UX coordinator edges (20260709-161249-s-tac-bg7 and the text-only-search footer 20260709-152943-s-tac-jbm). Batch 2 documents the feature against the now-settled surface (20260708-170127-s-tac-ume) — README, per-agent skill templates, and served procedure/engine guidance — sequenced after the code so it never documents a moving target. Consolidating to two batches is deliberate: the fixes are small and interlocking, and the goal is one, at most two, implementation sessions rather than a fragmented slice-per-finding drip.

Deliberately out of scope: cross-repo query-latency profiling (already low-priority) and a groom-close of the config-misplacement insight (already realized by the placement directive). Cross-repo knowledge as embedded base facts is left to the separate base-facts focus rather than blocked on here — this release covers cross-repo in README, skills, and procedure text. Cutting the release tag itself is the final step via the release flow once both batches land.

## Acceptance criteria

Batch 1 — code:
- [ ] `sdd repo remove <repo-id>` behaves per d-tac-g8z: removes the committed `dependencies` entry from `.sdd/config.yaml`, auto-commits the change, refuses when any entry in this graph holds a cross-repo ref into the target, and offers `--force` that loudly names the refs it would strand; machine-level connection/cache/index teardown stays out of scope
- [ ] `sdd repo add` auto-commits its `.sdd/config.yaml` dependency-declaration write, consistent with `sdd init`/`new`/`summarize`
- [ ] `sdd lint` collects the distinct target repo-ids across all entries' cross-repo refs and reports any absent from the declared `dependencies`, giving resolve-or-block a standing check beyond capture time
- [ ] Bare entry IDs (short and unprefixed-full) resolve local-first then across the referring graph's declared dependencies — a unique match resolves, a collision errors with the candidates in full prefixed form — uniformly across `sdd show`, the `show` MCP tool, and move anchor resolution; refs written to entries always expand to full prefixed form
- [ ] MCP cross-repo vector search resolves the same global-first embedder as the CLI path, so both surfaces build and query one shared `(repo-id, fingerprint)` store
- [ ] `sdd index --repo`/`--all-repos --force` rebuilds connected member indexes, not only the local index, repairing stale or corrupt connected stores
- [ ] `sdd repo add` on the already-connected fast path does not start the coordinator view, so no DEC mode-query escape sequences leak to stdout or the shell prompt
- [ ] Ctrl-C during a long embed is recognized as user cancellation — clean teardown and exit, not a raw `context canceled` error with nonzero status
- [ ] Text-only `sdd search --repo` gives honest feedback for first-time cache clone/pull (a distinct label and/or streamed logs) rather than a mislabeled `indexing` footer

Batch 2 — docs & coverage:
- [ ] README documents cross-repo onboarding end to end: repo identity via `sdd init`, connecting a repo, the committed `dependencies` declaration, the shared embedder and eager indexing, and the pushed-state cache model (a connected cache is a clone of the remote's pushed branch, so a new entry resolves across repos only after commit and push, and the cache refreshes on `sdd repo sync`)
- [ ] The per-agent skill templates cover cross-repo authoring and onboarding guidance, rendered for each supported agent
- [ ] Served base-procedure/engine guidance reflects cross-repo where it touches capture (resolve-or-block plus the declared-dependency precondition), show/anchor bare-ID resolution, and cross-repo search (`--repo`/`--all-repos`)
