Shipped per-agent MCP registration in `sdd init` (commit e4e49d7), so engine mode works out of the box without manual setup (closes wfl) and Codex can sign auto-commits without hanging (closes ay1). Under project scope, init now writes — per supported agent, add-if-missing — the SDD MCP server registration alongside the skill render: for Claude Code a `.mcp.json` stdio `sdd serve` entry with `alwaysLoad: true` (so its tools skip the deferred-schema ToolSearch ceremony, s-tac-gt3) plus an `mcp__sdd__*` rule in `.claude/settings.json`; for Codex a `.codex/config.toml` `[mcp_servers.sdd]` table forwarding `env_vars = ["SSH_AUTH_SOCK"]` so `sdd serve` under Codex's filtered environment reaches the ssh-agent.

Config generation and merge live in `internal/model` (pure); the init handler does the I/O, tracks written files for the existing init commit, and gates the step to project scope. Writes are add-if-missing — an existing `sdd` entry, allow-glob, or `[mcp_servers.sdd]` header is left byte-identical, so the user owns any customization and re-init is idempotent. JSON round-trips through stdlib (keys re-order); TOML is text-appended to stay dependency-free and comment-preserving. This realizes Slice D's project-scope registration from the completion directive (dbk) without closing it — B and C remain — and user-scope registration is deferred to a follow-up.

Verified: go vet, golangci-lint, and the full suite green (new model + handler tests cover fresh-write, add-into-existing with preservation, present-entry no-op, malformed-input errors, and the user-scope skip); plus a live `sdd init --scope project --agents claude,codex` producing all three files with the expected content and committing them.
