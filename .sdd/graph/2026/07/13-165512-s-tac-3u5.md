FilesystemGraphStore can expose a partially applied canonical graph batch after returning MutationUnknown, violating the public atomic-apply contract. The inner evaluation (20260713-165141-s-tac-78g) reproduced this against the implementation governed by (20260712-234500-d-tac-x1m): a two-file batch prepared both temporary files, renamed the first successfully, failed while renaming the second over an incompatible target, and left the first file visible. The apply record remained unknown; because the graph revision had changed, Reconcile could neither classify the batch as not applied nor complete or roll back the partial state. The existing unknown-outcome test does not cover this failure mode—it injects lost acknowledgement only after the underlying store has fully applied and recorded success. Canonical apply therefore needs a storage design that prevents partial visibility or a durable journal that deterministically completes or rolls back interrupted batches, plus a mid-batch failure regression test.
