Fixed the flaky `TestE2E_HybridFusion` by scoping the finders e2e fixture's corpus to the entries each test actually writes, resolving the base-procedure contamination diagnosed in 20260706-183610-s-tac-qtz. The fixture's `loadGraph` helper now strips the embedded base procedures that `LoadGraph` injects into every graph, rebuilding the search graph from only the on-disk fruit entries. Because `runVector` filters index hits through the candidate set and `textSearch` iterates the same candidates, dropping the base procedures from the query graph removes them from both RRF arms — so the intended orange entry now appears in the vector rollup as well as winning the text arm, and its two fused contributions strictly beat any single-arm competitor.

The gap is retired because the root cause it named is gone: the effective corpus is deterministic and no longer depends on the fake embedder's collinear fallback vectors. This scope-the-corpus fix was chosen over teaching the embedder a citrus→orange synonym, which would have fixed only this one query and left the corpus contaminated for future e2e tests. The affected suite is the one delivered with `sdd search` in 20260505-181352-s-tac-96a, so this repair is the next step on that chain. Verified stable over 100 consecutive runs of the previously-flaky test and 20 runs of the full e2e suite, with `go vet`, `golangci-lint`, and the full `go test ./...` clean. Shipped in commit e11d9bf as a test-only change; no production behavior was touched.
