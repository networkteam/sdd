The groom procedure's sweep step (20260706-171500-d-prc-grm) probes for procedure forks by instructing the agent to run `sdd lint`, "which flags competing heads" — but unlike the stale-marker case, no engine capability backs this probe. The function registry exposes no query or view that surfaces competing procedure heads, so the instruction is a CLI shell-out with no engine equivalent, unreachable when the graph is not mounted locally. Closing it needs an engine-side path: either a `viewLayout`/query that surfaces competing canonical heads (the data `sdd lint` computes), or a reframe of the sweep probe that drops the fork shape until such a query exists. Recorded separately from the stale-marker gap because that one reuses an existing command while this one has no engine capability to route to yet.
