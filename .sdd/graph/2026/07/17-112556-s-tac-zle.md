Branch-targeted workflow writes can succeed on a work branch while the capture and implementation steps that immediately consume the new artifact still read the base/session graph, blocking the tracked closeout before landing. In a real worktree run, capture correctly persisted and committed the closing done on the explicitly selected work branch, but the generated-summary injection then reported the new entry missing; after that step was manually advanced using the stored summary, implementation's done-entry guard rejected the same entry because it also resolved against the base graph.

This builds on the completed local mutation-target delivery in 20260716-153108-s-tac-spx: mutation authority is branch-correct, but artifact-dependent reads, injections, predicates, and resume/re-serve are not yet consistently target-aware. It sharpens the implementation lifecycle in 20260713-214251-d-prc-pop because a closing done must remain consumable on the work branch throughout summary verification and the landing transition while the WIP marker remains on the base branch. The conceptual authority rule in 20260713-214050-d-cpt-65i therefore needs to apply to the complete workflow interaction with a written artifact, not only to mutations: once a write names a concrete branch target, every follow-up operation concerning that artifact must resolve through the same target until the workflow deliberately returns to the base authority.

A regression should exercise distinct base and work graphs with the new entry present only on work: confirm a capture seeded to the work branch, reach summary verification without merging, verify or replace the summary, report the produced entry as implementation's closing done, and reach the landing junction while the base-branch WIP marker remains. Resume and re-serve from the post-write capture state must follow the same target-aware path.
