In an engine-mode dialogue, the session orientation's open-threads / continuation-order block surfaces a concurrently-active session — one another agent or window is driving right now — as a resumable continuation option for this dialogue, without distinguishing a live-active session from a genuinely parked or idle one. The open-threads design (20260703-142447-d-tac-nqo) deliberately lists other open dialogues after the current dialogue's own threads, presented as continuation choices, but flags each only by label and last-active timestamp — never by whether that session is currently live. In this Slice C evaluation session the orientation listed 'Implement d-tac-y7l' (last active minutes earlier) as an open thread to continue; it was in fact an actively-running concurrent session, which led the agent to mis-read it as a parked thread and wrongly cite it as evidence that park survived a restart. The risk is twofold: an agent may resume into a session another participant is actively driving, and live concurrent work is presented as this dialogue's own pickup. Fix direction: surface session liveness/concurrency in the open-threads listing — distinguish parked-or-idle from active-elsewhere — so continuation options don't conflate them.
